# QA-B-103 게이트 — 출력이 바뀌지 않는 행 밴드 병렬화 (#179)

커밋 `d158d40`, 미푸시. 요구 초과 4건이 모두 요구 안으로 들어왔다.

## 1. 주장

### 구조

- `parallel_rows.h` 를 두 모듈에 각각 두었다(`enhance_advanced/src/detail/`, `enhance_basic/src/`). `modules/common` 은 다른 레인 소유라 공용 라이브러리를 쓰지 않았다. `perf_measure.h` 와 같은 방식이다.
  - `ResolveThreads(requested, rows)`: 0 이면 자동, 자동은 `min(4, 논리 프로세서/2)`. 행 수보다 많은 스레드는 쓰지 않는다.
  - `ForRows(rows, threads, body)`: 연속된 행 구간 `[y0, y1)` 마다 `body` 를 부른다. 스레드는 호출마다 만든다.
- **결과가 스레드 수와 무관한 이유**: 각 밴드는 다른 밴드가 쓰지 않는 입력만 읽고, 행을 가로지르는 누적이 없다. 같은 값을 같은 순서로 계산하므로 1·2·4·8 스레드의 결과가 모두 같다.
- 병렬화한 곳
  - fractional: 입력 정리(NaN/Inf), 가로·세로 합성곱, 기울기 합성, SAF-100 과잉 보정 제한.
  - bilateral: 세로 패스(밴드마다 자기 링버퍼).

### 스레드 수 설정 (ABI 추가만)

```
xpe_enhance_basic_set_max_threads(int32_t) / _get_max_threads(void)
xpe_enhance_advanced_set_max_threads(int32_t) / _get_max_threads(void)
```

- 0(기본) = 자동, 1 = 호출 스레드에서만, 음수는 0 으로 저장한다.
- 프로세스 전역이며 핸들별이 아니다. 출력은 이 값과 무관하다(헤더에 적었다).
- **기본값 상한 4 의 근거**
  - XPE 파이프라인은 한 프로세스에서 여러 모듈이 돌고 GUI 스레드가 함께 있다. 기본값이 기계 전체를 가져가면 다른 작업을 밀어낸다.
  - 측정에서도 4 이후 이득이 완만하다(§2 표: bilateral 4→8 스레드에서 38→25 ms, fractional 은 계속 줄지만 20 스레드까지 가야 100 ms 대).
  - 기계를 독점하는 호출자는 명시적으로 큰 값을 넣으면 된다.
- **이 모듈들이 스레드를 쓰는 것은 처음이다.** 과다 구독 위험: 두 모듈이 각각 최대 4 스레드를 쓰므로, 같은 프로세스에서 동시에 부르면 최대 8 + 호출자 스레드가 된다. 20 논리 프로세서에서는 여유가 있으나, 코어가 적은 기계나 GUI 가 동시에 도는 상황에서는 호출자가 값을 낮춰야 한다.

### bilateral 의 단일 스레드 경로

- 병렬 경로는 밴드가 **원본 복사본**에서 읽고 `px` 에 쓴다. 제자리로 하면 밴드가 다른 밴드가 이미 덮어쓴 행을 h-블러하게 된다(기존 순차 루프는 자기 읽기 위치 뒤에만 썼기 때문에 안전했다).
- 복사는 영상 하나만큼의 메모리와 한 번의 통과 비용이다. 그래서 **스레드 1개면 복사 없이 기존 순차 경로**를 탄다. 측정: 복사 경로 219 ms, 순차 경로 110 ms(변경 전 113–121 ms).

### 반증

- 병렬을 끄면(스레드 1) 시간이 변경 전으로 돌아온다: bilateral 110 ms(변경 전 113–121), fractional 733 ms(변경 전 842). 출력은 그대로다(아래 비교).

## 2. 증거

### 출력 동일 (기준 파일 비교)

- 변경 전 소스(HEAD `cedce22` 의 `noise_reduce.cpp`, `fractional_derivative.cpp`)로 빌드해 기준 파일을 만들었다(`before/`, `_build_before.log` BUILD=0).
- 변경 후 기본 설정(자동)으로 다시 만들어(`after3/`) 비교: bilateral 4개(512·1024 × 384·1024), fractional 8개(512·1024 × order 0.6/1.0/1.2/1.8) **모두 일치**.
- fractional 은 QA-B-102 의 기준 파일(`QA-B-102/before/`)과도 일치한다. 즉 B-102 이전 코드와도 같은 출력이다.

### 스레드 수 독립 (시험으로 고정)

- `EnhanceBasicThreads.BilateralIsBitIdenticalForEveryThreadCount`: 1 기준으로 2·3·4·8·자동 이 `memcmp` 0. 대조로 "필터가 실제로 영상을 바꿨다" 를 함께 단언한다.
- `AdvThreads.FractionalIsBitIdenticalForEveryThreadCount`: order 0.6/1.0/1.8 각각 같은 비교. 대조 포함.
- 두 모듈의 설정 함수 저장·조회 시험.
- 영상 크기 512×384 는 쓰는 스레드 수의 배수가 아니다(밴드 나머지 경로를 지난다).

### /fp:fast 에서 관찰한 것 (측정으로 좁힘)

`enhance_basic` 만 `/arch:AVX2 /fp:fast` 로 컴파일된다(`modules/enhance_basic/CMakeLists.txt:51`). 여기서는 계산을 바꾸지 않아도 코드 구조만 바꾸면 마지막 자리가 달라졌다.

| 시도 | 기준 파일과 비교 |
|---|---|
| 세로 패스 결과를 별도 버퍼에 쓰고 마지막에 복사 | 다름(512×384 에서 18,276/196,608 화소, 최대 차 1.2e-4) |
| 읽기만 원본 복사본으로 바꿈(구조 그대로) | 같음 |
| 본문을 람다로 감싸기만 함(스레드 1개) | 다름 |
| 본문을 일반 static 함수로 빼고 밴드 인자를 받음 | **같음** ← 채택 |

- 그래서 bilateral 의 밴드 본문은 람다가 아니라 `bilateral_band()` 함수다.
- `enhance_advanced` 는 `/fp:fast` 가 아니라 람다로 감싸도 출력이 같았다.

- "변경 전" 시간은 QA-B-102 의 최종값(같은 기계, 같은 절차): bilateral 121, fractional order 1.0 842, order 1.2 961 ms.

- 기기·빌드·전원 설정은 QA-B-99 gate.md §1 과 같다.

## 4. 미검증

- 다른 모듈이 실제로 동시에 도는 상황에서의 과다 구독 영향은 재지 않았다(해당 상황을 만드는 시험이 없다). 배경 부하 19.5% 환경에서만 쟀다.
- CI 에서의 값(푸시 전).
- 코어 수가 적은 기계(4 코어 이하)에서의 동작.
- 스레드 생성 비용은 3072² 기준으로만 무시 가능하다고 보았다. 작은 영상에서 자동값이 손해인 지점은 재지 않았다.
- `xpe_multiscale_process`, 콜리메이션, 그리드 억제는 병렬화하지 않았다.
- 스레드 수를 처리 중에 바꾸는 경우는 시험하지 않았다(헤더에 "그 호출은 옛 값이나 새 값 중 하나를 쓴다" 고 적었다).

## 5. 잔여 위험

- 두 모듈이 각각 최대 4 스레드를 잡을 수 있어, 한 프로세스에서 동시에 부르면 8 스레드가 된다. 호출자가 낮출 수 있지만 기본값은 그렇다.
- bilateral 병렬 경로는 영상 하나만큼(3072² float = 36 MB) 메모리를 더 쓴다. 단일 스레드 경로는 쓰지 않는다.
- `/fp:fast` 모듈에서는 앞으로도 코드 구조 변경이 마지막 자리를 바꿀 수 있다. 기준 파일 비교 없이 리팩터링하면 조용히 달라진다.
- 측정 흔들림은 여전하다(fractional 1 스레드 733–1198 ms).

## 6. ENH-012 요구의 파라미터 부재 (리더 요청)

- 현재 요구(`SPEC-XPE-P1B-ENH/spec.md:278`)는 "3072×3072 float32 에서 `xpe_noise_reduce` 를 100 ms 안에" 다. **모드도 필터 파라미터도 없다.**
- `xpe_noise_reduce` 는 두 모드를 가진다. NLM(REQ-ENH-008)은 탐색창·패치 크기에 따라 훨씬 느리므로, 파라미터 없는 100 ms 는 모드에 따라 만족 여부가 갈린다.
- bilateral 도 `sigma_space` 가 반경을 정한다: 반경 = ceil(2σ), ksize = 2·반경+1. σ=3 이면 13, σ=6 이면 25 로 계산량이 약 2배다.
- **제안**: 요구에 측정 조건을 넣는다.
  - 모드: `XPE_NOISE_BILATERAL`
  - `sigma_space = 3.0`, `sigma_range = 50.0`
  - 근거: 현재 벤치 시험(`test_noise_reduce.cpp:258`)이 쓰는 값이고, 구현 주석이 밝힌 2σ 절단(ksize 13)의 기준점이다. 이 조건에서 이번 측정은 39 ms(자동) / 110 ms(단일 스레드)다.
  - 스레드 조건도 함께 적어야 한다. 단일 스레드 기준이면 110 ms 로 100 ms 를 넘고, 기본 설정(자동) 기준이면 39 ms 로 들어온다.
