## why /fp:fast refuses NaN by accident: how the ordinary comparison is compiled
/fp:fast    s <= 0  ->  vcomiss s,0 ; jbe reject   (an unordered compare sets CF=ZF=PF=1, so jbe, which jumps on CF or ZF, rejects NaN)
/fp:precise s <= 0  ->  vcomiss 0,s ; jae reject   (operands swapped; jae needs CF=0 and NaN sets CF=1, so NaN is NOT rejected -- the _fdclass test above it is the only thing that stops it)
