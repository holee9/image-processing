# QA-B-200 M2a2 — mAs: (0018,1152)+(0018,1153) 을 쓰고 (0018,9332) 는 쓰지 않는다 (#251)

리더 결정(M2a 수신 후): "9332 는 쓰지 않고 1152(mAs) + 1153(µAs, 정밀도 보존)을 쓴다. 읽기는 1153 → 9332 → 1152." 이 보고서는 `m2a_report.md` §3 (C1)을 **대체한다**. M2a 보고서의 C1 서술(9332 를 쓰고 읽기가 9332 → 1152)은 이 커밋 이후 사실이 아니다. 같은 커밋에 `REQ-DISP-029 → 036` 주석 재번호(주석만)도 있다.

## 1. 인용 확인 — (0018,1153) 이 DX 모듈에서 Type 3 인가

PS3.3 Table C.8-33 X-Ray Acquisition Dose 모듈(Digital X-Ray Image IOD, 사용 U)의 속성 목록에 `(0018,1153) Exposure in µAs`, Type Optional(3), VR Integer String(IS)가 있다(`standards_cited.txt` 4·5번, 같은 페이지에서 `(0018,1150)` `(0018,1152)` 와 같은 줄에 나란히 나옴). PS3.6 Table 6-1 에서 `(0018,1153) Exposure in µAs`, 키워드 `ExposureInuAs`, VR IS, VM 1. 따라서 `(0018,1152)` 와 `(0018,1153)` 은 DX 모듈이 허용하는 Type 3 속성이고, `(0018,9332)` 는 그 모듈 목록에 없다.

## 2. 바뀐 것

**쓰기** (`DicomWriter.cpp`, mAs > 0 일 때):
- `(0018,1152)` Exposure = mAs 를 가까운 정수로, 0.5 는 올림(2.5 → "3", 2.4 → "2", 0.5 → "1", 0.4 → "0"). 2³¹−1 을 넘으면 쓰지 않는다.
- `(0018,1153)` Exposure in µAs = mAs × 1000 을 같은 규칙으로 반올림한 정수(2.5 mAs → "2500", 0.4 → "400", 0.0004 → "0"). 2³¹−1 µAs(약 214만 mAs)를 넘으면 쓰지 않는다. 그래서 소수 셋째 자리까지 보존된다(이전 9332 의 `%.4f` 는 넷째 자리였다 — 0.0001 mAs 단위의 정밀도는 줄었다).
- `(0018,9332)` 는 쓰지 않는다.
- 둘 다 범위를 넘으면(약 21억 mAs 이상, 검출기 노출이 아님) 파일에 mAs 가 없다.

**읽기** (`DicomReader.cpp`): 순서대로 첫 번째로 유효한 것을 쓴다 — `(0018,1153)`(µAs ÷ 1000) → `(0018,9332)`(FD 정확값) → `(0018,1152)`(정수 mAs). 속성이 없거나 비었거나 숫자가 아니거나 음수이면 건너뛰고 다음 것을 시도한다. `(0018,9332)` 는 읽기에 남겨 두었다: 이 모듈이 M2a 이전에 쓴 파일은 그것만(또는 그것과 1152)을 가진다.

## 3. 시험 (`test_dicom_failure_paths.cpp`, `DicomExposureTag` 5개)
- 외부 시스템 파일(DCMTK 로 직접 만든, `(0018,1152)`만 있는 파일)이 100 으로 읽힌다(M1 의 재현 그대로).
- 읽기 순서: 세 속성이 서로 어긋나게 있으면 1153 값, 1153 이 없으면 9332 값, 둘 다 없으면 1152 값.
- 9332 만 있는 옛 파일이 그 값으로 읽힌다.
- 쓰기 표(9행): 100·2.5·2.4·0.4·0.5·0.0004·3000·3.0e6·3.0e9 mAs 에서 1152 와 1153 의 값(둘 다 VR IS), 범위를 넘는 행의 생략, 9332 부재, 모듈 자신의 왕복.
- 비숫자·음수·빈 값은 건너뛰고 다음 속성(1153 `abc` → 1152 값 7 로 읽힘 등).

## 5. REQ-DISP-029 → 036 주석 재번호
main 의 `SPEC-XPE-P1B-DISP/spec.md`(내 브랜치는 아직 이 spec 을 갖고 있지 않음, `git fetch` 로 읽기만 함)에서 `REQ-DISP-029` 는 휘도 배열(GSDF 입력), `REQ-DISP-036` 은 ABI("내보낸 6개 함수는 C 연결·`__cdecl`·blittable 형식만")이다. `modules/display` 의 `REQ-DISP-029` 인용 12줄을 하나씩 읽어 가렸다.
- **그대로 `029` (휘도 배열을 뜻함, 6줄)**: `presentation_lut.cpp` 94·101, `display_api.h` 325·328, `test_presentation_lut.cpp` 449·482.
- **`036` 으로 옮김 (내보낸 함수를 뜻함, 6줄)**: `test_display_integration.cpp` 55·60("Full Pipeline Test"), 291·295("Version API"), 파일 머리말과 CMake 의 범위 `029..035` → `030..036`.
점검: `python tools/docs/check_req_citations.py` — main 의 spec 을 임시로 내 작업 트리에 놓고 돌리면 `no new orphans (1 known orphan ids, 6 citations)` 로 통과, 되돌린 뒤(내 브랜치 spec)에는 `REQ-DISP-036 is cited at modules/display/tests/test_display_integration.cpp:5 but no SPEC … defines it` — 브랜치가 main 의 spec 을 갖게 되면 해소된다(임시 덮어쓰기는 `git checkout` 으로 되돌렸고 `git status` 에 spec 변경이 없다).

## 7. Gap / 잔여 위험
Gap
- `(0018,9332)` 를 쓰지 않으므로 이 모듈이 M2a 이후·M2a2 이전에 쓴 파일은 9332 를 가진다. 읽기는 그것을 받는다(시험). 이 모듈이 쓴 옛 파일을 엄격한 IOD 검증기에 돌리지는 않았다.
- 엄격한 검증기(dciodvfy 등)로 새 파일의 `(0018,1152)`·`(0018,1153)` 이 통과하는지 돌리지 않았다. 근거는 PS3.3 표의 Type 3 인용뿐이다.
- DX 영상 IOD 의 다른 모듈에 mAs 를 담는 속성이 더 있는지는 확인하지 않았다.
- 소수 mAs 의 정밀도는 0.001 mAs 단위로 줄었다(이전 `%.4f` 의 0.0001). 0.0005 mAs 미만은 µAs 정수 0 이다.
- `check_req_citations.py` 는 이 브랜치가 main 의 spec 을 병합하기 전에는 `REQ-DISP-036` 을 고아로 본다(§5).

잔여 위험
- 다른 시스템이 `(0018,1153)` 을 `(0018,1152)` 와 다른 값으로 써 둔 파일은 1153 이 이긴다(가장 정밀하다는 판단). 표준이 둘의 일관성을 요구하지만 읽는 쪽은 검사하지 않는다.
- 범위를 넘는 mAs(검출기 노출이 아님)는 파일에 담기지 않는다.
