(a) REQ-024 criteria: four. Negative controls: [1] preamble/magic: only a 24-byte garbage file and a dataset-without-meta file (error text must contain 'meta'); no file with a valid dataset but a bad magic. [2] Type 1 present/non-empty: control only for Patient ID (tag identity asserted); ValidateStrippedTags removes four tags and asserts >=4 errors without naming them; no control for Patient Name, Modality, Rows, Columns, BitsAllocated, BitsStored, PixelData; no empty-value control (the code cannot catch one). [3] UID format: one control (SOPInstanceUID 'not.a.valid.uid' -> warnings non-empty); none for >64 characters, none for Study/Series UID. [4] Pixel representation consistency: no code, no test. The only 'passes' file is the module's own writer output, and ValidateNonDxSopClass_RoundTripsAsConformant shows a CT file validates, so 'DX IOD conformance' is not what is checked.

(b) REQ-004: yes, each of the four is exercised by a fixture (.1 DCMTK saveFile; .70 and .57 DCMTK DJ encoders with .57 predictor forced to 2 and checked distinct from .70; .90 module writer and test-side OpenJPEG codestreams). The loop in EverySupportedTransferSyntaxActuallyReads iterates the code's own table, so on its own it cannot detect a shortened list; dedicated .70 and .57 tests cover that.

(c) REQ-020: asserted on pixels against the caller's input array (256x256 ramp i&0xFFFF; 64x48 12-bit ramp), full 16-bit range included; decode is the module's OpenJPEG path, no second decoder; no noise/edge-saturation images; bit-exactness for prec<16 relies on the writer refusing out-of-range pixels.

(d) Mock SCP: a real DCMTK DcmSCP subclass in the test process, listening on a probed loopback port; accepts any called AE (setRespondWithCalledAETitle), three abstract syntaxes (DX Pres, SC, MWL) x three TS; C-FIND answers three hard-coded entries filtered by PatientID only, then Success; C-STORE goes through handleSTORERequest and the received dataset is deleted unseen (status Success). It cannot reject, return failure status, stall, or inspect content. CStoreSuccess_ReturnsOK would pass against an accept-everything SCP (it is one); only CStoreCalledAeInHost checks a C-STORE-RQ was counted. Both 'Timeout' tests connect to a port with no listener, which is refusal, not timeout.

(e) REQ-044: heap-walk tests exist (writer 1000 write cycles; reader failing-J2K reads), each with a 64 B/cycle control, Windows-only, loose bound; none for success-path read, J2K write, validate, C-STORE, C-FIND. REQ-041: no test of any kind (no export-table/ABI check). REQ-042: no test (no fault injection). REQ-043: no test, and the code only partly matches.

(f) REQ-039/040: the only cancel-in-flight test is an unconditional GTEST_SKIP (kCancelRaceUnobservable); the remaining cancel test calls xpe_dicom_cancel twice when idle. There is no test with a real in-flight operation and no flag-level test either (no test checks that cancel latches or that a pre-set flag is cleared).

Known issues not re-reported: #236 (signed pixel representation: reader refuses signed pixels with UNSUPPORTED_FORMAT, dicom_api.h:117), #237 (GSPS), #239 (characters in file paths: loadFile/saveFile take char* paths; no test).

Fixture weaknesses: the main reader/validator/network fixtures are written by the module's own xpe_dicom_write (so a writer/reader tag disagreement cancels); pixel content is a synthetic ramp or constant (xpe_alloc_image contents in validator/network/param tests are not set at all); no real-world or third-party DICOM file anywhere; several negative tests GTEST_SKIP when DCMTK cannot encode (UnsupportedCompressedTS) or when the mock SCP cannot bind; leak tests skip off Windows; metadata is only round-tripped (never read from a file whose tags were set independently).

Test-name overstatements: CloseValid_NoLeak asserts no leak behaviour; RescaleDefaults_OneAndZero only checks validator valid=true (the real rescale check lives in Tc109_CurrentBehaviour_*); GetMetadata_MissingTagsDefault opens a file with all tags; CStoreTimeout/CFindTimeout test refusal; CancelCStore_TerminatesOperation is skipped unconditionally.

Writer behaviour not in SPEC: PatientName/ID fixed 'ANONYMOUS' and a fresh random StudyInstanceUID per file (DicomWriter.cpp:113-120), so two images of one acquisition never share a study.
