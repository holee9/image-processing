## 재현 (수정 전 = 207c)
- Codex 8x8 (`[2^-100, 4095, 1,1,1,1, 1,1,1,1, 2,3,4,5,6,7]` x4, 타일 2x2, clip 3): 값 1 의 정확 값 **511.875**, 207c DLL **767.8125**, 64개 중 **56개** 어긋남 (`d_py_red.txt`).
- 무작위 영상 120건(극단값을 지수 범위별로 뽑음, 정확 구간 경계 화소): 수십 건이 어긋남 (vmin=5e-29/vmax=8e8, vmin=4e-40 등 — 모두 vmin 이 작은 양수 또는 음수).

## 구조 (clahe_bin_internal.h — 식을 더 찾지 않고 구조를 바꿈)
- **빠른 길(double)** 은 정확함이 증명되는 영상에서만. 증명(헤더 주석 전문): 모든 값이 2^L 의 정수배이고 R' = R/2^L < 2^41 이면 `v-vmin`, `vmax-vmin` 이 double 에서 정확하고, `4095*D'` 와 `bin*R'` 은 2^53 아래라 정확 → 비교가 정확 유리수 비교. 구간 = 역수 추정(약간 낮게 치우침, 높지 않고 1 이하로 낮음) + 정확한 곱 비교 1회. 영상 한 번의 판정으로 충분하다(화소마다 필요 없음):
  - (A) vmin == 0 → 빼기가 없다 → 항상 빠름
  - (B) vmin > 0 → 모든 화소가 vmin 이상이라 마지막 비트가 vmin 이상 → `ilogb(vmax)+1-lsbexp(vmin) <= 41`
  - (C) vmin < 0 → 작은 화소의 마지막 비트가 낮을 수 있어 극단값만으로는 증명 불가. 비영 화소의 최저 마지막 비트 지수(`min_lsb_exp`, 음수 vmin 영상만 한 번 더 훑음)로 `H+2-Lpix <= 41`
- **정확한 느린 길**: 부호·지수·가수에서 만든 **320비트 정수**(64비트 5워드). 오프셋 2^277 을 더해 부호를 없애고(모든 float 가 2^-149 단위 정수 < 2^277) 빼기·`4095*D`·`bin*R` 곱·비교를 정수로. 필요한 폭: 2^278 x 4095 < 2^290 < 320. 구간 = 더블 추정 + 정확한 보정 비교. 정수 연산뿐이라 `/fp:fast` 와 무관.
- `bin & 4095` 같은 감춤 없음. 빠른 길: 추정 <= 4094 라 +1 해도 <= 4095 (유도). 불변식 [0,4095] 는 시험이 모든 벡터에서 직접 단언.
- 속도 때문에: 화소별 구간을 `uint16_t` 로 보관(207c), 행 단위 `fill_bins` 가 상수를 지역 변수로 복사(멤버를 매 화소 다시 읽으면 +3 ms).

## 추가 (리더 요청): 느린 길은 실제 영상에서 얼마나 자주, 얼마나 느린가

측정: `bench_d_paths.py.txt` (3072², 실제 `/fp:fast` DLL, 영상마다 빠른 쌍둥이 = 같은 영상에서 화소 하나만 0.0 으로 바꿔 규칙 A 로 보냄, 번갈아 2회, 중앙값 3회) → `d_paths_bench.txt`.

**경로는 영상 하나에 하나다.** 최소·최대(음수 최소는 최저 비트 지수)로 한 번 판정하므로 느린 길로 가는 화소는 영상당 **100 % 또는 0 %** 이다. 화소 일부만 가는 경우는 없다.

| 영상 | 경로(판정) | 시간 | 빠른 쌍둥이 | 배수 | 느린 길 화소 |
|---|---|---|---|---|---|
| (1) 균일분포 소수 0.0123..4000 | 느림 (B: S=42 > 41) | 564~675 ms | 46~55 ms | **12x** | 100 % |
| (2a) 오프셋 포화 뺄셈 x 화소별 게인 (전처리 비슷) | 빠름 (B: S=31) | 61~69 ms* | 66 ms | 1 | 0 % |
| (2b) 같은 영상, 가장 어두운 화소 ~10 | 빠름 (B: S=31) | 45 ms | 66~69 ms* | 1 | 0 % |
| (2c) 2b + 화소 **하나**만 0.0123 | 느림 (B: S=42) | 699~724 ms | 45 ms | **15x** | 100 % |
| (2d) 2b + 화소 하나만 -3.7 (음수 언더슈트) | 빠름 (C: S=35) | 58~83 ms* | 55 ms | 1 | 0 % |

\* 이 기계의 잡음(같은 코드가 45~69 ms). 빠른 길끼리는 차이가 없다.
실영상 픽스처는 이 저장소에 없다(`tests/` 에 .raw/.dcm/.tif 없음). (2a)(2b) 는 전처리 코드(`offset_correct`: 정수 포화 뺄셈, `gain_correct`: 화소별 배수)를 흉내 낸 합성이며 실영상 측정이 아니다 — 미관측.

**읽는 법**
- 느린 길은 정확하지만 **화소당 약 60 ns, 영상 전체로 0.6~0.7 s** (빠른 길의 12~15배, 3072² 에서 CLAHE 예산 50 ms 의 13배).
- 분기점은 얕다: 최솟값이 약 0.0156(=2^-6) 아래의 양수이고 최댓값이 수천이면 S>41 이다. 최솟값 0.05 이상이면 빠르다(S<=40). 예: 0.0123 이면 S=42 로 **한 비트 차이로 느린 길**.
- **절벽**: 화소 **하나**가 작은 양수(2c)이면 영상 전체가 15배 느려진다. 반대로 하나의 0.0 은 영상을 빠른 길로 돌려보낸다(A).
- 전처리 출력이 흔히 최솟값 0(포화 뺄셈이 0 을 만들면 규칙 A) 이거나 최솟값이 1 이상이면 빠른 길이다. 위험한 것은 "최솟값이 0 이 아니고 0.0156 미만" 인 영상이다.

**제안 (구현하지 않음, 리더 판단)**: 절벽은 영상 단위 판정이 화소 단위 사실보다 보수적이어서 생긴다. 느린 길 안에서도 대부분의 화소는 부동소수점 필터로 증명할 수 있다 — 빼기·나눗셈의 상대 오차 합이 4.4e-16 이면 `q̂ = D̂ * (4095 / R̂)` 의 절대 오차는 2e-12 이하이므로, `q̂` 의 소수부가 1e-9 와 1-1e-9 사이이면 `floor(q̂)` 가 정확하다고 **증명**된다. 소수부가 경계 1e-9 안인 화소(전체의 약 2e-9)만 320비트 정수로 보내면 느린 길 영상도 빠른 길과 비슷한 속도가 된다(추정, 미측정). 정확성은 지금과 같고(필터가 못 믿으면 정수로 간다), 시험은 필터 경계 화소 벡터를 추가하면 된다. 별도 카드로 지시해 주세요.
