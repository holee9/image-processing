# QA-B-112 게이트 — 과보정 가드가 후처리 뒤를 못 막는다 (#180)

커밋 `6bf0358`, 미푸시. **기본값은 바꾸지 않았다**(`PostGuard::None`). 카드 §1 대로 비교만 했고 결정은 리더 몫이다.

## 1. 주장

### (1) 바닥의 정의

선택지 셋이 모두 같은 바닥을 쓴다. 가드 자신이 함의하는 값이다:

```
floor(x) = I(x) / (1 + cap(x))
```

`S <= I*cap/(1+cap)` 이므로 `P = I - S >= I/(1+cap)` 다. 격자가 되돌리는 잔여 산란 항 `Rf*S >= 0` 은 빼고 잡았으므로 **보수적인 바닥**이다. `SmoothFloor` 모드만 비율이 아니라 `S` 에 직접 걸리므로 `floor = I - (1-eps)*min(I)` 로 정의했다.

선택지:

| | 이름 | 무엇을 하는가 |
|---|---|---|
| (a) | `None` | 지금 그대로. 후처리 뒤 아무것도 안 한다 |
| (b) | `Clamp` | 화소별로 `out = max(out, floor)` |
| (c) | `GlobalDetailScale` | 디테일 전체에 **한 배율** — 모든 화소가 바닥 위에 남는 가장 큰 값 |
| (d) | `SymmetricHeadroom` | 화소별로 `\|out − pre\| <= pre − floor`. 증폭이 가드가 남긴 여유보다 더 쓰지 못한다(양방향) |

(d)는 카드의 "여러분이 제안하는 것"이다. (b)가 아래쪽만 막는 데 비해 위쪽도 같은 여유로 막아, 증폭이 한 방향으로만 제한되어 생기는 비대칭을 없앤다.

## 4. 미검증

- **마스크 경로의 속도·메모리.** §1(4)는 마스크 없는 경로다. QA-B-111 에서 마스크가 +111 MB 였으므로 (c)·(d)는 400 MB 대가 될 수 있다. 020 여유가 줄어드는 쪽이라 결정 전에 재는 것이 좋다.
- **클램프가 만드는 새 경계.** (b)는 화소별로 자르므로 자른 화소와 안 자른 화소 사이에 계단이 생길 수 있다. 이번에는 0 근처 화소 수와 최대 과다 뺌만 봤고, 경계가 눈에 보이는지는 재지 않았다.
- **(d)의 위쪽 제한이 걸리는 조건.** 이 장면에서는 한 번도 걸리지 않아, (b)와 구별되는 상황을 확인하지 못했다.
- 과대 추정 ×1.5 같은 중간값. ×1·×2·×3 만 봤다.
- 실제 장비 표에서의 동작(#151). 표가 과소 추정이면 이 문제 자체가 나타나지 않는다.
- CI 판정. push 를 하지 않는다.

## 5. 잔여 위험

- **018 문턱 여유 0.013 은 이 카드로 해결되지 않는다.** (b)·(d)는 봉우리를 그대로 두고, (c)만 낮추는데 그것은 대비 복원을 끄는 방식이다. 문턱을 다시 볼지 기본값을 되돌릴지는 QA-B-111 의 CI 결과와 함께 봐야 한다.
- 바닥이 보수적이라(잔여 산란 항 제외) 격자비가 낮아 `Rf` 가 큰 설정에서는 실제보다 낮은 바닥을 쓴다. 안전한 방향이지만, 그만큼 (b)·(d)가 늦게 걸린다.
- `postFloor` 는 전 해상도 버퍼 하나다. 4096² 이상에서는 (c)·(d)의 두 버퍼가 020 에 먼저 닿을 수 있다.
- 선택지는 전부 시험 스위치다. 리더가 하나를 기본값으로 정하면 기존 기준 파일이 다시 필요하다(QA-B-110 과 같은 상황).
