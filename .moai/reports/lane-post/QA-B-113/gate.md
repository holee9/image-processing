# QA-B-113 게이트 — 과보정 가드를 후처리 뒤까지, 선택지 (b) 를 기본으로 (#180)

커밋 `224b2bb`, 미푸시. `PostGuard` 기본값 `None` → **`Clamp`**.

## 1. 주장

### (1) 바꾼 것

`VgSwitches::postGuard` 기본값을 `Clamp` 로 바꿨다. `SymmetricHeadroom` 은 설정으로 남는다. `GlobalDetailScale` 은 채택하지 않았으나 비교용으로 남겨 두었다(제거하면 QA-B-112 의 비교를 재현할 수 없다).

### (2) 바뀌는 기대값 — 3건

| 시험 | 옛 기대가 전제한 것 | 바꾼 방법 |
|---|---|---|
| `PostGuardOptionsHoldTheFloor_REQ_GSVG_018` | 기본값이 `None` | `Clamp` 로 단언을 바꿈 |
| `PostStepsReintroduceNearZeroPrimaries_REQ_GSVG_018` | 기본 설정으로 돌리면 0 근처 화소가 생긴다 | 이 시험이 기록하는 현상은 **가드가 없을 때**의 것이다. `postGuard = None` 을 명시하도록 바꿈 |
| `GsvgVirtualGridMc.CompareToPrimary` | 보정이 무보정보다 정답에 가깝다 | **기대를 바꾸지 않았다 — 제품 코드를 고쳤다.** 아래 (3) |

### (3) 시험이 잡은 결함 — 상한이 `None` 일 때 바닥이 틀렸다

`CompareToPrimary` 의 `C0.it5.g4`(상한 없음) 설정에서 `|r−1| 중앙값` 이 무보정과 **완전히 같아졌다**(계단 2.8446 대 2.8446, 쐐기 2.9216 대 2.9216). 즉 보정 결과가 입력 그대로였다.

원인: QA-B-112 에서 바닥을 `I/(1+cap)` 으로 잡으면서 `CapMode::None` 의 `cap` 을 0 으로 두었다. 그러면 `floor = I/(1+0) = I` 가 되어, 클램프가 출력을 입력으로 되돌린다. **가드가 없으면 바닥도 없어야 한다.**

고쳤다 — `None` 은 바닥 0, `PrimaryFloor` 는 `eps*I`(그 모드의 정의 그대로), `SmoothFloor` 는 `I − (1−eps)·min(I)`, 나머지는 `I/(1+cap)`.

QA-B-112 의 비교 표는 `GlobalSum`(기본 상한)에서만 잰 값이라 그 결론은 영향을 받지 않는다. 다만 **B-112 에서 이 결함을 잡지 못한 이유**는 비교가 기본 상한만 썼기 때문이고, MC 시험이 여러 상한 모드를 도는 덕에 이번에 드러났다.

### (4) 클램프가 새 경계를 만드는가 (카드 §2.3)

클램프가 걸린 화소 집합의 **경계**에서, 걸린 화소와 안 걸린 이웃 사이의 상대 단차를 클램프 전후로 비교했다(합성 계단 장면, 256²).

| 커널 | 걸린 화소 | 경계 화소 | 이웃 쌍 | 단차 평균 (켬) | 단차 평균 (끔) | 단차 최악 (켬) | 단차 최악 (끔) |
|---|---|---|---|---|---|---|---|
| ×2 | 12,776 (19.49%) | 1,564 | 2,012 | **0.1568** | 0.1739 | **0.8895** | 0.9869 |
| ×3 | 23,077 (35.21%) | 2,948 | 3,612 | **0.1332** | 0.1452 | **0.8544** | 0.9302 |

**클램프는 새 경계를 만들지 않는다 — 있던 단차를 줄인다.** 평균은 9~10%, 최악은 8~10% 작아진다. 이유는 방향에 있다: 클램프는 너무 어두워진 화소를 바닥까지 **올리는** 동작이고, 그 화소는 원래 이웃보다 어두웠으므로 올리면 이웃과 가까워진다.

한 가지 기록할 것: ×2 에서 **한 화소가 자기 값의 9.51배까지 올라갔다**(×3 은 1.18배). 값이 거의 0 이던 화소가 바닥까지 올라간 경우라 상대 배수가 크게 나오며, 그 바닥은 가드가 애초에 허용한 값이다. 경계 단차가 함께 줄어든 것을 보면 밝은 점으로 튀지는 않지만, **절대값으로는 재지 않았다**(§4).

카드는 "보이면 기록하고 멈추라" 고 했다. 측정 결과 보이지 않으므로 멈추지 않고 진행했다.

### (5) 마스크 경로의 메모리 (카드 §2.2)

3072², 스레드 자동, 5회 중앙값:

| 선택지 | 마스크 | 시간 | 최대 메모리 | 020(512 MB) 여유 |
|---|---|---|---|---|
| None | 없음 | 443.0 ms | 151.8 MB | 360 MB |
| None | **있음** | 654.0 ms | 263.7 MB | 248 MB |
| **Clamp(기본)** | 없음 | 489.8 ms | 223.8 MB | 288 MB |
| **Clamp(기본)** | **있음** | **619.9 ms** | **323.0 MB** | **189 MB** |
| SymmetricHeadroom | 있음 | 760.1 ms | 395.7 MB | 116 MB |

- **요구 019b(1.0 s) 안**: 최악 619.9 ms(기본값 기준), 여유 380 ms.
- **요구 020(512 MB) 안**: 최악 323.0 MB, **여유 189 MB**.
- 클램프가 마스크 경로에 더하는 것은 바닥 버퍼 하나(약 59 MB 관측; 3072² double 은 75.5 MB 이고 마스크 경로는 압축 보관 배열과 겹쳐 덜 든다).
- `SymmetricHeadroom` 을 골랐다면 395.7 MB 로 여유가 116 MB 였다 — 카드 §2.2 가 우려한 400 MB 대가 맞았고, 기본값을 (b)로 정한 판단이 메모리 면에서도 맞았다.
- 시간은 실행마다 흔들린다(같은 조건에서 None 마스크 654.0 ms 가 Clamp 의 619.9 ms 보다 컸다). **클램프가 더 빠르다고 읽어서는 안 된다** — 둘 다 600~660 ms 대라는 것만 말할 수 있다.

### (6) 반증 (카드 §2.4)

기본값을 `None` 으로 되돌리면:

| | 기본값 `Clamp` | `None` 으로 되돌림 |
|---|---|---|
| 0 근처 화소(커널 ×2) | 0.00000 | **0.00037** |
| `PostGuardOptionsHoldTheFloor_REQ_GSVG_018` | 초록 | **빨강** |

카드가 요구한 0.037% 복귀를 그대로 확인했다. 되돌리면 초록.

## 3. 기준선 귀속

- §1(4)(5)(6)의 값은 `224b2bb` 와 같은 소스의 `build/ci-post` 에서 오늘 잰 값이다.
- 0.037% / 0.9626 / 0.7235 는 QA-B-112 §1(2)의 값이고 이번에 같은 방법으로 재현했다.
- 속도·메모리 측정 방법은 QA-B-107/108/111/112 와 같다(커밋 차지, 0.5 ms 표본). §1(5)의 None 값(443.0 / 654.0 ms)은 QA-B-112 의 420.9 ms 와 다른데, 같은 조건이지만 실행이 달라서다 — **같은 표 안에서만 비교해야 한다.**

## 4. 미검증

- **클램프가 올린 화소의 절대 크기.** §1(4)는 상대 배수와 경계 단차만 봤다. 9.51배 올라간 화소가 DN 으로 얼마인지, 눈에 띄는 밝은 점인지는 재지 않았다.
- **실제 영상에서의 모습.** 합성 장면과 MC 만 봤다. 과대 추정 조건 자체가 실제 표에서 나타나는지는 #151 에서 확인해야 한다.
- 상한 `LocalSum`·`PrimaryFloor`·`SmoothFloor` 에서의 클램프 동작. 바닥 정의는 고쳤지만 그 모드들로 비교 측정을 하지는 않았다(기본 상한은 `GlobalSum` 이다).
- `SymmetricHeadroom` 의 위쪽 제한이 걸리는 조건은 이번에도 찾지 못했다.
- CI 판정. push 를 하지 않는다.
- 018 봉우리(1.4521)는 이 변경으로 바뀌지 않는다(QA-B-112 §1(3)에서 확인). 이번에 다시 재지는 않았다.

## 5. 잔여 위험

- 마스크 경로 기본값이 **323 MB** 다. 020 까지 189 MB 남는데, 4096² 로 커지면 버퍼가 비례해 늘어 먼저 닿을 수 있다.
- 바닥이 보수적이라(잔여 산란 항 제외) 격자비가 낮아 `Rf` 가 큰 설정에서는 클램프가 늦게 걸린다. 안전한 방향이다.
- §1(3)의 결함은 **기본 상한이 아닌 모드에서만** 드러났다. 새 설정을 더할 때 기본값만으로 비교하면 같은 종류의 구멍이 생길 수 있다 — MC 시험이 여러 모드를 도는 덕에 잡혔다.
- 성능 게이트 2건이 부하 때문에 한 번 빨강이었다. CI 는 로컬보다 느린 기계일 수 있으므로(#153 의 교훈), 이 두 게이트의 CI 결론을 확인해야 한다.
