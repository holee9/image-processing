# QA-B-164 (`#226`) — `/wd4150` 을 떼니 **0 건**. 영구히 걷었습니다

## 1. 주장

1. **0 건입니다** — 네 조합(`xpe_ai`·`xpe_ai_worker` × 스텁·풀) 전부. §2
2. **그 0 은 측정입니다.** 일부러 불완전 타입 `delete` 를 넣으니 **정확히 1건**이
   나왔습니다 — 계수와 제거가 둘 다 작동한다는 증거. §3
3. **억제를 영구히 걷었습니다.** 걷은 뒤 **다른 파일**에 같은 손상을 넣어 경고가
   나는지도 확인했습니다. §4
4. **`/W4` 에서 다른 경고도 0 건**입니다 — 목록으로 적을 것이 없습니다. §2
5. **주석의 절반이 결함을 살린 자리**에 규칙 **전체**를 적었습니다. §5
6. `/wd4996` 은 건드리지 않았습니다.

## 3. §5 — 0 이 측정임을 보이는 양성 대조군

`0` 만으로는 *"세는 방법이 고장났다"* 와 구별되지 않습니다. 그래서 `ai.cpp` 에
일부러 넣었습니다:

```cpp
struct XpeB164Incomplete;
static void XpeB164Probe(XpeB164Incomplete* p) { delete p; }
```

| 구성 | `C4150` |
|---|---|
| 스텁 `xpe_ai` | **1** |
| 풀 `xpe_ai` | **1** |

**계수가 작동하고 억제가 실제로 빠졌습니다.** 주입은 되돌렸고
`git diff --stat` 로 잔재 0 을 확인했습니다.

> 첫 주입 시도는 **앵커가 안 맞아 아무것도 안 들어갔는데 측정은 돌았고 0 이
> 나왔습니다.** 그 0 을 대조군으로 읽었으면 *"계수가 작동한다"* 는 거짓 증거가
> 됐을 자리입니다 — 주입이 실제로 들어갔는지(`grep` 로 줄 확인) 먼저 본 뒤에
> 측정했습니다.

## 5. §4 — 주석의 **절반**이 결함을 살렸습니다

`QA-B-161` 이 찾은 규칙을 두 자리에 **전부** 적었습니다:

> **`delete pimpl_` 하는 것은 (a) `.cpp` 에 있고, (b) `struct Impl` 정의
> **아래**여야 한다.**

옛 주석은 *"must be in .cpp for PIMPL"* — **(a)만** 있었습니다. 소멸자는 그것을
**지켰는데도 틀렸습니다**: 구조체 **위**에 있었으니까요.

적은 곳:

| 파일 | 내용 |
|---|---|
| `src/ai_onnx_session.cpp` | 규칙 두 조각 + 왜 절반이 위험했는지 + `#226` 이 억제를 걷었다는 것 |
| `include/xpe/ai/ai_onnx_session.h` | 같은 규칙(이동 생성자는 왜 인라인으로 남는지 포함) |
| `modules/ai/CMakeLists.txt` × 2 | 왜 걷었는지, 무엇을 쟀는지, `/wd4996` 은 왜 남는지 |

## 7. 미검증 · 잔여 위험

- **누수가 실제로 사라지는지는 관측하지 않았습니다.** 카드 §5 가 *"가능하면 해제가
  일어나는지 관측하라"* 고 했는데, **범위를 "경고 소멸까지" 로 둡니다.**
  `~Impl()` 이 호출되는지를 계측하려면 소멸자에 부작용을 넣어야 하고, 그것은
  제품 코드를 시험용으로 바꾸는 일입니다. `C4150` 이 *"소멸자가 호출되지 않는다"*
  를 **컴파일러가 단언**하는 진단이라 그 소멸이 곧 호출 생성이지만,
  **런타임으로 확인한 것은 아닙니다**
- **0 건은 오늘의 코드에 대한 것입니다.** 억제를 걷었으므로 **다음 `C4150` 은
  경고로 보이지만**, 두 제품 타깃은 `/WX` 를 안 받으므로 **빌드를 깨지는 않습니다** —
  경고가 로그에 묻힐 수 있습니다. `/WX` 를 제품 타깃에 붙이는 것은 이 카드 범위
  밖이라 **보고만** 합니다
- **다른 모듈은 보지 않았습니다** — `/wd4150` 은 `modules/ai` 두 자리뿐이라는
  리더 확인을 제 쪽에서도 전수로 재현했습니다(저장소 전체 검색, 보고서 제외 2건)
- `/wd4996` 뒤에 무엇이 있는지는 **묻지 않았습니다**(카드 §6)
