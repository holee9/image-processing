### (1b) T308 이 묶음 안에서 느려지는 원인

측정으로 가른 것(`_t308.log`, `_t308b.log`, 모두 BUILD=0):

| 조건 | T308 중앙값 |
|---|---|
| A 단독 실행 | 87 ms |
| B 같은 프로세스에서 3072² fractional 뒤 | 118 ms |
| C 같은 3072² 작업 직후 **새 프로세스** | 90 ms |
| D 같은 프로세스에서 3072² 콜리메이션 뒤 | 124 ms |
| E 같은 프로세스에서 3072² 버퍼 할당·쓰기만 한 뒤 | 90 ms |

- C 가 빠르므로 **열·전원 상태가 아니다**.
- E 가 빠르므로 **큰 할당 자체가 아니다**.
- B·D 가 느리므로 원인은 **같은 프로세스에서 3072² 처리를 끝낸 뒤의 프로세스 상태**다. 어떤 상태인지(할당자 재사용, 페이지 배치, TLB) 는 재지 못했다.
- **문턱은 바꾸지 않았다.**
- 이번 개선 뒤 묶음 안 T308 은 121 → 99 ms 로 내려갔다(단독 84–94 ms).

### (2) 출력이 같은 개선 4가지

모두 계산 순서와 값이 바뀌지 않는다.

1. `edge_detection`: 방향 지도(`atan2`)를 선택 인자로 분리했다. 저장소 어디에서도 `EdgeGradientResult::direction` 을 읽지 않는다(시험 포함, grep 0건). 콜리메이션은 `withDirection=false` 로 부른다. 기본값은 `true` 라 다른 호출자는 그대로다. 3072² 에지 단계 610 → 381 ms.
2. `hough_transform::buildAccumulator`: theta 마다 `cos`/`sin` 을 미리 계산한다. 같은 인자에 같은 함수이므로 값이 같다.
3. `fractional_derivative`:
   - `safeAdd` 의 두 분기는 IEEE 덧셈이 내는 값과 같았다(유한 값의 합이 범위를 넘으면 같은 부호의 무한대). 분기를 없앴다.
   - 국소 표준편차와 두 합성곱에서 **내부 화소**는 clamp 가 필요 없다. 경계만 기존 경로로 둔다. 읽는 값·순서는 같다.
4. `grid_dwt`:
   - 열 방향 필터를 전치본에서 수행한다. 3072² 에서 열 접근은 1536 double 간격이라 탭마다 캐시 미스였다. 필터 자체는 그대로다.
   - 주기 인덱스 `(2i+k) % n` 을 조건부 뺄셈으로 바꿨다(`n ≥ 8` 일 때 `2i+k < n+7`). 인덱스가 같다.

### 줄이지 못한 항목의 선택지 (결정은 리더·사용자)

**REQ-ADV-061 fractional (842 ms, 요구 400 ms)**
- 남은 비용의 큰 덩어리는 `applyOvershootLimiting` 의 화소별 3×3 국소 표준편차다(9.4M 화소 × 9 이웃).
- 선택지
  - 알고리즘 교체: 국소 합·제곱합을 분리형 누적(적분 영상/슬라이딩 창)으로. 합산 순서가 바뀌어 **출력이 달라진다**.
  - 병렬화: 행 분할. 각 화소가 독립이라 결과는 같지만 스레드 도입은 모듈 정책 문제다.
  - 요구 개정: 400 ms 가 어떤 구현·기계를 전제로 한 값인지 확인.

**REQ-ENH-012 bilateral (121 ms, 요구 100 ms)**
- 이미 분리형 + 링버퍼 + SVML `exp` 로 구현돼 있다. 출력이 같은 개선을 찾지 못했다.
- 선택지
  - 알고리즘 교체: 범위 커널 LUT·양자화(근사 → 출력 달라짐), 더 짧은 절단 반경(현재 2σ, ksize 13).
  - 병렬화.
  - 요구 개정: 요구에 필터 파라미터가 없다. sigma_space 3.0 기준인지 정해야 비교가 성립한다.

## 4. 미검증

- ADV 요구의 "AVX2 목표"(120 / 200 ms)가 어떤 구현을 전제로 한 값인지. 이 모듈들에는 명시적 SIMD 가 없다.
- T308 이 같은 프로세스에서 느려지는 **정확한 기전**.
- bilateral 의 요구 조건(필터 파라미터)이 정해지지 않아, 121 ms 를 요구와 직접 비교할 근거가 약하다.
- CI 에서의 개선 효과는 아직 측정하지 않았다(푸시 전).
- 기준 파일 비교는 합성 장면 15개다. 실제 영상으로는 비교하지 않았다.
- `EdgeGradientResult::direction` 을 저장소 밖(다른 레인·GUI)에서 쓰는지는 이 워크트리 기준으로만 확인했다.

## 5. 잔여 위험

- `computeSobelGradients` 의 기본값은 `withDirection = true` 라 기존 호출자는 영향이 없지만, 새 호출자가 `false` 로 부른 뒤 `direction` 을 읽으면 0×0 행렬이다.
- 전치 때문에 그리드 억제의 임시 메모리가 레벨 1 에서 약 72 MB 늘어난다(3072² double 기준). REQ-GSVG-020(512 MB) 은 재지 않았다.
- 측정 흔들림은 여전하다(같은 조건에서 bilateral 117–152 ms).
