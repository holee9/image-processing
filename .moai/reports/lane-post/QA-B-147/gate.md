# QA-B-147 (#154) — 상쇄는 **지금도** 실재합니다. 그리고 기준은 저장소 안에 있습니다

## 1. 주장 (Claim)

1. **`#154` 의 전제는 참입니다.** `exposure_index.cpp:103-106` 에 그대로 있고, 고친
   커밋은 없습니다(§2).
2. **한 축 스윕: 부위를 9가지로 흔들어도 DI 가 비트까지 동일합니다.** 표를 임시로
   **9 자릿수(EI 0.001 → 1.23e6)** 벌려도 여전히 **0/9 차이 없음** — 정밀도가 아니라
   **상쇄**입니다(§3).
3. **약분 지점을 식으로 짚었습니다**: `ei = eit·(mean/S0)` 를 `di = 10·log10(ei/eit)`
   에 넣으면 `eit` 가 사라집니다. 부동소수 잔여도 **0 비트**입니다(§3).
4. **기준이 있습니다 — 다만 IEC 원문이 아니라 저장소 안 2차 문서입니다**(§4).
   `XPE-ALG-001 §7.2` 와 `SRS-ENHANCE-BASIC-001 FR-100-001` 둘 다 **EI 에 EIT 가
   들어가지 않는다**고 적습니다. **코드 자신의 역산이 아닙니다.**
5. **규모: 오늘 부위별 DI 폭은 0.00 dB, 기준대로면 5.05 dB** 입니다(§5). 이 수는
   **`C_ei` 없이도 구해집니다** — 차이에서 약분되기 때문입니다.
6. **고치지 않았습니다**(§7). 측정 시험 2건만 더했습니다.

## 3. 할 일 (b) — 한 축 스윕과 약분 지점

### 약분 (식)

```
ei = eit · (mean / S0)
di = 10·log10(ei / eit) = 10·log10( eit·(mean/S0) / eit ) = 10·log10(mean / S0)
```

`eit` 는 `:103` 에서 곱해지고 `:106` 에서 나뉩니다. **두 줄 사이에서만 존재합니다.**

### 스윕 1 — 출하 표 전수 (부위 9가지, 같은 64×64 영상, fill 1234)

| 부위 | EI | DI | DI 비트 |
|---|---|---|---|
| CHEST | 246.8 | 0.913152 | 기준 |
| HAND / FOOT | 123.4 | 0.913152 | **동일** |
| ABDOMEN / PELVIS | 308.5 | 0.913152 | **동일** |
| SPINE | 370.2 | 0.913152 | **동일** |
| SKULL | 394.88 | 0.913152 | **동일** |
| 미지 문자열 / 빈 문자열 | 246.8 | 0.913152 | **동일** |

**EI 는 3.2배 움직이고 DI 는 비트까지 같습니다 — 9건 중 0건 차이.**

EI 가 움직인다는 것이 중요합니다: **표를 안 봐서 DI 가 안 움직이는 것**과
**보고도 상쇄돼서 안 움직이는 것**은 다른 결함인데, 전자가 아님을 EI 가 보입니다.

### 스윕 2 — **자릿수** (카드의 "6 자릿수" 요구)

출하 표는 100..320(0.5 decade)뿐이라, 표를 **임시로** `CHEST 0.001`, `HAND 1e6` 로
바꿔 재고 되돌렸습니다(`_decade_build.log`, `===BUILD=0===` 확인).

| 부위 | EI | DI |
|---|---|---|
| CHEST | **0.001234** | 0.913152 |
| HAND | **1.234e+06** | 0.913152 |

**EI 가 10⁹ 배 벌어져도 DI 비트가 동일합니다 — 0/9.**

> **작게 흔들어 안 움직이면 정밀도일 수 있지만, 9 자릿수를 흔들어도 비트가 같으면
> 상쇄입니다.** 부동소수 잔여조차 0 입니다(`ei/eit` 가 정확히 `mean/S0` 로 복원됨 —
> 곱하고 나누는 값이 같은 `float` 이라 왕복이 정확합니다).

### 대조군

측정이 **무언가는** 볼 수 있어야 합니다. 부위 대신 **노출**을 흔들면:
`DI 0.913152 → 3.92345` (fill ×2). **축을 바꾸면 움직입니다.**

### 귀결 — `REQ-ENH-026` 의 경고 (측정)

mean 3000, 부위만 변경:

| 부위 | EIT | EI | DI | 경고 |
|---|---|---|---|---|
| HAND | 100 | 300 | **4.77121** | 1건 |
| CHEST | 200 | 600 | **4.77121** | 1건 |
| SKULL | 320 | 960 | **4.77121** | 1건 |

**셋 다 경고, DI 동일.** 부위별로 갈리는 일이 **구조적으로 불가능**합니다.

## 4. 할 일 (c) — 기준은 있는가

**있습니다. 다만 등급을 정확히 적습니다.**

| 등급 | 있는가 | 내용 |
|---|---|---|
| **IEC 62494-1 원문** | **없습니다** | 저장소에 표준 본문이 없습니다(검색 범위: `docs/`, `modules/`, `.moai/` 전체. `62494` 는 전부 **인용**이고 원문 텍스트나 표는 없습니다) |
| **저장소 안 2차 문서** | **있습니다** | 아래 둘 |

**`docs/post-processing/xpe/XPE-ALG-001_…md:3478` (§7.2)**

> ```
> // EI = C_ei × s_cal (IEC 62494-1 §7.2)
> // C_ei: detector-specific calibration constant
> ```
> 그리고 `compute_deviation_index(ei, ei_target) = 10·log10(ei/ei_target)`

**`docs/enhance-basic/SRS-…md:41` (FR-100-001)**

> 공식: `EI = K_gain × Q_mean`, `K_gain` 은 검출기별 보정 계수

**둘 다 EI 에 `EI_target` 이 들어가지 않습니다.** 목표는 DI 에서만 등장합니다.

> **이것은 코드 자신의 역산이 아닙니다.** `#155` 에서 `StandardLut()` 이 디스플레이
> 특성을 **가정**해야 했던 것과 다릅니다 — 여기서는 저장소가 **독립적으로 기록한
> 요구 문서**가 EI 의 정의를 말합니다. 다만 **IEC 원문은 아니므로**, 아래 수치를
> *"표준과의 거리"* 라고 부르지 않고 **"저장소 자신의 알고리즘 명세와의 거리"** 로
> 부릅니다.

**그리고 같은 문서가 EIT 표도 다르게 적습니다**(`§7.4`) — 범위 밖이라 손대지
않았고, 보고만 합니다:

| 부위 | ALG-001 §7.4 | 코드 | 차이 |
|---|---|---|---|
| Chest PA | 200 | 200 | — |
| Skull | **200** | **320** | 1.6배 |
| Hand/Foot | **80** | **100** | 1.25배 |
| Spine | **200** | **300** | 1.5배 |
| Abdomen | 250 | 250 | — |
| Pelvis | 250 | 250 | — |
| Extremity | 100 | (항목 없음 → 기본 200) | **2배** |

## 5. 규모 — `C_ei` 없이도 구해집니다

`EI = C_ei · s_cal` 이면 `DI(부위) = 10·log10(C_ei·s_cal / EIT)` 이고, **부위 사이의
차이**에서 `C_ei` 와 `s_cal` 이 약분됩니다:

```
DI(부위) − DI(CHEST) = −10·log10( EIT(부위) / EIT(CHEST) )
```

출하 표 기준, **오늘 대 기준**:

| 부위 | 오늘 DI 오프셋 | 기준대로면 |
|---|---|---|
| CHEST | 0.00 | 0.00 |
| HAND / FOOT | 0.00 | **+3.01 dB** |
| ABDOMEN / PELVIS | 0.00 | **−0.97 dB** |
| SPINE | 0.00 | **−1.76 dB** |
| SKULL | 0.00 | **−2.04 dB** |

**부위별 DI 폭: 오늘 0.00 dB, 기준대로면 5.05 dB** (`10·log10(320/100)`).

### 경고 문턱에서의 귀결 (조건부)

`C_ei` 를 "오늘의 CHEST EI 와 맞게"(mean 3000 → EI 600) 잡으면:

| 부위 | 기준 DI | `\|DI\|>3` |
|---|---|---|
| HAND / FOOT | +7.78 | 경고 |
| CHEST | +4.77 | 경고 |
| ABDOMEN / PELVIS | +3.80 | 경고 |
| SPINE | +3.01 | 경고(경계) |
| **SKULL** | **+2.73** | **경고 없음** |

**같은 노출에서 SKULL 만 경고를 벗어납니다.** 오늘은 셋 다 경고합니다(§3).

> **이 표는 조건부입니다** — `C_ei` 를 저장소가 정하지 않으므로 **절대 DI 값은
> 임의**입니다. **조건 없이 참인 것은 §5 상단의 폭(5.05 dB)** 이고, 그것이 `C_ei` 와
> 무관한 부분입니다. 두 가지를 섞어 읽지 마십시오.

## 7. 할 일 (d) — 고치지 않았습니다

`exposure_index.cpp` 는 **한 글자도 안 바꿨습니다**(임시 측정 편집은 되돌렸고
`grep -c "0.001f"` = **0**). 공식을 바꾸면 **보고되는 임상 수치**가 바뀌고, 방향은
`REQ-ENH-023` 원문과 그 근거 문헌이 판정할 일입니다.

**리더께 필요한 것**: IEC 62494-1 **원문 §7.2**(EI 정의)와 **부위별 EI_target 표**.
`#155` 에서 PS3.14 를 가져오신 것과 같은 자리입니다. 원문이 오면 §4 의 2차 문서
읽기가 맞는지, §4 의 표 불일치가 어느 쪽이 맞는지 둘 다 판정됩니다.

## 8. baseline 귀속 · 미검증 · 잔여 위험

**귀속**: 트리 `dev/postprocess`, `origin/main c6162f3` 병합 후.

**미검증**

- **IEC 62494-1 원문을 못 봤습니다.** §4·§5 는 **저장소 2차 문서**를 기준으로 한
  것이고, 그 문서가 표준을 옳게 인용했는지는 확인하지 않았습니다.
- **`C_ei` 값을 저장소가 정하지 않습니다.** 그래서 §5 의 절대 DI 표는 조건부입니다.
- **ROI 를 보지 않았습니다.** `ALG-001 §7.3` 은 ROI 선택을 요구하는데 구현은 전체
  평균입니다(`:87-90`). `#154` 의 범위가 아니어서 재지 않았고, 후속 후보로 적습니다.
- **`enhance_advanced` 쪽은 측정하지 않았습니다** — 공식이 다르다는 것을 코드에서
  읽었을 뿐(`c1·g·mean + c2`), 그쪽 DI 가 부위에 반응하는지는 **실행으로 확인하지
  않았습니다.** 읽기는 주장이고 실행이 결론입니다.

**잔여 위험**

- 부동소수 잔여가 **이 플랫폼에서** 0 비트입니다. 다른 컴파일러가 `ei` 를 확장
  정밀도로 유지하면 잔여가 생길 수 있고, 그러면 비트 비교 시험이 빨강이 됩니다 —
  그때의 빨강은 **상쇄가 고쳐진 것이 아니라 반올림**이므로, 실패 메시지가 아니라
  이 문단을 먼저 읽어야 합니다.
