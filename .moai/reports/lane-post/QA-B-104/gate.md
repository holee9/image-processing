# QA-B-104 게이트 — 스레드 도입의 부작용, GSVG 가상 그리드 (#179, #180)

**측정·판독만 했다. 코드 변경은 없다.** 커밋 없음(임시 측정 시험은 지웠다).

## 1. 주장

### (1) 동시 실행 — 과다 구독 (3072², 기본 설정 = 자동 4스레드, 5회 중앙값)

| 상황 | bilateral | fractional(order 1.0) |
|---|---|---|
| 혼자 | 39 ms | 214 ms |
| 두 모듈 동시(각자 다른 스레드에서 호출) | **47 ms** (+21%) | **218 ms** (+2%) |
| 바쁜 스레드 1개(GUI 흉내)와 함께 | 39 ms | **314 ms** (+47%) |

- 두 모듈을 동시에 불러도 요구 안이다(100 / 400 ms).
- 느려지는 폭은 bilateral 이 +8 ms, fractional 이 +4 ms 다. 두 모듈이 각각 4스레드를 잡아 8스레드가 되지만, 이 기계(20 논리 프로세서)에서는 여유가 있다.
- GUI 흉내 스레드 하나가 계속 도는 상황에서 fractional 이 +100 ms 느려졌다. bilateral 은 변화가 없었다.
- **선택지(구현은 하지 않았다)**
  - 그대로 둔다: 이 기계에서는 요구 안이다.
  - 공용 스레드 풀: 모듈이 하나의 풀을 공유해 총 스레드 수를 묶는다. `modules/common` 이 다른 레인 소유라 배치 결정이 필요하다.
  - 상한 조정: 호출자가 파이프라인 단계마다 `set_max_threads` 로 낮춘다(지금도 가능).

### (2) 코어가 적은 기계 (프로세스 선호도로 흉내, 3072²)

| 논리 코어 | 스레드 1 | 자동 |
|---|---|---|
| 2 | bilateral 113 ms / fractional 746 ms | **bilateral 108 / fractional 540 ms** |
| 4 | bilateral 121 ms / fractional 739 ms | **bilateral 70 / fractional 304 ms** |

- 방법: `SetProcessAffinityMask` 으로 논리 프로세서 2개·4개만 쓰게 했다.
- **자동값이 손해인 경우는 없었다.** 2코어에서도 자동이 같거나 빨랐다.
- 단, **`std::thread::hardware_concurrency()` 는 선호도를 반영하지 않는다**(2코어로 묶어도 20을 보고했다). 그래서 이 측정에서 자동값은 여전히 4스레드였다. 진짜 2코어 기계에서는 자동이 `min(4, 2/2) = 1` 이 되어 단일 스레드가 된다 — 그 경우는 이 방법으로 재지 못했다(§4).

### (3) 작은 영상 (자동 vs 단일 스레드, 5회 중앙값)

| 크기 | bilateral 1 / 자동 | fractional 1 / 자동 |
|---|---|---|
| 128² | 1.183 / **0.679 ms** | 2.521 / **1.694 ms** |
| 256² | 3.763 / **1.315 ms** | 8.898 / **2.721 ms** |
| 512² | 12.490 / **2.594 ms** | 27.631 / **10.343 ms** |
| 1024² | 15.583 / **13.690 ms** | 101.248 / **39.960 ms** |

- **손익 분기는 128² 까지 내려가도 나타나지 않았다.** 모든 크기에서 자동이 빨랐다.
- 그래서 "작은 영상에서는 자동으로 단일 스레드" 규칙은 지금 측정으로는 근거가 없다. 128² 미만은 재지 않았다.
- 선택지: (a) 그대로 둔다(권장 근거: 위 표), (b) 임계 크기를 넣는다 — 넣는다면 128² 미만에서 먼저 측정해야 한다.

## 2. GSVG (#180)

### 가상 그리드, 제품용 표, 3072²

- **640 ms**(5회 중앙값). 설정: `vg_kvp 80`, `vg_grid_ratio 10`, `vg_grid_frequency_per_cm 40`, `vg_pixel_pitch_mm 0.139`, `vg_air_signal 60000`, `vg_iterations 3`, 피라미드 6단·gain 1.3·denoise 2.
- 비교: 시험용 합성 표로는 597–613 ms 였다(B-99·B-103). 제품 표가 약 5% 느리다. 커널이 gauss4(항 4개)이고 합성 표는 gauss2 다.

### REQ-GSVG-019 가 가상 그리드를 포함하는가 — 원문 판독

```
### REQ-GSVG-019: Processing Time
When a 3072x3072 16-bit image is processed,
the system shall complete processing within 1.0 seconds (Tier 1 DWT, Intel i7 or equivalent).
```
(`.moai/specs/SPEC-XPE-GSVG/spec.md:219-222`)

- 괄호의 조건이 **"Tier 1 DWT"** 다. Tier 1 은 문서에서 DWT 기반 그리드 억제를 가리킨다(`docs/post-processing/gsvg/README.md:101,221`).
- 따라서 이 요구는 **그리드 억제 경로의 시간**을 말한다고 읽힌다. 가상 그리드(#180 에서 추가된 별도 경로)는 이 문장에 조건으로 들어 있지 않다.
- 두 경로는 배타적이다(같은 호출에서 함께 돌지 않는다. `gsvg.cpp` init 에서 둘 다 켜면 `XPE_ERR_CONFIG_INVALID`). 그래서 "억제 757 ms + 가상 그리드 640 ms 합계" 라는 상황은 한 번의 호출에서 발생하지 않는다.
- 판정 제안(결정은 리더): 요구에 가상 그리드 경로의 시간 조건을 **따로** 적는다. 지금 값은 제품 표에서 640 ms 다.

### 같은 방식의 병렬화가 가능한가 — 판독만

**그리드 억제 (`grid_dwt.cpp`)**

| 단계 | 3072² 비중(B-102 측정) | 병렬화 |
|---|---|---|
| `Dwt2` 행 패스 | 정방향 229 ms 의 일부 | 가능. 행마다 독립이다 |
| `Dwt2` 열 패스(전치본) | 같음 | 가능. 열마다 독립이다 |
| `Idwt2` | 255 ms | 가능. 같은 구조다 |
| `Transpose` | 위에 포함 | 가능. 블록마다 독립이다 |
| `CheckSubband`/`DetectInputGrid` 의 `LineProfile` | 149 ms 의 일부 | **조건부**. 행 축 프로파일은 행마다 독립이라 가능하지만, 열 축 프로파일은 행을 가로지르는 누적이라 밴드로 나누면 덧셈 순서가 바뀐다. 출력 동일을 지키려면 이 축은 순차로 두어야 한다 |
| FFT | 같음 | 라인 단위로 가능하나 크기가 작다 |

- 즉 시간의 약 80%(정방향+역방향 DWT)는 출력 동일 병렬화가 가능해 보인다.

**가상 그리드 (`virtual_grid.cpp`)**

| 단계 | 병렬화 |
|---|---|
| `ScatterEstimate`(축소 격자 합성곱) | 가능. 출력 화소마다 독립이다 |
| 두께 추정 반복 루프 | 가능. 화소마다 독립이다. 단 `nHigh`/`nLow`/`nCapped` 카운터는 밴드별로 세어 합쳐야 한다(정수라 순서 무관) |
| 업샘플·최종 화소 루프 | 가능. 행마다 독립이다 |
| `PyramidContrast` | 판독 못 함. 피라미드 단계 간 의존이 있어 단계별로 나눠야 한다 |

- gsvg 는 `/fp:fast` 가 아니다(`cmake/Platform.cmake:10` 의 `/arch:AVX2` 만 적용). B-103 에서 마지막 자리를 바꾼 함정은 `/fp:fast` 인 enhance_basic 에서 나왔으므로 위험이 더 낮다. 다만 **구조를 바꿀 때마다 기준 파일 비교가 필요하다**는 점은 같다.

## 4. 미검증

- **진짜 코어가 적은 기계**. 선호도로 묶어도 `hardware_concurrency()` 는 20을 보고해 자동값이 4로 유지됐다. 코어가 2인 기계에서는 자동이 1스레드가 되는데, 그 경로의 시간은 재지 못했다.
- 128² 미만 영상.
- CI 러너의 코어 수(로그에 없다).
- GUI 흉내는 바쁜 스레드 1개다. 실제 GUI 의 렌더링·입력 처리 부하와 같지 않다.
- 동시 실행 측정은 두 모듈만이다. display·gsvg 를 함께 돌리는 경우는 재지 않았다.
- 가상 그리드 640 ms 는 합성 입력(난수 DN)이다. 실제 영상이 아니다.
- 병렬화 가능성은 **코드 판독**이다. 실제로 출력이 같은지는 구현하고 기준 파일로 비교해야 안다.

## 5. 잔여 위험

- CI 에서 bilateral·fractional 이 요구를 넘는다. 판정 기준이 기준 기계라는 결정에 의존한다.
- 자동값은 `hardware_concurrency()` 에 기대는데, 이 값은 프로세스 선호도를 반영하지 않는다. 컨테이너나 선호도로 CPU 를 제한한 환경에서는 실제 가용 코어보다 많은 스레드를 잡을 수 있다.
- 동시 호출에서 fractional 이 GUI 부하에 +47% 느려졌다. 스레드 수를 호출자가 낮추지 않으면 그대로 노출된다.
