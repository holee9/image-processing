# QA-B-157 (`#210`) — 번호는 고쳤습니다. 다만 **고치는 행위가 orphan 을 하나 늘렸습니다**

## 1. 주장

1. **전제 참 — 다만 "존재하지 않는다" 를 제 손으로 다시 갈랐습니다.** `REQ-AI-009`
   문자열은 SPEC 에 **2건 있습니다.** 둘 다 리더가 이 결함을 서술한 산문이고,
   **정의는 0건**입니다(전체 정의 46건). §2
2. **(a) `092` 가 맞는 요구입니다** — 주제는 같습니다. 다만 **구현은 일부뿐**이라
   그 사실을 주석에 같이 적었습니다. `alert` 는 0건입니다. §3
3. **(b) 시간 예산은 배선돼 있지 않습니다.** 브리지를 만드는 곳이 `src/` 에 0곳,
   `ai.cpp` 는 브리지를 참조하지 않고, 파싱한 `timeoutMs` 는 **로그로만** 쓰입니다. §3
4. **§2 전수: 15개 번호 중 orphan 은 `009` 하나가 맞습니다.** 다만 **인용 자리는
   4곳**이고 도구가 세는 "1건" 은 번호 기준입니다. §4
5. **고치는 도중 orphan 이 4→5 로 늘었습니다** — 옛 번호를 설명하려고 그대로 적었더니
   도구가 **인용과 언급을 구별하지 못했습니다.** §5
6. orphan **20 ids / 73 citations → 19 / 69**, AI 계열 **소멸**. §6

## 2. 전제 — "존재하지 않는다" 를 다시 확인했습니다

카드는 *"그 번호는 `SPEC-XPE-P3-AI` 에 존재하지 않습니다 — 제가 확인했습니다"* 라고
했습니다. 문자열만 세면 **틀립니다**:

| 검색 | 결과 |
|---|---|
| `grep -c "REQ-AI-009"` (SPEC) | **2** |
| 그 2건의 정체 | `:152`·`:160` — **리더가 이 결함을 서술한 산문** |
| 정의 패턴 `^\*\*REQ-AI-009\*\* \(` | **0** |
| **대조군** 같은 패턴, `092`·`002`·`061`·`006` | 각 **1** |
| **대조군** 정의 전수 | **46** (리더가 말한 "요구 46건" 과 일치) |

**결론은 같지만 근거가 다릅니다.** "문자열이 없다" 가 아니라 **"정의가 없다"** 입니다.
문자열 계수로 판정했으면 *"2건 있으니 존재한다"* 로 뒤집혔을 자리입니다.

정의 대조는 **리더의 main 체크아웃 SPEC** 을 봤습니다. 제 워크트리의 `.moai/specs`
는 다릅니다(spec 파일 53 vs 18, AI 정의 47 vs 46) — 제 브랜치가 리더의 SPEC 커밋을
아직 안 받았기 때문입니다. **두 트리 모두에서 `009` 는 orphan** 이라 판정은
트리 의존이 아닙니다.

## 3. (a)(b) — 카드 §1

### (a) `092` 가 그 코드가 하려는 것인가 → **주제는 맞고, 구현은 일부**

`REQ-AI-092`: *"AI inference shall enforce time budget (configurable, default
5s); exceeding budget triggers fallback and alert."*

| 요구 조각 | 실재 | 근거 |
|---|---|---|
| configurable | **예** | `ai.cpp:202` 가 `"timeout_ms"` 를 파싱 |
| default 5s | **예** | `XPE_AI_DEFAULT_TIMEOUT_MS` = `5000` |
| fallback | **예** | 타임아웃이 `XPE_ERR_PROCESSING_FAILED` 반환 |
| **and alert** | **아니오** | `ai_ipc_bridge.cpp` 의 alert 호출 **0건** |

`alert` 만 없는 것이 아니라 **없다는 것을 확인했습니다**: 대조군으로
`xpe_common` 의 alert API(`xpe_get_pending_alert`·`xpe_alert_push` 등)가 실재하고
다른 곳에서 쓰입니다 — 그 기능이 프로젝트에 없어서가 아닙니다.

**판정**: 번호를 바꾸되, *"바꿨으니 충족"* 으로 읽히지 않게 **무엇이 없는지를 같은
주석에 적었습니다.** 카드 §1 의 *"번호를 바꿔 초록을 만드는 것이 목적이 아니다"* 에
대한 제 답입니다.

### (b) 시간 예산이 실제로 구현돼 있는가 → **배선이 없습니다**

| 관측 | 값 |
|---|---|
| `xpe_ai_ipc_bridge_create` 를 부르는 곳 (`src/`, 시험 제외) | **0** (정의 1줄뿐) |
| `ai.cpp` 의 `ipc_bridge`/`IpcBridge` 참조 | **0** |
| `state->timeoutMs` 사용처 | 선언 `:86` · 설정 `:203` · 설정 `:262` · **로그 `:349`** — 끝 |

**파싱해서 저장한 예산이 로그에만 쓰입니다.** `confidenceThreshold`(`#210`,
`QA-B-156`)와 **같은 형태**입니다 — 계산되고 저장되는데 소비하는 코드가 없습니다.

브리지 안의 타임아웃 자체는 실재합니다(연결 `:86` 루프, 수신 `ERROR_TIMEOUT`).
**다만 배포 빌드에서 그 경로에 도달하지 않습니다** — 추론 진입점이 IPC 앞에서
스텁으로 돌아갑니다(`QA-B-154` 의 `InferenceEntryPointsStopBeforeTheModel`).

> 카드 §1(b) 의 예상대로 **주석이 없는 기능을 서술**하는 형태입니다. `QA-B-155`·
> `B-156` 과 같아서 같은 처방(지우지 말고 수치로 적기)을 썼습니다.

## 5. 고치는 행위가 orphan 을 늘렸습니다

옛 번호를 기록으로 남기려고 주석에 **그대로 적었습니다.** 결과:

```
(수정 전)  009  x4
(1차 수정) 009  x5      ← ai_ipc_bridge.cpp 에 설명문 2줄이 더 잡힘
```

**도구는 인용과 언급을 구별하지 못합니다.** `SPEC` 쪽에서 리더의 산문 2건이
문자열로 잡힌 것(§2)과 **정확히 같은 성질**이고, 이번에는 제가 그 함정을 코드
쪽에 새로 만들었습니다.

고침: 기록은 남기되 **문자열 형태를 피했습니다** — *"was cited as AI requirement
009"*. 그리고 왜 그렇게 썼는지를 주석에 적어 다음 사람이 되돌리지 않게 했습니다:

```
 *   The literal "REQ-AI-" + "009" form is deliberately not written anywhere
 *   in this repo: the citation checker greps for it and cannot tell a
 *   citation from a historical note, so spelling it out here ADDED an
 *   orphan (4 -> 5) instead of removing one.
```

> `QA-B-155`·`B-156` 에서 쓴 *"옛 문구를 그대로 인용해 남긴다"* 는 방식이 **이
> 자리에서는 역효과**였습니다. 같은 처방이 도구가 읽는 문자열에 닿으면 반대로
> 작동합니다.

**이 보고서 자체는 안전한가 — 재서 확인했습니다.** 이 `gate.md` 에는 리터럴이
**4건** 있습니다. 도구를 다시 돌리니 여전히 `19 / 69` 이고 AI 계열은 없습니다 —
`.moai/reports/**` 는 스캔 범위 밖입니다(도구가 세는 것은 spec 53 + code 212).
**추측이 아니라 측정입니다**; 범위가 넓어지면 이 보고서가 orphan 4건을 새로
만듭니다.

## 8. 미검증 · 잔여 위험

- **나머지 14개 번호의 "뜻" 은 확인하지 않았습니다.** 실재만 봤습니다 —
  `#211`(`REQ-P1A-008` 이 원문에서는 `006`) 형태가 `modules/ai` 에 있는지는
  **모릅니다.** 도구로는 구조적으로 못 잡습니다
- **`alert` 부재를 "구현 안 됨" 으로 판정했지만**, alert 를 브리지가 아니라
  호출자가 올리는 설계일 가능성은 배제하지 않았습니다 — 다만 그 호출자가 없습니다(§3-b)
- **수정한 주석에는 회귀 가드가 없습니다.** `check_req_citations.py` 는 orphan 은
  잡지만 *"살아 있는 번호를 틀린 뜻으로"* 는 못 잡고, §5 의 함정(설명문이 인용으로
  세어짐)도 **다음 사람이 다시 밟을 수 있습니다** — 주석 한 줄이 유일한 방어입니다
- **`ai_worker_protocol.h:180`** 의 `"timeout_ms": 5000` 예시가 실제 워커 프로토콜과
  맞는지는 확인 안 했습니다 (범위 밖)
- 제 워크트리 SPEC 이 main 과 다릅니다(§2) — 정의 대조는 main 을 봤지만, **제 트리
  기준 orphan 수치(20/73→19/69)는 제 트리의 SPEC 집합에 대한 것**입니다
