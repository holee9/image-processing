# QA-B-201 M3b — 하한을 샤프닝 여부와 무관하게 출력 전체에 적용 (#251)

리더 정정(M3 수신 후): 사용자가 고른 문구는 "모듈이 0보다 작은 값을 내보내지 않게" 이다 — 샤프닝 여부와 무관하게 **출력 전체**를 0 이상으로. M3(`963d48a9`)는 하한을 샤프닝된 값에만 적용하고 샤프닝되지 않은 음수 입력은 그대로 두었는데(M3 보고서 §1) 그것을 이 커밋이 바꾼다. 이 보고서는 M3 보고서 §1 의 "내가 정한 것" 단락을 **대체한다**.

## 0. 결과

| 항목 | 내용 |
|---|---|
| 바뀐 것 | `edge_enhance.cpp`: 샤프닝 결과를 `result = (abs_diff >= threshold) ? sharpened : orig` 로 먼저 고르고 `row[x] = result < 0 ? 0 : result`. 상한은 그대로. 헤더 doxygen 문구도 "출력에 0 미만 없음, 샤프닝되지 않는 화소는 입력 그대로이되 음수 입력은 0 으로". |
| 시험 | M3 의 `APixelThatIsNotSharpenedKeepsItsInputValueEvenWhenItIsNegative` 를 **`TheOutputHasNoNegativeEvenForANegativeInputThatIsNotSharpened`** 로 바꿈(리더 지시): 입력이 −5 로 평평한 영상은 샤프닝이 일어나지 않지만 출력 4096 화소가 모두 0. 대조군 `APositivePixelThatIsNotSharpenedIsStillReturnedAsItCame` 추가: −50 / 1000 계단에서 출력에 음수가 없고(최소 0), 에지에서 먼 양수 화소는 1000 그대로, 에지에서 먼 음수 입력은 0. |
| 입력이 음수였다는 사실 | 이 단계 입력의 음수는 파이프라인에서 생기지 않는다(log 단계가 0 으로 자름, REQ-ENH-002). 그래서 이 하한은 정상 경로에서는 샤프닝된 화소에만 작용한다. 입력이 음수인 화소가 0 으로 돌아오는 것은 계약 밖 입력에 대한 방어이며, 헤더와 코드 주석에 같은 문장으로 적었다. |
| 16비트 결과 | **여전히 바뀌지 않는다 — 측정**: 같은 96개 경우에서 바닥 없는 바이너리(HEAD) 대 M3b 바이너리의 16비트 변환 결과가 달라진 화소 0개(`m3b_equiv_16bit_out.txt`; 장면 입력은 모두 0 이상이라 입력 음수 경로는 이 측정에 들어가지 않는다). |
| 반증 | 4팔 모두 터졌고 소스는 팔마다 바이트 단위로 복원(`m3b_arms_out.txt`). |
| 성능 | M3 바이너리 대 M3b 바이너리를 번갈아 40회씩: **40/40 대 40/40 통과**(`m3b_ab_perf_out.txt`). |
| 검증(관측) | ci-post ctest(CI 필터) 1365개 통과·0 실패(루트 `schemas/` 를 임시로 놓았을 때, 이전 1364 + 새 1), `EdgeEnhance*` 53개 통과, doxygen 경고 0, 헤더 점검 20개 0건. |

## 1. 반증 (`m3b_arms_driver.py.txt`)

| 끈 방어 | 빨개진 시험 |
|---|---|
| 하한 제거(`row[x] = result`) | 바닥 시험, 상한 시험, 음수 입력 시험, 양수 대조 시험(최소 0 단언) |
| 하한을 샤프닝된 값에만(M3 의 동작으로 되돌림) | 음수 입력 시험, 양수 대조 시험(에지에서 먼 음수 입력이 −50 으로 남음) |
| 하한을 1 로 | 바닥 시험, 음수 입력 시험, 양수 대조 시험 |
| 하한을 입력값으로(`result < 0 ? orig`) | 바닥 시험, 음수 입력 시험 |

(뒤의 두 팔에서 20 ms 단발 성능 시험이 함께 빨갰다 — 재빌드 직후 기계 상태에 흔들리는 시험이다. 같은 줄을 둔 바이너리를 번갈아 40/40 으로 돌린 결과는 위 표.)

## 2. Gap / 잔여 위험
Gap
- 입력이 음수인 화소가 샤프닝 영역에 있을 때(상한 계산이 음수 원본에서 어떤 값을 내는지)는 시험하지 않았다. 하한을 마지막에 적용하므로 결과는 0 이상이다 — 코드 읽기.
- 16비트 동일성 측정의 장면 입력에는 음수가 없다(위 표).
- 이 브랜치에 루트 `schemas/` 가 없어 ctest 의 모델카드 시험 3개는 병합 전에는 빨갛다(QA-B-201 M2 보고서 §4); 검증 때만 임시로 놓았다가 지웠다.

잔여 위험
- 음수 입력을 0 으로 돌려주므로, 어떤 호출자가 이 단계에 음수 값을 일부러 넘겨 부호 있는 결과를 기대한다면 달라진다. 지금 코드베이스에서 그런 호출자는 찾지 못했다(M1 §3 의 소비자 목록 기준).
