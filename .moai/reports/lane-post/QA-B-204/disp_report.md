## 1. D1 — 검은 수준이 표준 범위 아래

REQ-DISP-025/026, `presentation_lut.cpp`. 헤더는 "비양수 최소는 0.01 로 바뀐다" 고 적었지만, 0.05 cd/m² 아래는 PS3.14 식 7-2 의 정의 구간(0.05–4000) 밖이다.

관측(감마 2.2 곡선 256점, Lmax 300 cd/m², 기준 LUT 은 PS3.14 식 7-2 를 이분법으로 뒤집어 직접 계산):

| 검은 수준 | rc | 최대 차이 | 300 초과 항목 | 모듈 LUT 앞부분 | 기준 앞부분 |
|---|---|---|---|---|---|
| 0.00 | OK | 1172 | 34 | 0,0,0,0 … | 590,597,604,611 … |
| 0.01 | OK | 1046 | 26 | 0,0,0,0 … | 0,43,89,138 … |
| 0.03 | OK | 1434 | 33 | 0,0,0,0 … | 0,273,366,466 … |
| 0.05 | OK | 24 | 0 | 24,329,462,559 … | 0,316,451,556 … |
| 0.20 | OK | 6 | 0 | 0,448,625,773 … | 0,450,625,772 … |
| 1.00 | OK | 8 | 0 | 8,678,939,1134 … | 0,677,938,1133 … |

- j(0.01) = −20.84, j(0.05) = 1.03, j(4000) = 1023.16 (같은 스크립트로 계산; 이전 후보 서술의 "−20.8" 과 일치). 모듈의 역함수(`luminance_from_jnd`)는 표 B-1 의 j = 1..1023 에 맞춘 유리함수라 j < 1 에서는 외삽이고, 그 결과 앞 33개 항목이 0 이 된다(`j <= 0` 인 항목 수 33 과 같다).
- rc 는 모두 OK 라서 호출자는 이상을 모른다(헤더의 "silently coerced" 주의와 일치).
- 판정: 확정. 대처 선택지는 둘이다 — 0.05 미만을 `INVALID_INPUT` 으로 거부(표준 구간 밖이라는 결정), 또는 0.05 로 올려 쓰고 알림. 어느 쪽인지는 요구 결정이라 리더 몫.
- 0.05 에서 24 카운트(0.05–0.2 구간 모두 8 이하)는 기준 계산의 반올림·표 B-1 맞춤 오차 수준으로 보고 결함으로 세지 않았다. 이 오차의 원인 분해는 하지 않았다(Gap).

## 2. D2 — 표 모드에서 +2³¹ 이상 입력

REQ-DISP-002 "범위 밖은 가장 가까운 경계 항목으로". 표(1000..16000, 16항목, 첫 매핑 0)와 float 입력:

| 입력 | 출력 | 기대 |
|---|---|---|
| −3.4e38, −1e12, −3e9, −2³¹, −100, 0 | 1000 | 1000 |
| 7 | 8000 | 8000 |
| 15, 16, 100 | 16000 | 16000 |
| **+2³¹, +2147483904, 3e9, 1e12, 3.4e38** | **1000** | 16000 |

- 음의 쪽은 맞고 양의 쪽만 첫 항목으로 감긴다: float→int32 변환이 범위를 넘으면 정의되지 않은 동작이고, 이 환경에서는 INT_MIN 이 되어 아래쪽 경계로 간다고 읽힌다(원인을 소스에서 확인하지 않았다 — Gap).
- 실영상은 UINT16 이 원본이므로 2³¹ 이상 값이 이 경로에 오는 일은 드물다. 그래도 요구 문구가 명시한 경계 거동이 어긋난다.
- 판정: 확정, 심각도 낮음(드문 입력). 수정은 변환 전에 float 에서 클램프하는 한 줄이다.

## 3. D3 — LINEAR 의 width ∈ (0, 1]

REQ-DISP-009 식 `((x − (c − 0.5)) / (w − 1) + 0.5)·(max−min)+min`, REQ-DISP-015 는 `w ≤ 0` 만 거부. center 100, 출력 0..1, 입력 99, 99.5, 99.9, 100, 100.1, 100.5, 101 (모듈 | SPEC 식):

| width | 모드 | 결과 |
|---|---|---|
| 0.25 | LINEAR | 모듈 0,0,1,1,1,1,1 / SPEC 1,0.5,0,0,0,0,0 (분모 −0.75 라 램프가 뒤집힘) |
| 0.5, 0.999 | LINEAR | 같은 모양(모듈은 계단, SPEC 은 뒤집힌 램프) |
| 1.0 | LINEAR | 모듈 0,0,1,1,1,1,1 / SPEC 은 0 으로 나눔 |
| 1.5, 2.0 | LINEAR | 모듈 = SPEC (일치) |
| 0.25 … 2.0 | LINEAR_EXACT | 모듈 = SPEC 전 구간 일치(대조군) |

- 판정: 확정(요구 공백). 두 표현이 다 영상이 무의미한 구간이다. DICOM 은 LINEAR 의 width 를 1 이상으로 규정하므로 가장 자연스러운 해결은 LINEAR 에서 `width < 1` 을 `INVALID_INPUT` 으로 거부하는 것이다(요구 문구 갱신 + 시험). 이 DICOM 문구는 내가 이번에 원문으로 대조하지 않았다 — Gap.

## 4. D4 — REQ-DISP-021 문구와 비유한 값

`xpe_apply_presentation_lut` 에 입력 [−1, 0, 0.5, 1, 2, 1e30] → 출력 [0, 0, 32799, 65535, 65535, 65535] (LUT[0]=0, LUT[1023]=65535 라 클램프가 맞다). +inf, −inf, NaN 한 화소씩 → 전부 `INVALID_INPUT`, 버퍼는 float 그대로(호출 거부).

- 판정: 코드는 QA-B-181f 이후 의도대로. 요구 문구("[0,1] 밖은 클램프")가 비유한 값에 대해 반대로 읽힌다. 문구 갱신("유한한 값은 클램프, 비유한은 `INVALID_INPUT`")은 리더 몫(SPEC 소유).

## 5. D6 — GSDF 광도의 NaN

NaN 을 첫·중간·끝에, +inf 를 끝에, −inf 를 첫에, 내림차순 [5,1,3] — 7경우 전부 `INVALID_INPUT` 이고 출력 파라미터(0xABCD 로 채워 둔 1024항목과 `gsdfEnabled = 7`)가 그대로다. 대조군(오름차순 [1,50,100]) 은 OK 로 파라미터가 갱신됐다.

- 판정: 코드 결함은 없음, 후보 철회. SPEC 의 "NaN 광도는 가드를 통과한다" 서술은 낡았다(리더 몫, 이미 상태 메모가 달려 있음).

## 6. D7 — 함수 수

main SPEC: `REQ-DISP-036 (구 REQ-DISP-029 의 두 번째 정의): All 6 exported functions`, 정정 노트가 헤더의 `XPE_API` 6개(`xpe_display_version`, `xpe_apply_modality_lut`, `xpe_apply_voi_lut`, `xpe_voi_preset_create`, `xpe_apply_presentation_lut`, `xpe_gsdf_calibrate`)를 근거로 든다. 내가 이 체크아웃의 헤더에서 센 값도 6 개이고 헤더 머리말도 "6 exported functions". 이미 해결.

## 7. D8 — minOut > maxOut

center 100, width 100, 입력 0, 50, 100, 150, 200:

| 모드 | (minOut, maxOut) | 출력 |
|---|---|---|
| LINEAR | (0, 1) | 0, 0, 0.505, 1, 1 |
| LINEAR | (1, 0) | 1, 1, **1**, 0, 0 (뒤집힌 램프라면 중심은 ≈0.5) |
| LINEAR_EXACT | (0, 1) | 0, 0, 0.5, 1, 1 |
| LINEAR_EXACT | (1, 0) | **0, 0, 1, 1, 1** (뒤집힌 램프라면 1, 1, 0.5, 0, 0) |
| SIGMOID | (0, 1) | 0.018, 0.119, 0.5, 0.881, 0.982 |
| SIGMOID | (1, 0) | **1, 1, 1, 1, 1** (뒤집힌 S 곡선이어야 함) |

- 모든 호출이 rc OK. 원인은 값 계산 뒤의 `clamp(x, minOut, maxOut)` 가 하한 > 상한이면 한쪽 값으로 붙기 때문으로 읽힌다(소스를 이 후보에서 다시 읽지는 않았다 — Gap).
- 판정: 확정. 요구에 `minOut < maxOut` 이 없고 거부도 처리도 없다. 영상 반전을 의도한 호출자는 조용히 깨진 출력을 받는다. 선택지: `minOut >= maxOut` 거부(요구 추가), 또는 반전을 지원(식은 이미 그대로 쓰이므로 클램프만 `min/max` 로 정렬).

## 8. 처리 우선순위 제안(DISP)

1. **D8** — 조용히 틀린 영상(rc OK), 선택지 둘, 요구 한 줄. 반전 의도가 있는 호출은 gui 쪽에 없는지 먼저 확인(grep 으로 `minOut` 사용처).
2. **D1** — 디스플레이 보정이 조용히 틀림. 실사용은 측정한 검은 수준 < 0.05 일 때(OLED·LCD 어두운 방) — 거부 쪽이 안전.
3. **D3** — LINEAR 의 width < 1 거부(한 줄 + 요구).
4. **D2** — 한 줄 클램프, 실사용 낮음.
5. **D4·D6** — 문서 갱신뿐(코드 변경 없음). D7 은 완료.

## 9. Gap / 잔여 위험

Gap
- 원인 소스(클램프 순서, float→int 변환 위치)는 이번에 다시 읽지 않았다. 판정은 관측한 출력에 근거한다.
- D1 의 0.05 이상 구간의 24 카운트 차 원인을 분해하지 않았다.
- D3 의 "DICOM 은 LINEAR width ≥ 1" 은 PS3.3 원문 대조 없이 기억에 근거한 서술이다(수정 방향 제안에만 쓰였고 판정에는 쓰이지 않음).
- gui(clients/, gui/)가 `minOut > maxOut` 이나 width < 1 을 실제로 보내는지 확인하지 않았다.
- 측정은 이 체크아웃의 `ci-post` 빌드 한 개(MSVC, native)이다.

잔여 위험
- D1 의 기준 LUT 은 표준 식을 외삽한 것이라 표준 구간 밖에서 "맞는 값" 자체가 정의돼 있지 않다. 판정은 "모듈의 값이 표준 영역 안의 거동과 어긋난다" 이지 "기준이 정답" 이 아니다.
