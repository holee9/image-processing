# QA-B-111 게이트 — 후처리 기본값을 요구에 맞춘다 (#180)

커밋 `1d59157`, 미푸시. 기본값 `pyramidLevels` 0→**4**, `pyramidGain` 1.0→**1.3**, `denoiseK` 0.0→**2.0**.

## 1. 주장

### (1) 기본값 0 은 의도였고, 그 의도가 요구와 어긋난다

카드가 확인을 요구한 항목이다. **의도였다** — 근거 둘:

- `modules/gsvg/src/virtual_grid.h` 옛 주석: `// Optional post-steps: pyramidLevels == 0 means neither step runs.`
- `modules/gsvg/include/xpe/gsvg/gsvg_api.h` 옛 문서: `Optional post-steps (off when absent)`

즉 "설정을 안 보내면 끈다" 가 설계였다. 그러나 REQ-GSVG-013 은 `**the system shall** apply Laplacian Pyramid decomposition` 이고 조건이 붙어 있지 않다. GUI 는 `vg_pyramid_levels` 를 보내지 않으므로(GUI-C-103), 제품 기본 상태에서 요구가 꺼져 있었다. 누락이 아니라 **의도와 요구의 불일치**다.

### (2) 단수만 올리면 요구가 형식적으로만 충족된다 (질의 → 리더 결정)

이득 기본값 1.0 은 피라미드의 항등이다. 기존 시험 `UnitGainIsIdentityAndGainRaisesDetail` 이 이미 그것을 단언하고(최대 차이 < 1e-6), MC 로도 확인했다 — **단수 0 과 4 의 정답 비율이 완전히 같았다**:

| 팬텀 | 단수 0 | 단수 4 (이득 1.0) |
|---|---|---|
| 계단 | 중앙값 1.0591, \|r−1\| 0.0658 | 1.0591, 0.0658 |
| 쐐기 | 1.0784, 0.0796 | 1.0784, 0.0796 |

분해와 복원은 돌지만 대비는 하나도 살아나지 않고 시간·메모리만 쓴다. 카드의 반증 조건("대비 복원 시험이 빨강")도 성립하지 않는다. 리더에게 질의했고, **헤더 예시 값(4 / 1.3 / 2)을 기본값으로** 하는 결정을 받았다.

### (3) 바뀌는 기대값 — 6건, 모두 "후처리가 꺼져 있다" 를 전제했다

| 시험 | 옛 기대가 전제한 것 | 바꾼 방법 |
|---|---|---|
| `GsvgVirtualGridPyramid.UnitGainIsIdentityAndGainRaisesDetail` | `plain` = 후처리 없는 출력 | 기준선을 `pyramidLevels = 0`(이득 1·잡음 0)으로 **명시** |
| `GsvgVirtualGridPyramid.DefaultLevelsRestoreContrast_REQ_GSVG_013`(이번에 추가) | — | 기준선을 이득 1.0 으로 명시 |
| `GsvgVirtualGridCapChoice.CompareCandidates` | 상한의 성질을 **후처리 없이** 잰다 | 후처리를 명시적으로 끔. 후처리가 켜진 상태의 결과는 새 기록 시험으로 분리 (아래 (4)) |
| `GsvgVirtualGridMcMask.MaskEqualsZeroedInput` | 마스크 경로 = 입력을 0 으로 채운 경로의 **정확한 일치** | 이 등식은 **뺄셈 단계의 성질**이다. 후처리를 끄고 잰다 |
| `GsvgVirtualGridMcMask.PublicEntryPoint` | 같은 등식을 공개 API 로 | JSON 에 `vg_pyramid_levels: 0, vg_pyramid_gain: 1, vg_denoise_k: 0` 추가 |
| `GsvgVirtualGridMcMask.NoMaskOverSubtracts` | 마스크 없는 **뺄셈**의 기록값(min 0.7275 / 0.7694) | 후처리를 끄고 잰다 — 기록값 유지 |

**등식이 깨지는 크기**: 후처리가 켜진 채로는 마스크 경로와 0 채운 경로가 계단 팬텀에서 최대 **1903 DN** 차이 난다. 마지막 자리 문제가 아니라, 마스크 밖 처리(가장자리 복제, QA-B-110)가 실제로 일을 하는 것이다. 이득 1.0·잡음 0 이던 중간 상태에서는 이 차이가 상대 2.9e-16 이었다.

### (4) 새로 드러난 것 — 상한 뒤 피라미드가 가드를 뚫는다

과보정 가드(`CapMode::GlobalSum`)는 **산란 뺄셈 단계**에서 동작한다. 기본값이 켜지면서 그 뒤에 피라미드 대비 증폭이 돌고, 가드가 지켜 둔 화소를 다시 아래로 밀어낸다.

과대 추정 표(커널 ×2), 계단 장면:

| | 0 에 가까운 화소 비율 | 최대 과다 뺌 |
|---|---|---|
| 가드만 (후처리 끔) | **0.000%** | 0.6933 |
| 기본값(후처리 켬) | **0.037%** | 0.9626 |

후보 비교 시험의 같은 장면에서는 최대 과다 뺌이 **1.063** 까지 갔다 — 1.0 이상은 화소가 0 까지 내려갔다는 뜻이다.

기록 시험 `GsvgVirtualGridCapChoice.PostStepsReintroduceNearZeroPrimaries_REQ_GSVG_018` 로 남겼다. **이것은 기본값이 틀렸다는 뜻이 아니라, 가드의 보장이 자기가 도는 단계에 한정된다는 뜻이다.** 가드를 후처리 뒤에도 돌릴지는 설계 판단이며 리더 몫이다(REQ-GSVG-018).

### (5) MC 정답 대비 비율 — 전후 (나빠진 것 포함)

| 팬텀 | 지표 | 전(후처리 꺼짐) | 후(기본값) | 방향 |
|---|---|---|---|---|
| 계단 | 비율 중앙값 | 1.0591 | 0.9689 | 1 에 가까워짐 |
| 계단 | \|r−1\| 중앙값 | 0.0658 | **0.0623** | 좋아짐 |
| 계단 | 최소 | 0.8048 | **0.6275** | **나빠짐** |
| 계단 | 최대 | 1.5347 | **1.5522** | **나빠짐** |
| 쐐기 | 비율 중앙값 | 1.0784 | 1.0389 | 1 에 가까워짐 |
| 쐐기 | \|r−1\| 중앙값 | 0.0796 | **0.0583** | 좋아짐 |
| 쐐기 | 최소 | — | 0.5987 | **나빠짐** |

**중앙값은 좋아지고 양 끝은 나빠진다.** 대비 증폭이 편차를 키우기 때문이며, 대비 복원의 목적과 모순되지 않지만 "정답에 가까워졌다" 고 말할 수는 없다.

**QA-B-109 의 018 잠정 방지선에 대한 경고**: 계단 경계 봉우리가 1.3946 → **1.4521** 로 올라갔다. 문턱은 1.465 다. **여유가 0.013 밖에 남지 않았다** — 통과하지만 아슬아슬하다. 최악 화소는 1.5347 → 1.5522(문턱 1.612), 중앙값 \|r−1\| 은 0.0658 → 0.0623 으로 오히려 내려갔다.

### (7) 반증

기본값 `pyramidLevels` 를 0 으로 되돌리면 `DefaultLevelsRestoreContrast_REQ_GSVG_013` 이 빨강이다(기본값 단언과 대비 증가 단언 둘 다). 되돌리면 초록.

### (8) B-110 미검증 2건

**오목한 모서리** — ㄱ자 조사야(정사각에서 우상단 사분면을 뺀 모양), 512², 4단. 오목한 경계 안쪽 링과 깊은 안쪽의 단차:

| 대안 | 단차 |
|---|---|
| 가장자리 복제 | **0.2108** |
| 입력 그대로 | 0.2160 |
| 0 | 0.2210 |

복제가 여전히 가장 작지만 차이는 5% 안이다. **오목한 모서리에서는 세 대안이 거의 같다** — 복제의 이점은 바깥 경계에 있지 오목부에 있지 않다. 복제가 오목부를 해치지도 않는다(바운딩 사각형으로 클램프하므로 오목부는 조사야 밖 값으로 채워지는데, 그 값이 경계 안쪽 값과 크게 다르지 않았다).

**복제 뒤의 속도·메모리** — (6)의 "마스크 있음" 행이 그것이다. 복제는 추가 버퍼 없이 클램프 읽기 한 번이라, 마스크 경로의 비용 증가(옛 264.5 → 새 629.2 ms)는 피라미드 때문이지 복제 때문이 아니다.

### (9) 부수 발견 — `vg_pyramid_levels: 0` 만 보내면 거부된다

`virtual_grid.cpp:697` 은 `pyramidLevels == 0` 일 때 `pyramidGain == 1.0 && denoiseK == 0.0` 을 함께 요구한다. 기본값이 1.3/2.0 이 되었으므로, **후처리를 끄려는 호출자는 세 값을 모두 보내야 한다**. 헤더 문서에 그 문장을 적었다. 이 규칙을 완화할지(0단이면 나머지 둘을 무시)는 설계 판단이라 바꾸지 않았다.

## 3. 기준선 귀속

- "전(후처리 꺼짐)" 값은 이번 실행에서 후처리를 명시적으로 끄고 잰 것이다. QA-B-109 의 018 값(봉우리 1.3946, 최악 1.5347, 중앙값 0.0658)과 일치하므로 같은 기준선이다.
- "후(기본값)" 값은 `1d59157` 과 같은 소스의 `build/ci-post` 에서 잰 값이다.
- 속도·메모리 측정 방법은 QA-B-107/108 과 같다(커밋 차지, 0.5 ms 표본, 준비 호출 뒤 기준선 대비). 기계는 한가한 상태였다.
- (8)의 오목 모서리는 4단으로 쟀다 — 512² 에서 6단은 영향 범위가 깊은 안쪽까지 닿아 기준 영역을 잡을 수 없다(QA-B-110 §1(6)의 계산).

## 4. 미검증

- **CI 판정.** push 를 하지 않으므로 확인하지 못했다. 특히 QA-B-109 의 018 봉우리 문턱(1.465)에 여유가 0.013 밖에 없어, CI 에서 조금만 달라도 빨강이 될 수 있다. **이 카드에서 가장 먼저 볼 것.**
- 가드를 후처리 뒤에도 돌리면 (4)의 0 화소가 사라지는지. 구현하지 않았다.
- 실제 영상에서 이득 1.3·잡음 2 가 적절한 값인지. 합성 장면과 MC 에서만 봤다(#151).
- 공개 API(`xpe_gsvg_process`) 경로 전체의 속도·메모리는 다시 재지 않았다. (6)은 `RunVirtualGrid` 단독이다. 기존 019 벤치(단수 6·이득 1.3·잡음 2 를 명시)는 QA-B-108 에서 494.8 ms 였고 이번 변경으로 달라지지 않는다(명시 설정이라).
- 오목 모서리는 ㄱ자 하나만 봤다. 더 복잡한 모양(여러 오목부, 원형 조사야의 절단)은 보지 않았다.

## 5. 잔여 위험

- **018 잠정 방지선의 여유가 거의 없다**(1.4521 / 1.465). 기본값을 그대로 두면, 앞으로 이 경로를 건드리는 변경이 이 시험을 쉽게 터뜨린다. 문턱을 다시 볼지 기본값을 되돌릴지는 리더 판단이다.
- (4)의 0 에 가까운 화소는 제품 경로에서 uint16 으로 내려갈 때 0 DN(검은 점)이 된다. 과대 추정 표에서만 관측했지만, 실제 장비 표가 과대 추정 쪽이면 같은 일이 난다(#151).
- 후처리가 기본으로 켜지면서, 마스크를 쓰는 호출자의 출력이 이전과 크게 달라진다((3)의 1903 DN). 기존 기준 파일이 있다면 전부 다시 만들어야 한다.
- 시간이 2.4배 늘었다. 019b 안이지만, 더 큰 영상이나 더 느린 기계에서는 여유가 줄어든다.
