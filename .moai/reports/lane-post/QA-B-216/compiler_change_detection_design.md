# 컴파일러 변화 감지 설계 초안 (QA-B-216 5항)

초안만 있다. `.github/workflows/`·`tools/` 는 리더 소유이므로 패치 초안은 `patch_draft_*.txt` 로 두고 직접 커밋하지 않았다.

## 풀려는 문제

QA-B-215 에서 같은 소스가 MSVC 14.51(CI)과 14.44(로컬)에서 다른 영상을 냈다. CI 는 `vswhere -latest` 로 도구 모음을 고르기 때문에, 러너 이미지가 올라가는 날 **소스 변경 없이** 출하 수치가 바뀐다. 아무도 모른 채 바뀌는 것이 위험이고, 바뀌는 것 자체는 위험이 아니다.

## 감지 수단 두 가지 (서로 다른 것을 본다)

| 수단 | 보는 것 | 못 보는 것 |
|---|---|---|
| A. 버전 기록 비교 | CI 가 쓴 `VCToolsVersion` 이 기록된 값과 같은가 | 같은 버전인데 옵션·정적 라이브러리가 달라 수치가 바뀐 경우 |
| B. 수치 지문 시험 | 고정 입력에 대한 enhance_basic 단계 해시가 기록된 값과 같은가 | 지문이 안 걸리는 입력에서만 생기는 차이 |

B 가 실제로 쓸 만한지 측정했다(`fixture_*.txt`, `fix216.py.txt`). 정수로만 만든 512×512 합성 입력 세 개(램프, 블록, 질감, 각각 ±30 잡음)에서:

| DLL | 양방향 해시가 post(14.44)와 같은가 |
|---|---|
| MSVC 14.29 | **같다** (세 입력 모두) |
| CI 14.51 (`39f9727a` 산출물) | **다르다** (세 입력 모두, 로그 해시는 같음) |
| `/fp:precise` | **다르다** (세 입력 모두) |

즉 3072² 실영상이 아니라 **수 ms 짜리 합성 입력으로도** 14.44→14.51 변화를 잡는다(위험을 겨눈 입력으로 확인된 지문이다). 입력은 libm 없이 정수 LCG 로 만들어 어느 기계에서도 같은 바이트다.

## 제안 구성

1. **A (버전 기록)** — `tools/ci/toolchain-record.txt` 에 허용된 `VCToolsVersion` 목록을 둔다. `post-build` 의 "Configure MSVC developer environment" 직후 한 단계가 현재 값과 비교한다. 다르면 아래 3절의 동작을 한다.
2. **B (지문 시험)** — `modules/enhance_basic/tests/` 에 시험 하나. 기대 해시는 `VCToolsVersion` 의 주.부(14.44, 14.51)별 표로 둔다.
   - 표에 있는 도구 모음에서 해시가 다르면 **실패**(진짜 회귀다).
   - 표에 없는 도구 모음이면 **건너뜀(skip) + 현재 해시를 출력**한다. 개발자가 다른 버전을 쓰는 것만으로 로컬이 빨개지지 않게 하기 위해서다.
3. **알림 내용** — 감지되면 같은 메시지에 다음 조치 목록을 붙인다: (a) 새 DLL 로 기준 영상 재생성(`m2-post-v<N+1>`), (b) 이전 기준과 단계별 차이 표(`compare_stages.py.txt` 방식), (c) 지문 표에 새 행 추가, (d) 요구 문구의 "같은 DLL" 조건은 그대로.

## 경고냐 실패냐

| 선택 | 장점 | 단점 |
|---|---|---|
| 버전 비교를 **경고**(`::warning::`) | 러너 이미지 갱신이 모든 PR 을 막지 않는다. 사람이 읽을 때만 비용 | 아무도 안 읽는 경고가 된다(이 저장소에서 읽는 사람 없는 빨간불이 실제로 있었다) |
| 버전 비교를 **실패** | 변화가 반드시 보인다 | 러너 갱신일마다 전 레인이 막힌다. 기록 갱신 PR 이 먼저 병합돼야 풀린다 |
| 지문 시험을 **실패**(표에 있는 도구 모음) | 같은 도구 모음인데 수치가 바뀌면 진짜 회귀 | 거의 없음 |
| 지문 시험 **skip**(표에 없는 도구 모음) | 로컬 개발이 안 막힌다 | 새 도구 모음의 변화가 자동으로는 빨갛지 않다 |

권고(리더가 정함): **버전 비교는 `main` push 에서만 실패, PR 에서는 경고**로 한다. 출하 기준이 되는 main 의 CI 산출물만 엄격히 보고, 러너 이미지 갱신으로 PR 들이 일제히 막히는 일은 피한다. 지문 시험은 위 표대로. 이 조합이면 "소리 없이 바뀐다"는 빠지고 "러너 갱신일에 모두가 멈춘다"도 피한다.

## 이 설계가 못 하는 것

- 컴파일러가 같고 옵션만 바꾼 경우는 B 만 잡는다(A 는 같은 버전이라 조용하다).
- B 의 입력 세 개가 모든 코드 경로를 지나지는 않는다. 양방향·CLAHE·USM 을 지나지만 EI(노출 지수) 경로는 다르다.
- 지문은 enhance_basic 4단계만 본다. 표시 쪽(자동 창 등)의 도구 모음 의존은 214d 의 "같은 DLL" 문구로만 다룬다.
- 도구 모음을 고정(`-version` 지정)하는 대안은 이 설계에 넣지 않았다. 러너 이미지에 그 버전이 계속 있다는 보장이 없고, 없어지는 날 CI 가 멈춘다. 필요하면 별도 결정이다.
