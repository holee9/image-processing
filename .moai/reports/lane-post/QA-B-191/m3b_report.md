# QA-B-191 M3b — 크기 조정 지연 시간 측정 (측정만)

**이것은 측정이지 주장이 아니다.** 장난감 모델의 추론 시간은 실제 모델(예: PRD 의 512×512 MobileNet-v3-Small)의 성능에 대해 아무것도 말하지 않는다. 장난감은 4×4 입력에 행렬곱 하나다. 이 보고서가 말할 수 있는 것은 **이 저장소가 소유한 부분, 크기 조정의 비용**뿐이다.

## 1. 무엇을 쟀나

PRD(`xpe-ai-prd.md` SWU-2.7)는 "≤ 300 ms (3072×3072, 리사이즈 + 추론 포함)"을 요구한다. 대표 입력 크기 1024², 3072²에서 12회의 **최솟값**과 중앙값(리더 지시: 12회 최솟값).

1. **크기 조정만**, 목표 512×512(PRD 의 입력 크기), 모델 없이 `ResizeImageFloat` 직접 호출.
2. **C ABI 한 호출 전체**(`xpe_bodypart_recognize`: 잠금 + 크기 조정 + 세션 실행 + 출력 검증)를 **장난감 모델**(입력 4×4)로.
3. 장난감 모델 추론만(이미 4×4 인 영상) — 규모 감각용.

시험: `BodyPart.MeasureResizeAndRecognizeLatency`(`test_bodypart_inference.cpp`). **시간 상한을 단언하지 않는다**(한 기계에서 잰 한계는 다른 기계에서 거짓이 된다, #214). 단언하는 것은 측정이 눈멀지 않았다는 것뿐이다: 크기 조정 결과의 첫 표본이 0.75 이고 마지막 줄 표본이 0 이며(실제로 크기를 조정했다), 호출이 `OK` + `CHEST` 로 답했고, 9배 큰 영상이 더 오래 걸린다.

## 2. 결과 (3회 실행, 각 12회의 최솟값 / 중앙값, ms)

| 측정 | 1회 | 2회 | 3회 |
|---|---|---|---|
| 크기 조정 1024² → 512² | 1.72 / 1.77 | 1.80 / 1.85 | 1.75 / 1.81 |
| 크기 조정 3072² → 512² | 7.16 / 7.39 | 7.29 / 7.61 | 7.10 / 7.53 |
| C ABI 한 호출 1024² (장난감) | 0.47 / 0.48 | 0.47 / 0.48 | 0.46 / 0.47 |
| C ABI 한 호출 3072² (장난감) | 4.52 / 4.61 | 4.55 / 4.66 | 4.40 / 4.53 |
| 장난감 추론만(4×4) | 0.005 / 0.005 | 0.005 / 0.005 | 0.006 / 0.007 |

세 번의 실행에서 최솟값은 ±3% 안이다. 면적 9배(1024² → 3072²)에 크기 조정 비용은 4.1배다(`7.16 / 1.72`), 즉 비용은 면적보다 완만하게 자란다(512 폭으로 내리는 가로 방향 패스가 원본을 한 번 읽는 비용이 지배적이라 읽는 양에 비례하는 것으로 보이나, 이 설명은 프로파일링으로 확인하지 않았다).

원본 파일: `m3b_latency.txt`(3회 전체 출력).

## 3. 읽는 법

- **PRD 예산 300 ms 에 대해**: 이 저장소가 소유한 크기 조정은 3072² 에서 약 7 ms 로 예산의 2~3% 다. 예산 전체를 만족하는지는 **알 수 없다** — 실제 모델의 추론 시간이 필요하고, 그것은 이 저장소에 없다(모델 부재, #130). 장난감 추론의 0.005 ms 를 예산에서 빼는 계산에 쓰면 안 된다.
- "C ABI 한 호출(3072²) 4.5 ms" 가 "크기 조정(3072² → 512²) 7.2 ms" 보다 작은 것은 모순이 아니다: 앞은 목표가 4×4 라 출력이 작아 세로 방향 패스가 가볍다. **실제 모델이 512×512 를 요구하면 호출 전체의 크기 조정 부분은 두 번째 줄의 7 ms 에 가깝다.**

## 4. 기준 (Baseline) 과 조건

i7-12700(12세대), `ci-ai` 프리셋의 RelWithDebInfo, 단일 스레드, 같은 트리. 첫 실행 시 CPU 부하 28%(다른 세션들이 이 기계를 같이 쓴다). 측정 중에 소스를 고치지 않았다.

## 5. 미검증 (Gaps)

- **실제 모델의 추론 시간** — 없다(모델 부재).
- **첫 호출의 모델 적재 비용**(`OnnxSession::Create` + 사이드카 읽기)은 재지 않았다. 12회 측정은 데워진 상태다.
- 다른 하드웨어(검출기 PC 사양)·Debug 구성·다중 스레드 동시 호출의 지연은 재지 않았다. 호출은 모듈 락 아래에서 직렬이다.
- 3072² 영상을 `ci-ai` 에서 생성하는 비용(시험 준비)은 측정에 포함하지 않았다.
- 크기 조정 알고리즘의 대안(예: 정수 비율 전용 빠른 경로)은 시도하지 않았다. 7 ms 가 예산의 작은 부분이라 필요가 확인되지 않았다.

## 6. 잔여 위험

장난감 모델의 수치가 실모델 성능으로 인용될 수 있다. 이 시험의 출력은 "BP-LATENCY … TOY model … NOT a real model" 문구를 단 채로 찍힌다.
