## 1. 주장

1. 두 조건(올바른 커널에서 나빠지지 않음, 과대 추정에서 확실히 나음)과 과소 추정 무영향을 **네 장면 모두에서** 만족한 후보는 C2, C3(ε 0.05·0.10·0.20), C4(ε 0.02·0.05) 이다.
   - C4 ε 0.10 은 ×1 에서 1.2 % 에 걸리지만 오차 차이는 +0.00013 이하다.
   - C1 과 C3 ε 0.30, C4 ε 0.20 은 ×1 에서 나빠진다.
2. **C2(전역 Σa)를 기본으로 골랐다.** 표에서 나오는 값이라 지어낸 상수가 없고, ×1·×0.5 에서 네 장면 모두 C0 과 같다(걸린 비율 0). ×2·×3 에서는 음수·0 근처 1차가 0 이다.
3. 과대 추정에 가장 강한 것은 C3·C4 의 ε 0.20 이다(최대 과보정 0.61–0.72). 그러나 ε = 0.2 는 SPR ≤ 4 를 뜻한다. MC 표의 Σa 는 30 cm·120 kVp 에서 약 8.5 이므로, 실제 조건에서는 올바른 데이터에도 걸릴 수 있다. 합성 장면의 SPR(최대 4.22)만으로 ε 를 정하지 않았다.
4. **C2 는 과대 추정의 중앙값 오차를 줄이지 못한다.**
   - C2: ×2 0.369–0.565, ×3 0.490–0.724
   - C0: ×2 0.369–0.565, ×3 0.488–0.725
   - C2 는 극단값(음수·0)만 막는다.
   - 중앙값을 줄이는 것은 ε 가 큰 하한이다. C3 ε0.20 은 ×2 0.231–0.461, C4 ε0.20 은 ×2 0.163–0.361. 이들은 표를 무시하고 산란을 넓게 깎는다. 실제 SPR 이 큰 조건에서는 그만큼 과소 보정이 된다(1.3).

6. 두께가 고르지 않으면 **화소 하나의 참 SPR 이 전역 Σa 보다 클 수 있다.** 얇은|두꺼운(5|27 cm) 장면에서 4.22 > 3.9. 이번 측정에서는 축소 격자 평균 때문에 C2 가 걸리지 않았지만(0 %), 이 여유가 보장된 것은 아니다.
7. 이 비교는 **같은 합성곱 코드로 만든 장면 안의 비교**다. pre 레인 MC 영상(QA-A-98, main `bc14757`)에서 다시 확인해야 한다.

## 2. 후보 정의 (`CapMode`)

| 후보 | 축소 격자 반복 | 원해상도 |
|---|---|---|
| C0 `None` | 없음(곱셈형 갱신만) | 없음, `I−S<0` 은 0 으로 자르고 센다 |
| C1 `LocalSum` | `SPR ≤ SprCapAt(T)` | `S ≤ I·cap(T)/(1+cap(T))`(cap 을 올려 보간) |
| C2 `GlobalSum` | `SPR ≤ G`, G = kVp 에서 표 노드 두께들의 `SprCapAt` 최대 | `S ≤ I·G/(1+G)` |
| C3 `PrimaryFloor` | `SPR ≤ 1/ε − 1` | `S ≤ (1−ε)·I` |
| C4 `SmoothFloor`(제안) | `S ≤ (1−ε)·Imin_블록` → SPR 상한으로 환산 | `S ≤ (1−ε)·minfilter(I, 반경 = 축소 배율)` |

C4 의 근거: 산란은 축소 격자 한 칸보다 넓게 매끄럽고, 어느 화소에서도 측정값 I 를 넘지 못한다. 그래서 주변 창의 최솟값이 그 근방 산란의 상한이 된다. 표를 쓰지 않으므로 표 오차에 흔들리지 않는다. 대가는 ε 라는 상수 하나와 최솟값 필터(O(n), `MinFilter2D`)다. 필터는 전수 비교 시험(`GsvgVirtualGridMinFilter.MatchesBruteForce`, 반경 0·1·3·5·30)으로 확인했다.

`[spr_cap]` 구획이 있으면 `SprCapAt` 이 그 값을 쓰므로, C2 의 G 는 구획의 kVp 별 최대가 된다.

## 4. 시험과 반증 (`_vg5.log`, BUILD=0, 27건 통과)

`GsvgVirtualGridCapChoice.CompareCandidates` 가 선택을 단언한다.
- 네 장면, ×1·×0.5: C2 의 중앙값·최대가 C0 과 같다(허용 1e-4, 1e-3).
- 네 장면, ×2·×3: C2 의 음수 = 0, 0 근처 = 0, 최대 과보정 < 0.9 이고 C0 이하.
- **반증**: 상한을 빼면(C0) ×3 에서 네 장면 중 셋 이상이 0 이 된 화소를 가진다(측정: 계단·공기·얇은|두꺼운 1.0, 경사 0.92).
- C1 을 고르지 않은 이유: ×0.5 에서 상한이 걸린다(계단 14.2 %).

그 밖의 변경:
- 기존 C1 시험 두 건은 C1 을 명시해 기록으로 남겼다(`LocalKernelSumCapBindsOnCorrectDataToo`).
- `SprCapPreventsOvercorrection` 은 기본(C2)으로 돈다. 상한 켬: 음수 0, 걸린 비율 37.4 %. 상한 끔: 음수 658.
- 기본을 바꾸기 전(`_vg3`)과 후(`_vg5`)의 VGCAP 132줄이 같다(`diff`). 후보를 명시적으로 넘기므로 기본값과 무관하다.
