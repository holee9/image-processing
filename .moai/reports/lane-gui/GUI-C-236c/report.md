## 2. 계측 정리 (P2) — 완료

`MainWindowViewModel.cs`:
- **늦게 끝난 이전 열기가 값을 덮지 않는다**: 열기마다 세대 번호를 올리고, 기다림이 끝났을 때 세대와 "넘긴 그림이 아직 화면의 그림인지"(참조 비교)를 다시 검사해 어긋나면 쓰지 않고 로그에 "dropped" 를 남긴다.
- **구독 해제**: `CompositionTarget.Rendering` 구독을 한 곳(`WaitForCompositionTicksAsync`)에서만 잡고 `finally` 에서 푼다(틱·제한 시간·취소 어느 쪽으로 끝나도). 같은 프레임에서 두 번 올 수 있어 `RenderingTime` 으로 프레임을 구분한다. 창이 닫히는 중(종료 시작)이면 대기를 취소해 아무것도 쓰지 않는다(`BeginShutdown` 에서).
- **제한 시간은 따로 표시**: 상태 줄에 `(TIMED OUT: no second composition tick within 5 s; …)`, 로그에도 같은 줄.

재현 시험 (`gui/ImageProcTest.SelfCheck/LifetimeScenarios.cs`, 시나리오 `10 frame timing of an open`; 창이 없는 실행기라 틱 대기는 시험 쪽에서 대체하고, 진짜 대기는 직접 호출):
- 대조: 방해 없는 열기는 줄을 쓴다.
- 연속 두 번 열기: 앞 열기의 틱이 늦게 와도 줄이 바뀌지 않고 로그에 "dropped"(줄은 로그에 1건).
- 제한 시간 → 줄과 로그에 TIMED OUT. 창 닫힘 → 줄 없음, 로그에 "not written: the window is closing".
- 진짜 대기: 대기 중 구독 수 1, 끝난 뒤 0 (제한 시간으로 끝난 경우, 취소, 이미 취소된 토큰 모두). 이 기계에서는 120 ms 안에 틱이 와서 `Ticked` 로 끝났다(창 없이도 틱이 온다). 구독 수는 내가 `+=` 앞뒤에 두는 계수이고 이벤트의 실제 구독자 수를 읽은 것은 아니다.
- 실행기 전체 통과(29 시나리오). **반증 4팔**(`falsify_p2.txt`): 세대·그림 검사 제거 → 빨강 3건, `finally` 의 계수 감소 제거 → 빨강 4건, 종료 시 취소 제거 → 빨강, 시간 초과 표시 제거 → 빨강. 복원 바이트 동일, 다시 빌드 통과.
