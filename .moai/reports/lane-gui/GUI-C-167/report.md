# GUI-C-167 (#225) — 전수를 세니 **자리가 정해졌습니다**: `Run()` 입니다

상태: **완료.** 호출부 전수 3곳, 사각 시나리오 9건·launch 10회, 반증 3방향.

**제 `C-166` 보고의 "아홉 건" 은 측정이 아니었습니다** — 시나리오 수로는 맞았지만 세어 본 것이 아니었고, **선택을 정하는 것은 호출부 쪽**인데 그건 아예 세지 않았습니다(§1.1).

## 1. §2 전수 — `ResolveApplicationExecutable` 을 부르는 곳 (선언 제외 **3곳**)

| 자리 | 앱을 띄우나 | 지금 가드를 지나나 |
|---|---|---|
| `ApplicationFixture.cs:109` | **예** | **예**(`:121`) |
| `AutomationReportBackendTests.cs:321` (`Run()` 안) | **예** | **아니오 ← 사각** |
| `EvidenceBundleScenarios.cs:210` (`EvidenceRoot`) | **아니오 — 경로만** | 해당 없음 |

세 번째는 이렇습니다:

```csharp
private static string EvidenceRoot(ApplicationFixture app) =>
    Path.Combine(Path.GetDirectoryName(ApplicationFixture.ResolveApplicationExecutable()!)!, "evidence");
```

**디렉터리 이름만** 만듭니다. 그 시나리오의 앱은 fixture 로 띄웠으므로(매개변수 타입이 `ApplicationFixture`) **그 launch 는 이미 가드를 지납니다.**

사각 시나리오 수도 **세었습니다**: `[SkippableFact]` **9건**, `Run("A..")` 호출 **10회**(A-08 이 두 프로세스를 띄웁니다 — `A08a`·`A08b`).

### 1.1 제 "아홉 건" 이 왜 측정이 아니었나

`C-166` 보고에 *"사각이 `A01`~`A09` 아홉 건"* 이라 적었습니다. 시나리오 수로는 맞습니다 — 그러나 **파일을 읽고 이름을 떠올린 것**이고 세어 본 것이 아닙니다. 그리고 **선택을 정하는 것은 시나리오 수가 아니라 호출부의 성질**인데, 그건 세지도 언급하지도 않았습니다.

리더가 같은 검색에서 찾은 `EvidenceBundleScenarios.cs:210` 이 **바로 그 결정을 뒤집는 자리**입니다. 저장소의 *"첫 검색어가 결함의 절반만 잡는다"* 형태이고, 이번엔 제 쪽이 절반이었습니다.

### 1.2 이름으로 센 뒤 **행위로 다시** 셌습니다

`ResolveApplicationExecutable` 이라는 **이름**으로 센 census 는 그 이름을 쓰지 않는 launch 를 못 봅니다. 그래서 **띄우는 행위**로 다시 셌습니다:

| 자리 | 무엇을 띄우나 |
|---|---|
| `ApplicationFixture.cs:506` | **보정 생성기** 도구 |
| `PolynomialCalibrationApplicationFixture.cs:74` | 같은 생성기(`--gain-poly`) |
| `AutomationReportBackendTests.cs:362` | **앱** — 이 카드가 가드 |
| `NativeProvenanceTests.cs:69` | `git rev-parse` |
| `ApplicationFixture.cs:190` (`Application.Launch`) | **앱** — 기존 가드 |

`PolynomialCalibrationApplicationFixture` 는 `ApplicationFixture` 를 **상속**하므로 앱 launch 가 기반 생성자를 지나고 **가드를 통과합니다.**

**즉 앱을 띄우는 자리는 둘뿐이고 둘 다 가드를 지납니다.** `C-166` 에서 미검증으로 남긴 *"`Process.Start` 로 넓혀 보지 않았다"* 를 **측정으로 바꿨습니다.**

## 2. §3 의 선택: **`Run()` 안** — 경로만 쓰는 호출부가 실재하므로

| 후보 | 왜 아닌가 / 왜인가 |
|---|---|
| `ResolveApplicationExecutable()` 안 | **아님.** `EvidenceRoot` 에서 던집니다 — 디렉터리 이름에 영향을 줄 수 없는 낡음으로 **거짓 양성**입니다 |
| **`Run()` 안** | **채택.** 그 클래스의 **launch 10회 전부**가 이 헬퍼를 지납니다 |
| 시나리오 기반 클래스 | 이 스위트에 그런 자리가 없습니다(각 시나리오가 자기 fixture 를 만듭니다) |

가드 이름을 **지키는 대상으로** 붙였습니다 — `EnsureLaunchTargetIsFresh(exePath)`. *"resolve 하면 검사한다"* 가 아니라 *"띄우기 전에 검사한다"* 입니다. 복사하지 않고 기존 `EnsureApplicationIsFresh` 로 **위임**합니다.

**카드 §3 첫째 칸의 우려는 그대로 남습니다**: `Run()` 을 쓰지 않는 새 자체 launch 시나리오는 또 샙니다. 그걸 막는 유일한 자리는 resolver 이고, 그 대가가 거짓 양성입니다. **지금은 launch 전부가 두 자리(fixture·`Run()`)를 지나므로 사각이 0이고, 새 자체 launch 가 생기면 다시 샙니다** — 이 사실을 여기 적어 두는 것이 제가 할 수 있는 것입니다.

## 6. 미검증 / 잔여 위험

- **실제 CI 미실행** — ③ 은 `C-166` 의 구조적 논거 재사용이고, 이 카드가 빌드 순서를 바꾸지 않았다는 것까지입니다

- `mtime` 보존 복사의 거짓 음성, 러너 자신의 소스 — 카드 §5 대로 **손대지 않았습니다**
