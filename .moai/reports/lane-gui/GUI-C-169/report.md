## 4. §3 둘째 칸 — 실측 (이 카드의 본체)

**진짜 앱을 자동화 모드로 돌려** 세 상태를 잽니다. "생성됨"은 위 CI 의 **실제 Doxygen 출력 265개**를 임시로 `docs/help/generated/doxygen/html/` 에 풀어서 쟀습니다(`gitignore` 대상이고 끝나고 지웠습니다).

| 상태 | 앱이 말한 것 |
|---|---|
| **생성된 적 없음**(이 체크아웃의 실제 상태) | *"API reference has not been generated. Generate it: in docs/help/doxygen run 'git clone …/doxygen-awesome-css doxygen-awesome' and then 'doxygen Doxyfile' (Doxygen 1.12+; see docs/help/doxygen/README.md)."* — 경로 null |
| **생성이 중간에 멈춤**(디렉터리는 있고 `html/index.html` 없음) | *"API reference is incomplete: … exists but has no html/index.html. Generate it: …"* |
| **진짜 출력** | *"API reference (Doxygen) opened — generated 2026-09-30 13:56: …\html\index.html (launch suppressed under automation)"* |

**빈 창도 무반응도 없습니다.** 가운데 상태는 카드에 없던 것인데 넣었습니다 — "생성된 적 없음"이라 말하면 **이미 있다고 믿는 사람을 엉뚱한 문제로 보내기** 때문입니다.

### 4.1 힌트가 **완전한가** — 이것이 두 번째 거짓말의 자리입니다

`doxygen Doxyfile` 만 적으면 깨끗한 체크아웃에서 **동작하지 않는 지시**입니다. `Doxyfile:73-75` 가 스타일시트와 스크립트를 `doxygen-awesome/` 에서 읽기 때문입니다. README 와 CI 잡(`doxygen-headers`)은 둘 다 **클론을 선행**합니다. 힌트에 그것을 넣었고, 시험이 (a) 힌트에 `doxygen-awesome` 과 `doxygen Doxyfile` 이 **둘 다** 있는지, (b) 같은 클론 명령이 **README 에도 있는지** 를 잠급니다.

**이 명령들은 로컬에서 실행하지 못했습니다**(도구 없음). README + CI 를 그대로 옮긴 것이고, 증거는 **CI 가 정확히 그 단계로 초록**이라는 것입니다.

**"generated 13:56" 은 생성 시각이 아니라 압축 해제 시각입니다** — 진짜 출력이지만 이 기계에서 만든 것이 아니므로 파일 시각이 풀린 때입니다.

## 5. 셋째 칸(낡음) — **소스와 비교하지 않고, 시각을 값 옆에 보여 줍니다**

카드가 하실지 판단하고 **안 하면 이유를 적으라**고 했습니다. 안 합니다:

1. **`BuildFreshnessGuard` 의 규칙을 그대로 쓸 수 없습니다.** 그 규칙(`.cs`/`.xaml`/`.csproj`/`.resx`, `bin`/`obj` 제외)은 **C# 컴파일 입력용으로 측정한 것**입니다. Doxygen 의 소스는 `Doxyfile` 의 `INPUT` 이 지정한 **일곱 개 모듈의 `*.h`** 이고, 그 목록을 파싱해 헤더의 최신 시각과 비교하는 **다른 규칙**이 필요합니다. 재사용하면 `C-166` 에서 세운 기준(*"공유하는 것은 드리프트하면 위험한 규칙이고, 소스가 어디냐는 공유하지 않는다"*)을 **어기게** 됩니다.
2. **`0 ms` 와 위험의 종류가 다릅니다.** 꺼진 단계의 `0 ms` 는 **없는 값이 숫자로 보이는** 것이고, 낡은 참조는 **실제로 생성됐던 시점의 API** 를 보여 줍니다. 그리고 **언제 것인지가 값 옆에 있으면**(`generated 2026-09-30 13:56`) 읽는 사람이 판단할 수 있습니다 — `C-168` 에서 정한 "값 옆에 언제 것인지" 와 같은 해법입니다.
3. 생성은 CI 가 **매번 게이트로** 돌립니다. 로컬 낡음은 개발자가 같은 명령을 다시 치면 됩니다.

**대안의 값과 대가**: `Doxyfile` 의 `INPUT` 을 파싱해 `*.h` 의 최신 시각과 비교하면 *"헤더가 바뀐 뒤 재생성 안 됨"* 을 말할 수 있습니다. 그러나 파싱이 깨지기 쉽고(줄 이음 `\`, `EXCLUDE_PATTERNS`) 이 카드는 그 필요를 **측정하지 못했습니다.** 필요가 생기면 그때 카드로 내는 것이 맞습니다.

## 6. 앱의 자체 판정에 **바닥**이 걸려 있었습니다

첫 측정에서 세 실행이 모두 `exit 1, Passed=False` 였습니다. 사유를 읽었더니 두 겹이었습니다:

| 겹 | 원인 |
|---|---|
| ① 러너 둘이 `FAILED` | **`C-166` 가드가 저를 잡았습니다** — `gui/` 소스를 고치고 **앱만** 빌드했습니다. 앱이 그 사유를 상태줄에 **그대로** 실었습니다 |
| ② 러너를 짓고도 `Passed=False` | **`report.DisabledFutureCommandCount >= 10`** — 앱이 **자기 판정에** 미구현이 10개 **이상**이어야 통과라는 바닥을 걸었습니다. 행 20 이 세 값을 10 → 9 로 내리자 **자기 자신의 판정이 실패**했습니다 |

`git log -S`: 그 바닥은 **`d5432d2`(2026-04-16, 최초 메뉴 커밋)** 에서 사유 없이 들어왔습니다. `C-168` 이 정확히 10 에 내려앉았고 행 20 이 처음 넘었습니다. **`gui-automation`(Mock)과 `A02` 가 빨개질 자리**였고, *줄어드는 집합에 건 바닥은 일이 끝나는 순간 깨집니다* — 0 이 되면 반드시 다시 깨집니다.

### 6.1 지우지 않고 **동등성으로 옮겼습니다**

새 항은 `DisabledFutureCommandCount == UnimplementedMenuLeafCount`. 뒤의 수는 **살아 있는 메뉴 트리를 훑어** 세운 것입니다(명령 없는 **잎** 항목 중 비활성). 앞은 손으로 쓴 이름 목록 — **독립된 두 경로**라 (a) 세지 않은 자리표시자, (b) 자리표시자가 아닌데 센 항목 둘 다 잡고, **0 에서도 참**입니다.

`ItemsSource` 가 있는 항목은 **일부러 뺐습니다.** `Open Recent` 는 이력이 비면 *비활성·자식 없음·명령 없음* — 자리표시자와 **똑같은 모양**이지만 "아직 나열할 게 없다"는 뜻입니다. 세면 수가 *파일을 열어 봤는지*에 좌우됩니다 — `C-165` 가 러너의 `:140` 에서 찾은 함정입니다.

### 6.2 세 축이 일치합니다 (리더가 `C-168` 에서 한 방식의 상시판)

| 축 | 값 |
|---|---|
| 앱의 이름 목록 | **9** |
| 앱의 메뉴 트리 순회 | **9** |
| `MainWindow.xaml` 의 `IsEnabled="False"` `MenuItem` (시험이 XML 로 파싱) | **9** |

`A-11` 이 셋의 일치를 **영구히** 단언합니다.

### 6.2b 함께 찾은 것 — 제 이전 카드들이 만든 빈 껍데기

`PlannedMenuPlaceholdersDetected`(이름: "자리표시자 감지")는 `C-160`·`C-163`·`C-168` 이 **각자 구현한 항목을 옳게 하나씩 뺀** 끝에 지금은 **`OpenCurrentWorkflowHelpMenuItem.IsEnabled` 하나**만 읽습니다. 카드마다 국소적으로 맞았지만 합치면 **이름이 말하는 것을 더는 검사하지 않습니다.** 그 검사(도움말 항목이 켜져 있다)는 실재해서 **지우지도 이름을 바꾸지도 않고**(보고서 필드), **지금 무엇을 검사하는지** 주석으로 적었습니다.

## 9. 미검증 / 잔여 위험

- **CI 미실행** — 전부 로컬
- **진짜 브라우저 실행을 관측하지 못했습니다.** 자동화는 launch 를 억제하고(행 14 와 같게), 손으로 눌러 보지도 않았습니다. `Process.Start(UseShellExecute)` 의 실패 경로도 **재현하지 않았습니다**
- **생성 명령은 로컬에서 실행하지 못했습니다**(도구 없음). README + CI 의 그대로이고 CI 초록이 증거입니다
- "generated" 시각은 **압축 해제 시각**입니다(§4.1)
- **DocFX 메타데이터가 비는 원인은 확인하지 않았습니다** — 후보만 적었습니다. **그리고 이것이 이 메뉴의 절반을 뺀 이유**이므로, 리더가 고치면 그때 **관리형 API 를 여는 갈래를 더할 수 있습니다**
- **낡음은 값 옆 시각으로만** 답했습니다(§5). 헤더가 바뀐 뒤 재생성 안 된 것은 **말하지 못합니다**
- **못 잡는 것 하나**: 자리표시자가 **아무 일도 하지 않는 명령**을 달고 있으면(`CanExecute` 로만 회색인 경우 포함) 트리 순회는 그것을 "명령 있음" 으로 보고 세지 않습니다. 이름 목록에도 없으면 **세 축 어디에도 안 잡힙니다.** 정의가 "명령이 없는 회색 잎" 이라 생기는 구조적 한계이고, 지금 메뉴에는 그런 항목이 없다는 것만 확인했습니다
- 행 7·8·17 은 손대지 않았습니다
