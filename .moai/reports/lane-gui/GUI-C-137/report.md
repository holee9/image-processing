# GUI-C-137 — `#200`: 문턱 전에 분포를 봤다. **요약 통계는 쓸 수 없다**

> 산출은 시험이 아니라 표다. **시험은 다음 카드**다.

## 1. 결론 셋

1. **평균·표준편차·분위수·0 아닌 화소 비율 — 전부 탈락이다.** 이유가 하나로 모인다:
   **상하 반전은 화소를 재배열만 하므로 분포가 그대로다.** 전 프레임 요약 통계는 위치를
   보지 못한다.
2. **쓸 수 있는 것은 저장된 기준 프레임과의 차이 통계다** — `mean|Δ|`, `max|Δ|`,
   `changed%`. 즉 **저장할 것이 숫자가 아니라 프레임**이다. 이슈가 적은 "평균 + 허용치"
   형태는 그 지점에서 무너진다.
3. **프레임을 통째로 저장하지 않아도 된다.** `32×32` 타일 평균 서명(**8 KB**)이 같은
   구별력을 유지한다 — 반전도 잡는다(`mean|Δtile|` 61.76).

## 3. 무엇을 어떻게 쟀나

**정당한 정정은 지어내지 않았다** — `#156` 의 실제 식 변경을 `voi_lut.cpp:71-74` 에서
읽어 두 렌더를 계산했다.

```
old LINEAR : out = clamp( ((x - center)       / width       + 0.5) * 255 )
new LINEAR : out = clamp( ((x - (center-0.5)) / (width - 1) + 0.5) * 255 )
```

입력은 실제 픽스처 `fixtures/gui-s0/raw/synthetic_1024x1024.raw`(1,048,576 px, 0–63426).
창은 GUI 기본값 `c=32768, w=65535`. 기준선(pre-`#156`) 통계: `mean 123.396868`,
`stddev 50.426561`, `p50 123`, `p95 208`, `nonzero% 99.998569`.

**파손은 합성했다**(카드 허용): 전체 0 / 상수(=평균) / 스케일 ×2 / 상하 반전, 그리고
**국소 파손 하나** — 가운데 한 행만 반전. 국소 파손은 **평균계 통계를 1/H 로 희석**하므로
`max|Δ|` 가 제 값을 하는지 가리는 축이다.

재배열이므로 평균·표준편차·모든 분위수·0 아닌 비율이 **정확히 보존된다.** 이것은 이
프레임의 성질이 아니라 **순열의 성질**이라 다른 프레임에서도 같다.

## 5. 프레임을 저장해야 하는가 — 타일 서명으로 피할 수 있다

`mean|Δ|`·`max|Δ|`·`changed%` 는 모두 **기준 프레임**을 요구한다. P10 이 쓰는 손목
프레임은 3072² 이라 8비트로 **약 9 MB** 다 — 저장소에 두기엔 큰 비용이다.

`32×32` 타일 평균(**1024개 수, 8 KB**)으로 다시 쟀다.

| 변형 | `mean\|Δtile\|` | `max\|Δtile\|` |
|---|---|---|
| **정당 정정** | 0.000019 | 0.019531 |
| 전체 0 | 123.396868 | 243.041016 |
| 상수 | 41.144175 | 120.041016 |
| ×2 | 86.191863 | 126.160156 |
| **상하 반전** | **61.758732** | **119.677734** |
| 한 행 반전 | 0.060589 | 3.994141 |

| 통계 | 정당 | 가장 약한 파손 | 간격 |
|---|---|---|---|
| `mean\|Δtile\|` | 0.000019 | 0.060589 (한 행) | **3,177** |
| `max\|Δtile\|` | 0.019531 | 3.994141 (한 행) | **205** |

**타일 서명이 전 프레임 차이 통계와 같은 구별력을 낸다** — 반전도 잡는다(타일 평균은
위치에 묶여 있으므로). `max|Δtile|` 은 오히려 **전 프레임 `max|Δ|`(124)보다 좋다**:
타일 평균이 정당 정정의 1-카운트 잡음을 0.0195 로 눌러 주면서 국소 파손은 3.99 로 남긴다.

## 6. 고른 것과 문턱 — 그리고 왜 그 값인가

**`32×32` 타일 평균 서명 + 두 통계.**

| 통계 | 문턱 | 정당 대비 | 파손 대비 |
|---|---|---|---|
| `mean\|Δtile\|` | **≤ 0.001** | 53× 위 | 57× 아래 |
| `max\|Δtile\|` | **≤ 0.3** | 15× 위 | 13× 아래 |

**문턱을 정한 규칙**: 두 경계의 **기하평균**. 비율로 위아래 여유가 같아지는 자리이고,
`√(0.000019 × 0.060589) ≈ 0.00107` → `0.001`, `√(0.019531 × 3.994141) ≈ 0.279` → `0.3`.
**이것은 선택이지 법칙이 아니다** — 다만 "정당 정정에서 얼마나 멀고 파손에서 얼마나
가까운가" 를 숫자로 말할 수 있는 선택이다. 카드가 경계한 *"먼저 정하고 나중에 맞추는"*
것과 다른 점이 그것이다.

**둘을 함께 쓰는 이유**: `mean|Δtile|` 은 넓은 오차를, `max|Δtile|` 은 **국소** 오차를
본다. 한 행 반전에서 전자는 0.0606(작다)이고 후자는 3.99(크다) — 평균만 쓰면 국소 파손이
희석된다.

`changed%` 는 **탈락시키지 않았지만 고르지 않았다**: 간격 52 로 쓸 수는 있으나 여유가
가장 얇고, 전 프레임을 요구한다.

## 7. 골든을 늘리지 않는다 (카드 §3)

이 제안은 **골든을 하나 더 만드는 것이 아니다.** 타일 서명은 `P10` 의 해시를 **대체**할
후보다 — 같은 정정에서 조용하고 파손에서 시끄러우므로, 대체가 서면 해시를 뺄 수 있다.
다만 **P10 을 지금 건드리지 않았다**(카드 §5: 지금 살아 있는 유일한 보호).

## 8. 미검증 (Gaps)

- **P10 의 실제 렌더 화소로 재지 않았다.** E2E 표면이 내주는 것은 해시와 평균뿐이라,
  이 분석은 **같은 픽스처 원본에 실제 VOI 두 식을 적용한 렌더**를 대역으로 썼다. 비율은
  프레임에 둔감하다고 보지만 **P10 의 GSVG 가상 그리드 렌더에서 다시 재지는 않았다.**
  그래서 §6 의 문턱은 **이 프레임의 값**이다.
- **1024² 한 프레임, 기본 창 하나.** 좁은 창(`c=100, w=200`)에서는 정당 정정의 `max|Δ|`
  가 커지므로(해석적 상한 `0.5/(w-1)×255` ≈ 0.64 카운트로 여전히 1 이하지만) 재지 않았다.
- **파손 5종은 합성이다.** 실제로 렌더러를 깨뜨려 얻은 것이 아니다. **채널 뒤바뀜**은
  이 경로가 단일 채널이라 넣지 않았고, **부분 영역 시프트**(1픽셀 평행이동) 같은 것도
  넣지 않았다 — 그것은 타일 평균이 약할 수 있는 형태다.
- **타일 크기를 하나만(32×32) 봤다.** 더 잘게 나누면 국소 검출력이 오르고 정당 잡음도
  오르는데, 그 곡선을 재지 않았다.
- **저장 형식·비교 비용을 재지 않았다.** 8 KB 라는 것은 `double` 1024개 기준이고, 실제로
  어떤 형식으로 저장하고 시험이 얼마나 걸리는지는 다음 카드의 몫이다.

## 9. 잔여 위험

- 타일 평균은 **타일 안에서 상쇄되는 파손**에 약하다 — 한 타일 안에서 절반을 +k, 절반을
  −k 하면 평균이 그대로다. `max|Δtile|` 도 못 본다. 전 프레임 `changed%` 는 그것을 보는데,
  그것이 `changed%` 를 완전히 버리지 않은 이유다.
- 문턱은 **이 기계·이 프레임**에서 나왔다. CI 에서 렌더가 비트 단위로 같지 않다면(부동
  소수 차이) 정당 쪽 `|Δ|` 가 커질 수 있고, 그러면 여유가 줄어든다 — **CI 에서 한 번
  재야 한다**(이 저장소가 게이트를 잘못된 기계에서 잡은 전례가 있다).

# 10. 두 가지를 덧붙인다 (판정 뒤)

## 10.1 이 결론은 **측정이 아니라 항등식**이다

lead 가 정확히 좁혔다. `mean` 의 간격 `1.00` 은 **이 프레임의 우연이 아니다.**

상하 반전은 **순열**이다. 순열은 화소값의 **다중집합을 보존**하고, 평균·표준편차·모든
분위수·0 아닌 화소 비율은 **다중집합만의 함수**다. 따라서 그 통계들은 반전 전후로
**정확히 같다** — 부동소수 오차조차 없다(같은 수들을 다른 순서로 더하는 것뿐이고, 여기서는
정수 히스토그램으로 셌다).

**그래서 이 탈락은 재측정으로 뒤집히지 않는다.** 다른 프레임, 다른 창, 다른 기계에서도
같다. 표의 다른 칸들은 측정값이지만 **이 칸은 증명**이다.

반대로 **간격이 존재한다는 쪽**(`mean|Δtile|` 3,177 등)은 여전히 측정이고, 프레임과 창에
따라 달라질 수 있다 — §8 의 미검증이 그것이다. **두 종류의 주장을 섞어 읽지 않도록**
여기 갈라 둔다.

## 10.2 다음 카드의 전제 — **화소를 꺼낼 수단이 이미 있다**

§8 의 첫 미검증("P10 의 실제 렌더 화소로 재지 않았다")이 다음 카드의 전제이므로, 그것이
막히는지 미리 확인했다.

**E2E 표면에는 없다.** 뷰포트 자동화 peer 가 내주는 것은 문자열 두 개뿐이다.

```
ImageComparisonViewport.cs:347   processedMean=…; hud=…
                         :651    rendered=<mode>
```

**그러나 앱 안에는 있다.** 같은 파일의 해시 계산이 **이미 화소를 복사해 들고 있다**:

```
ImageComparisonViewport.cs:168-173
    if (image is BitmapSource bitmap) { …
        var stride = converted.PixelWidth * 4;
        var buffer = new byte[stride * converted.PixelHeight];
        converted.CopyPixels(buffer, stride, 0);
```

즉 **새 화소 접근 경로를 만들 필요가 없다** — 이미 만들어진 `buffer` 를 한 번 더 쓰면 된다.
자동화 스위치는 8개가 이미 있으니(`--automation-raw|report|backend|calib|width|height|fault|settings`)
하나 더하는 것이 확립된 형태다.

**두 모양이 있고 목적이 다르다:**

| 모양 | 무엇 | 다음 카드에 쓸 수 있나 |
|---|---|---|
| 타일 서명만 노출 | `buffer` 에서 32×32 평균을 계산해 내보낸다 | **부족하다** — 합성 파손을 실제 렌더에 가할 수 없다 |
| 렌더 프레임 덤프 | `buffer` 를 파일로 쓴다(자동화 전용 스위치) | **충분하다** — 표 전체를 실제 프레임에서 다시 재려면 화소가 필요하다 |

**다음 카드는 후자를 먼저 필요로 한다.** 표를 재확인하려면 정당 정정(옛/새 display DLL 두
벌은 `build/c134-stage-{old,new}` 에 그대로 있다)과 합성 파손을 **같은 실제 프레임**에
가해야 하고, 그것은 화소 없이는 안 된다.

**이것은 제안이고 착수하지 않았다** — 제품 코드를 건드리는 일이라 카드로 받는 것이 맞다.
