# GUI-C-159 (#225) — 행 15 시나리오를 메우고, 측정 뒤 행 16 을 구현했습니다

상태: **완료.** 행 15 시나리오 3건 추가(A-04·A-05·A-06), 행 16 동작, 집계 **16 → 15**,
반증 3건 모두 빨강 → 원복 후 초록, 회귀 0.

`§2` 의 두 측정은 **통과**했고, 그중 하나는 **측정이 아니라 구조로 답이 나왔습니다**(§2.2).

## 1. 행 15 — 성공만 보지 않게 만들었습니다 (카드 §1)

`C-158` 은 `SelfCheckPassed` 를 보고서에 실었지만 **단언하지 않았습니다.** 그대로 두면
*"판정을 옳게 싣는다"* 와 *"전부 통과로 싣는다"* 가 같은 초록입니다 — `#205`·`#207`·`#212`
가 각각 그 형태였습니다.

| 시나리오 | 무엇을 단언하나 |
|---|---|
| **A-04** | 자가진단이 **실제로 돌아** `SelfCheckPassed=True`, 상태줄에 `passed` |
| **A-05** | 자가진단이 **실패하면** `False`, 그리고 상태줄에 **사유**(`Repository root`) |

### 1.1 실패를 어떻게 만들었는가 — 소스를 망가뜨리지 않았습니다

`A-05` 는 **러너 복사본을 저장소 밖에 스테이징**하고 앱이 그쪽을 보게 합니다.
`GUI-C-157` 이 실측한 대로 그 자리에서 러너는 `Repository root could not be located.` 로 죽습니다.
**구조적 실패**라 상시로 둘 수 있고, 제품 소스는 손대지 않습니다.

앱이 그쪽을 보게 하려면 경로 주입구가 필요해서 **`--automation-selfcheck-exe`** 를 만들었습니다 —
`#171` 의 `--automation-fault` 와 **같은 이유·같은 전례**입니다(실패 경로가 관측 가능해야 함).
자동화 전용이고 안 주면 종전대로 저장소에서 찾습니다. 그 사유를 상수 문서에 적었습니다.

### 1.2 구성 의존이 없어 건너뛰지 않습니다

`C-155` 의 셋은 Native 에서만 단언하고 Mock 은 사유 붙여 건너뜁니다. **이 셋은 다릅니다** —
자가진단 러너는 **일부러 목 디스플레이를 검사**(`v0.0.0-mock-display`)하므로 판정이 네이티브
DLL 유무에 의존하지 않습니다. 건너뛸 전제가 없어서 **양쪽 구성 모두에서 단언**합니다
(실측: Mock 4/5 통과·1 건너뜀은 `A-03`, Native 6/6 통과).

## 2. `§2` 두 측정 — **행 16 을 짜기 전에** 쟀습니다

### 2.1 완주 시간: 앱이 떠 있어도 느려지지 않았습니다

| 구성 | 표본 1 | 표본 2 |
|---|---|---|
| 러너 단독 | exit 0 · **4.08 s** | exit 0 · **4.07 s** |
| **운영자 앱이 떠 있는 상태** | exit 0 · **3.04 s** | exit 0 · **4.03 s** |

두 경우 모두 운영자 창은 **살아남았습니다**. `C-157` 의 4.09초는 앱이 없을 때 값인데,
앱이 있어도 같은 범위입니다. 느려진 표본은 없습니다.

### 2.2 동시 실행: 측정 전에 **구조가 답했습니다**

카드는 *"창 둘일 때 러너가 엉뚱한 창을 잡을 수 있습니다"* 라고 했습니다. 러너 소스를 읽었더니
**잡을 창을 찾는 단계 자체가 없습니다**: 자기 프로세스 안에서 STA 스레드를 띄우고
`new Application` · `new MainWindow()` 를 **직접 만듭니다**(`Program.cs:16-74`). 바탕화면을
뒤지지 않으므로 `#228` 이 겪은 창 식별 실패는 **여기서는 구조적으로 불가능**합니다.

다만 이것은 **읽기**이므로 실행으로도 짝지었습니다: 위 두 표본이 실제로 창 둘인 상태였고,
§3 의 자동화 실행은 **떠 있는 앱 안에서** 러너를 띄워 `GuiE2EPassed=True`(3143 ms)를 받았습니다.

**둘 다 통과했으므로 행 16 으로 갔습니다.**

## 3. 행 16 구현 — 카드 §3 의 네 조건

| 조건 | 어떻게 |
|---|---|
| **비동기 + 진행 표시** | `Task.Run` + `Running GUI E2E…`, `GuiE2ERunning` 으로 재진입 차단 |
| **판정 `== 0`** | 행 15 와 **같은 코드**를 씁니다(아래) |
| **저장소 없으면 상태줄** | 같은 코드. `IsEnabled` 는 끄지 않습니다(`C-156` §3.2) |
| **E2E 시나리오** | **A-06** — 그리고 이것이 §2.2 의 관측을 **상시화**합니다: 이미 떠 있는 앱이 러너를 띄우므로, 창 둘이 서로 방해하는 회귀는 한 번 읽고 만 보고서가 아니라 **빨간 시험**으로 나타납니다 |

행 15 와 행 16 은 이름·경로만 다르고 나머지가 같아서 **공용 `RunConsoleRunnerAsync`** 로 묶었습니다.
반환값 `null` 은 **"돌지 않았다"**(체크아웃 아님·미빌드)이고 **실패가 아닙니다** — 호출부는 그때
판정을 기록하지 않습니다. 둘을 같은 값으로 뭉개면 "전제 미성립"과 "결함 없음"이 같아집니다.

집계는 앱을 실제로 돌려 확인했습니다: `DisabledFutureCommandCount` **16 → 15**.

## 4. 반증 (카드 §4) — 셋 다 터졌습니다

| # | 주입 | 결과 |
|---|---|---|
| 1 | 자가진단 러너의 단언 하나를 거짓으로 | **`A-04` FAIL** → 원복 후 초록 |

앱이 거짓말을 해도 초록이었을 것이고, 그게 §1 이 없애려던 형태입니다.
`C-158` 에서 상수 자체를 바꿔 반증이 빗나갔던 것(자기 비교)을 피하려고, 세 팔 모두
**단언이 인용하는 값이 아니라 그 값을 만드는 쪽**을 망가뜨렸습니다.

원복 확인: 두 러너 소스 `git diff --stat` **비어 있음**.
