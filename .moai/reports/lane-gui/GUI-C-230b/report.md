## 앱의 기존 안내 방식

`ApplyNativePreview` 의 다른 거절(원본 없음, DLL 준비 안 됨, 보정 폴더 미선택)이 이미 `SetNativePreviewText("Native preview: …")` + `return` 이고 실패는 `SetStatus(…, Brushes.OrangeRed)` 입니다. 새 안내는 그 둘을 그대로 씁니다(새 UI 없음). 칸의 값은 건드리지 않습니다.

## 하한 처리 (카드 질문)

코드로 확인: 하한도 같은 `ParseClamped` 로 0.1 미만(0, 음수, 0.05)을 조용히 0.1 로 올려 실행했습니다. 모듈은 `sigma_space > 0` 만 요구하므로 0.05 는 모듈에서 유효한 값인데 앱이 다른 값(0.1)으로 바꿨던 것입니다. 상한과 같은 방식으로 맞춰 **하한 미만도 안내하고 실행하지 않습니다**(`0.05`, `0`, `-3` 시험). 숫자가 아닌 글자(`abc`)는 이번 범위 밖이라 기존대로 기본값 3.0 으로 실행합니다(이 칸의 조용한 기본값 대체 — 아래 결정 사항).

## 틀린 주석 정정

"7.5 초과는 7.5 처럼 동작했다 / 한도를 낮춰도 이전 효과 유지" 를 지우고, 근거를 "2σ 범위가 반경 15 안에 온전히 들어가는 최대값" 으로, 7.5 초과의 실제 동작을 "반경만 15 로 고정, 가중치 exp(-0.5·d²/σ²) 는 σ 를 따른다(거리 10: σ=7.5 → 0.411, σ=8 → 0.458)" 로 적었습니다. 두 수는 시험이 직접 계산해 대조합니다(0.411/0.458). grep(`grep_old_claim.txt`, 대조군=새 문장 2곳 발견): gui 소유 경로·lane-gui 보고서에 옛 주장은 **0건**(남은 건 그 주장을 부정하는 문장과 재유입 방지 단언).

## 시험

- 안내 문구: 범위 안 8종은 오류 없음, 밖 10종(7.6, 8, 50, 100, 1e6, 0.05, 0, -3, NaN, Infinity)은 입력값·경계·"Nothing was run" 을 담은 문구.
- 배선(원본 소스 대상): 검사가 우회 판정·실행 호출보다 앞, 거절 블록이 문구+상태+`return` 이고 `lastNativePreviewResult` 등 결과를 건드리지 않음, 백스톱이 `if (GetEnhanceBasicInputError(selection) is { } inputError)` 전체 조건으로 존재.
- 반증 (`falsification_*.txt`, 모두 원복·재확인): g 검사 제거 → 빨강 1, h 백스톱 무력화 → 처음엔 **초록으로 남았음**(조건 일부만 단언) → 전체 조건 단언으로 강화 후 빨강, i 상한 통과 → 6, j 거절이 결과 지움 → 1, k 틀린 주석 복귀 → 1, l 하한 오류 제거 → 3, m(E2E) 원본 없이 실행 버튼 활성 → L01 빨강.

## E2E — 카드 요구와 다른 점 (측정 결과)

카드는 "8 입력 → 실행 시도 → 안내, 7.5 → 실행됨" 을 UIA 로 단언하라고 했습니다. **이 두 장면은 구현하지 못했습니다.** 실행에는 원본 영상이 필요하고 앱이 영상을 여는 길은 "Load Raw..." 공용 파일 대화상자뿐인데(고정 데이터 상자는 `Visibility=Collapsed`):

- 대화상자는 UIA 로 열렸고 파일 이름 칸(id 1148, Edit)에 경로를 넣으면 읽어 보면 같은 값이었습니다.
- 그러나 **열기 버튼은 UIA 로 눌러도 닫히지 않았습니다**. 시도: InvokePattern, LegacyIAccessible `DoDefaultAction`, 칸에 먼저 Focus, 대화상자를 전경으로 올림. 다섯 번 모두 15초 대기 뒤에도 대화상자가 열려 있었고(`MODAL title='Select Target Raw Image'`, 입력 값 그대로) 앱이 "failed to exit" 로 끝났습니다.
- Enter 키로는 열릴 가능성이 있으나 키 입력은 전경 창으로 가므로(공유 데스크톱, 리더 터미널 사고 이력) 하지 않았습니다.

그래서 시도한 도우미는 모두 지웠고, 대신:
1. 앱 쪽 결정 함수와 배선은 위 통합 시험으로(원본 소스·함수 수준),
2. L01(UIA)을 바꿨습니다: 입력하는 동안 칸은 입력값 그대로이고(이것이 안내 문구가 입력값을 그대로 말할 수 있는 근거), 안내·대화상자가 없으며, **원본이 없으면 실행 버튼이 비활성**이라 칸에 8 이 있어도 실행이 시작될 수 없음을 단언합니다(반증 m). 왜 바뀌었는지는 시험 주석에.

## 미검증 (Gaps)

- 실제 창에서 8 을 넣고 Run Selected 를 눌렀을 때 문구·빨간 상태줄이 보이는 것, 7.5 에서 실제로 실행되는 것은 **관측하지 못했습니다**(위 사유). 코드 배선과 함수 단위만 확인했습니다.
- 실제 E7 DLL 로 7.5 초과가 INVALID_INPUT 이 되는 것은 실행하지 않았습니다(#98).

## 결정 사항 (리더)

1. 위 E2E 대체가 받아들여질지, 아니면 열기 버튼을 누를 다른 UIA 방법이나 테스트용 로드 경로(앱에 시험 전용 환경 변수로 원본 자동 열기)를 허용할지. 후자는 제품 코드에 시험 진입점을 넣는 일이라 제가 정하지 않았습니다.
2. `abc` 같은 숫자 아님 → 조용히 3.0 대체는 이번 범위 밖이라 두었습니다(같은 종류의 조용한 대체).
