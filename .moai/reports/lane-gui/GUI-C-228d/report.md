# GUI-C-228d — 예외 구간을 없애고 주석만 안전하게 뺀다 (Codex #127)

같은 요구(문자열·리플렉션 경로 감시)로 네 번째 보류라, 패턴을 더 보정하지 않고 틈을 만드는 구조를 없앴다.

## 구조 변경

- **예외 구간 폐지**: 패턴표·허용 목록(3줄)·통제 입력을 `Resources/forbidden-reflection-apis.json`(출력 폴더로 복사, 컴파일되지 않음)으로 옮겼다. `MockBlockingStaticTests.cs` 를 포함한 모든 `.cs` 를 예외 없이 스캔한다. 이 시험 파일은 금지 API 이름을 코드에 쓰지 않는다(정규식은 데이터 파일에서 읽고, 통제에 필요한 이름은 문자열 조각 `"Acti"+"vator.Create"+"Instance"` 로 만든다).
- **데이터 파일 방어**: 파일이 없거나 JSON 이 아니거나 패턴 id 8개(`load-by-context` 등 이름이 아니라 라벨)가 하나라도 빠지거나 정규식이 비면 빨강. 각 패턴은 통제 줄을, 허용 항목은 이유를 가져야 한다.
- **주석 규칙(`CodeLines`)**: 줄 전체가 주석인 줄만 뺀다 — 공백 뒤 `//` 로 시작하거나, 줄 처음부터 끝까지 블록 주석 안에 있는 줄. 줄 끝 주석과 문자열은 계속 스캔한다. `*/` 뒤에 코드가 있는 줄도 스캔한다. 추가로 **따옴표가 든 줄은 주석처럼 보여도 스캔**한다(리더 규칙보다 한 칸 보수적): 여러 줄 문자열의 중간 줄이 `//` 로 시작하고 같은 줄에서 문자열을 닫은 뒤 코드를 잇는 모양을 막기 위해서다. 그 대가로 따옴표를 쓴 설명 주석에 API 이름이 있으면 오탐이 나고 허용 목록으로 처리한다.

## 미검증 / 잔여 위험

- 여러 줄 문자열 안에서 따옴표 없이 `//` 로 시작하는 줄은 주석으로 보고 건너뛴다. 그 줄에서 문자열이 닫히고 코드가 이어지려면 따옴표가 필요하므로 그 모양은 막히지만, 문자열 내용이 API 이름이면 못 본다(실행되지 않는 문자열이다).
- 패턴표는 내가 떠올린 API 목록이다. 표에 없는 API, 다른 어셈블리를 거친 호출, 코드 생성은 못 본다(문서에 명시).
- 반증 (e1)~(e3) 은 임시 편집이라 출력 폴더의 데이터 파일이 한 번씩 바뀌었다가, 마지막 전체 실행 전에 복사본이 원본과 같아짐을 비교로 확인했다.
- DLL 없는 구성으로는 이번에도 다시 돌리지 않았다(이 시험들은 DLL 을 쓰지 않는다고 읽음).
