# GUI-C-229c — 입력 직후 관측을 없애 600 ms 읽기를 원래대로 (Codex #132)

앱 코드는 고치지 않았다. 바뀐 것은 E2E 프로젝트의 `RealInputScenarios.cs`, `Fixtures/KeyLossDiagnosis.cs`, `KeyLossDiagnosisTests.cs` 이다.

## 무엇을 바꿨나

1. **순서가 원래 R02 와 같다** (Codex 1): 직전 관측(전경 확인 포함) → `SelectAll` → `Type("4321")` → 600 ms 대기 → Center 읽기(판정). 입력 직후 관측을 없앴다. 타이머는 `Type` 이 돌아온 직후 시작하고(`Thread.Sleep(600)` 이었던 자리에서 `600 - 경과` 만큼 잔다, 경과는 거의 0), 판정 읽기는 Center 하나만 읽는다. Width·포커스·전경은 판정 읽기 **뒤에** 읽고, 실패하면 1.5 s 뒤에 다시 읽는다.
2. **판정 읽기가 늦으면 타이밍 실패** (Codex 1): 마지막 키부터 판정 읽기 시작까지의 경과를 잰다. `590..1000 ms` 를 벗어나면 읽은 값과 무관하게 `Timing failure:` 로 실패하고, 늦게 읽은 값으로 통과하지 않는다.
   - **창의 근거**: 600 ms(원래 대기)를 기준으로 앞은 `-10 ms`(대기가 몇 ms 일찍 끝날 수 있음), 뒤는 `+400 ms`. 윈도우 타이머 해상도 때문에 대기는 수십 ms 늦게 끝나고 UIA 읽기 한 번에 또 수십 ms 가 들므로 600~1000 ms 안의 읽기는 이전과 같은 조건이라고 보았고, 그 밖은 키가 1.67배 이상 길게 처리될 시간을 얻은 다른 조건이다. **이 값은 고른 여유이지 측정한 값이 아니다.** 측정한 두 점: R02d 가 600 ms 대기 뒤 `+609 ms`, R02e 의 정상 호출이 `+604 ms` 에 읽었다(UIA 읽기·입력 없이, 두 번만).
3. **전경은 사실이고 목적지가 아니다** (Codex 2): `ForegroundLeftDuringTyping` 범주와 "입력 중" 단정을 없앴다. 600 ms 판정 시점이나 1.5 s 재읽기에서 다른 프로세스가 전경이면 `FACTS` 에 "그 시점에 전경은 프로세스 N 이었고 앱이 아니었다. 언제 바뀌었는지는 관측되지 않으므로 키가 어디로 갔는지도 마찬가지다" 만 적고, 분류는 다른 일치와 상관없이 `Unclassified` 다.

R02 자체의 "판정 앞에 관측을 끼우는" 실수는 R02e 가 `TakeJudgment` 로 가리킨다: 지연이 600 ms 를 넘기면 타이밍 실패가 된다. 600 ms 안에 끝나는 관측을 판정 앞에 끼우는 것은 읽기 시점을 바꾸지 않으므로(`TakeJudgment` 가 남은 시간만 잔다) 타이밍 검사로는 잡히지 않는다. 그 실수는 코드 리뷰로 막아야 하고, 이 시험은 그것을 잡지 못한다.

## 새 R02 를 실제 키 입력으로 돌려 보았나 (Codex 5)

**돌리지 않았다.** R02d·R02e 가 이번에도 전경으로 **PickerHost 의 "Windows 보안" 창(pid 47456, hwnd 0xFFF1CEE)** 을 보고했고 키보드 포커스도 그 창이다(`r02d_r02e_real_window.txt`). 직전 보고와 같은 hwnd 라 계속 떠 있는 창이다. 조건대로 멈췄고, 그 창은 열지도 닫지도 않았다. 새 R02 의 실제 키 경로(직전 확인 → Ctrl+A → `Type` → 판정 읽기 → 타이밍 검사 → 판정)는 컴파일만 되었고 한 번도 실제 입력으로 돌지 않았다.

## 미검증 / 잔여 위험

- 새 R02 의 실제 입력 경로는 한 번도 실행되지 않았다. 처음 도는 것은 CI 일 가능성이 크다.
- 창의 상한 400 ms 는 고른 값이다. 부하가 큰 러너에서 판정 읽기가 1000 ms 를 넘으면 새 `Timing failure` 가 생길 수 있다. 그것은 값이 달라서가 아니라 조건이 달라서 실패하는 것이고, 메시지에 읽은 시각이 남는다.
- 직전 관측(UIA 읽기 4번과 전경 확인)이 `Focus()` 와 Ctrl+A 사이에 들어가 있는 상태는 229b 와 같고 영향은 측정하지 않았다. 이 변경 뒤의 초록을 이전 초록과 같은 것으로 세지 말 것.
- 판정 앞에 600 ms 안에 끝나는 관측을 끼우는 실수는 시험으로 못 잡는다(위 설명).
