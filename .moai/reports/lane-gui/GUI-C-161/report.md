# GUI-C-161 (#225) — 제 시험이 main 을 빨갛게 했습니다. 제품이 하던 구분을 시험이 지웠습니다

상태: **완료.** `A04`·`A06` 이 세 상태를 셋으로 다루고, CI 형태(러너 exe 없음)에서 **실패 0**.

**이 결함은 제가 만들었고, 제가 `C-159` 에서 옳게 한 것을 같은 카드의 시험에서 지운 것입니다.**

---

## 1. 무엇이 잘못됐나

| | |
|---|---|
| 제품 코드 | `RunConsoleRunnerAsync` 가 **`null` 을 "돌지 않았다"** 로 돌려주고 실패로 기록하지 않습니다 |
| 필드 | `bool? SelfCheckPassed` — 세 상태를 담는 자리 |
| **제 시험** | `report.GetProperty("SelfCheckPassed").GetBoolean()` — **두 상태만 읽습니다** |

`gui-automation` 잡은 `gui/ImageProcTest` 만 짓습니다. 러너 exe 가 없으니 명령이 안 돌고 필드가 `null` → JSON `null` → `GetBoolean()` 이 던집니다. **`Failed: 2`.**

즉 *"측정 불가"* 를 값으로 취급했습니다 — `#219`·`#221` 이 반복해 닫은 형태입니다. 제품은 그 구분을 하는데 시험이 없앴다는 것이 이번 건의 정확한 모양입니다.

## 2. 고친 것 (카드 §2)

`VerdictOrSkip` 하나로 세 상태를 셋으로 유지합니다:

| 상태 | 시험 |
|---|---|
| 필드 없음 / `null` | **건너뜀** — 사유에 *왜* 없는지와 **그것이 정상**이라는 것을 적습니다 |
| `false` | 돌았고 실패 → **단언** |
| `true` | 돌았고 성공 → **단언** |

사유 문구에 러너 프로젝트 이름, 잡이 무엇만 짓는지, 그리고 **앱의 상태줄 문구**(`Self-check runner is not built.`)를 함께 싣습니다. 읽는 사람이 "왜 건너뛰었나" 를 CI 로그 한 줄에서 알 수 있게.

**느슨하게 통과시키지 않았습니다.** 그러면 *"러너가 없다"* 와 *"러너가 실패했다"* 가 같은 초록이 됩니다(`#214`, `C-155`).

`A05` 는 **이미 맞았습니다** — `ImageProcTest.SelfCheck.exe was not built, so its failure cannot be observed.` 로 사유를 적고 건너뜁니다. 같은 원인이고 이미 처리돼 있었습니다(카드 §4 의 확인 요청 사항).

## 3. 왜 로컬에서 안 보였나 (카드 §3)

**이 트리는 세 프로젝트를 다 짓습니다.** 그래서 러너 exe 가 항상 앱 옆에 있고 두 필드가 항상 `true` 였습니다. **러너가 없는 구성을 한 번도 돌리지 않았습니다.**

`C-159`·`C-160` 에서 "양쪽 구성에서 돌렸다" 고 적은 것은 **Mock/Native** 두 축이었고, **러너 유무**라는 축은 제 표에 없었습니다. 구성 축을 하나 빼먹은 것입니다.

**앞으로 이 스위트를 로컬에서 돌릴 때 러너 없는 상태도 한 번 잰다** — 이번에 실제로 그렇게 재서 이 카드의 증거를 만들었습니다(§4).

## 4. 반증 (카드 §4)

| # | 무엇 | 결과 |
|---|---|---|
| 1 | 러너 exe 둘을 치우고 돌림 | `A04`·`A06` **건너뜀**, 사유 그대로 출력. `A05` 도 건너뜀(원래 맞음) |
| 2 | 러너를 되돌리고 돌림 | **실패 0, 통과 3, 건너뜀 0** — 단언이 돌아옵니다 |
| 3 | **CI 형태 전체 스위트**(러너 없음) | **실패 0**, 통과 138, 건너뜀 34, 전체 172 |

건너뜀이 32 → 34 로 늘었고 **늘어난 둘이 정확히 `A04`·`A06`** 입니다.

## 5. `C-160` §3.1 의 제 근거가 거짓이었습니다 — 정정

행 14 판단을 올릴 때 *"제품 코드에 `Process.Start` 로 셸을 여는 곳 **0건**"* 이라고 적었습니다. **사실이 아닙니다.**

| | |
|---|---|
| 실제로 검색한 것 | `OpenEvidenceFolder`, `Process.Start("explorer`, `explorer.exe` |
| 실제 | `Services/HelpBundleService.cs:52-55` — `Process.Start` + **`UseShellExecute = true`** 로 도움말을 기본 브라우저로 엽니다 |

제 검색어에는 `explorer` 리터럴만 있었으므로 **그 선례를 구조적으로 찾을 수 없었습니다.** 그리고 **부재 주장에 검색 범위를 적지 않았습니다** — 적었다면 범위가 좁다는 것이 그 문장에서 드러났을 것입니다(저장소의 *"한 표에 없는 것이 없는 것은 아니다"*, *"부재 단언에는 대조군이 필요하다"*).

판단을 리더에게 올린 것은 맞았지만, **근거가 거짓이었고 그 근거로 반대 결론이 날 수도 있었습니다.** 리더가 정정했습니다.

## 6. 미검증 / 잔여 위험

- **CI 미실행** — 로컬에서 CI **형태**를 재현했을 뿐입니다. 실제 `gui-automation` 잡의 초록은 리더가 푸시한 뒤 확인됩니다
- 러너 없는 구성은 **exe 를 치워서** 만들었습니다. CI 는 애초에 **짓지 않는** 것이고, 둘이 같은 상태인지는 "앱이 파일을 못 찾는다" 수준에서만 같습니다
- `gui-automation` 이 러너를 짓게 할지는 **리더 몫**입니다(카드 §6). 그쪽이 만든 `gui-shell-runners` 가 이미 두 러너를 돌립니다
- 행 5·1(`6345139`)은 **아직 병합되지 않았습니다** — main 이 초록이 된 뒤라는 리더 결정
