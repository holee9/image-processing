# GUI-C-215 (1/2) — 212b 의 안 터진 반증 팔 2b 를 잡는 판정 단위 시험 (#249)

## 공백

212b 의 반증 2b(오라클의 gain 판정식을 212b 이전 조건 "호출이 OK 이고 출력 중 0 이 아닌 값이 있음"으로 되돌림)는 빨강 0건이었다. 다른 시험은 **실제 모듈**을 돌리는데 모듈의 gain 은 맞게 동작하므로 약한 조건도 강한 조건도 통과시킨다. 판정식 자체를 "아니오"라고 말하게 만드는 시험이 없었다.

## 한 것

- 판정을 순수 함수로 뺐다: `XpePreprocessSyntheticOracle.GainStagePassed(code, gainEffect, offsetOut, gainOut)` = `code == OK && gainEffect > 0 && GainStageMatchesExpected(offsetOut, gainOut)`. 오라클 동작은 같다(호출 한 줄을 이 함수로 바꿨을 뿐).
- `PreprocessSyntheticOracleVerdictTests`(7건)가 **틀린 gain 이 내놓을 출력**을 직접 넣는다. 모든 틀린 출력에 대해 "옛 조건은 이것을 통과시켰다"를 같은 시험 안에서 먼저 단언해(대조), 이 입력들이 옛 조건과 새 조건을 가르는 입력임을 보인다.
  - 입력 그대로 복사(카드가 든 예): 옛 조건 통과, 효과 0 + 기대값 불일치로 새 조건 거부
  - 배율 오류 1.1배(효과는 있으나 값이 틀림): 거부
  - 한 화소만 5% 틀림: 거부
  - 허용오차(상대 1e-3) 안(0.01%)은 통과, 바로 밖(0.5%)은 거부
  - 올바른 출력이지만 오류 코드: 거부
  - 올바른 출력: 통과 / 전부 0: 거부
- 기대 gain 출력은 시험 안에서 flat 으로부터 산술로 다시 적었다(오라클의 계산을 호출하지 않는다).

결과: 오라클 관련 시험 19/19 통과(기존 12 + 7).

## 반증 (`falsification_arms.txt`)

| 시도 | 결과 |
|---|---|
| a 판정을 212b 이전 조건으로 되돌림(2b 와 같음) | **4건 빨강** (복사·배율·한 화소·허용오차) |
| b 기대값 비교를 뺌 | 4건 빨강 |
| d 오류 코드를 무시 | 1건 빨강 |
| e 허용오차를 100배 느슨하게 | 2건 빨강 |
| f 허용오차를 100배 엄격하게 | 7건 빨강(올바른 출력의 float 반올림도 거부) |
| **c 효과(`gainEffect > 0`) 요구를 뺌** | **빨강 0건** |

**c 는 잡히지 않았고, 잡을 수 없는 것으로 판단한다.** 이 합성 데이터에서는 `GainStageMatchesExpected` 가 이미 "입력과 달라야 함"을 함의한다: flat 이 화소마다 달라 올바른 출력은 입력과 상대 1e-3 이상 다른 화소가 있으므로, 효과가 0 인 출력(입력 복사)은 기대값 비교에서 먼저 거부된다. 즉 `gainEffect > 0` 은 이 픽스처에서 **동치 변이**(어떤 입력에서도 결과를 바꾸지 않는 변경)다. 따로 잡는 시험을 만들려면 기대 출력이 입력과 같은 픽스처(균일 flat)가 필요한데, 그러면 올바른 gain 도 효과가 0 이라 요구 자체가 틀린다. 그래서 효과 요구는 중복 방어로 남겨 두고, 동치 변이라는 사실만 적는다. (이전 교훈: 안 터진 반증을 곧 "중복이라 지워도 된다"로 읽지 않는다 — 여기서는 지우지도 않았다.)
