# Troubleshooting Guide

This page lists the messages the operator app shows when something does not work, what each one means, and what to do about it.

How to use it: search this page for the words you see on screen. Every message in the first column (and every other text in backticks) is quoted exactly as the app writes it. Text in angle brackets, such as <path> or <message>, stands for something that varies from case to case.

## Where the messages appear

- **Status bar**: most messages in sections A and B.
- **Alerts list and log panel**: alerts. Every alert is also written to the log as a line that starts with ALERT, followed by its severity, its code and its text.
- **Native alerts** (section C) are raised by the processing modules, not by the app. They appear in the alerts list with the code NATIVE_ALERT. The severity is INFO, WARN or ERROR; a severity the app does not know is shown as ERROR.

Where a row says that the help is "in the log panel", the status bar alone does not show it.

## A. Commands, runners and exports

| Message | What it means | What to do |
|---|---|---|
| `<command> needs the repository; this build is not running from a checkout.` | Shown by Self-check, GUI E2E, Benchmark runner and API reference. The app looked for the repository by walking up from its own folder and did not find docs/project/sprint-plan.md, so it is not running from a checkout. | No action is defined; the message itself is the diagnosis. |
| `<command> runner is not built.` | Self-check or GUI E2E: the runner executable was not found at gui/<project>/bin/Debug/net8.0-windows/<executable>. | The log panel (not the status bar) says: `Build gui/<project> first.` |
| `Benchmark runner is not built: <directory> has no <file>.` | The benchmark tests cannot be run from here: build/ci-post has no CTestTestfile.cmake. Nothing was started. | Build it first: `cmake --preset ci-post` and then `cmake --build --preset ci-post --parallel`. |
| `<command> did not run: '<executable>' could not be started (<reason>). Nothing was executed.` | The program could not be started at all (missing file, a file that is not a program, or a start error), so there is no pass or fail verdict. When the operating system reports "file not found", the reason reads `the file was not found; a bare name such as 'ctest' has to be on PATH: <OS message>`. | Make the program available. For a bare name such as ctest the reason says it has to be on PATH. |
| `<command> FAILED (exit <code>): <line>` | The program started and exited with a non-zero code. The line shown is the first line the program wrote to its error output, or its last output line if it wrote no error output; for the Benchmark runner it is the ctest summary from the "tests passed" line onwards. | No action is defined; the message itself is the diagnosis. |
| `<command> ended abnormally: <message>` | The program started, but reading its output failed. It did run, so this is not a "did not run" case. | No action is defined; the message itself is the diagnosis. |
| `Self-check is already running.`<br>`GUI E2E is already running.`<br>`Benchmark runner is already running.` | The same command was started again while it was still running. | No action is defined; the message itself is the diagnosis. |
| Shown as the reason of a failed Self-check or GUI E2E run:<br>`is older than its sources, so this run would test the PREVIOUS build.`<br>`Build the RUNNER, not the app: dotnet build gui/<runner>/<runner>.csproj -c Debug.`<br>`Building gui/ImageProcTest alone does not refresh this copy.` | The runner carries a copy of the app that is older than the app's sources. It stops instead of testing the previous build. | Run the command quoted in the message. Building the app project alone does not refresh the runner's copy. |
| `API reference has not been generated.` | docs/help/generated/doxygen/html/index.html does not exist, and neither does the output folder docs/help/generated/doxygen. | The message continues with how to generate it: `Generate it: in docs/help/doxygen run 'git clone https://github.com/jothepro/doxygen-awesome-css doxygen-awesome' and then 'doxygen Doxyfile' (Doxygen 1.12+; see docs/help/doxygen/README.md).` |
| `API reference is incomplete: <directory> exists but has no html/index.html.` | The output folder exists but its entry page is missing: generation stopped part-way. | The message continues with the same generation instructions as above. |
| `API reference could not be opened: <message>`<br>`Evidence folder could not be opened: <message>`<br>`Runtime logs could not be exported: <message>`<br>`Export failed: <message>` | The browser or file-browser launch, the file write, or the zip step raised an error. <message> is the error's own text. | No action is defined; the message itself is the diagnosis. |
| `Runtime logs not exported: no run set has started.`<br>`No evidence folder to open: no run set has started.`<br>`Export failed: no run set has started.` | No run set has been started, so there is no run id. (An empty id would make the export zip the evidence folder into a file inside itself.) | No action is defined; the message itself is the diagnosis. |
| `Runtime logs not exported: the log is empty.` | There are no log lines to export. | No action is defined; the message itself is the diagnosis. |
| `No evidence folder yet for this run set: <path>`<br>`No evidence directory found for current run-set.` | The folder evidence/<run id> next to the app does not exist yet. | No action is defined; the message itself is the diagnosis. |

## B. Loading, processing and settings

| Message | What it means | What to do |
|---|---|---|
| `Load failed: <message>`<br>`Raw width and height must be positive.`<br>`Raw file is too small. Expected at least <bytes> bytes, got <bytes>.` | Loading the image raised an error; it is also raised as an ERROR alert with code LOAD_FAILED. The last two messages are the ones the loader writes itself; any other message is the error's own text. | No action is defined; the message itself is the diagnosis. |
| `Display pipeline requires a loaded raw image.`<br>`Load a raw image before running preprocessing.` | There is no loaded image. The first message is also raised as a WARN alert with code DISPLAY_NO_IMAGE. | Load a raw image first; both messages name that requirement. |
| `Display pipeline failed: <message>`<br>`STALE — the display pipeline failed; the image shown is from before the failed attempt.`<br>`<function> failed with XPE error code <code>.` | A display pipeline call raised an error (also an ERROR alert with code DISPLAY_PIPELINE_FAILED). The processed image on screen is the one from before the attempt, marked STALE until a render succeeds or a new image is loaded. When the cause is a native error, the message names the function and the error code (see the appendix). | No action is defined; the message itself is the diagnosis. |
| `STALE — display parameters changed since this image was rendered. Apply the display pipeline to update it.` | A display parameter was edited and differs from the value used for the image on screen. | Apply the display pipeline, as the message says. |
| `Stop requested; the render in flight will be discarded.`<br>`Render stopped; the result was discarded after <ms> ms of work.`<br>`Stop: no render is in flight.` | Stop was pressed. If a render was running its result is discarded and the preview is marked STALE; otherwise there was nothing to stop. | No action is defined; the message itself is the diagnosis. |
| `Preprocessing failed: <message>`<br>`VOI preset failed: <message>`<br>`Backend initialization failed: <message>` | The step raised an error; <message> is the error's own text. A failed VOI preset is also an ERROR alert with code VOI_PRESET_FAILED. A failed initialization keeps the current run set. | No action is defined; the message itself is the diagnosis. |
| `<stage> was requested and not applied; the display used its input. <reason>` | Raised as a WARN alert (code PREPROCESS_NOT_RUN for preprocessing, CHAIN_STAGE_NOT_APPLIED for other stages). A requested processing stage did not run, so the display shows that stage's input. <reason> is one of the messages in the following rows. | Read <reason>; it says why. |
| `Preprocessing skipped: calibration file(s) not found — <paths>. Generate a set with xpe_calib_fixture_gen --out <dir> and point the calibration directories at it.` | At least one of the offset, gain and defect-map files is missing from the configured calibration directories. | As the message says: generate a set with xpe_calib_fixture_gen and point the calibration directories at it. |
| `xpe_preprocess_init failed (<code>).`<br>`Loading <name> calibration failed (<code>).`<br>`xpe_offset_correct failed (<code>).`<br>`xpe_nonlinearity_correct failed (<code>).`<br>`xpe_gain_correct failed (<code>).`<br>`xpe_defect_correct failed (<code>).` | That native call returned a non-zero error code. The codes are listed in the appendix. | No action is defined; the message itself is the diagnosis. |
| `Preprocessing requires the native backend (xpe_preprocess.dll).`<br>`Grid correction requires the native backend (gsvg.dll).`<br>`Stage '<id>' is not available in the mock backend.`<br>`Stage '<id>' is not available in the native backend.` | The mock backend is active, and processing stages need the native backend; or the active backend does not know that stage. | No action is defined; the message itself is the diagnosis. |
| `<stage> threw: <message>`<br>`<stage> returned <n> pixels for an input of <m>.` | The stage raised an error, or returned a different number of pixels than it was given. The chain records the stage as not applied. | No action is defined; the message itself is the diagnosis. |
| `The virtual grid needs a parameter table; none was configured and none was found beside gsvg.dll.`<br>`The virtual-grid table was not found: <path>`<br>`xpe_gsvg_init refused the configuration (<code>). See the alerts for the reason.`<br>`GSVG refused this image: <detail>` | The virtual-grid table is neither configured nor next to gsvg.dll / the configured path has no file / the module refused the configuration / the module refused the image (non-zero code). | For a refused configuration the message points to the alerts (section C). |
| `GSVG was requested but no correction was enabled in its config — check the key names.`<br>`The image is too small for GSVG: <detail>`<br>`GSVG saw a grid peak but no sub-band confirmed it; nothing was filtered and a grid may remain.`<br>`The virtual grid refused this exposure or these settings; the module restored the original.`<br>`GSVG returned a reason this build does not know: <detail>` | The module's answer for a GSVG stage that did not apply. <detail> reads reason=…, vignette=…, grid=…, virtualGrid=…, restoredOriginal=…, code=…. | Only the first message names an action: check the key names in the GSVG configuration. The third says a grid may remain. |
| `Your saved settings could not be read, so this session started from defaults.`<br>`The original file was kept at '<path>'.`<br>`An earlier failure already rescued your original settings, kept at '<path>'.` | Also raised as a WARN alert with code SETTINGS_UNREADABLE. The stored settings file could not be read, so the app started with default settings. The original file is preserved. | The message gives the location of the preserved original file. |
| `Recent file is not available: <path>` | The file is not at that path. The entry stays in the Recent list on purpose, because a file on a disconnected share can come back. | No action is defined; the message itself is the diagnosis. |
| `Failed to write verdict file: <message>` | Writing the verdict file raised an error (shown in the log; also an ERROR alert with code VERDICT_WRITE_FAILED whose text is the error's own message). | No action is defined; the message itself is the diagnosis. |
| `Could not copy the log line: <message>`<br>`Detached comparison viewer failed to open: <exception name>.` | Copying: the clipboard can be held by another process. Viewer: opening the detached comparison window raised an error. | No action is defined; the message itself is the diagnosis. |

## C. Native alerts

The severity is given in the second column.

| Message | What it means | What to do |
|---|---|---|
| `1 alert was dropped because the alert queue overflowed.`<br>`<N> alerts were dropped because the alert queue overflowed.` | ERROR, code ALERT_QUEUE_OVERFLOW. The native alert queue (capacity 64) overflowed and alerts were dropped. | No action is defined; the message itself is the diagnosis. |
| `[unreadable alert]` | ERROR. One entry of the native alert queue could not be read. It is kept as this text instead of being dropped silently. | No action is defined; the message itself is the diagnosis. |
| `ALL <N> pixel(s) fell outside the gain polynomial's fitted dose range [<a>, <b>] -- the whole frame was evaluated at one range edge, so the gain applied is effectively constant. Check that the calibration's dose levels are in pixel values (ADU): a file fitted in other units loads without error and produces this (issue #194)` | WARN. Every pixel of the frame is outside the gain polynomial's fitted dose range. | As the message says: check that the calibration's dose levels are in pixel values (ADU). |
| `<N> pixel(s) fell outside the gain polynomial's fitted dose range [<a>, <b>] and were evaluated at the range edge; values beyond the calibrated levels are not extrapolated (issue #194)` | WARN. Some pixels are outside the fitted dose range and were evaluated at the range edge. | No action is defined; the message itself is the diagnosis. |
| `gain polynomial dose levels span [<a>, <b>], far below the pixel-value range they index (0..65535). CHECK THE UNIT OF THIS CALIBRATION'S dose_levels: they must be pixel values (ADU), and a ladder fitted in mGy loads without error while producing a wrong image. If the unit is right and the calibration is simply very dark, this warning can be ignored. This is a magnitude check, not a unit check -- the file carries no unit field (issue #194)` | WARN, raised when the gain calibration is loaded. The largest dose level is very small compared with the pixel values it indexes. This is a magnitude check, not a unit check. | As the message says: check the unit of dose_levels; if the unit is right and the calibration is simply very dark, the warning can be ignored. |
| `gain polynomial loaded without a dose range: this file was generated before the range field existed, so the out-of-range clamp does not apply to it and pixel values beyond the fitted levels are extrapolated; regenerate the calibration to enable the clamp (issue #194)`<br>`gain polynomial carries an inverted dose range [<a>, <b>]: the clamp is not applied and pixel values are extrapolated. The file's dose levels were not ascending when it was generated, so its coefficients may be fitted against mispaired gain maps -- regenerate it (issue #194)` | WARN. The gain file has no dose-range field, or its dose range is inverted. | As the messages say: regenerate the calibration. |
| `panel.nonlinearity_mode selects the polynomial method but no panel.nonlin_poly_c0..c4 coefficients are present; falling back to the LUT method (SRS-CALIB-FUNC-006-EXT 6b, issue #186)`<br>`nonlinearity polynomial has a non-finite coefficient; falling back to the LUT method (FUNC-006-EXT 6b, #186)`<br>`nonlinearity polynomial is non-monotone in [0, ADC_max]; rejected and falling back to the LUT method (SRS-CALIB-FUNC-006-EXT 6b step 5, issue #186)` | WARN for the first and third message, ERROR for the second. The polynomial nonlinearity method was selected but cannot be used (no coefficients, a non-finite coefficient, or a non-monotone polynomial); the LUT method is used instead. | No action is defined; the message itself is the diagnosis. |
| `panel.linear is false but no nonlinearity LUT is loaded; call xpe_calib_load_nonlin_lut() before processing (SRS-CALIB-FUNC-006, issue #186)`<br>`nonlinearity correction did nothing: no LUT is loaded and panel.linear is not "false", so the frame passed through unchanged; load a LUT with xpe_calib_load_nonlin_lut() if this panel needs correcting (issue #196)` | ERROR for the first message: the panel needs nonlinearity correction but no LUT is loaded. WARN for the second: no LUT is loaded and the frame passed through unchanged. | As the messages say: load a LUT with xpe_calib_load_nonlin_lut(). |
| `gsvg config key '<key>' is not read by this module and has no effect` | WARN. The GSVG configuration contains a key the module does not read. | No action is defined; the message itself is the diagnosis. |
| `gsvg virtual grid: <reason>`<br>`gsvg virtual grid: no collimation field mask; scatter outside the field is treated as object`<br>`gsvg virtual grid: thickness above the table in <x>% of the pixels (limited to the table maximum in <y>% of the reduced grid)` | The first message is an ERROR: reading the virtual-grid configuration or table failed for <reason>. The other two are WARN: no collimation mask was given, so scatter outside the field is treated as object / some pixels have a thickness above the table and were limited to the table maximum. | No action is defined; the message itself is the diagnosis. |

## Appendix. Native error codes

The codes that appear in messages such as "failed with XPE error code <code>." and "failed (<code>).".

| Code | Name | Meaning |
|---|---|---|
| 0 | `XPE_OK` | Success — operation completed without error |
| -1 | `XPE_ERR_INVALID_INPUT` | NULL pointer, wrong pixel format, or invalid parameter value |
| -2 | `XPE_ERR_OUT_OF_MEMORY` | Heap allocation failure |
| -3 | `XPE_ERR_PROCESSING_FAILED` | Internal algorithm failure (e.g. singular matrix, zero-mean image) |
| -4 | `XPE_ERR_CONFIG_INVALID` | Configuration file missing, malformed, or version mismatch |
| -5 | `XPE_ERR_CALIBRATION_EXPIRED` | Calibration data present but outside its valid-use window |
| -6 | `XPE_ERR_NOT_INITIALIZED` | Module-level init function has not been called |
| -7 | `XPE_ERR_UNSUPPORTED_FORMAT` | Pixel format or image dimensions not supported by this function |
| -8 | `XPE_ERR_BUFFER_TOO_SMALL` | Caller-supplied output buffer is smaller than required |
| -9 | `XPE_ERR_IO_FAILED` | File read or write failure |
| -10 | `XPE_ERR_NETWORK_FAILED` | Network communication failure (DICOM send/receive) |
