# GUI-C-166 (#225) — 러너가 자기 빌드의 나이를 **거부**합니다. 공유 한 벌로

상태: **완료.** 반증 3방향 전부, 기존 가드 불변 확인, CI 순서 로컬 재현.

그리고 **첫 반증 시도가 통과했는데 그것은 가드가 깨진 것이 아니라 그 경로에 가드가 없다는 뜻**이었습니다(§5.1).

---

## 1. 공유는 가능했습니다 — 어떻게 (카드 §2 마지막)

| 프로젝트 | 앱을 어떻게 보나 |
|---|---|
`gui/ImageProcTest.E2E`·`gui/ImageProcTest.SelfCheck` | **`ProjectReference`** |
`clients/ImageProcTest.E2ETests` | **참조 없음 — 결정된 것.** csproj 주석: 앱을 참조하면 빌드가 `ImageProcTest.exe` 에 의존하고, 남아 있던 앱 인스턴스가 그 exe 를 잡아 **빌드를 한 번 깨뜨렸습니다**(`GUI-C-35`, `MSB3027`). 그래서 **링크 소스** 패턴을 씁니다 |

그래서 비교 로직을 **앱 프로젝트**(`Services/BuildFreshnessGuard.cs`)에 두고, 러너 둘은 참조로, 시험 프로젝트는 **그 한 파일만 링크**합니다 — **구현 한 벌, 호출 셋, 새 `ProjectReference` 없음.**

### 1.1 한 번 쪼개야 했습니다

처음엔 러너용 헬퍼까지 같은 클래스에 넣었는데 **컴파일이 안 됐습니다**:

```
error CS0103: 'GuiFixtureManifestService' 이름이 현재 컨텍스트에 없습니다
```

링크된 파일이 **링크되지 않은 서비스**를 끌어온 것입니다. 그래서 갈랐습니다:

| 파일 | 무엇 | 링크되나 |
|---|---|---|
`BuildFreshnessGuard` | **시각 비교만** — 의존성 0 | **예** |
`RunnerBuildFreshness` | 저장소 루트를 찾아 앱 소스 위치를 정함 | 아니오 |

**공유하는 것은 드리프트하면 위험한 부분**입니다: `bin`/`obj` 제외(`obj` 는 빌드 **중에** 쓰이므로 포함하면 빌드를 자기 자신과 비교합니다)와 **컴파일 입력 확장자만**(앱이 자기 소스 옆에 `automation-report.json` 을 쓰는데 그것을 소스로 치면 `gui-automation` 이 전부 거짓 빨강이 됩니다 — CI 실행 `35399591335` 에서 127건 중 97건). **"내 소스가 어디냐" 는 공유하지 않습니다** — 호출부마다 실제로 다르고, 그것을 공유하면 **버그를 공유**합니다.

## 2. 왜 규율이 아니라 기계인가 (카드 §1 그대로 받습니다)

제가 쓰는 규칙 — *"러너를 돌릴 거면 러너 프로젝트를 빌드한다"* — 은 옳고, **그 규칙을 아는 제가 `C-165` 에서 밟았습니다.**

그리고 대가가 **틀린 초록이 아니라 틀린 지식**이었습니다. 초록은 다음 실행이 반박하지만, *"WPF 가 `CanExecute` 로 `IsEnabled` 를 강제한다"* 가 보고서에 들어가면 **아무것도 반박하지 않습니다.** 그 문장을 코드 주석에 사유로 남겼습니다.

## 3. 무엇을 만들었나 (카드 §2)

| 지킬 것 | 어떻게 |
|---|---|
| **던진다, 건너뛰지 않는다** | `InvalidOperationException`. 건너뛰면 *"안 돌았다"* 가 *"통과했다"* 옆에 조용히 섭니다 |
| 무엇이 무엇보다 낡았는지 | **두 경로 + 두 시각(UTC, `:O`)** + **실행할 명령** |
| 두 러너 모두 | `RunSelfCheck()` 앞, 그리고 SelfCheck 의 첫 줄 — **아무 단언보다 먼저** |

명령 문구는 **반직관적인 쪽**을 말합니다: *"Build the RUNNER, not the app"*. `C-165` 에서 제가 빌드한 것은 앱이었고, 그것이 정확히 함정이었습니다.

## 4. 반증 세 방향 (카드 §3 — 이 카드의 본체)

| 방향 | 결과 |
|---|---|
| **① 앱만 재빌드 → 던지는가** | 러너 bin 의 dll `10:43:14`, 앱 `10:43:37`(23초 차) → **exit -532462766**, *"The copy of the gui app that ImageProcTest.E2E runs against is older than its sources…"* — `C-165` 상황 그대로 거부 |
| **② 러너 빌드 후 → 안 던지는가** | SelfCheck **exit 0**, E2E **exit 0**. 늘 던지는 가드는 가드가 아닙니다 |
| **③ CI 에서 안 던지는가** | **로컬에서 CI 순서를 재현**했습니다 — §4.1 |

### 4.1 ③ 을 어떻게 쟀는가

CI 를 돌릴 수 없으니, `origin/main`(`890fd5f`)의 `ci.yml` 에서 `gui-shell-runners` 의 명령을 **그대로 가져와** **깨끗한 상태**(세 프로젝트의 `bin`·`obj` 삭제 — 새 체크아웃과 같게)에서 순서대로 실행했습니다:

```
dotnet build gui/ImageProcTest/ImageProcTest.csproj -c Debug              오류 0개
dotnet build gui/ImageProcTest.SelfCheck/...csproj -c Debug               오류 0개
dotnet build gui/ImageProcTest.E2E/...csproj -c Debug                     오류 0개
dotnet run --project ...SelfCheck... --no-build   exit 0
dotnet run --project ...E2E...       --no-build   "GUI-S0 E2E passed."
```

그리고 **앱이 러너를 띄우는 경로**도 같은 상태에서: `A04`·`A05`·`A06`·`A09` **4/4 통과**.

**왜 CI 에서 던질 수 없는지**도 적어 둡니다: 가드는 러너의 dll 을 **앱의 소스와** 비교합니다(앱의 dll 과 비교하지 않습니다). 두 잡 모두 **하나의 체크아웃에서 앱 → 러너 순서**로 짓고 소스는 손대지 않으므로, 소스 시각이 모든 빌드 산출보다 앞섭니다.

**이것은 CI 관측이 아니라 로컬 재현입니다** — 실제 잡의 초록은 리더의 실행에서 확인됩니다.

## 5. 기존 가드는 약화되지 않았습니다 (카드 §4 첫째)

`gui` 소스를 만지고(재빌드 없이) fixture 를 쓰는 시나리오를 돌렸더니 **같은 메시지로 던집니다**:

> *"The gui app executable is older than its sources … exe written `01:45:44`; newest source `MainWindow.xaml.cs` written `01:47:30`. Build the app first: …"*

### 5.1 첫 반증 시도가 통과했고, 그것이 **다른 사실**이었습니다

처음엔 `A09` 로 확인하려 했는데 소스를 만져도 **통과**했습니다. 가드가 깨진 것이 아니라 — **`A0x` 자동화 보고서 시나리오는 그 가드를 지나지 않습니다.** `ApplicationFixture.ResolveApplicationExecutable()` 로 경로만 얻고 `Process.Start` 로 직접 띄우므로 **fixture 를 생성하지 않고**, 따라서 `EnsureApplicationIsFresh` 가 돌지 않습니다.

**즉 앱 신선도 가드의 사각이 하나 있습니다** — `A01`–`A09` 아홉 건. 이 카드의 범위가 아니라 **보고만** 합니다(막는 방법은 `Run()` 이 같은 검사를 부르는 것입니다).

## 6. 회귀 — 전체 스위트

| 구성 | 전체 | 통과 | 건너뜀 | 실패 |
|---|---|---|---|---|
| Mock, 전체 | **173** | 142 | 31 | **0** |

`C-163` 기준선(142 / 31 / 173)과 **차이 0**. `ApplicationFixture` 를 고쳤으니 부분 확인으로 끝낼 자리가 아니었습니다 — 그 파일은 모든 FlaUI 시나리오의 공통 입구입니다.

## 7. 미검증 / 잔여 위험

- **실제 CI 미실행** — ③ 은 **로컬 재현**입니다. 잡의 초록은 리더 실행에서 확인됩니다
- 가드는 **시각**으로 판단합니다. 시계가 뒤로 가거나 파일 복사가 mtime 을 보존하면 **거짓 음성**(낡았는데 통과)이 납니다 — 기존 가드도 같은 성질이고 바꾸지 않았습니다
- 러너 가드의 주체는 **`ImageProcTest.dll` 하나**입니다. 러너 자신의 소스(`Program.cs`)가 낡는 경우는 보지 않습니다 — `dotnet run --no-build` 가 아니라 `dotnet build` 로 짓는 CI 에서는 같이 갱신되지만, **검사하지는 않습니다**
- §5.1 의 사각(`A0x` 아홉 건)은 **보고만** 했습니다
