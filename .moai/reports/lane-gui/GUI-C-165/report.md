# GUI-C-165 (#225) — 낡은 단언은 **셋**이었고, 결정성은 **충족되지 않았습니다**

상태: **완료.** 러너 `exit 0`. 반증 3건. 그리고 **제 반증 두 개가 무효였고 그것이 틀린 결론을 만들 뻔했습니다**(§4).

## 1. §1.1 의 답: **"deterministic artifacts exist" 는 충족되지 않았습니다** — 재서

같은 입력으로 두 번 돌려 zip 을 바이트로 비교했습니다:

| | `runtime-log.txt` | 내용 sha256 | zip sha256 |
|---|---|---|---|
| 1차 | 5737 B | `9c231676e8b3d1a5` | `900da9b18b4addff` |
| 2차 | 5737 B | **`afde1a18801c6adc`** | **`a6ce1bb1b31736a6`** |

**크기는 같고 내용 해시가 다릅니다.** 비결정성의 출처 셋이 모두 관측됩니다: 로그 안의 **시각**, zip **이름**(RunId 가 시계를 담음), 멤버 **mtime**.

**그래서 결정성 단언은 넣지 않았습니다.** 넣으면 빨간 단언을 커밋하는 것입니다.

### 1.1 그렇다고 행 3 이 "이른" 것도 아닙니다 — 판단에 필요한 사실

옛 단언이 **지키던 것이 아무것도 없었습니다.** 같은 명령이 `54a3ae7`(2026-05-09)부터 **워크벤치 버튼 둘**에 묶여 있었으므로, 운영자는 **줄곧 비결정적 번들을 만들 수 있었습니다.** 그 줄은 **메뉴에서만** 막고 있었습니다.

| 주장 | 참인가 |
|---|---|
| 번들 능력이 있다 | **예** — `2026-05-09` 부터 |
| 그 산출물이 결정적이다 | **아니오** — §1 실측 |
| 옛 단언이 비결정적 export 를 막고 있었다 | **아니오** — 버튼으로 항상 가능했습니다 |

**되돌려도 그 보호는 돌아오지 않습니다.** 행 3 을 다시 비활성으로 만들면 **메뉴만** 다시 막히고, 버튼은 그대로입니다. 결정성을 요구로 세울지는 **리더 판단**이고, 그때 대상은 메뉴가 아니라 **번들 규격**(행 3 의 "묶는 규격")입니다.

## 2. 낡은 단언은 **셋**이었습니다

카드가 하나를 지목했고, 러너를 끝까지 돌려 셋을 찾았습니다.

| 줄 | 무엇 | 왜 낡았나 | 빨갰나 |
|---|---|---|---|
| `:140` | `Open Recent` 비활성 | 행 1(`C-160`) | **아니오 — 우연히 통과** |
| `:142` | 번들 export 비활성 | 행 3(`C-163`) | **예** (카드가 지목) |
| `:231` | 증거 폴더 비활성 | 행 14(`C-163`) | `:142` 를 고친 뒤 **드러남** |

**`:140` 이 통과한 이유가 중요합니다.** 이 러너는 새 창을 만들고 그 창의 이력이 **비어 있어서** 항목이 꺼집니다. 즉 그 단언은 *"기능이 없다"* 가 아니라 **"목록이 비었다"** 를 재고 있었습니다. 설정 파일에 저장된 파일이 하나라도 있으면 **아무것도 깨지지 않은 채 빨개집니다.**

셋 다 **지우지 않고** 현재 계약으로 옮겼습니다(`#228` 에서 세운 원칙).

### 2.1 손대지 않고 **보고만** 하는 것 하나

`:200` `!runPreprocessingMenuItem.IsEnabled`("until Phase 1a") — `#141`(`C-36`)이 **네이티브 백엔드에서 그 항목을 켰고**, 자동화 스크립트 주석이 그렇게 적고 있습니다. 이 러너가 Mock 을 돌려서 통과합니다. **`:140` 과 같은 우연한 통과**이지만 제 행이 아니고 빨갛지도 않으니 **판단을 올립니다.**

## 3. 제가 쓴 단언 하나가 **자기 비교**였습니다 — 스스로 걷어냈습니다

`:140` 의 첫 대체안은 이랬습니다:

```
Assert(openRecentMenuItem.IsEnabled == viewModel.HasRecentRawFiles)
```

XAML 이 `IsEnabled="{Binding HasRecentRawFiles}"` 입니다. **양변이 같이 움직이므로 절대 실패할 수 없습니다** — `C-158` 의 제목 상수와 같은 형태입니다.

독립된 짝으로 바꿨습니다: `IsEnabled` ↔ **하위 메뉴 자신의 `Items.Count`**(바인딩이 만들어 낸 것), 그리고 `ItemsSource is not null`. 팔 B 가 그것이 실제로 터지는 것을 보여 줍니다.

## 4. 반증 — 그리고 **무효 결과 둘**

### 4.1 하마터면 틀린 사실을 보고서에 적을 뻔했습니다

| 팔 | 1차 결과 | 제가 쓰려던 결론 |

| A′ (명령 바인딩 제거) | exit **0** | — |

**둘 다 무효였습니다.** 타임스탬프를 비교해 찾았습니다:

**둘 다 터집니다.** "강제 변환" 은 **낡은 바이너리가 만든 허상**이었습니다. 저장소의 *"동적 링크라 제품만 고치면 시험 exe 타임스탬프가 안 바뀐다"* 그대로입니다.

## 5. §2 의 답 — **짓는 것으로 충분합니다. 넘길 인자는 없습니다**

앱이 찾는 곳(`RunConsoleRunnerAsync`):

```
<repoRoot>/gui/ImageProcTest.SelfCheck/bin/Debug/net8.0-windows/ImageProcTest.SelfCheck.exe
<repoRoot>/gui/ImageProcTest.E2E/bin/Debug/net8.0-windows/ImageProcTest.E2E.exe

repoRoot = 앱 자신의 디렉터리에서 위로 올라가며 docs/project/sprint-plan.md 를 찾은 지점
```

| 확인할 것 | 상태 |
|---|---|
| **`-c Debug` 여야 합니다** | 경로에 `Debug` 가 **리터럴**로 박혀 있습니다(`C-158` 이 Release 공백으로 기록). 그 잡은 앱을 이미 `-c Debug` 로 짓고 있으니 **러너도 `-c Debug`** 면 맞습니다 |
| 저장소 표지 | `docs/project/sprint-plan.md` — 체크아웃 루트에 있습니다 |
| **넘길 인자** | **없습니다.** `--automation-selfcheck-exe` 는 `A05` 전용이고, `A05` 는 **자기가** 빌드된 러너를 임시 폴더로 복사해 실패를 만듭니다 — 필요한 것은 `SelfCheck.exe` 가 그 경로에 **있다**는 것뿐입니다 |
| `A05` 의 "실패하는 자가진단" | CI 가 제공할 것이 없습니다. 저장소 밖 복사본이 `Repository root could not be located.` 로 죽는 **구조적 실패**입니다 |

**근거**: `C-159` 의 Native 구성 실행에서 `A04`·`A05`·`A06` 이 **6/6 통과**했고, 그때 러너는 위 경로에 있었으며 **인자를 넘기지 않았습니다.** 그리고 `C-161` 이 **없는 경우**를 쟀습니다 — 건너뛰기 사유가 없는 exe 를 이름으로 말합니다.

## 6. 반증 (카드 §3 둘째) — 러너 지우면 건너뛰는가

`C-161` 에서 이미 쟀고 이 카드에서 다시 쓰지 않았습니다: 러너 exe 둘을 치우면 `A04`·`A06` 이 사유와 함께 건너뛰고, 되돌리면 단언 3/3 으로 돌아옵니다. **그 자리는 살아 있습니다.**
