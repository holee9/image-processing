# GUI-C-133 — **고치지 않았다.** 클릭 분기는 이 시나리오에서 죽은 경로다

## 1. 결론 먼저

`§2` 계측 결과가 **0** 이므로 카드 지시대로 **고치지 않고 보고한다.**

```
20회 실행 = 120번 호출
  120  PATTERN
    0  FALLBACK_CLICK
```

**다만 카드의 추론 한 줄은 정정이 필요하다.** 카드는 *"0 이면 원인 확정이 틀린 것"*
이라고 적었다. **0 은 원인 확정을 반박하지 않는다** — 이유는 §3 이다.

## 2. `§1` 전제 — 셋 다 참

| # | 전제 | 확인 | 결과 |
|---|---|---|---|
| 1 | 클릭이 하위 메뉴 헤더를 토글해 부모 팝업을 닫는다 | `GUI-C-130` 개입 실험 (Click 15/5, Expand 20/0, 복귀 20/0) | **참** |
| 2 | `ExpandCollapse.Expand()` 경로가 20/20 무실패 | 같은 측정 + 오늘 재측정 20/20 | **참** |
| 3 | `TryGetPattern` 실패 시 클릭으로 내려가는 분기가 있다 | `ComparisonEntryPointScenarios.cs:229-231` | **참 (있다)** |

같은 형태를 다른 곳에서도 찾았다 — `:261`·`:266` 에 `TryGetPattern` 이 있지만
`DescribeMenuState`(진단 출력) 안이고 **클릭하지 않는다.** 고칠 대상은 :229-231 하나다.

## 3. `§2` 계측 — **0 이 무엇을 뜻하는가**

### 측정

임시 계측을 넣어 어느 분기가 도는지 파일에 적고 20회 돌렸다.

```
BASELINE(Expand): pass 20 / fail 0 (20회)
§2 분기 계측 (총 120 회 호출)
    120 PATTERN
```

**한 실행에 6번 호출된다**(W-13 은 메뉴 항목 6개를 도는 `Theory`) — 20 × 6 = 120,
수가 맞는다. **파일이 비어 있지 않은 것이 계측이 실제로 돈 증거다**(§5 의 함정 참조).

### 0 은 원인 확정을 반박하지 않는다

원인은 **강제 개입**으로 세웠다 — `GUI-C-130` 의 팔 B 는 그 블록을 `TryGetPattern`
검사 **없이** `compare!.AsMenuItem().Click();` 하나로 **교체**했다. 즉 클릭이 실패를
만든다는 것은 *"대체 분기가 탔다"* 가 아니라 *"클릭만 하게 만들면 5/20 로 실패한다"*
로 입증됐다. 그러니 대체 분기가 0회여도 모순이 없다.

**0 이 실제로 뜻하는 것은 고칠 대상이 비어 있다는 것이다.**

- `#163` 의 결함은 **이미 고쳐져 있다** — `GUI-C-108` 이 넣은 `Expand()` 경로가
  120/120 을 담당한다.
- 남은 `else` 는 이 시나리오에서 **죽은 코드**다. `TryGetPattern` 이 한 번도 실패하지
  않았다.

### 그래서 `G2` 를 만족시킬 수 없다

| 게이트 | 상태 |
|---|---|
| **G1** (n=20 실패 0) | **이미 만족** — 오늘 20/20, `n` 은 측정 전 고정 |
| **G2** (되돌리면 실패가 다시 나타난다) | **만족 불가** |
| **G3** (다른 메뉴 경로 회귀) | 해당 없음 — 바꾼 것이 없다 |

죽은 코드를 고친 뒤 되돌려도 **실행되지 않으므로 실패가 나타나지 않는다.** 그 상태에서
20/20 초록을 보고하면 **카드가 경고한 바로 그 거짓 초록**이다 —
*"고쳐졌다" 와 "원래 그 경로가 안 쓰였다" 가 구별되지 않는다.* `§2` 를 먼저 재라는
지시가 이 결과를 막았다.

## 4. 남은 위험 — 이론적이고, 측정으로 닫을 수 없다

`else` 는 `TryGetPattern` 이 실패할 때만 돈다. 그때는 토글이므로 `#163` 이 되살아난다.
그러나:

- 120회 중 **0회**이므로 이 시나리오에서는 도달 불가에 가깝다.
- 고쳐도 **표본에 나타나지 않으므로 효과를 잴 수 없다.** 잴 수 없는 변경을 넣으면
  다음 사람이 "이것이 무엇을 고쳤는가" 에 답할 수 없다.

**그러니 방향은 lead 결정으로 넘긴다.** 선택지와 측정 가능성을 같이 적는다:

| 선택지 | 측정 가능성 |
|---|---|
| 그대로 둔다 + 왜 죽은 경로인지 주석 | 측정할 것이 없다. 계측 결과(120/0)가 근거로 남는다 |
| `else` 를 **실패 처리**로 바꾼다(토글하지 않음) | 이 시나리오에서는 **차이가 관측되지 않는다.** `TryGetPattern` 이 실패하는 조건을 따로 만들지 않으면 G2 불가 |
| 패턴 부재를 **강제**하는 조건을 만들어 대체 경로를 시험한다 | 가능하지만 **새 카드**다 — 패턴을 없앨 수단을 먼저 찾아야 한다 |

세 번째가 유일하게 G2 를 만족시킬 수 있는 길인데, 지금 카드의 범위를 넘는다.

## 5. 도중에 잡은 것 — **빌드 실패가 "0회" 로 위장하려 했다**

첫 계측 주입에서 `\n` 이 C# 문자열 안에 **실제 줄바꿈**으로 들어가 빌드가 **20개 오류**로
실패했다. `--no-build` 로 시험을 돌렸으므로 **낡은 바이너리**가 그대로 20/20 을 찍었고,
계측 파일은 비어 있었다.

**그 빈 파일을 "클릭 분기 0회" 로 읽었으면 결론이 우연히 같아서 통과했을 것이다.**
잡은 방법은 두 개를 같이 본 것이다 — 빌드 오류 수, 그리고 **계측 파일이 비어 있지
않은지.** 두 번째가 없으면 계측 자체가 안 돌았는지 알 수 없다.

원복은 백업에서 바이트 단위로 했다:

```
INSTRUMENT left: 0, Tally left: 0
git diff --stat  → 비었음 (HEAD 와 바이트 동일)
빌드 오류 0
```

## 6. 빌드·시험

```
BUILD_EXIT=0
Mock E2E W-13 (ComparisonEntryPointScenarios): 20회 × 6항목 = 120 호출, 실패 0
계측: PATTERN 120 / FALLBACK_CLICK 0
```

제품 코드 변경 0건, 시험 코드 변경 0건 — **이 카드는 측정만 했다.**

## 7. 미검증 (Gaps)

- **`TryGetPattern` 이 실패하는 조건을 모른다.** 0회이므로 "언제 실패하는가" 를 재지
  못했다. 요소 종류·타이밍·UIA 공급자 상태 어느 것이 조건인지 확인하지 않았다.
- **Native 에서 재지 않았다.** 120회 전부 Mock 이다(메뉴 상호작용은 백엔드와 무관하다고
  보지만 재지는 않았다).
- **다른 메뉴 경로의 토글 함정을 보지 않았다.** `PipelineMenu`·`ViewMenu` 등은 이
  카드의 범위가 아니었고, `:261`·`:266` 이 클릭하지 않는 것만 확인했다.
- **옛 4/6 실패가 같은 원인인지는 여전히 단언하지 않는다**(`GUI-C-130` 에서와 동일).

## 8. 잔여 위험

- 20회 × 6 = 120 호출은 **이 기계·이 부하**의 값이다. CI 에서 `TryGetPattern` 이
  실패하는 경우가 있을 수 있고, 그러면 죽은 줄 알았던 경로가 살아난다 —
  게이트를 잘못된 기계에서 잡은 사례가 이미 있다.
- `#163` 을 닫을지는 lead 결정이다. **원인은 확정됐고 현재 코드는 20/20 이지만**,
  남은 `else` 가 그대로 있는 한 "고쳤다" 는 조건부다.
