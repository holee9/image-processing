## 1. 발견 3: SwipeVertical 표시 시간 값 공개 (판정 아님)

- `W15c_SwipeVertical_TheTimeIsDisclosed_NotJudged`: W15 와 같은 `MeasureOpens`(정착 + 변화 + 정체)로 SwipeVertical 5회를 재고, 프록시·화면 값과 각 열기의 일치율을 출력한다. **단언하는 값이 없다**(측정을 못 하면 예외로만 실패). 정체 기준은 그 모드에서 앱이 그린 처리 상태 화면, 처리 전 기준은 Source-only 화면이다.
- W15 의 판정 경로와 값은 바꾸지 않았다(표 출력만 공용 함수 `PrintMeasurements` 로 분리). `MeasureOpens` 는 비교 모드 인자를 받고 기본값은 W15 와 같은 ProcessedOnly.
- 이 세션은 화면을 읽을 수 없어(두 기준 캡처가 100% 같음 → "구별 불가") 화면 값이 나오지 않는다. 로컬 출력: W15c 프록시 중앙값 1242 ms, 화면 0/5 유효. 화면 값은 CI 러너에서 처음 나온다.

## 2. 발견 5: 레거시 열기 대화상자의 확인창 입력 (411c7c30)

- 새 시험 `LegacyOpenDialogMessageBoxScenarios.OpeningAFileThatDoesNotExist_…`: 없는 파일 이름으로 [열기]를 누른다. 키·마우스 입력 없이 UIA 로 대화상자를 찾고 이름을 넣은 뒤, 이후는 **네이티브 창 메시지만** 쓴다(클릭은 게시, 확인창은 `EnumWindows` 로 찾아 OK 버튼 또는 `WM_CLOSE` 로 닫음, 파일 대화상자는 [취소]). 앱은 120초 워치독(`AppWatchdog`)으로 묶었다.
- **관찰**: 첫 [열기] 클릭은 확인창을 띄우지 않았고(10초 동안 창 변화 없음), 두 번째 클릭 뒤 약 2.2초에 `#32770` 확인창('Select Target Raw Image')이 떴다. 그래서 시험은 최대 4번까지 2초 간격으로 다시 누르고 누른 횟수를 센다(첫 클릭이 자동완성 목록 등에 쓰였을 가능성; 원인은 확정하지 않았다). 확인창에는 OK 버튼(id 1)이 없어 `WM_CLOSE` 로 닫혔다.
- 결과: 확인창이 실제로 뜸 → 닫힘 → 파일 대화상자 취소 → 앱 최상위 창 수가 시험 전과 같음, 교착 없이 5초(`legacy_missing_file.txt`).
- 반증(`falsify_legacy.txt`): 버튼 누르기를 한 곳(`PressDialogButton`)으로 모으고 그것만 동기 전송으로 바꾸면 이 시험이 워치독(120초)에 걸려 실패("the watchdog had to kill the app: a click blocked"). 복원 후 통과.
- `LoadRawThroughDialog` 가 같은 `PressDialogButton` 을 쓰도록 바꿨고(411c7c30 의 게시 클릭과 동작 동일), `Kill()` 을 추가했다.

## 4. 이 커밋에 없는 것 (DICOM, 보류)

카드의 발견 2(`PreflightModule` 이 적재 핸들을 버려 DICOM 호출마다 모듈 참조가 쌓임)와 그 반복 시험은 작업 트리(`NativeModuleAudit.cs`, `LifetimeScenarios.cs`)에 **미커밋**으로 있다. 리더는 사용자 결정으로 "결함 하나만 고치고 병합"(참조 해제 + 시험 1건 + A19 1회)을 전했으나, 사용자가 이 세션에서 직접 한 말은 "DICOM 은 보류인데 왜 계속 하느냐"였고 이 세션에서 그 결정을 직접 받지 못해 DICOM 부분은 커밋하지 않았다. 구현 쪽 참고: 처음 구현한 `Free` 방식은 검사가 모듈의 첫 적재자일 때 모듈을 언로드하는 문제가 있어 "프로세스당 하나의 참조를 유지"로 바꾼 상태이고, 카드가 요구한 `try/finally Free` 와 다르다. 어느 쪽으로 할지는 사용자 결정 뒤에 정한다.
