## §2. Evidence — 증거

### 2-1. 변경 내용 (카드 1항)

```cpp
// before
std::vector<float> diff;
diff.reserve(w * h);
for (...) diff.push_back(row[x + 1u] - row[x]);
...
diff.clear();
for (...) diff.push_back(row[x + w] - row[x]);

// after
const size_t hCount = (w >= 2u) ? h * (w - 1u) : 0u;
const size_t vCount = (h >= 2u) ? (h - 1u) * w : 0u;
std::unique_ptr<float[]> diff(new float[maxCount]);
float* dst = out + y * (w - 1u);
for (...) dst[x] = row[x + 1u] - row[x];
```

**`std::vector<float>(n)` 대신 `new float[n]` 을 쓴 이유**를 적어 둔다. `vector` 의 크기 지정
생성은 값 초기화를 하므로 **37.75 MB 를 0으로 채우는 패스가 새로 생긴다** — 기존 `reserve` 는
내지 않던 비용이다. 모든 원소가 읽히기 전에 쓰이므로 기본 초기화 저장으로 충분하고, 그러면
그 패스가 없다. 이득을 재려다 다른 비용을 들여오는 것을 피한 것이다.

`madSigma` 와 `SelectKthSmallest` 에 포인터+개수 형태를 추가했다. 벡터판은 포인터판에
위임하므로 **구현은 하나**이고 기존 파리티 테스트가 그대로 그 코어를 덮는다.

### 2-2. 공정 비교 (카드 2항)

A-58 이 "사과 대 사과가 아니다" 라고 스스로 단 단서를 이번에 맞췄다. `ComputeGlobalSigma` 는
**할당을 자기 안에서** 하므로, 함수를 통째로 재는 `--sigma` 측정은 **할당이 타이밍 안에 있다**.
같은 명령·같은 맥락(조밀 반복 루프)·7회.

```
before:  raw: 166.0 171.0 172.5 171.6 169.2 171.7 171.6
         min 166.0  median 171.6  max 172.5  spread 6.5 ms = 3.8% of median

after:   raw: 138.3 142.0 137.4 136.9 141.6 140.2 139.8
         min 136.9  median 139.8  max 142.0  spread 5.2 ms = 3.7% of median
```

| | 중앙값 | 스프레드 |
|---|---|---|
| 전 | 171.6 ms | 3.8% |
| 후 | **139.8 ms** | 3.7% |
| 차 | **−31.8 ms (−18.5%, 1.23배)** | — |

**개선 18.5% 대 스프레드 3.8% — 다섯 배 차이라 산포에 묻히지 않는다.**

A-58 프로브(143.2 ms)는 **할당을 밖에** 뒀었다. 출고본은 이제 **할당을 안에 두고 139.8 ms** 다.
즉 프로브가 보여 준 이득은 실재했고, 출고 경로가 프로브와 같거나 그 이하로 내려왔다.
(그때 "1.2배 이득" 이라고 주장하지 않은 것은 옳았다 — 그 비교는 성립하지 않았고, 성립하는
비교를 이제 했다.)

전체 파이프라인(`--decompose`, 같은 맥락끼리):

| 3072² | A-55 후 | **A-59 후** |
|---|---|---|
| TOTAL | 732.1 ms | **707.5 ms** |
| 전역 σ | 199.8 | **156.6** |
| 픽셀 루프 | 532.0 | 550.6 |
| SPEC 초과 | 20.9배 | **20.2배** |

(픽셀 루프는 손대지 않았다. 532.0 → 550.6 은 A-55 가 기록한 맥락 변동 범위 안이다.)

### 2-5. 반증 — 두 건, 그리고 내 근거 문구의 정정 (카드 4항)

**반증 1 — 스트라이드 드리프트.** 수평 패스를 `w−1` 대신 `w` 간격으로 쓰게 했다.
빌드 `BUILD_EXIT=0`, `[14/14] Linking` 확인.
- 신규 스위트: **SEH 0xC0000005**(1024×3 에서 버퍼 초과) → 실패
- 정사각 전용 스위트(`RadixSelectParityTest`): **`GlobalSigmaMatchesThePreviousImplementation` 실패**

**여기서 내가 테스트 파일에 적어 둔 근거가 틀렸다.** 나는 "정사각 프레임은 이 변경이 지닌
위험을 잡을 수 없다" 고 썼는데, **이 드리프트는 정사각도 잡는다.** 추정으로 적은 문장이었고
측정이 반박했다. 파일 주석을 **측정한 그대로** 고쳤다(아래 반증 2와 함께).

**반증 2 — 개수 스왑.** 수평 패스에 `hCount` 대신 `vCount` 를 넘겼다.
빌드 `BUILD_EXIT=0`, `[14/14] Linking` 확인.
```
=== 정사각 전용 스위트 (RadixSelectParityTest) ===
[  PASSED  ] 4 tests.                 ← 전혀 눈치채지 못한다
=== 신규 비정사각 스위트 (SigmaBufferParityTest) ===
[  FAILED  ] SigmaBufferParityTest.NonSquareFramesMatchThePushBackImplementation
[  FAILED  ] SigmaBufferParityTest.DegenerateDimensionsMatchThePushBackImplementation
 2 FAILED TESTS
```
**정사각에서는 두 개수가 같은 수라 완전히 보이지 않고, 신규 스위트만 잡는다.**
이것이 파일 분리가 실제로 값을 내는 지점이고, 이제 그 근거가 **측정된 것**이다.

**복원 확인**: `a59-restore-build.log` exit 0, 파리티 3스위트 **11/11 통과**.

## §3. 게이트 (카드 3항)

```
[perf-gate] 3072x3072 single thread, warm, min of 3: 702.3 ms  (samples 702.3 / 708.8 / 707.2, spread 0.9%)
[perf-gate] 1024x1024 single thread, warm, min of 3: 82.8 ms

```

**조이지 않았다**(카드 지시). 판단 근거만 적는다 — 결정은 리더가 한다.

| | 값 |
|---|---|
| 현재(게이트 맥락, min of 3) | **702.3 ms** |
| 현 게이트 | 810 ms (여유 15.3%) |
| A-57 설정 당시 | 731.4 ms (여유 10.7%) |

조일 때 참고할 것: ① A-57 이 810 을 정할 때 쓴 여유가 **약 10%** 였고, 지금 같은 비율이면
**약 775 ms** 다. ② 이번 게이트 실행의 샘플 스프레드는 0.9% 였지만 A-55·A-56 이 잰 **맥락 간
차이는 17~23%** 이고, CI 기계는 아직 한 번도 재지 않았다(§5-1). ③ 한 번의 개선으로 조이면
**다음 회귀가 쓸 여유가 사라진다** — 이번 개선분 29 ms 를 전부 회수하면 그다음 20 ms 짜리
회귀가 게이트를 통과한다.

## §4. Baseline-attribution — 무엇에 대고 쟀나

- **전/후 전역 σ**: 같은 명령(`--sigma`)·같은 맥락·7회. **전 측정은 이번 턴에 변경 전 코드로
  새로 실행**했다 — A-55 보고서의 171.3 을 옮겨 적지 않았다(171.6 이 이번 값이다)
- **전체 파이프라인**: `--decompose`, A-55 로그와 같은 명령·같은 맥락
- **동작 동일**: A-50 이 남긴 로그 파일과 `diff`
- **게이트**: 이번 턴 테스트 실행의 인쇄값(샘플 3개 포함)
- **반증 2건**: 각각 빌드 후 실제 실행. 두 스위트를 **따로 돌려** 어느 쪽이 잡는지 분리 관측
- **테스트 수**: 이번 트리 ctest 전체. 615 → 618 증가분이 신규 3건

## §5. Gaps — 관측하지 않은 것

1. **CI 기계에서 한 번도 재지 않았다.** 게이트 여유(15.3%)도 이 기계 기준이다
2. **`new float[]` 의 할당 비용을 따로 재지 않았다.** 전/후 차 31.8 ms 안에 섞여 있고,
   `reserve` 의 할당과 얼마나 다른지 분리하지 않았다
3. **push_back 제거분과 `clear()+재성장` 제거분을 나누지 않았다.** 둘 다 한 번에 바꿨다
4. **픽셀 루프 532.0 → 550.6 ms 를 맥락 변동으로 보았지만 확인하지 않았다.** 코드는 안 바뀌었다
5. **스레드에서 실제로 분할해 보지 않았다.** A-58 §1 이 지목한 자료구조 장애물은 제거됐지만,
   **그것이 실제로 분할을 가능하게 하는지는 이 카드에서 시험하지 않았다**
6. **비정사각 실프레임이 있는지 모른다.** 검출기가 정사각만 받는다면 §2-5 의 반증 2가 잡는
   드리프트는 현실에서 발생할 수 없다 — 그래도 테스트는 값이 있지만, 우선순위는 달라진다
7. 실프레임 미확인(#151), 이 기계·이 컴파일러 한 조합

## §6. Residual-risk — 남는 위험

1. **내가 근거로 적은 문장이 틀렸던 사례가 이번 카드에서 나왔다**(§2-5). 테스트 분리의
   이유를 추정으로 적었고 측정이 반박했다. 고쳤지만, **다른 곳에도 같은 종류의 추정이
   남아 있을 수 있다** — 이 보고서의 "근거" 중 측정이 아닌 것은 그렇게 표시했는지 다시 볼 일이다
2. **`new float[]` 는 예외 안전성이 `vector` 보다 약하다.** `unique_ptr` 로 감쌌으므로 누수는
   없지만, 이 함수가 앞으로 중간에 예외를 던지는 코드를 갖게 되면 다시 볼 지점이다
3. **Gap 5 가 다음 결정에 걸린다.** "자료구조 장애물을 제거했다" 는 A-58 §1 의 판정에
   근거한 것이고, 실제 스레드 분할은 여전히 미시험이다. 스레드 정책이 결정되면 그때
   A-55 형식의 비트 단위 파리티가 필요하다
4. **20.2배는 여전히 예산 밖이다.** 이 카드는 0.7배를 줄였을 뿐이다
5. 게이트를 조이지 않은 선택은 **회귀를 늦게 잡는 대가**를 치른다. 지금 702.3 인데 810 까지
   허용하므로, 15% 느려지는 변경은 게이트에 걸리지 않고 통과한다
