# QA-A-195 (#216) — 캐시 적중이 하지 않는 검사가 판정을 바꾸는가 (관측만, 코드 변경 없음)

시작 HEAD `a2867119`. 질문(리더): QA-A-193 의 한계 "적중은 만료·SHA·세션 검사·품질 메타를 복원하지 않음" 에 실제로 판정을 바꾸는 입력이 있는가.
방법: DISABLED 프로브 한 개(`evidence/03_probe_source.cpp.txt`, 파일은 지움), 4×4 맵, 실행 로그 `evidence/02_probe_run.txt`.

## 결과: 세 가지 모두 적중과 미스가 다르다

| 입력 | 미스(평범한 로더, 캐시 비운 뒤) | 적중 (`*_cached`) |
|---|---|---|
| 캐시된 뒤 만료된 게인 파일 (`check_expiry` 도 만료 `is_expired=1`) | `-5` (CALIBRATION_EXPIRED) | `0` OK, 같은 캐시 포인터 |
| 캐시된 뒤 만료된 오프셋 파일 | `-5` | `0` OK |
| 캐시된 뒤 마지막 바이트를 바꾼 오프셋 파일 (SHA 불일치) | `-4` | `0` OK, 같은 포인터. `xpe_calib_cache_clear()` 뒤에는 `-4` |
| 게인 품질 메타 (`xpe_calib_get_quality_meta`) | 파일의 r²=0.900·차수 2 를 보고 | 적중 직전 저장소에 있던 다른 파일의 값(r²=0.500·차수 1)을 그대로 보고 — 복원 안 됨 |

대조(양성): 첫 미스에서 r²=0.900·차수 2 가 읽혔으므로 JSON 키가 파싱되는 입력이다. 평범한 로더의 `-5`·`-4` 와 `check_expiry` 의 `is_expired=1` 이 파일 상태를 독립적으로 확인한다.

## 해석 (관측이 말하는 것 / 말하지 않는 것)

- 적중은 **만료된 교정과 변조된 파일을 정상으로 올린다**. 미스였다면 거절됐을 입력이다. 캐시를 쓰는 호출자는 만료·무결성 거절을 캐시 비움 전까지 못 본다.
- 이것이 ⚠3(파일 변경은 감지하지 않는다)의 안전 쪽 귀결이다: "오래된 맵"이 아니라 "거절됐어야 할 맵"이 올라간다. QA-A-193 이전에는 적중이 저장소를 안 채웠으므로 이 경로가 저장소에 닿지 않았다 — 193 이 이 경로를 열었다.
- 품질 메타는 게인에서 틀린 값이 보고된다(저장소의 다른 교정의 것). 값 자체가 판정에 쓰이는 곳은 이 관측으로는 보지 않았다.
- 관측하지 않음: 다항식 파일, 결함 맵(만료·SHA 는 같은 구조로 추정이지만 안 쟀다), 세션 id 불일치가 판정을 바꾸는지(세션 id 는 193 에서 복원하므로 적중이 틀리게 만들지 않는다), 만료 직전 경계.

## 결정 재료 (리더 몫)

1. 적중에서 만료를 다시 검사하려면 엔트리에 만료 시각을 넣어야 한다(헤더 `expiry_epoch_ms`, 지금은 보관 안 함). 비용은 시각 비교 하나.
2. SHA 는 적중에서 다시 못 한다(파일을 읽지 않는 것이 캐시의 존재 이유). 선택지는 "캐시는 무결성을 보증하지 않는다"를 요구에 적는 것(헤더에는 이미 "not repeated on a hit"), 또는 적중에서 파일 크기·수정 시각을 비교하는 것.
3. 게인 품질 메타는 엔트리에 보관·복원 가능(JSON 을 엔트리에 보관하거나 파싱한 구조체를 보관).
