# QA-A-237b M2 — 출력이 바이트 단위로 같은 후보 셋을 하나씩 넣었다

카드: QA-A-237b · Refs #245 · 기준 커밋 `55d781da`(M1) · 최종 `5408b20c`. offset 정수화와 고스트 float16/bfloat16 은 카드대로 하지 않았다.
단위: MiB(2^20 B), 괄호 안은 십진 MB(1 MiB = 1.048576 MB). 200 MB = 190.7 MiB. 메모리는 모듈 몫(하네스 기준선 A 를 뺀 값), 3072² 고스트 포함, 출하 경로 `xpe_preprocess_pipeline_ex`.
시간은 이 기계의 이 세션 값이다. 전/후는 **번갈아**(쌍마다 순서를 뒤집어) 새 프로세스로 쟀다.

## 0. 결론 먼저

1. **세 후보 모두 출력이 바이트 단위로 같다.** 변경 전에 기록한 다이제스트 32개(DLL 구성 29 + 훅 구성의 gain 3)가 후보를 넣은 뒤에도 그대로 통과하고, 실영상 3개 티어(프레임 6장)와 합성 프레임의 출력 다이제스트가 전/후 모든 실행에서 같다(§3).
2. **출하 경로의 최대가 423.9 → 207.5 MiB(444.5 → 217.6 MB)로 내려갔다.** 200 MB 대비 222% → **109%** 이고, **200 MB 아래에는 들어오지 못했다.** 남은 격차는 **16.8 MiB(17.6 MB)** 다.
3. 시간은 늘지 않았다. 누적으로 프레임 시간 최솟값이 티어 1 에서 117.2 → 96.3 ms(비 0.822), 티어 3 에서 331.6 → 290.5 ms(비 0.876)다. 이 기계의 같은 빌드 대조(같은 빌드끼리)에서 최솟값 비가 1.001 이었으므로 이 차이는 잡음보다 크다.
4. 남은 격차를 **출력을 바꾸지 않고** 메우려면 단계 1~4 를 블록 단위로 합치는 구조 변경이 필요하고(§5), 그래도 여유는 1.2 MiB 에 그친다. offset 정수화(사용자 결정 필요)와 합치면 171.5 MiB(179.8 MB)다.

## 2. 각 후보가 지키는 것

### ① reciprocal 평면 제거 (`gain_correct.cpp`)
- 전체 맵을 **읽기 전용으로 먼저 검증**한 뒤 8192 화소 블록마다 `1.0f / gain` 을 작은 버퍼에 계산해 곧바로 적용한다. 값과 곱이 같으므로 출력이 같고, 거부된 맵이 `dst` 를 건드리지 않는 성질도 그대로다(시험: 다섯 가지 무효 값 모두 `XPE_ERR_CONFIG_INVALID` 에 버퍼 불변).
- 비용: 맵을 한 번 더 읽는 검증 순회. 측정에서 시간은 늘지 않았다.

### ② 단계 버퍼 수명과 제자리 (`pipeline.cpp`)
- 단계 1~3(uint16)은 다음 단계가 자기 복사본을 가진 뒤 해제, 단계 4(float)는 defect 가 끝난 뒤 해제한다.
- defect 와 ghost 는 **파이프라인이 직접 만든 float 버퍼일 때만** 제자리로 돌린다. 호출자 버퍼(float32 입력 + gain 우회 설정)에서는 예전처럼 복사본을 준다: 제자리로 돌다 실패하면 호출자 버퍼가 바뀌기 때문이다. 이 분기는 uint16 입력으로는 실행되지 않아서 float32 입력 시나리오를 따로 만들었다(§3).
- 제자리 defect 는 `QA-A-146` 이 보증한 호출 형태이고, 한 단계의 `memcpy`(36.0 MiB)가 사라진다. ghost 는 `stage7` 복사가 없어진다. 시간이 15~18% 줄어든 것은 이 두 복사가 없어진 결과로 읽히지만 단계별 시간은 재지 않았다.

### ③ 고스트 `next1`·`next2`·`backup` (`ghost_correct.cpp`)
이 세 평면은 `xpe_ghost_correct` 호출 안에서만 쓰였고, 목적은 하나다: **프레임이 도중에 실패하면 픽셀·이력·상태를 그대로 둔다**(QA-A-202c, QA-A-217, REQ-P1A-032). 그 보장을 다른 방식으로 지킨다.

- **실패할 수 없는 프레임은 제자리로.** 프레임의 최대 |값| M, 이력 상한(핸들이 `bound' = decay × bound + M` 재귀로 들고 있고 평면은 읽지 않는다), 계수에서 모든 중간값(보정값·새 이력·tier 3 의 3×3 합과 혼합)의 상한을 double 로 계산해, float 한계의 1/34(1e37) 이하이면 어떤 화소도 실패할 수 없다. 되돌릴 것이 없으므로 이력 평면에서 읽고 같은 자리에 쓴다.
- **증명되지 않는 프레임은 예전 알고리즘 그대로.** 그 호출 안에서만 평면 3장을 잡고, 실패하면 픽셀을 되돌리며 이력·상태는 그대로다. 실패 시 원상 보존은 예전과 코드가 같다.
- tier 3 의 3×3 평균은 "들어온 프레임" 을 읽어야 한다(QA-A-218b). 제자리 프레임에서는 아직 안 쓴 아래 행(`px`)과 저장해 둔 행 두 줄(핸들이 `W` float 두 줄을 가짐)에서 읽는다. 합산 순서는 같다.
- 시험으로만 보증하는 부분: 증명이 틀리면 제자리 길에서 실패 프레임이 이력을 깨뜨린다. 그래서 **차등 시험**을 넣었다(§3).

**이 설계의 대가**: ① 극단 프레임(값이 1e30 대)이 지나간 뒤 이력 상한이 커서, 한동안(느린 감쇠 성분 τ2 에서는 수십 프레임) 프레임이 느린 길을 타고 호출마다 평면 3장(108.0 MiB)을 잡는다. 그 호출의 최대는 계산상 153.3 + 36.0(`stage4`) + 108.0 = 297.3 MiB 로 전과 같은 수준이다(**계산, 미측정**). 정상 데이터에서는 일어나지 않는다. ② 프레임마다 최대값 훑기 한 번이 더해진다(측정된 시간 영향 없음).

## 5. 결론: 출하 경로 최대가 200 MB 아래인가 — **아니오**
