### 왜 이것이 없는 63건보다 위험한가

없는 ID 는 검색하면 나옵니다. **재사용된 번호는 나오지 않습니다** — 새 SPEC 에 그 번호가 존재하므로 "인용이 유효하다" 고 읽힙니다. 지금 이 25개 번호를 인용하는 코드는 **조용히 다른 요구를 가리키고 있습니다.**

**인용 건수**(`modules/` 의 `.cpp`/`.h`/`.hpp`, 실측):

| | 건수 |
|---|---|
| 세 자리 ID 인용 총계 | **345** |
| 재사용 25개 번호 | **277** |
| 새 SPEC 에 없는 16개 ID | **63** |
| 나머지(`066` 5건) | **5** |

277 + 63 + 5 = 345 로 맞습니다. **즉 인용 345건 중 340건이 재사용 번호이거나 사라진 번호입니다.**

> **QA-A-127 에서 "350건" 으로 보고했는데 345 가 맞습니다.** 그때 정규식이 `016a`·`020a` 같은 접미 붙은 형태를 세 자리 부분으로 중복 계수했습니다. 분류 결론은 바뀌지 않습니다.

| 분류 | 건수 | 확정 근거 |

**분류가 겹칩니다 — 한 옛 ID 가 "요구는 삭제, 번호는 재사용" 일 수 있습니다.** 겹치는 것은 **12개**(005, 012–015, 020–022, 030–033)입니다. 스크립트로 검산했습니다:

```
재사용 25  이동 13  삭제 18  미확정 15
삭제 ∩ 재사용 = [5,12,13,14,15,20,21,22,30,31,32,33] = 12
어느 분류에도 없는 옛 ID = [58,59,61,62,63,64,65,66,68,69,70,71] = 12
```

겹치지 않게 세면:

- **확정 = 25 + 13 + 18 − 12 = 44**
- **미확정 = 15(위 표) + 12(어느 분류에도 못 넣은 058·059·061–066·068–071) = 27**
- 44 + 27 = **71** ✓

> 이 문단을 두 번 틀렸습니다. 처음엔 "겹침 14 / 그 외 14", 고친 뒤엔 미분류 12 를 확정 쪽에 세어 "확정 56" 이라고 적었습니다. **확정은 44, 미확정은 27 입니다.** 손으로 센 값이 두 번 다 검산에서 어긋났고, 스크립트가 잡았습니다.
