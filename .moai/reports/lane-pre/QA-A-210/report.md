# QA-A-210 — 게인 생성기의 음수 R²: 원인 실측, 끝점 선형 대체의 품질 정책

조사 카드(수정 없음). 기준 커밋 `90c1b6b1`. 증거: `01_independent_recomputation.txt`(독립 재계산 출력 전문). 이슈 #233.

## 1. 결론 (먼저)

| # | 질문 | 답 |
|---|---|---|
| 1 | 음수 R² 의 원인은? | **끝점 선형 대체**다. 입력 1024 화소 중 517 개(50.5%)가 이 갈래로 갔고, 그 화소들의 모델이 최소제곱해가 아니라서 418 개 화소는 자기 평균보다도 못 맞는다(SS_res > SS_tot). **R² 공식도 수치 계산도 아니다.** Codex #45 의 설명이 실측과 일치한다. |
| 2 | 결함인가 정의 차이인가? | **R² 계산은 맞다.** 공식·산술 모두 독립 재계산으로 확인했다. 그러나 그 R² 가 평가하는 **모델 선택 정책에 결함 후보가 있다**: 끝점 선형 대체는 자기를 불러온 단조성 검사를 스스로 통과하지 못한다(아래 3.3). |
| 3 | 208c/208d 의 "음수 허용" 이 결함을 덮고 있나? | **덮지 않는다.** 음수 R² 는 결함이 숨는 곳이 아니라 **드러나는 곳**이다(`calibration_pass = 0` + 경고 알림이 같이 나간다). 음수를 거부했다면 제품이 쓴 파일을 제품이 못 읽었을 뿐이다(208c 에서 실측). 다만 허용 결정은 정책 문제를 고치지 않는다 — 정책은 별건이다. |
| 4 | 품질 판정이 R² 에 의존하나? | **의존한다.** `calibration_pass = (R² >= 0.999)`. 음수 R² 도 다른 낮은 R² 와 똑같이 `0`(실패)이고 `XPE_WARN_CALIB_POOR_FIT` 알림이 나간다(5절). |

## 2. 생성기의 적합과 R² (줄 인용, `xpe_calib_generate_gain.cpp`)

- **적합**(`fit_polynomial_ls`, 56-130): `y = c0 + c1·x + c2·x² …`, 정규방정식 `AᵀA·c = Aᵀy`, 절편 포함(행 `A[i][j] = x[i]^j`, `j = 0` 이 절편), 부분 피벗 가우스 소거. **절편 없는 적합이 아니다.**
- **정책**(`:510-550`): 화소마다 차수 `max_degree` 부터 1 까지 내려가며(`:514`) 최소제곱 적합 → `validate_monotonicity`(`:531`)가 통과하면 채택. 하나도 통과하지 못하면(`:545`) **"첫 점과 마지막 점을 잇는 직선"**: `c0 = y[0]`, `c1 = (y[last] - y[0]) / (dose[last] - dose[0])`.
- **단조성 검사**(`validate_monotonicity`, 142-174): 선량 구간을 100 점으로 표집해 `y < prev_y` 이면 실패(`:166`). 즉 **비감소(non-decreasing) 만 통과**다.
- **R²**(`:554-568`, `:604`): 화소마다 `y_mean` 과 `SS_tot += (y-y_mean)²`, `SS_res += (y-예측)²` 를 **전 화소·전 선량에 걸쳐 합산**(pooled)하고 `R² = 1 - SS_res/SS_tot`(`SS_tot == 0` 이면 1.0). 예측은 **실제로 선택된 모델**(대체된 직선 포함)의 값이다.
- 카드의 후보 표와 대조: 절편 없는 적합 — 아님(위). 적합과 평가 데이터가 다름 — 아님(같은 `y_vals`). 공식 차이 — 아님(`SS_tot` 은 화소별 평균 기준의 표준형, 합산만 다름). 화소별 R² 의 평균 — 아님(합산 후 한 번 나눔). 수치 오류 — 아님(아래 독립 재계산). **남는 것: 평가 대상 모델이 최소제곱해가 아니다**(Codex #45 의 설명).

## 3. 실측 (`01_independent_recomputation.txt`)

입력: `xpe_calib_fixture_gen --width 32 --height 32 --seed 7 --gain-poly`(`FixtureGenGainPolyTest` 가 쓰는 것과 같은 호출)의 4개 선량 단계(8000, 12000, 16000, 20000), 최대 차수 2. 선량별 게인 맵 4장과 생성된 `gain_poly.xcal` 을 읽어 표준 라이브러리만 쓰는 파이썬으로 다시 계산했다. 적합은 **유리수(`Fraction`) 정확 산술**의 최소제곱.

### 3.1 공식과 산술은 맞다

| 계산 | R² |
|---|---|
| 생성기가 파일에 쓴 값 | -0.076637433 |
| (A) 생성기가 **저장한 계수**를 정확 산술로 평가해 같은 공식에 넣음 | -0.076637434 (SS_res 2.629733e-03, SS_tot 2.442543e-03) |
| (C) 같은 정책(2차 → 1차 → 끝점, 비감소 검사)을 정확 산술의 최소제곱으로 돌림 | -0.076637433 |

(A)·(C) 가 생성기 값과 일치하고, (C) 는 **1024 화소 모두에서 생성기와 같은 갈래**를 고른다(2차 105, 1차 402, 끝점 517). 2차 채택 화소의 계수는 정확 최소제곱과 상대 차 중앙값 3.2e-8, 최대 5.7e-8(float32 저장 정밀도 수준)이라 **정규방정식의 조건수는 이 입력에서 문제가 아니다.**

### 3.2 최소제곱 그대로였다면

| 모델 | R² |
|---|---|
| 정확 최소제곱 2차, 단조성 검사 없음 | **+0.7639** |
| 정확 최소제곱 1차, 단조성 검사 없음 | **+0.4612** |

절편 포함 최소제곱을 자기 데이터로 평가하면 R² ≥ 0 이라는 카드의 전제가 맞다는 확인이기도 하다. 음수는 **최소제곱해가 아닌 모델을 고른 결과**다.

### 3.3 끝점 선형 대체가 스스로를 어긴다

끝점 갈래의 517 개 화소는 **전부** 1차 최소제곱 기울기가 음수다(데이터가 선량에 따라 내려간다) — 그래서 "비감소" 검사가 1차까지 탈락시킨 것이다. 그런데 대체로 쓰인 끝점 직선의 기울기는 **485 개가 음수**, 32 개만 0 이상이다. 즉 **이 대체 모델 485 개는 자기를 불러낸 단조성 검사(비감소)를 스스로 통과하지 못한다.** SRS-CALIB-FUNC-027 의 "계수는 유한하고 다항식은 `[D_min, D_max]` 에서 단조여야 한다"는 보장이 이 갈래에서는 성립하지 않는다.

### 3.4 입력의 성격 (판단에 필요한 사실)

선량별 게인 맵의 평균은 모두 1.000000(생성기가 단위 평균으로 정규화함)이고, 화소별 선량 간 변동(max-min)은 평균 1.8e-3, 최대 6.1e-3 이다. 이 픽스처의 4단계 맵은 **선량에 따른 곡선이 아니라 독립 잡음**이다. 그래서 절반 가까운 화소의 최소제곱 기울기가 우연히 음수이고, 합산 SS_tot 가 작아(2.4e-3) 어떤 모델도 R² 로는 나빠 보인다. 같은 경고 알림이 보고하는 잔차 백분율은 최대 0.371%, 평균 0.061% 로 작다.

## 4. 끝점 선형 대체는 품질 정책으로 맞는가

판단 근거 — **SRS-CALIB-FUNC-027**(`docs/calibration/SRS-CALIB-001_Software_Requirements_Specification.md:182`): "polynomial must be monotone in [D_min, D_max]. If non-monotone, reduce degree until monotonicity achieved (minimum degree 1 = linear)."

1. **SRS 에 끝점 직선이 없다.** 요구가 정한 저하 경로는 "차수를 줄여 **1차(선형)에서 멈춘다**". 1차는 최소제곱이고 R² ≥ 0 이다. 끝점 직선은 구현이 덧붙인 갈래다.
2. **SRS 는 방향을 정하지 않는다.** "monotone" 이다. 구현은 **비감소**만 받는다(`:166`). 감소하는 게인 곡선을 거부하고, 거부한 뒤에 감소하는 직선(485/517)을 대신 쓴다 — 방향 정책이 한쪽으로 쓰이면서 대체 모델은 다른 쪽이 되는 모순이다.
3. **결과가 R² 를 오염시킨다.** 같은 입력에서 "어느 방향이든 단조면 수용, 아니면 1차 최소제곱"이면 R² = +0.4648(2차 198·1차 826), "전 화소 1차 최소제곱"이면 +0.4612 — 음수는 이 정책에서만 나온다.

**판단: 결함 후보.** R² 의 정의("정합도")는 맞고, 모델 선택이 SRS 를 어긴다. 결함 여부를 확정하는 것은 요구 해석(방향)이라 이 카드의 몫이 아니다 — 리더가 정할 선택지:

| 선택지 | 효과 | 비용/주의 |
|---|---|---|
| A. SRS 문구 그대로: 방향 무관 단조 수용, 최종 대체는 **1차 최소제곱**(끝점 직선 폐기) | R² ≥ 0(생성기가 쓰는 한), 대체 모델도 단조 | 이 입력 기준 R² +0.46, 하향 기울기 화소가 그대로 보존됨. 게인이 선량에 따라 **감소**하는 것이 물리적으로 허용되는지 확인 필요 |
| B. 비감소가 물리 요구라면: 1차 기울기가 음수인 화소는 **대체 직선이 아니라 위반으로 취급**(상수 모델로 두고 결함/경고 계수) | "단조 증가" 보장 성립, 위반 화소 수가 보임 | R² 가 그 화소들에서 0(평균 예측)이 되고 경고가 늘 수 있음; 요구 문서에 방향을 명시해야 함 |
| C. 현 상태 유지 + 문서화 | 변경 없음 | SRS 단조 보장이 거짓인 갈래가 남음(3.3), 음수 R² 가 계속 나옴 |

(이 표는 권고가 아니라 선택지다. 코드는 건드리지 않았다.)

## 5. 품질 판정과 사용자에게 보이는 것

- `xpe_calib_record_quality_meta`(`xpe_calib_mode.cpp:297`): `passed = (r_squared >= XPE_CALIB_R_SQUARED_GATE)`, 게이트는 0.999. `calibration_pass` 는 그 결과. **음수 R² 도 낮은 R² 와 같이 실패(0)** — 부호에 따른 별도 처리는 없다.
- 실패 시 경고 알림(`XPE_ALERT_WARNING`): `XPE_WARN_CALIB_POOR_FIT: fit_r_squared=-0.076637 below 0.999 (max_residual=0.371%, mean_residual=0.061%); increase dose levels or check detector stability` (생성기 `:626` 의 서식).
- 파일의 설정 블록: `"fit_r_squared":-0.076637433,…,"calibration_pass":0`. 적재 후 `xpe_calib_get_quality_meta` 는 `r_squared = -0.0766`, `has_r_squared = 1`, `calibration_pass = 0`(208d 이후).
- 조언 자체(선량 단계를 늘리거나 검출기 안정성을 확인)는 이 입력에 어울리지 않는다: 문제는 선량 단계 수가 아니라 입력이 잡음이라는 것이고, 잔차(0.06%)는 작다. R² 는 "선량에 따른 게인 변화" 대비 적합도라서 **게인이 선량에 거의 안 변하는 데이터에서는 어떤 모델도 R² 로 나빠 보인다**(SRS 의 0.999 게이트를 그대로 구현한 결과이며 구현 오류는 아니다).

## 6. 미검증 (Gaps)

- 입력은 **합성 픽스처**(4단계 독립 잡음)뿐이다. 실제 교정 데이터(CalData_6, cyan_test)로는 돌리지 않았다 — 실제 곡선에서 끝점 갈래가 얼마나 자주 가는지, 게인이 선량에 따라 감소하는 검출기가 있는지는 모른다. 방향 정책(4절 2항)의 물리적 타당성은 이 데이터 없이 판단할 수 없다.
- 5개 이상 선량 단계, 차수 3 이상은 재계산하지 않았다(`FixtureGenGainPolyTest` 의 4단계·차수 2 한 입력).
- 다항식 계수의 float32 저장이 실제 보정(`xpe_gain_correct`) 오차에 주는 영향은 이 조사 범위 밖이다(R² 계산 쪽은 저장 계수로 다시 평가해도 같음 — 3.1 (A)).
- 생성기 입력으로 R² 가 정확히 -1.0 이 되는 경우(208d 의 경계)를 구성하지 않았다. 이 입력에서 SS_res/SS_tot = 1.0766 이고 -1.0 은 2.0 이 필요하다.
