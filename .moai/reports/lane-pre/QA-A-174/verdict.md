# QA-A-174 (`#230`) — 출하 ÷ 하한, 같은 실행 안에서: 1.17 ~ 1.19

**판정 문장** (카드 §3 형식):

> 같은 세션 `출하 82.6 ms ÷ 하한 69.6 ms = 1.19` (하한 구성: 독립 12.3 ms + in-situ 57.3 ms + 계산 0 ms).
> `R ≤ 1.3` 이므로 **충족**. in-situ 항 제외 비: **독립 하한 없음** (선택 항에 대해서만. 선택을 분자·분모 양쪽에서 뺀 비 `R' = 2.06` 은 아래 §3 에 따로 적습니다).

위 문장의 수는 **첫 번째 실행**입니다. 세 번 실행했고 세 번 모두 같은 모양이었습니다 (§2). 판정은 리더가 하고, 이 보고서는 수와 그 수가 **보지 못하는 것**을 적습니다.

**조건**: 3072×3072 FLOAT32, AVX2, 단일 스레드, `i7-12700`, RelWithDebInfo. 한 실행(프로세스) 안에서 열한 항을 라운드마다 돌려 20라운드, 워밍업 1회 폐기, 짝수 라운드는 정방향·홀수 라운드는 역방향 순서(어느 쪽도 첫 자리·끝 자리를 독점하지 않게). 각 항의 **최솟값**을 쓰고 중앙값·최댓값을 함께 적었습니다. 세션 사이의 절대 ms 는 비교하지 않았습니다.

## 1. 하한의 항별 출처 (카드 §1)

`QA-A-166/167` 의 하한 `76 ms` = 검출 망 `7.71` + 타일 차분 `5.28` + 선택 `63` 입니다 (메모리 `2.46` 은 `max` 안에 들어가 더해지지 않습니다). 같은 정의로 이 세션에서 다시 쟀습니다 (첫 번째 실행, ms):

| 항 | 값(최솟값) | 출처 | 어떻게 얻었나 |
|---|---|---|---|
| 검출 망 | **7.29** | 독립 (커널 측정) × 계산 (개수) | `MedianOfEight8` 을 레지스터만 쓰는 루프에서 재어 ns/망을 얻고, 화소당 두 번(`2 × N`)을 곱함. 개수는 계산, 커널은 측정 |
| 타일 차분 | **5.03** | 독립 | 차분 생성 루프를 따로 복사해 직접 측정 |
| 선택 | **57.25** | **in-situ** | 출하 `BuildFrameConfig` 단계 `62.28` − 차분 `5.03`. 출하 코드 자신의 실측입니다 |
| 메모리 | 2.34 (합에 안 들어감) | 계산 | 최소 트래픽 85.25 MB ÷ `memcpy` 대역폭 36.4 GB/s |
| **하한 (옛 정의)** | **69.56** | | `7.29 + 5.03 + 57.25` |

**구조상 문제는 그대로입니다.** 하한의 선택 항은 `출하 단계 − 차분` 이므로 분모가 출하 값을 품고 있고, `출하 ÷ 하한` 에서 선택 항은 구조적으로 `1.0` 입니다. 그래서 아래 두 가지 비를 적습니다.

### 비 1 — 기존 정의 그대로 (이전 수와 비교 가능)

`R1 = 출하 ÷ (검출 망 + 차분 + in-situ 선택)` = `82.60 ÷ 69.56` = **1.187**

### 비 2 — in-situ 항을 독립 측정으로 바꿀 수 있는가

**선택 항은 바꿀 수 없습니다 — "독립 하한 없음".** 근거를 셋 적습니다.

| 선택을 하는 방법 (같은 세션, 같은 라운드, 복사 비용 `1.13` 제외) | 최솟값 | 출하 대비 |
|---|---|---|
| in-situ (`BuildFrameConfig` − 차분) | 57.25 | 1.00 |
| **출하 알고리즘 `SelectKthSmallest` 를 격리 루프에서** | **57.23** | **1.00** |
| 히스토그램 재사용판 (고정비 제거) | 112.46 | 1.96 |
| `std::nth_element` | 239.28 | 4.18 |

1. 격리 루프에서 잰 출하 알고리즘은 in-situ 와 **0.03% 차이**(첫 실행) ~ 1.7% 차이(셋째 실행)입니다. 서로 다른 측정으로 같은 항을 얻었다는 **재현**이지, 하한이 아닙니다 — 둘 다 "출하 알고리즘이 필요한 만큼"을 잽니다.
2. 같은 세션에서 잰 정확 선택 알고리즘 둘은 출하보다 **2배·4배 느립니다.** 출하보다 빠른 정확 선택은 이 저장소 안에서 측정된 적이 없습니다.
3. 알고리즘에 독립인 하한(예: 어떤 정확 선택이든 최소로 치러야 하는 값)을 세울 근거를 이 카드는 만들지 못했습니다. 물리적으로는 프레임을 한 번 읽는 트래픽(`2.3 ms`)이 하한이지만, 알려진 어떤 알고리즘도 거기에 닿지 않으므로 **하한으로 쓰면 지어낸 수가 됩니다.** 쓰지 않았습니다.

격리 루프판으로 분모를 바꾼 비를 참고로 적습니다 (선택 항이 출하 알고리즘이라는 점은 같습니다): `R2 = 82.60 ÷ (7.29 + 5.03 + 57.23)` = **1.188**.

## 2. 세 번의 실행 (각 실행이 독립된 프로세스)

한 실행 안의 비만 의미가 있으므로 실행마다 따로 계산했습니다. 증거: `evidence/05_launch{1,2,3}.txt`.

| | 실행 1 | 실행 2 | 실행 3 |
|---|---|---|---|
| 출하 전체 (최솟값 / 중앙 / 최대) | 82.60 / 86.84 / 91.20 | 93.64 / 96.09 / 105.87 | 84.47 / 85.71 / 88.95 |
| 검출 망 + 차분 | 7.29 + 5.03 | 7.37 + 5.13 | 7.55 + 5.28 |
| in-situ 선택 | 57.25 | 66.78 | 58.27 |
| 격리 루프 선택 (출하 알고리즘) | 57.23 | 67.86 | 59.26 |
| 하한 (옛 정의) | 69.56 | 79.28 | 71.10 |
| **R1** | **1.187** | **1.181** | **1.188** |
| R2 (격리 루프 선택) | 1.188 | 1.165 | 1.172 |
| R' (선택을 양쪽에서 뺌) | 2.058 | 2.149 | 2.042 |
| 라운드별 R1 (최소 / 중앙 / 최대) | 1.076 / 1.168 / 1.227 | 1.070 / 1.159 / 1.323 | 0.908 / 1.175 / 1.224 |

- **비는 실행마다 거의 같고 절대 ms 는 흔들립니다.** 실행 2 는 모든 항이 약 13% 느립니다(출하 `93.6`, 하한 `79.3`). 비는 `1.181` 로 그대로입니다. 이 기계의 이중 모드(`QA-A-167`)가 분자·분모에 같이 걸린다는 뜻이고, 이 카드가 같은 실행 안에서 재야 하는 이유입니다.
- 실행 3 의 라운드별 R1 최솟값 `0.908` 은 **하한이 출하보다 크다는 뜻이 아니라 짝짓기의 잡음**입니다. 같은 라운드 안이라도 항들이 순서대로 돌기 때문에 빠른 구간에서 잰 출하와 느린 구간에서 잰 하한 항이 만날 수 있습니다. 그래서 판정에는 항별 최솟값의 비를 쓰고, 라운드별 비는 분포를 보이기 위해 적었습니다.
- 출하 전체와 단계 합의 차는 `1.4 / 2.6 / 1.3 ms` 입니다. 출하 진입점에 단계 밖의 몫이 약간 있다는 뜻이고, 이번에도 `QA-A-169` 처럼 크게 설명 못 한 몫은 없습니다.

## 3. 이 수가 무엇을 못 보는가

### (a) `R1 ≤ 1.3` 은 "선택이 지금보다 빠르게 안 된다" 는 가정 위에 서 있습니다

분모의 선택 항이 출하 자신의 값이므로, **더 빠른 정확 선택이 존재하면 `R1` 은 낮게 읽힌 것**입니다. 가정이 깨지는 지점을 계산으로 적습니다 (측정이 아닙니다):

| 가상의 선택 하한 | 실행 1 | 실행 2 | 실행 3 |
|---|---|---|---|
| 출하 선택의 1.00배 (오늘) | 1.187 | 1.181 | 1.188 |
| 0.75배 | 1.495 | 1.496 | 1.494 |
| 0.50배 | 2.017 | 2.041 | 2.013 |
| 0.25배 | 3.101 | 3.207 | 3.083 |
| `R = 1.3` 이 되는 선택 하한 (ms) | 51.2 | 59.5 | 52.1 |
| 그 값 ÷ 출하 선택 | 0.895 | 0.891 | 0.895 |

**출하보다 약 11% 더 빠른 정확 선택이 하나라도 있으면 같은 세션의 `출하 ÷ 하한` 은 `1.3` 을 넘습니다.** 이 저장소에서 측정된 대안은 출하보다 느렸습니다(§1). 그러나 "측정된 것이 없다"는 "없다"의 증명이 아닙니다. `QA-A-172` 가 이미 같은 말을 적었습니다 (*"다른 정확 선택 알고리즘은 이 카드에서 재지 않았습니다"*).

### (b) 선택을 양쪽에서 빼면 격차의 위치가 보입니다

`R' = (출하 − in-situ 선택) ÷ (검출 망 + 차분)` = `(82.60 − 57.25) ÷ (7.29 + 5.03)` = **2.06** (세 실행 2.04 ~ 2.15).

선택 밖의 출하 시간이 같은 범위 하한의 약 2배라는 뜻입니다. 출하 − 하한 격차(`13.0 / 14.4 / 13.4 ms`)의 구성:

| | 실행 1 | 실행 2 | 실행 3 |
|---|---|---|---|
| 행 순회 − 검출 망 (`18.55 − 7.29` …) | 11.26 | 11.37 | 11.62 |
| `memset` | 0.38 | 0.40 | 0.45 |
| 단계 합 밖의 몫 | 1.40 | 2.59 | 1.30 |

격차의 약 80~87% 는 행 순회에서 검출 망을 뺀 몫(적재·편차·σ·비교·저장)입니다. 이 비는 **판정 기준이 아닙니다.** 선택을 빼면 분모가 `12.3 ms` 로 작아져 비가 부풀기 때문에, 격차가 어디 있는지 보는 용도로만 적었습니다.

### (c) 그 밖의 한계

- **검출 망 항은 레지스터 루프의 커널 값**입니다. 메모리·캐시 효과가 없고, 개수(`2 × N`)는 계산입니다.
- **격리 선택 루프는 한 내부 타일의 실제 차분을 576개 타일에 복사해** 돌립니다(`QA-A-167` 방식). 입력이 캐시에 더운 상태라는 점에서 실제 경로(타일마다 다른 데이터)와 다릅니다. in-situ 와의 일치(0.03% ~ 1.7%)가 이 차이가 작다는 근거이지만, 한 프레임·한 타일 기준입니다.
- **합성 균일 잡음 프레임**(σ=10)입니다. 구조가 있는 영상에서의 비는 재지 않았습니다 (`QA-A-173` 이 실영상 7장에서 지도 동일성만 확인).
- **최솟값은 항별로 서로 다른 라운드에서 나올 수 있습니다.** 세 실행에서 비가 같았으므로 영향은 작아 보이지만, 라운드별 비의 분포는 위 표대로 넓습니다(`0.91 ~ 1.32`).
- **이중 모드의 원인은 이번에도 가리지 않았습니다.** 비가 모드에 둔감하다는 것만 관측했습니다.
- **배경 부하를 만들지 않았지만 측정하지도 못했습니다.** `wmic cpu` 가 이 셸에서 값을 돌려주지 않았고, 다른 레인 세션이 동시에 돌고 있었는지 확인하지 못했습니다. 세 실행의 비가 일정한 것이 간접 근거일 뿐입니다.
- **옛 수와의 비교**: 이전 `QA-A-173` 의 `95.5 ÷ 76 = 1.26` 은 서로 다른 세션 값의 비였고, 이번 같은 세션 비는 `1.17 ~ 1.19` 입니다. 비끼리의 비교이고 절대 ms 는 비교하지 않습니다. 옛 비가 낮은 쪽을 가리켰다는 것만 말할 수 있고, 어느 세션의 어느 모드였는지는 모릅니다.
