# QA-A-164 (`#143`) — **`6d` 착지.** 착지 조건이 닫혔고, 시간 근거는 고쳐 적습니다

착지 조건(SIMD)은 닫혔습니다. 다만 **`6d` 를 고른 근거 중 시간(1.41배)이 출하 경로에서 1.88배**였고, 그 차이의 출처를 찾아 일부를 걷었습니다.

---

## 착지 조건 — **SIMD 경로에서 같은 수입니다**

### (1) 등가성 — 네 프레임 전부 화소 단위 일치

```
[a164] EQUIVALENCE uniform    shipped vs probe-6d differing = 0 / 1048576
[a164] EQUIVALENCE scatter    shipped vs probe-6d differing = 0 / 1048576
[a164] EQUIVALENCE edge       shipped vs probe-6d differing = 0 / 1048576
[a164] EQUIVALENCE lines(p13) shipped vs probe-6d differing = 0 / 1048576
```

AVX2 런은 **여덟 화소가 한 타일 안에 있을 때만** 벡터로 가고, 타일 경계를 걸치면 스칼라로 떨어집니다 — 참조 σ 가 브로드캐스트라 여덟 개가 서로 다른 값을 가질 수 없기 때문입니다. 타일 128·런 8 이면 **16런 중 1런**이 그렇습니다.

### (2) 요구 — 네 프레임 전부 충족 (출하 진입점, 5시드 pooled)

| 프레임 | FP 합계 | pooled FPR | 요구 | TPR@10σ |
|---|---|---|---|---|
| uniform | 41 | 7.8201e-06 | ✅ | **1.0000** |
| scatter | 41 | 7.8201e-06 | ✅ | **1.0000** |
| edge | 41 | 7.8201e-06 | ✅ | **1.0000** |
| lines(p13) | 12 | 2.2888e-06 | ✅ | 0.9865 |

### (3) AVX2 는 **살아 있습니다**

출하 **17.0 ms** 대 프로브 스칼라 **65.9 ms** — **3.9배**. 타일 테이블이 벡터 경로를 죽이지 않았습니다.

---

## 시간 — **근거가 1.41배였는데 실측 1.88배입니다**

`6d` 를 고른 근거 하나가 *"시간 1.41배"* 였습니다. 그 값은 프로브의 **스칼라 루프끼리** 비교한 것이고, 출하 경로에서는 다릅니다.

### 왜 다른가 — 비용을 분해했습니다 (3072², 개선 전)

| 구간 | 시간 | 비중 |
|---|---|---|
| `ComputeGlobalSigma` | 55 ms | 30% |
| `ComputeTileSigmas` | 72 ms | **39%** |
| 검출 행 루프 (AVX2) | 55 ms | 30% |

**σ 추정 둘이 127 ms 로 전체의 70%** 였습니다. 스칼라 프로브에서는 화소 루프가 60 ms 라 타일 비용이 묻혔지만, 출하 경로는 화소 루프가 AVX2 로 빨라서 타일 비용이 그대로 드러납니다.

### 걷어낸 것 — **전역 σ 는 읽는 곳이 없었습니다**

`ResolveSigma` 는 `blendWeight > 0` 이면 floor 가지를 타지 않습니다. 그런데 출하 경로는 **`globalSigmaFloor` 를 위해 프레임 전체를 한 번 더 돌고** 있었습니다 — 쓰지 않는 값에 55 ms.

없앴습니다. 잴 수 없는 타일(1화소 폭)의 대체값은 **측정된 타일들의 중앙값**으로 바꿔, 프레임 전체 패스에 남은 독자가 없게 했습니다.

| | 3072² | 목표 `60 ms` 대비 | 착지 전(69.7) 대비 |
|---|---|---|---|
| 개선 전 | 187 ms | 3.12배 | 2.68배 |
| **개선 후** | **131 ms** | **2.18배** | **1.88배** |

**결과는 바뀌지 않았습니다** — 등가성 0/1048576, FPR·TPR 표 전부 동일. floor 가 읽히지 않았다는 것의 확인이기도 합니다.

> **이 기계가 `spec.md:271` 의 "개발 기계" 인지 확인하지 않았습니다.** `spec.md:5` 가 경고하는 함정이고 기존 게이트가 기계-상대 비율로 바뀐 이유입니다. **비율(1.88배)은 유효하고 절대값은 이 기계 것입니다.** 카드 §5·§7 대로 시간 예산은 리더가 별건으로 봅니다.

`blendWeight = 0` 이면 **`#143` 이전 규칙 그대로**입니다 — 직접 호출자의 동작이 바뀌지 않습니다.

하나만으로는 요구에 닿지 못한다는 주장이 양방향으로 확인됐습니다.

## `KnownDivergence_` — 셋을 고치고 하나를 새로 박았습니다

개선이 시험을 붉게 만들었고, **그것이 그 시험들의 일이었습니다.**

### `FprOnCleanFramesExceedsTheRequirement` → **`FprOnCleanFramesMeetsTheRequirement`**

```
4.730e-4 (pre-QA-A-42) → 1.718e-2 (QA-A-42) → 1.020e-4 (QA-A-43) → 4.768e-6 (QA-A-164)
```

**단언을 지우지 않고 뒤집었습니다** — 실패를 고정하던 시험이 실패가 멈춘 것을 알아차리는 물건이고, 같은 시험이 이제 통과를 고정해 회귀가 한 자리에서 보입니다.

### `TprStaysBelowTheFloorThroughTenSigma` → **`TprReachesTheFloorAtTenSigma`**

```
10σ: 0.998959 → 0.986472 (QA-A-43 floor) → 1.000000 (961/961)
 8σ: 0.955255 → 0.927159 → 0.997919
 6σ: 0.711759 → 0.753382 → 0.810614
```

floor 는 오검 168배 감소를 **검출률 9% 로 샀습니다**(`:211`). blend 는 그 값을 다른 방식으로 — 추정치의 **산포를 줄여서** — 사므로, 팔았던 검출률이 돌아옵니다.

### `TprAtFiveSigmaIsBelowTheRequirement` — **이름 유지, 사유 갱신**

요구가 10σ 로 개정됐으므로 이제 **요구 위반이 아니라 경계 측정**입니다. `0.553590 → 0.507804` 로 `ORACLE` 의 0.5088 **쪽으로** 움직였습니다 — 문턱에 붙박인 값에 대해 더 나은 σ 추정이 움직여야 할 방향입니다.

### 새로 박은 것 — `KnownDivergence_StripedFrameMissesTheTprFloor`

```
[rates] striped(p13), 10 sigma      injected=961 TP=948  TPR=0.986472
```

**요구 `0.999` 미달이 남습니다.** 사유를 시험 안에 적었습니다 — `ORACLE` 조차 이 프레임의 FPR 이 `2.92e-05` 로 요구를 넘으므로 **σ 추정 문제가 아니고**, 가설은 **지역 중앙값이 줄무늬 경계에 끌려간다**는 것이며 **미검증**입니다. 그 방향의 수정은 창 확대이고 시간이 10배라 카드 §5 대로 **쫓지 않았습니다**.

줄무늬 주기를 **13** 으로 쓴 이유도 적었습니다 — 32화소 격자와 주기 8 이 공명해 961개가 전부 같은 위상에 앉고, 같은 코드가 `0.2549` 대 `0.8887` 로 갈립니다.

## 깨진 기존 시험 넷 — **무엇을 단언하고 있었나**

`Avx2ParityTest.ShippedEntryPointAgreesWithTheScalarRule` (7/49152 불일치)과 `BufferReuseParityTest` 3건이 깨졌습니다.

**둘 다 출하의 config 구성을 손으로 복제하고 있었습니다.** 규칙이 바뀌자 출하 쪽만 움직이고 복제는 그대로여서, **경로 불일치가 아니라 낡은 사본**을 보고한 것입니다.

`QA-A-62` 가 이미 기록한 실패입니다 — *"a change landed in one while a tool measured the other"*. 그래서 복제를 **갱신하지 않고 없앴습니다**: `BuildFrameConfig` 를 만들어 출하와 두 시험이 **같은 함수**를 부릅니다. 단언 자체(경로 간 동등성)는 그대로이고 오히려 강해집니다.

AVX2 시험에서는 타일 테이블 수명 때문에 `Resolved` 구조체로 감쌌습니다 — config 가 테이블을 가리키므로 config 만 반환하면 dangling 입니다.

## 미검증 / 잔여 위험

- **`6d` 를 고른 시간 근거가 1.41배에서 1.88배로 바뀌었습니다.** 개선 후 값이고, `6a`(tile 64)를 같은 조건에서 다시 재지 않았습니다 — **두 후보의 순서가 출하 경로에서도 같은지 확인하지 않았습니다.**
- **이 기계가 spec 의 개발 기계인지 확인하지 않았습니다.** 절대값은 이 기계 것입니다.
- **타일 경계 런의 스칼라 강등 비용을 따로 재지 않았습니다.** 16런 중 1런이라는 것은 산술이고, 그것이 3.9배 안에서 얼마인지는 분해하지 않았습니다.

- **5시드**입니다. `6d` 는 예산의 78% 로 여유가 있지만 무한하지 않습니다.
- `ComputeTileSigmas` 는 타일마다 `diffs` 를 `push_back` 으로 채웁니다 — `QA-A-59` 가 `ComputeGlobalSigma` 에서 지적해 고친 바로 그 형태입니다. **남은 개선 여지이고 이 카드에서 손대지 않았습니다.**
