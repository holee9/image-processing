# QA-A-217 — 고스트 보정: 비유한 입력 입구 거부 + 이력 오버플로 + 실패 시 출력 복원 (Refs #233)

기준: dev/preprocess `e5be9c2d`(QA-A-216) 위의 작업 트리. 코드: `ghost_correct.cpp`, `xpe_preprocess_internal.h`(`backup` 평면), `preprocess_api.h`(문서), `CMakeLists.txt`, 시험 `test_ghost_input_finite.cpp`(7건 신규) + 기존 시험 1건 갱신. 푸시하지 않음. 215(76085cd7) 위에 쌓였고 커밋은 분리.

## 결론

1. **입구 거부**: NaN·±무한대가 든 프레임은 `XPE_ERR_INVALID_INPUT`, 쓰기 전 거부, 버퍼·핸들 불변, 알림 `XPE_WARN_GHOST_INPUT_NOT_FINITE`. (3 티어 × 첫 프레임/이력 있음 × 5종 = 30 경우 시험.)
2. **이력 오버플로**: 유한 입력에서 새 이력(`next1`/`next2`)이 비유한이 되면 `XPE_ERR_PROCESSING_FAILED`, **이력 미커밋**, 출력 불변. 다음 프레임은 reset 없이 성공하고 거부 없던 대조 핸들과 비트 동일.
3. **REQ-P1A-032 — 고스트가 실패 코드를 돌려주는 모든 경로**: 입구 거부(쓰기 전) 외에 남는 실패 경로는 전부 루프 안(보정값 비유한 / 새 이력 비유한)이고, 그 판정은 화소를 쓰는 도중에 나온다. 그래서 **프레임 입력을 `backup` 평면에 보관해 두었다가 실패하면 되돌린다**(쓰기 전 판정이 아니라 쓴 뒤 복원). 기존 시험이 쓰던 "티어 3 + nlcscBeta 1e37, 한 화소만 곱이 넘침" 경로도 이제 출력 바이트 불변(`AFrameThatFailsHalfWayThroughPutsItsPixelsBack`).
4. **비용**: 복원을 위한 백업이 있어 3072² 에서 프레임당 약 **+13~15 ms**, 핸들 메모리 +37.7 MB(아래).
5. **티어 3 윗줄 읽기 측정**: 맞다 — 코드는 이미 보정된 윗줄 화소를 읽고, 원본 이웃 평균과 결과가 **실제로 다르다**(아래). 고치지 않음.

## 변경 (`ghost_correct.cpp`)

- 입구(핸들·크기·형식 검사 뒤, 시각 계산 앞): `xpe_find_nonfinite` 한 번 훑기 → 알림 + `INVALID_INPUT`.
- 세 티어의 루프: `!isfinite(corrected)` 에 `!isfinite(n1[i])`, `!isfinite(n2[i])` 추가 → `PROCESSING_FAILED`.
- 티어 호출 전 `memcpy(backup ← px)`, 실패하면 `memcpy(px ← backup)`.
- `GhostCorrectorHandle::backup`: 핸들과 함께 한 번 할당(create 의 `try` 안 — 실패는 기존대로 `OUT_OF_MEMORY`).

알림 전체 문구(레인 간 계약, `XPE_ALERT_ERROR`):
```
XPE_WARN_GHOST_INPUT_NOT_FINITE: <N> pixel(s) of the input frame are NaN or infinite (first: index <I>, x=<X>, y=<Y>); the frame was not corrected; the buffer and the handle's history were not changed
```
(오버플로 실패에는 알림을 추가하지 않았다 — 요청에 없었고 이전에도 없었다.)

## 헤더 문서 (계약 변경)

`xpe_ghost_correct`: 이전 문구 *"corrected before the failure are not restored; a caller that needs the original keeps its own copy"* 는 **이제 거짓**이라 바꿨다 — 실패한 프레임은 `img` 도 그대로 둔다. `INVALID_INPUT` 에 비유한 프레임, `PROCESSING_FAILED` 에 오버플로를 명시. `xpe_ghost_create`: "이력 두 벌, 네 평면, 약 151 MB" → "다섯 평면, 약 **189 MB**".

## 기존 시험 갱신 (의도된 계약 변경)

`test_ghost_tiers.cpp` `EachTierRejectsNonFiniteInput`: `PROCESSING_FAILED` → `INVALID_INPUT` 으로, 그리고 "나쁜 화소 앞 화소가 안 건드려짐" 단언 추가, 알림 정리. 그 외 고스트 시험(실패 프레임·스레드·OOM·위생) 무변경 통과.

## 티어 3 윗줄 읽기 측정 (고치지 않음, `evidence/60_tier3_aside.txt`)

- 위치: `ghost_correct.cpp` `ghost_tier3`, 3×3 이웃 평균(`localMean`)이 `px[ni]` 를 읽는데, 같은 루프가 `px[i]` 를 제자리로 덮어쓰므로 `ni < i`(윗줄·왼쪽 화소)는 **이미 보정되고 0 으로 클램프된 값**이다.
- 측정(16×16, 프레임 2개, 기본 파라미터, float32 참조 구현): 코드가 하는 대로(보정된 이웃을 읽는) 참조와 **0 화소 차이**(프레임 1·2 모두), **원본 이웃을 읽는** 참조와는 프레임 2 에서 **113 화소가 다르고 최대 차이 2837**(내부 화소 196개 중). 즉 읽기 때문에 결과가 실제로 달라지고, 이 읽기는 순서 의존(왼쪽→오른쪽·위→아래)이다.
- 설계 의도가 어느 쪽인지는 확인하지 않았다(`tier3` 설명은 "blend with local neighborhood mean (3x3)" 뿐). 의도가 원본이면 결함(+ 출력이 "원본 복사본 필요"로 바뀌어 비트 동일이 깨지므로 임상 영향 평가 필요), 의도가 아니면 문서화 대상. **리더가 별도 카드로 결정**.
