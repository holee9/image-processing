# QA-A-197 (#216) — 다른 종류의 캐시 로더로 부른 적중도 미스와 같은 판정을 낸다 (TDD)

시작 HEAD `e9e2c0fa` (QA-A-196). 출처: 리더 메시지(Codex #18, HIGH): 캐시 키가 경로 문자열뿐이고 `get_copy<float>` 는 바이트 수만 보므로, `offset_cached(path)` 로 캐시한 뒤 같은 경로로 `gain_cached` 를 부르면 `OK` 와 함께 오프셋 화소가 게인 저장소에 들어간다. 일반 게인 로더는 그 XCal 타입을 거부하고, 오프셋 값이 [0.1, 10.0] 밖이면 게인 범위 검사도 우회한다.

## 교차 로더 시험의 구성

6조합(owner ∈ {offset, gain, defect}, other ≠ owner) 각각에서 같은 경로로: owner 로더로 캐시 → 대조(other 의 **평범한 로더**가 그 파일을 거절하는지, 그 코드가 `OK` 가 아닌지) → 저장소에 세 종류의 Q 맵을 올림 → other 의 캐시 로더 호출이 평범한 로더의 코드와 같은지 → 세 보정이 Q 맵의 결과인지(저장소 불변) → owner 로더가 다시 **같은 포인터**를 받는지(거절이 엔트리를 지우지 않음). 파일 값은 오프셋 100·게인 2: 100 은 게인 범위 밖이라 범위 검사 우회도 눈에 보인다.

## 같은 원칙을 다른 입력 축에서 훑은 표

## Gaps / Residual-risk

- 표의 5(압축 파일)·9(다항식 필드 지우기)·12(타임스탬프·세션 id)는 시험이 없거나 판별하지 못한다. 12 는 읽는 공개 API 가 없다.
- 7 의 `get_copy` 방어 분기(엔트리 크기 불일치)는 이제 종류 검사 뒤라 도달 경로가 없고, 시험으로 만들지 못했다.
- 같은 크기·같은 수정 시각의 변경은 여전히 감지하지 못한다 (QA-A-196 에서 결정 대기).
- 상대 경로를 쓰고 작업 디렉터리가 바뀌는 경우: 경로 문자열 키는 같고 가리키는 파일이 다르다. 크기·수정 시각이 우연히 같지 않으면 잡히지만 같으면 못 잡는다 — 위 한계와 같은 종류이며 시험하지 않았다.
- 종류 불일치 호출은 평범한 로더로 파일 전체를 읽고 SHA 를 계산한 뒤 거절하므로 오류 경로 비용이 미스와 같다. 측정하지 않았다.
- Codex #18 의 나머지 3건(만료·품질 메타·다항식)은 QA-A-196 에서 다뤘고 재감사(#19)에서 확인된다.
