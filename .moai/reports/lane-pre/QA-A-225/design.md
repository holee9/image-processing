## 0. 먼저 읽을 것 — 결론과 결정 항목

이 일은 "두 지표를 계산하는 함수 하나"가 아니었다. 조사해 보니 **지표를 만드는 것보다 그 지표가 속지 않게 하는 것이 일의 대부분**이다. 핵심 다섯 가지:

1. **E2E 프로토콜의 정의만으로는 속는다 — 실측.** `GhostRemovalPct`(빈 프레임 평균 기준)는 모듈의 기본 설정이 출력을 **전부 0 으로 만들어도 100%** 를 준다. 같은 설정을 클램프가 가리지 않는 측정(0 이 아닌 수준으로 떨어지는 계단)으로 보면 76.5%·44.3% 다(§2.2). 신호 보존 지표와 짝을 지어야 지표가 성립한다.
2. **자기 비교는 실제로 100% 를 준다 — 실측.** 모듈 자신의 재귀로 만든 지연에 같은 설정을 쓰면 100.00%(§2.1). 독립 생성기가 필수이고, 문헌(Starman 2012)의 모델과 신호 의존 모델 하나를 제안한다.
3. **정의의 빈칸이 일곱 개**이고 세 문서가 서로 다른 지표를 같은 이름 근처로 쓴다. 문서 숫자 일부는 출처가 잘못 읽혔다(§1).
4. **판정 위치는 "시험 쪽"을 권고한다**(§3). FUNC-019 선례와 같고 ABI 변경이 없다. 다만 FUNC-020 이 말하는 `tier`·`history length`·`bypass reason` 은 **모듈이 내보내야 하는 값**인데 지금 어디에도 없다.
5. **#238 은 구조로 답이 어느 정도 나와 있다 — 실측.** 티어 3 의 혼합은 균일 영역에서 보정을 0.7배로 줄여, 티어 1 이 정확히 되돌리는 지연에서도 티어 3 은 **72~84%** 에 머문다. 90% 를 요구하는 한 이 혼합은 구조적으로 도달 불가다(§4).

### 1.2 어긋남

- **같은 이름 근처의 서로 다른 지표 셋.** ① 시간 지표: 노출 뒤 빈 프레임의 평균 잔류(E2E·SRS-CALIB). ② 공간 지표: `GCR` = 블록 평균의 변동계수(옛 ghost SRS). ③ 이름만 "Ghost Coefficient Ratio" 인데 값은 아래처럼 Starman 의 잔류 지연 % 인 것(TDS-GHOST).
- **Starman 숫자의 출처가 잘못 읽혔다.** 논문 PMC3465354 (Med Phys 2012;39:6035)을 직접 읽었다(`evidence/11`, `19`). TDS-GHOST 가 "Table 1" 이라 한 숫자는 **Table 3**(Table 1 은 노출 수준표)의 **보정 후 잔류**다: 27% NLCSC 1번째 0.29%·50번째 0.0052%, 2% NLCSC 0.25%, 2% intensity-weighted 0.33%. TDS-GHOST 는 0.33% 를 "(미보정)" 이라 적지만 논문에서 이 숫자는 **보정 후 잔류와 일치**한다(숫자 일치에서 한 추론이고 TDS 작성 경위는 확인하지 못했다). 논문의 보정 전 지연은 **2% 3.7%, 27% 2.8%, 92% 2.4%** 다.
- **90% 선의 위치.** 논문의 자기 숫자에 E2E 식을 적용하면(`evidence/19`) 1번째 프레임 제거율은 NLCSC 가 2% 93.2%·**27% 89.6%**·92% 93.3%, LTI 가 62.2%·91.1%·99.8% 다. 즉 **첫 프레임에 90% 를 요구하면 출판된 최선의 알고리즘 근처**(27% 에서 NLCSC 는 90% 미만)이고 50번째 프레임은 98.8~99.7%(LTI 92% 만 42.9%: 과보정)로 여유가 크다. 어느 프레임에 90% 를 적용하는지가 합격 가능성을 크게 바꾼다.
- **TDS-CALIB 는 90% 를 Tier 3 데이터셋에만 건다.** E2E·SRS-CALIB 는 티어를 가리지 않는다.
- **공개 API 에 `ghost_bypassed`·tier·history length·bypass reason 이 없다**: 메타데이터 플래그에는 `XPE_FLAG_GHOST_CORRECTED` 하나뿐이고 `BYPASS` 는 타입 헤더에 0건(`evidence/16`).

### 1.3 빈칸 일곱 개 (D1) — 채우는 안

E2E 식은 다음을 정하지 않는다. 안과 근거를 적는다(결정은 리더).

| 빈칸 | 안 | 근거·주의 |
|---|---|---|
| k(몇 번째 빈 프레임) | **k = 1 과 k = 50** 을 각각 판정·보고 | 논문과 TDS-CALIB 가 두 지점을 쓴다. 90% 를 어느 k 에 거는지는 별도 결정(위 90% 선 참조) |
| `GhostRemovalPct` 의 집계 | `(k)` 가 없다 → **k 별로** 계산, 평균 내지 않음 | 한 값으로 합치면 k=1 의 미달을 k=50 의 여유가 덮는다 |
| `ExposureSignal` | **보정 전** 마지막 노출 프레임의 평균 | 보정 전/후 중 무엇인지 문서에 없음. 보정 후로 하면 분모가 보정기에 의존한다 |
| `LagRawPct` | 같은 식을 **보정 전** 빈 프레임에 적용 | 식이 없다 |
| `DarkRef` | **같은 처리 경로**를 거친 노출 전 암프레임 평균 | 클램프(출력이 0 이하이면 0)가 암프레임 평균을 올리는 편향을 상쇄하려면 같은 경로여야 한다 |
| ROI | 전체 유효 화소 | 평균 기반이라 해상도에 무관 |
| "lag is present" | 문턱이 없다 → **`LagRawPct(1) ≥` 문턱** 을 정해야 함 | 값은 근거 없음, 결정 항목 |

## 2. 시험 데이터 — 자기 비교 금지

### 2.1 자기 비교는 100% 를 준다 (실측, `evidence/14`·`13`)

모듈의 순방향 재귀(`y = x + α1·h1 + α2·h2`, `h ← decay·h + y`)로 지연을 만들고(안정한 α·τ: 0.02/3, 0.003/30) 모듈에 **같은 설정**을 주면 `GhostRemovalPct` 는 k=1·k=50 모두 **100.00%** 다. 틀린 설정이면 k=1 88.47%, 그런데 **k=50 은 100%**(신호 보존 1.027 로 과소보정인데도 클램프가 0 으로 만든다). 즉 자기 비교는 모듈이 아무것도 증명하지 않는데 만점을 준다.

더 나쁜 사실: **모듈의 기본 설정(`alpha1 0.9, tau1 1, alpha2 0.05, tau2 20`)은 지연 모델이 아니다.** 그 순방향 시스템은 불안정하다(`α1/(1−e^{-1}) + α2/(1−e^{-1/20}) = 1.43 + 1.02 = 2.45 > 1`). 처음 시도한 자기 모델 생성기가 기본값을 쓰자 값이 float 를 넘쳐 `XPE_ERR_PROCESSING_FAILED(-3)` 로 죽었다(`evidence/13` 끝의 오류). 이 기본값으로는 같은 모델의 시험 데이터조차 만들 수 없다.

### 2.2 빈 프레임 지표 단독은 속는다 (가장 큰 발견, 실측 `evidence/13`·`14`)

실제 `xpe_preprocess.dll`, 독립 LTI 지연(§2.3 T1), 27% 노출:

| 보정기 | 신호 보존 | 빈 프레임 k=1 | 빈 프레임 k=50 |
|---|---|---|---|
| 보정 없음 | 1.031 | 0% | 0% |
| **모듈 기본값, 티어 1·2·3** | **0.000**(출력이 전부 0) | **100%** | **100%** |
| 보존 ±0.5% 밴드에서 탐색한 2항 설정 | 0.995 | **100%** | **100%** |
| 보존 ±0.1% 밴드 | 1.000 | **100%** | **100%** |

이 표가 가리키는 것은 **빈 프레임 지표가 틀렸다는 것이 아니라 단독으로 못 쓴다**는 것이다. 모듈이 출력을 `corrected > 0 ? corrected : 0` 으로 클램프하고 빈 프레임의 참값은 0 이라 과보정이 보이지 않는다. 같은 설정들을 **클램프가 가리지 않는 측정**(27% → 5% 로 떨어지는 계단, 새 수준이 0 이 아니라 부호 있는 잔차가 보인다)으로 다시 재면:

| 설정 | k=1 부호 있는 잔차(새 수준 대비) | k=50 | 제거율(`|잔차|` 기준) k=1 / k=50 |
|---|---|---|---|
| 보정 없음 | +17.19% | +4.45% | — |
| 모듈 기본값 | −100% | −100% | 신호가 사라짐(보존 0.000) |
| 보존 ±0.1% 밴드 설정 | −0.26% | **−1.05%** | **98.5% / 76.5%** |
| 보존 ±0.5% 밴드 설정 | −2.87% | −2.48% | 83.3% / **44.3%** |

같은 설정이 빈 프레임으로는 100%, 계단으로는 k=50 에서 **76.5%·44.3%** 다. 빈 프레임 지표만으로 만든 게이트는 56점 모자란 보정기를 통과시킨다. 티어 2 도 같다: 자기 모델 지연에서 92% 노출의 신호 보존이 0.795 인데 빈 프레임 제거율은 100% 다(`evidence/17`).

**설계 요구:**

- **R1 신호 보존을 짝지표로 필수화**: 정상 노출 구간의 보정 후 평균 / 참 노출. 임계는 결정(탐색에서 ±0.1% 는 도달 가능, ±0.5% 는 위 표처럼 느슨하다).
- **R2 클램프가 가리지 않는 측정을 기본 판정에 포함**: 0 이 아닌 수준으로 떨어지는 계단의 부호 있는 잔차(절댓값으로 제거율). E2E 식(빈 프레임)은 그대로 요구 대로 계산하되 단독 합격 근거로 쓰지 않는다.
- **R3 음성 대조를 시험에 고정**: 보정 없음 = 0%(위 표), "출력을 전부 0 으로 만드는 보정" = 보존 0 으로 실패, 틀린 설정 = 90% 미만으로 판별된다는 것.

**독립성 규칙:**

- **R4** 생성기는 모듈 소스를 가져오거나 복제하지 않고, 모듈의 `alpha·tau` 로 지연을 만들지 않는다.

- **R6** 양성 대조(자기 모델에서 100% 라는 사실을 **일부러** 보이되 합격 근거로 쓰지 않음)와 음성 대조(R3)를 함께 둔다.

## 4. #238 판정에 쓰는 방법

### 4.1 구조에서 이미 보이는 것 (실측, `evidence/17`)

티어 3 은 `corrected = 0.7·corrected + 0.3·localMean(src)` 이고 `src` 는 **들어온 프레임**이다(QA-A-218b 이후). 균일한 영역에서 `localMean = raw` 이므로 `corrected ≈ raw − 0.7·(추정한 지연)`: **추정한 지연의 70% 만 제거**하고 30% 는 원본(지연 포함)으로 되돌린다. 자기 모델 지연(티어 1 이 같은 `α·τ` 로 100% 되돌림, `nlcscBeta = 0`, 64×64):

| 노출 | 티어 1 k=1 / k=50 | 티어 3 k=1 | 티어 3 k=50 |
|---|---|---|---|
| 2% | 100% / 100% | 72.1% | 71.9% |
| 27% | 100% / 100% | 75.3% | 72.3% |
| 92% | 100% / 100% | 83.5% | 73.5% |

(티어 2 는 `α` 에 `1 + 0.5·mean/32768`(92% 에서 약 1.9배)을 곱해 과보정한다: 같은 데이터에서 신호 보존이 0.996 / 0.940 / **0.795**.) 혼합 계수가 70%·가중이 겹쳐 티어 3 의 제거율은 70% 대에 묶인다 — **혼합을 빼지 않고는 90% 에 도달할 수 없다**(추정을 1/0.7 배로 부풀리지 않는 한). 이는 합성 자기 모델 위의 측정이라 "현재 티어 3 이 실제 지연에서 몇 % 인가"의 답이 아니다. #238 의 질문은 혼합을 **유지할 근거가 있는가**이고, 이 구조는 근거가 필요한 쪽이 유지임을 보여 준다.

### 4.2 비교 계획

- **S1 이음새**: 혼합 가중치를 0.3 → 0(혼합 없음)으로 바꿀 수 있는 시험 전용 이음새(`XPE_CACHE_TEST_HOOKS` 패턴: 출하 코드에는 선언·호출이 없다).
- **S2 표**: 같은 시퀀스(T1·T2 truth × 노출 3수준 × 잡음 σ = 0 / 5 ADU)에서 {티어 1, 2, 3(0.3), 3(0)} × {`GhostRemovalPct` k=1·50, 신호 보존, 계단 하강 부호 잔차, 나이퀴스트 응답(교대 격자 또는 사인 엣지 시험 패턴)}.
- **S3 사전 등록 판정 규칙(결정 후 고정)**: 혼합 제거 조건 = "혼합 0 의 제거율이 혼합 0.3 보다 `δ` 이상 나빠지지 않고, 나이퀴스트 응답이 0.6 에서 요구선으로 회복". `δ` 와 요구선은 결정 항목이다. **NFR-206(MTF ≥ 0.98 @ Nyquist)이 현행 요구인가**는 아직 답이 없다: SPEC-XPE-P1A 1.3.3 에서 `Nyquist`·`MTF` 검색은 **0건**(`evidence/16`, SPEC 안 검색뿐이고 SRS-CALIB 는 이 메모에서 검색하지 않았다).
- **S4 공정성**: 혼합이 *도움이 되는* 경우(잡음이 있는 프레임에서 이웃 평균의 평활)도 보이도록 잡음 σ > 0 시퀀스를 반드시 넣는다. 잡음 없는 균일 프레임만 쓰면 혼합은 손해로만 보인다.

## 6. 함께 결정할 것 (D4) — `xpe_verify_*` 의 비유한 입력

QA-A-224c 가 측정한 사실(`QA-A-224c/evidence/12`, 실제 DLL, 별도 프로세스 15케이스, **충돌 0**):

- `xpe_verify_defect`: 합격이 결함 **맵** 밀도(< 5%)뿐이라 **보정 영상이 전부 NaN 이어도 `overall_pass = true`**. 결함 위치의 NaN 만 `correction_error` 를 NaN 으로 만들고 판정에는 영향이 없다.
- `xpe_verify_pipeline`: 판정은 모두 실패인데 필드가 **NaN / −inf**.
- `xpe_verify_gain`: 224b·224c 로 보정 전·후 측정 조건을 갖췄다. 게인 맵의 비유한 한 화소는 설계된 1% 허용으로 합격.
- `xpe_verify_offset`: 입력이 둘 다 UINT16 이라 비유한이 있을 수 없다.

| 선택지 | 내용 | 비용 |
|---|---|---|
| **A 입구 거부** | `INVALID_INPUT` + 알림(다른 단계의 원칙: 고스트·비닝·런타임 검출이 따른다). 대상은 gain(보정 후·게인 맵)·defect·pipeline 셋 | ABI 동작 변경(NaN 이 오류가 됨). 검증 함수가 "결과를 재는 도구"라 불량 영상을 보고하고 싶은 호출자가 있다면 막힌다 |
| **B 측정값으로 보고** | 224b·224c 의 "측정 불가는 실패·측정 비트 해제" 규칙을 defect·pipeline 에 확장 | ABI 불변. 필드에 NaN 이 들어갈 수 있어 소비자가 견뎌야 한다(별도 필드 정리 필요) |

판단 재료: `verify_defect` 가 영상 값을 보지 않는 것이 가장 위험하다(garbage 영상이 합격). 입구 거부(A)는 이 점과 필드 NaN 을 한 번에 없애지만 도구의 성격과 충돌할 수 있다. 이 메모는 어느 쪽도 이미 정해진 것으로 쓰지 않는다.

## 7. 모듈에서 드러난 별도 문제 (이 메모의 범위 밖, 카드 후보)

1. **기본 설정이 파괴적이다**(D3). `tier=1`, `α1=0.9, τ1=1, α2=0.05, τ2=20` 에서 균일 200프레임 노출의 보정 후 평균은 참 노출의 **0.000**(측정 `evidence/13`). 핸들을 설정 없이 만들면 둘째 프레임부터 출력이 0 으로 클램프된다. 그 모델의 순방향 시스템은 불안정하다(§2.1).
2. **시간 단위가 문서와 코드에서 다르다**(D6). 핸들 주석은 `tau` 를 "frames", REQ-P1A-033 은 "시간 차는 프레임 단위"라 적지만 코드는 `acquisitionTime`(`uint64` **정수 초**)의 차를 그대로 `dt` 로 쓴다(`dt ≤ 0` 이면 1.0). 한 초 안의 연속 프레임(예: 15 fps)은 같은 타임스탬프를 가져 항상 `dt = 1` 프레임으로 취급되고, 분 단위 간격(환자 사이)은 `e^{-dt/τ}` 로 거의 완전히 감쇠한다 — "프레임"도 "초"도 아니다.
3. **티어 2·3 의 노출 가중**이 `α` 에 `1 + 0.5·mean/32768` 을 곱한다(92% 에서 약 1.9배): 자기 모델 지연에서 신호 보존 0.795(§4.1).
4. **내보내는 값이 없다**(D5). E2E §4.6·FUNC-020 이 말하는 tier·history length·bypass reason 과 §5.6 의 `ghost_bypassed` 는 API 어디에도 없다(`evidence/16`).
5. **상태 갱신 방식**: 모듈은 측정값(`raw`)으로 상태를 갱신하고, 논문 식(3)(4)과 PRD §5.3 의사코드는 **보정한 값 `x̂`** 으로 갱신한다(되먹임). 제안이 아니라 사실이다. 지연이 약할 때는 차이가 작지만 구조가 다르다.
