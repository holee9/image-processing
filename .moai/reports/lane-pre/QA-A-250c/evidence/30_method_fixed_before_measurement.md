# QA-A-250c — 측정 방법 (측정 전에 고정, 측정 전에 커밋)

이 문서는 v3 세트를 만들고 평가하기 전에 쓴다. 결과를 본 뒤 이 문서의 방법을 바꾸지 않는다. 바꿔야 한다고 판단되면 리더에게 보고만 한다.

## 0. 왜 다시 재는가

Codex #200 이 QA-A-250b 에서 병합을 막는 지적 4건을 냈고 리더가 동의했다 (QA-A-250b 의 B12 게인 합격·B13 합격은 철회).

| # | 지적 | 이 카드의 처리 |
|---|---|---|
| 1 | 판정용 프레임(`Bright_29·30`)이 결함 맵 생성 입력에 들어 있었다 | 분할을 다시 한다 (§1). 하니스가 manifest 를 읽어 판정 프레임의 sha256 이 어떤 역할에도 없음을 단언한다 |
| 2 | 선량 검사가 게인 생성기가 보는 신호와 다른 양을 쟀다 (`--gain-dark-ref` 무시, 0 아래 절단 무시) | 검사가 생성기와 같은 신호를 쓴다 (§2) |
| 3 | 같은 프레임을 한 역할에 두 번 줄 수 있다 | 경로·동일 파일·sha256 이 같은 중복은 종료 코드 13 으로 거부한다 (§3) |
| 4 | 단계 도중 실패하면 앞 단계 파일이 `--out` 에 남는다 | 옆 작업 디렉터리에서 만들고 4개가 모두 있을 때만 옮긴다 (§4) |

## 1. 분할

| 역할 | 프레임 |
|---|---|
| 오프셋 생성 | `Dark_07` ~ `Dark_14` (8장) |
| 게인 생성 | `Bright_23` ~ `Bright_28` (6장, 한 선량), 다크 참조 = 위 다크 8장의 평균 (기본값) |
| 결함 맵 생성 | 다크 `Dark_07~14` + 밝은 영상 `Bright_17~28` 과 `Bright_31~36` (18장, 선량 혼합 허용, `--bpm-bright`) |
| 오프셋 판정 (남김) | `Dark_15`, `Dark_16` |
| 게인 판정 (남김) | `Bright_29`, `Bright_30` |

`Bright_29·30` 은 어떤 생성 역할에도 넣지 않는다. 250b 에서는 결함 맵 입력에 들어 있었다.

판정 기준은 QA-A-250b 의 B12 와 같고, 결과를 본 뒤 바꾸지 않는다:

| 항목 | 정의 |
|---|---|
| 오프셋 (FUNC-016) | `Dark_15`·`Dark_16` 각각 `|DarkBias| ≤ 5 ADU` 또는 `DarkReduction_dB ≥ 10`, 둘 다 통과해야 합격 |
| 게인 (FUNC-017, 프로토콜 §5.3) | `Bright_29`·`Bright_30` 각각 ROI 평균 ≥ 2000 ADU 이고 `FlatResidualPct ≤ 1.0 %`, 둘 다 통과해야 합격 |
| 값 정의 | QA-A-250 §3 과 같다 (`DarkBias=mean(Y)`, `DarkReduction_dB=20·log10(std(R)/max(std(Y),1e-12))`, `FlatResidualPct=100·std/mean`, ROI = 게인이 유한하고 0 보다 큰 화소, 앱 구성의 `xpe_preprocess_pipeline_out`) |

## 2. 선량 검사 (지적 2)

규칙: 게인용 밝은 영상의 **신호** = 화소 평균 `max(0, 프레임 − 게인 다크 참조)` — `xpe_calib_generate_gain` 이 화소마다 빼고 0 아래를 0 으로 자른 뒤 평균하는 것과 같은 식. 참조는 실제 `--gain-dark-ref` (`mean` = 다크 입력의 화소별 평균, `none` = 0, 파일). 신호가 0 이하인 프레임이 있으면, 또는 최대/최소 비가 **1.25** 를 넘으면 종료 코드 12. 한도 1.25 는 바꾸지 않았다 (근거: QA-A-250b `10_dose_spread_basis.txt`). 적용한 기준(`gain_dose_basis`)은 manifest 에 적는다.

## 3. 중복 거부 (지적 3)

역할 안에서만 본다: 다크, 게인용 밝은 영상, 결함 맵용 밝은 영상 (`--bpm-bright` 가 있을 때). 같은 정규화 경로, `fs::equivalent` 로 같은 파일, 또는 sha256 이 같은 내용이면 종료 코드 13 (파일을 읽거나 쓰기 전, 내용 중복은 읽은 뒤 생성 전). 게인 역할과 결함 맵 역할이 한 프레임을 함께 쓰는 것은 의도된 공유라 허용한다 (manifest 의 `bright_and_bpm_bright`). 중복은 건너뛰지 않고 거부한다. 따라서 중복이 프레임 수 최소를 채우는 데 쓰이지 않는다.

## 4. 원자적 생성 (지적 4)

거부 경로(종료 코드 2·9·10·11·12·13)는 `--out` 도, 그 부모 디렉터리도 만들지 않는다. 생성은 `--out` 옆 `<이름>.building` 디렉터리에서 한다. 오프셋·게인·결함 맵·manifest 가 모두 만들어진 뒤에만 `--out` 으로 옮긴다. 실패하면 작업 디렉터리와 이 실행이 만든 부모를 지우고, 이미 있던 완전한 세트는 바이트까지 그대로 둔다. 옮기는 도중 실패하면 놓은 파일을 치우고 치워 둔 옛 파일을 되돌린다.

## 5. 생성과 평가

```
xpe_calib_fixture_gen --out D:/workspace-github/xpe-data/calib-cyan-v3 --expiry-ms 4102444800000
   --compare-bpm BPM.raw
   --dark Dark_07.raw ... --dark Dark_14.raw
   --bright Bright_23.raw ... --bright Bright_28.raw
   --bpm-bright Bright_17.raw ... --bpm-bright Bright_28.raw --bpm-bright Bright_31.raw ... --bpm-bright Bright_36.raw
```

평가는 QA-A-250b 하니스와 같은 형식에 §1 의 분리 단언을 더한 `DISABLED_A250c_CyanSeparatedJudgement` 한 번. 대조: 하니스는 생성 입력인 프레임 7개(`Dark_07`, `Dark_14`, `Bright_17`, `Bright_23`, `Bright_28`, `Bright_31`, `Bright_36`)가 같은 코드로 정확히 한 번씩 발견됨을 보인다. 이것이 없으면 "발견 0건" 은 단언이 아무것도 못 읽어도 통과한다. 팬텀 5장은 250·250b 와 같은 구성·같은 비교표로 낸다. 장비 회사 결함 맵 비교는 manifest 의 `bpm_comparison` 이며 판정이 아니다.

## 6. 실행 범위

도구 시험은 `CalibFixtureGenTest.*` 만. 생성 1회, 평가 1회. 한 번에 프로세스 하나, 각 실행 뒤 남은 프로세스 0 확인. 전체 스위트는 돌리지 않는다. push 하지 않는다.
