## 2. 증거 (Evidence)

### C1 — σ 분해, 그리고 처음 틀린 분해

새 모드 `xpe_detect_experiment --sigma-stages`.

**첫 시도는 틀렸다.** 선택 한 번을 재고 4를 곱했더니 명명 단계의 합이 전체의 **148%** 가 됐다. 부분이 전체를 넘으면 하네스가 틀렸다는 신호(A-64)이므로, 곱한 가정이 찾을 것이었다. 두 선택은 **입력 분포가 달라 같은 값이 아니었다** — 각각 따로 재자 합이 93.2% 로 맞았다.

```
[sigma-stages] 3072x3072  hCount 9434112 (36.0 MB), single thread, min of 5
  TOTAL ComputeGlobalSigma [measured]              137.8   100.0%
    allocate 37.75 MB (once per call)               0.01     0.0%
    difference fill (x2: h and v)                   8.12     5.9%
    selection 1, over differences (x2)              97.0    70.4%
    selection 2, over deviations (x2)               14.2    10.3%
    absolute deviation pass (x2)                    9.10     6.6%
    SUM of the named stages                        128.5    93.2%
    GAP (total - sum)                                9.4     6.8%
```

**같은 함수, 같은 원소 수, 6.8배 차이.** 이것이 이 카드의 실마리다. A-58/A-61 의 가설(16스레드 포화, 호출당 T×256 KB 할당)은 출발점으로 두었지만, 할당은 **0.01 ms** 로 측정돼 원인이 아니었다.

### C2 — 가설 둘을 기각하고 남은 것

**가설 1: 히스토그램 테이블 256 KB 가 캐시를 넘긴다.** 같은 데이터로 버킷 수만 바꿔 쟀다:

```
   8 bits     256 buckets    1.0 KB   26.8 ms
  10 bits    1024 buckets    4.0 KB   27.0 ms
  12 bits    4096 buckets   16.0 KB   26.9 ms
  14 bits   16384 buckets   64.0 KB   28.2 ms
  16 bits   65536 buckets  256.0 KB   27.3 ms
```

**기각.** 1 KB 와 256 KB 가 같은 값이다. 테이블 발자국은 비용이 아니다.

**가설 2: 도구 TU 가 `/arch:AVX2` 없이 빌드돼 헤더 인라인 코드가 느리다** (A-66 의 기준 커널이 그랬으므로 합리적인 의심이었다). 도구에 `/arch:AVX2` 를 붙여 재빌드했다 — 186.5 → 188.8 ms. **기각.**

**남은 것: 데이터.** 두 선택의 유일한 차이는 입력 분포이고, 한 패스 안에서 데이터에 의존하는 것은 `FloatSortKey` 의 삼항식뿐이다. 차분 배열은 약 절반이 음수(예측 불가), 절대 편차는 전부 비음수(완전 예측). 직접 쟀다:

```
  one histogram pass, same table, different key/data:
    branchy key,    signed differences          28.9 ms
    branchless key, signed differences           5.6 ms
    branchy key,    absolute deviations          4.4 ms
```

**5.2배.** 세 번째 줄이 대조군이다 — 예측 가능한 데이터에서는 분기 형태도 이미 빠르므로, 비용은 산술이 아니라 **예측 실패**다.

### C3 — 비트 동일

```cpp
const uint32_t mask =
    static_cast<uint32_t>(-static_cast<int32_t>(bits >> 31)) | 0x80000000u;
return bits ^ mask;
```

- 부호 비트가 1: `mask = 0xFFFFFFFF`, `bits ^ mask == ~bits` — 음수 갈래
- 부호 비트가 0: `mask = 0x80000000`, 그 비트가 0이므로 `bits ^ mask == bits | 0x80000000` — 비음수 갈래

모든 입력에서 같고 NaN 도 포함된다. 새 테스트 `BranchlessSortKeyEqualsTheTernaryItReplaced` 가 **옛 삼항식을 그대로 적어 놓고** 특수 패턴 17종(±0, ±denormal, ±inf, qNaN, sNaN, FLT_MAX …) + 20만 개 난수 패턴에 대해 비교한다. 범위는 명시했다 — **전수가 아니다**. 항등은 갈래별 증명이고 테스트는 편집을 잡기 위한 것이다.

**반증 두 방향:**

- **A (키 자체를 바꿈)**: `return (bits ^ mask) + 1u` — 순서는 보존되지만 비트가 달라진다. `BUILD_EXIT=0` 에서 키 테스트·순서 테스트·`MatchesNthElementBitForBit`·`GlobalSigmaMatchesThePreviousImplementation` **4건이 실패**했다.
  **여기서 A-65 의 구조가 그대로 적용되지 않는다는 것을 확인했다.** A-65 에서는 ±0 차이가 프레임 결과에 안 보였지만, 여기서는 키가 `SortKeyToFloat` 로 **되돌아가므로** 어떤 키 변경도 하류에 보인다. 그래서 두 층이 **서로 다른 사각을 덮지 않는다** — 이 함수에서는 그렇다. 적어 둔다.
- **B (선택 논리를 바꿈)**: `inner + hist[b] > rank` → `>= rank`. 키는 그대로. `BUILD_EXIT=0` 에서 **키 테스트 2건은 통과**하고 `MatchesNthElementBitForBit` · `GlobalSigmaMatchesThePreviousImplementation` 2건만 실패했다. 이 방향은 여전히 유효하다 — 키 테스트만으로는 부족하다.

두 주입 모두 원복했다.

### C5 — 게이트 재유도 (미루지 않음)

**정상 대역이 좁아졌다. 그리고 그 이유가 A-66 의 설명과 같다.**

```
QA-A-66   P-core 1.720   E-core 1.308   spread 24%
QA-A-67   P-core 0.651   E-core 0.630   spread  3.3%
```

A-66 은 "기준은 P→E 로 1.87배, 검출기는 1.42배 — σ 의 비용이 산술이 아니라서"라고 설명했다. 그 비용이 **분기 예측 실패**였고, 없애자 검출기가 1.80배로 기준(1.84배)과 다시 같이 움직인다. **같은 설명이 분기(divergence)와 그 소멸을 둘 다 예측했다** — 한 측정에 맞춘 이야기가 아니라는 뜻이다.

측정 대역 (매번 fresh build 확인):

```
clean         P 0.630 .. 0.651 (3회)   E 0.626 .. 0.630 (3회)
regression 1  P 1.583                  E 1.289    (분기 있는 키로 되돌림)
regression 2  P 6.183                  E 6.490    (AVX2 경로 제거)
```

**회귀 1 이 천장을 정한다.** 그리고 그 E-코어 값(1.289)이 A-66 의 P-코어 정상값(1.720)보다 **아래**다 — 상한 2.20 을 그대로 두면 이 회귀가 두 코어 모두에서 통과한다. 상한을 옮겨야 했던 이유가 이것이다.

**0.85**: 두 마이크로아키텍처 최악 정상(0.651)보다 30.6% 위(A-60·A-66 과 같은 여유), 최근접 회귀(1.289)보다 34% 아래. 어느 코어에서든 1.31배 회귀를 잡는다.

```
[perf-gate-ratio] 3072 ratio=0.659 limit=0.850
```

### C6 — 비-AVX2 경로를 실제로 빌드했다

카드 지시 그대로 `XPE_DETECT_HAS_AVX2` 를 0 으로 만들어 빌드했다.

```
BUILD_EXIT=0
[  SKIPPED ] Avx2ParityTest.NoAvx2PathCompiledIn
[       OK ] RadixSelectParityTest.* (5건 전부)
```

A-66 에서 고친 형태가 유지된다. 이번 변경은 조건부 컴파일을 추가하지 않았지만(σ 에 SIMD 를 쓰지 않았다), **양쪽 빌드 확인은 했다.**

### C7 — 정수 합의 근거를 따로 적었다

`ComputeGlobalSigmaThreaded` 문서에 추가했다. 요지:

- 화소 루프가 비트 동일한 이유는 **축약(reduction)이 아예 없어서** — 원소별 연산뿐이라 순서가 없다.
- 이 단계는 축약을 하지만 **정수**라서 결합적이고 정확하다. **같은 결론, 다른 근거.**
- 그리고 정수라고 자동으로 안전하지 않다는 것을 셋으로 나눠 논증했다:
  - **오버플로**: 버킷 하나가 세는 최대치는 원소 수이고, 버킷은 `uint32_t`, 원소 수는 `width*height`로 A-62 가 이미 2^32 로 묶었다. **두 한계가 같은 한계**라 따로 맞춰 둘 것이 없다.
  - **빈 경계**: 여기에는 float→빈 **산술이 없다**. 빈 인덱스는 정렬 키의 비트 조각(`key >> 16`, `key & 0xFFFF`)이고 키는 값의 양자화가 아니라 비트 재해석이다. 반올림으로 경계를 넘는 통상적 함정이 **이 히스토그램에는 존재하지 않는다**.
  - **float→키 변환**: 위험은 여기 있고, A-65 가 다른 옷을 입고 만난 것과 같다 — ±0 이 같게 비교되지만 다른 키로 간다. 의도된 것이고 `SelectKthSmallest` 에서 논증되며 테스트가 고정한다.

## 3. baseline 귀속 (Baseline-attribution)

- 모든 시간은 이 워크트리, 이 기계, 이번 세션. 셀마다 best-of-5, 워밍업 버림.

- CI 비율은 **재지 않았다**. 마지막 CI 관측값 1.251(런 `be9f68a`, A-66 코드)은 이번 상한 0.85 보다 위이므로, **그 값으로는 새 상한을 확인할 수 없다.** 리더의 CI 확인이 필요하다.
- 테스트 수 634 → 635.

## 4. 미검증 (Gaps)

- **새 상한 0.85 를 CI 에서 확인하지 않았다.** 이전 CI 값(1.251)은 옛 코드의 것이고 새 상한 위에 있다 — 즉 **새 코드의 CI 비율을 읽기 전에는 이 상한이 CI 에서 통과하는지 모른다.** A-66 때보다 위험이 크다: 그때는 마지막 CI 값이 상한 아래였다.
- **키 테스트는 전수가 아니다.** 특수 패턴 17종 + 난수 20만. 2^32 전수는 단위 테스트 시간에 맞지 않는다.
- **분기 예측이라는 설명은 성능 카운터로 확인하지 않았다.** 세 줄의 대조(분기/무분기/예측가능 데이터)로 추론한 것이다. 성능 카운터는 프로파일러가 필요하고 그것은 범위 밖이다.
- **σ 의 남은 항목은 손대지 않았다** — fill 17.4%, abs 18.4% 는 각각 한 번의 스트리밍 패스이고 이번 범위가 아니다.
- **스레드 경로는 재지 않았다.** `ComputeGlobalSigmaThreaded` 도 같은 키를 쓰므로 같은 이득을 받겠지만, **측정하지 않았다.**
- **Doxygen 로컬 확인 불가** — 여전히(#159).

## 5. 잔여 위험 (Residual-risk)

- **SPEC 목표 60 ms 까지 1.1배.** 다음 개선은 목표를 넘길 수 있고, 그러면 게이트 상한을 **또** 재유도해야 한다. SPEC `60a81c1` 의 [HARD] 가 그대로 적용된다.
- **0.85 는 A-66 의 2.20 보다 상대적으로 조인 값이다** — 최근접 회귀와의 거리가 69% 에서 34% 로 줄었다. 정상 대역이 3.3% 로 좁아서 가능한 것이지만, **CI 가 세 번째 마이크로아키텍처**라는 사실은 그대로다. CI 값이 0.85 를 넘으면 상한이 아니라 대역을 다시 봐야 한다.
- **분기 하나가 이만큼이었다는 사실 자체가 위험 신호다.** 이 파일에는 원소마다 실행되는 삼항식이 더 있고(예: `MedianSortCE` 의 두 갈래), 그쪽은 MSVC 가 `vminss`/`vmaxss` 로 낮추고 있다고 **주석에 적혀 있을 뿐 이번에 확인하지 않았다.**
- **정상 대역이 좁아진 것이 다음 변경에서 유지된다는 보장은 없다.** σ 구성이 다시 바뀌면 P/E 배수도 다시 바뀐다.
