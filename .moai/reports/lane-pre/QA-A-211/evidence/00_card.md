## 먼저 설계를 보고하고 멈출 것 (구현 전 리더 확인)

이 변경은 결함 맵의 의미와 공개 API 에 닿는다. 아래를 정리한 설계 메모(`design.md`)를 먼저 커밋하고 `설계 검토 요청: <SHA>` 로 알릴 것. 리더가 확인하면 구현한다.

1. **분류는 어디서 일어나는가**: 생성 시(스칼라 `xpe_calib_generate_gain`, 다항식 생성)인지 적재 시(`xpe_calib_load_gain`)인지 적용 시인지. 옛 파일(이미 0 이나 범위 밖 값을 가진 맵)도 다루려면 적재 시가 필요할 수 있다 — 장단을 적을 것
2. **결함 정보는 어디에 사는가**: 모듈 전역 교정 저장소의 결함 맵과 합치는가(합집합), 별도 "게인 유래 결함" 맵을 두는가. 결함 맵이 적재되지 않은 경우, 결함 단계가 우회된 경우(`bypassDefect`)에는 어떻게 되는가 — 우회 시 그 화소가 게인 1 그대로 나가는 것을 허용할지(경고?) 제안
3. **상한**: 몇 %(근거 — CalData_6 의 0.41~0.47%, cyan_test, 결함 맵 크기 분포). 상한 초과 시 반환 코드와 알림
4. **알림**: 분류 개수·상한·원인 분포(결함 맵 안/밖, 가장자리 띠)를 담은 문구 초안 — 레인 간 계약
5. **범위 통일**: 다항식 경로의 적용기 범위 [0.001, 1000] 를 [0.1, 10] 으로 맞출 때 210e 의 저장 후 검증·종단 시험과 어떻게 맞물리는지
6. **공개 API·파일 형식 변화**: 새 함수·필드가 필요한가, XCal 형식이 바뀌는가(바뀌지 않는 설계를 우선)
7. **시험 계획**: CalData_6·cyan_test 로 교정이 진행되고 분류 화소가 결함 보정으로 채워지는 종단 시험, 상한 초과 거부, 결함 맵 미적재·우회 경우, 정상 데이터(cyan_test) 결과 불변
8. **요구사항 문안**: SRS-CALIB·REQ-P1A 에 넣을 문장 초안(문서 수정은 리더)
