### CRC-32 구현은 있는데 **아무도 안 씁니다**

`calibration_manager.cpp:29` 에 `xpe_crc32()` 가 있고 `preprocess_api.h:945` 로 **공개 API 에 내보내집니다**. ISO-HDLC(`0xEDB88320`) 표를 만드는 완전한 구현입니다.

**호출처 0건** — 검색 범위 `modules/`·`clients/`·`gui/` 전체. 유일한 검색 결과가 정의(`:29`)와 선언(`:945`)입니다.

**대조군**: 같은 방식으로 `xpe_calib_load_gain` 을 찾으면 **98건**이 잡힙니다. 0건이 검색 실패가 아닙니다.

그리고 `calibration_manager.cpp` 가 내보내는 것은 **`xpe_crc32` 하나뿐**입니다 — SWU-1.5 "Calibration Manager — file I/O, CRC-32, expiry" 라는 파일 머리말이 무색하게, 파일 I/O 도 expiry 도 이 파일에 없습니다.

## (c) 옛 057 판정 — **이동입니다 (내용이 바뀐 이동)**

옛 057(`ee2c607`): *"IF a calibration file fails **CRC-32** verification during load, THEN the system SHALL return …"* (§2.12 Error Handling)

새 판본에 **057 이라는 번호는 없습니다**(새 ID 27개에 미포함) — 재사용 아님.
그리고 **그 요구가 사라지지도 않았습니다** — 새 `REQ-P1A-014`(`:337`)가 말합니다:

> *"…the module **shall** parse the XCal header, **validate SHA-256 integrity**, check session matching and expiry…"*

| 옛 057 | 새 014/015/016 |
|---|---|
| 적재 중 무결성 검증 실패 → 오류 | 적재 시 무결성 검증(SHA-256) |
| 알고리즘: **CRC-32** | 알고리즘: **SHA-256** |

**무결성 검증 요구 자체는 살아남아 교정 적재 요구 안으로 흡수됐고, 알고리즘만 바뀌었습니다.** 그래서 QA-A-128 의 "확정 못 한 27건" 에서 **057 은 이동으로 옮깁니다** — 다만 1:1 이 아니라 **하나가 셋(014·015·016)에 흡수된 이동**이고, **내용이 바뀐 이동**입니다.

이로써 QA-A-128 의 미확정이 **27 → 26** 이 됩니다.

## (가)/(나) 의견

카드의 두 갈래는 이렇습니다:
- **(가)** 요구가 살아 있다 → 요구와 구현 중 어느 쪽이 맞는지가 다음 질문
- **(나)** `#186`/`#197` 과 같은 원인의 또 하나의 증상 → P1D 결정에 묶음

**제 의견은 (가) 쪽에 가깝되, 이미 답이 나와 있는 (가) 입니다.**

근거:

1. **옛 057 은 삭제가 아니라 이동입니다.** 무결성 검증 요구는 새 SPEC 에 살아 있습니다(`REQ-P1A-014` 가 SHA-256 을 명시). 범위 밖으로 밀려나 받을 SPEC 이 없어진 온도·비선형·비닝·고스트와 **성격이 다릅니다.** `#186`/`#197` 의 "집이 없어진 요구" 유형이 아닙니다.
2. **"요구와 구현 중 어느 쪽이 맞나" 는 이미 결정돼 있습니다.** `SRS-CALIB-001:47` 이 적습니다 — *"무결성은 CRC-32 로 약화하지 않습니다 … PERF-003 의 200 ms 는 CNG 전환 뒤 3파일 합계 130–137 ms 로 충족합니다(#179)."* **구현(SHA-256)이 맞고 문서가 틀렸다** 는 판정이 이미 내려졌고, 성능 전제까지 측정으로 해소돼 있습니다.

**그래서 남은 것은 "판정" 이 아니라 "정정이 안 끝났다" 입니다.** SRS 본문에는 정정 블록이 붙었는데:

- **SRS 안의 FUNC-001·FUNC-002·SAFE-003·PERF-003 본문 자체는 여전히 CRC-32 를 말합니다.** 정정 블록이 위에 얹혀 있을 뿐입니다. 요구 본문만 읽는 사람은 CRC-32 를 봅니다.
- **SRS 밖 문서 넷은 정정조차 없습니다** — `KNOWLEDGE-BASE.md:117`, `ALGORITHM-VERIFICATION-GUIDE.md:170-189`(`payloadCrc32` 구조체 포함), `SAD-CALIB-001:97·134·571`, `CONCEPT-DIAGRAMS.md` 다이어그램 5곳.
- **코드에 쓰이지 않는 CRC-32 구현이 공개 API 로 나가 있습니다**(`xpe_crc32`, 호출처 0건).

**이 셋은 오늘 반복해서 만난 형태입니다 — 결과는 맞는데(SHA-256 으로 동작) 설명이 여러 곳에서 틀렸습니다.**

## 무결성 약화에 대하여

카드가 적은 대로, **어느 쪽에서도 CRC-32 로 되돌리는 결론은 나오지 않습니다.** 교정 파일이 조용히 손상되면 모든 영상에 계통 오차가 생기고, 성능 전제(200 ms)도 `#179` 에서 해소됐습니다. 제가 찾은 것은 **구현을 바꿀 근거가 아니라 문서가 덜 정정됐다는 사실**입니다.
