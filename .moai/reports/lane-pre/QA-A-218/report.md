# QA-A-218 — 고스트 티어 3 의 3×3 이웃 평균이 이미 보정된 윗줄을 읽는다: 의도인가 (보고서만, Refs #233)

기준: dev/preprocess `cafb92d8`. 코드 변경 없음. 증거: `evidence/10_orientation_and_quality.txt`, `evidence/20_nyquist_response.txt`(측정 스크립트 출력).

## 결론

**근거가 없어 결정이 필요하다 — 단, 결정의 한쪽 끝은 이미 정해졌다.**

1. **어느 문서도 티어 3 의 이웃 평균을 정하지 않는다 — 원본이든 보정된 것이든.** 이웃 평균·0.7:0.3 혼합 자체가 어떤 요구·설계 문서에도 없다. 문서화된 NLCSC 는 화소별 상태 기계(4차 다항식)이고 공간 항이 없다. 코드는 2026-04-19 의 일괄 커밋(`31d38a57`, "Ghost Correction 알고리즘 대규모 개선 +203줄")에서 주석 한 줄 *"Spatial context: blend with local neighborhood mean (3x3)"* 로만 들어왔다.
2. **주사 방향 의존은 실측으로 확정이다.** 프레임을 좌우·상하·180°·전치로 뒤집어 처리하고 되돌리면 현재 코드는 **화소의 약 40~91 % 가 달라지고(최대 차 340~2082)**, 원본 이웃을 읽는 변형은 **0 화소**(float 반올림 2e-3 이내) — 결과가 입력 방향에 의존하는 것은 의도일 수 없는 부작용이다.
3. **혼합 자체가 Nyquist 응답을 0.6 으로 깎는다**(현재 코드 0.625, 원본 이웃 0.600; 티어 1·2 는 1.000). 옛 ghost SRS NFR-206 은 MTF ≥ 0.98 @Nyquist 를 요구한다 — 이웃을 원본으로 바꿔도 이 손실은 그대로다(아래).
4. 제안: 이웃 읽기 순서 의존은 **어느 쪽 의도든 고쳐야 하는 결함**이다(원본 이웃으로 읽으면 방향 무관). 혼합을 **유지할지 없앨지**가 별도 결정 — 리더가 정한다.

## 3. 어느 쪽이 맞는가 — 품질 지표 (`evidence/10_…` 하단, `20_…`)

**고스트 품질을 재는 기존 시험·지표는 출하 코드에 없다**(시험은 유한·범위만). 문서의 지표는 GCR ≤ 0.3%(`NFR-202`, 계단 쐐기 팬텀 실측)와 MTF ≥ 0.98(`NFR-206`)이고, 이 저장소에는 팬텀 입력이 없다. 그래서 합성 장면으로 잰 것은 참고값이다:

- **한계**: 합성 잔상을 모듈 **자기 모델**(`a1·h1 + a2·h2`)로 주입했으므로 티어 1 은 정의상 정확(RMS 0)하다 — "계산한 모델이 약분된다" 형태. 티어 3 의 우열을 가리는 임상 증거가 아니다.

| 48×48, 왼쪽 절반에 밝은 계단이던 프레임 1 뒤의 프레임 2 | RMS 오차 | 계단 쪽 평균 오차 | 선 대비(진짜 4000) |
|---|---|---|---|
| 보정 안 함 | 16248 | +22800 | 2001 |
| 티어 1 | 0.0 | 0.0 | 4000 |
| 티어 3 현재(보정된 이웃) | 3345 | −4123 | 3503 |
| 티어 3 원본 이웃 | 2009 | −696 | 3590 |

읽는 법: 이 장면에서 원본 이웃이 현재보다 진짜에 더 가깝지만(RMS 2009 vs 3345), 둘 다 티어 1 보다 훨씬 나쁘다 — 혼합(30 % 이웃 평균)과 신호 의존 계수가 오차를 만든다. 선 대비는 둘 다 약 10~12 % 줄어든다(3503, 3590 / 4000).

**Nyquist 응답**(첫 프레임, 이력 0 이라 혼합만 작용하는 열 교대 패턴): 티어 1·2 = 1.000, 티어 3 현재 = **0.625**, 티어 3 원본 이웃 = **0.600**(해석값 `0.7 + 0.3·(−1/3) = 0.6`). 즉 티어 3 의 3×3 혼합이 이미 NFR-206(≥ 0.98)을 크게 못 미치고, 이웃을 원본으로 바꿔도 못 미치는 정도가 같다(0.625 → 0.600 은 오히려 조금 나빠짐).
