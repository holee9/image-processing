# 판독 — CI 성능 게이트 `Frame3072SquaredWithinMachineRatio` 빨강 (main `f1bafba`)

요청: 리더 메시지(2026-09-18). 카드 정식화 전 판독만. 코드 변경 없음.

## 1. 주장

1. 이 시험은 **런타임 결함 검출기의 3072² 처리 시간 ÷ 같은 프로세스에서 잰 고정 기준 커널 시간**을 본다. 한계 0.85.
2. 최근 변경(A-103 결함 보정, A-105 스트리밍 해시, A-106 CNG)은 **이 비율을 바꾸지 않았다.** 마지막 통과(main `cedce22`)와 실패(`f1bafba`) 사이에 `modules/preprocess` 와 `modules/common` 의 변경은 **0줄**이다.
3. CI 21회 표본의 비율은 0.472–0.638(중앙값 0.567)이고, 실패한 실행만 0.972다. 분포가 이동한 것이 아니라 **한 번 튄 값**이다.
4. 그 실행에서 기준 커널은 110.9 ms 로 표본 중 **가장 빨랐는데**, 검출기는 107.8 ms 로 **가장 느렸다**. 기계가 느려서 생긴 값이 아니다.
5. 같은 속도의 기계(기준 112.7 ms)에서 앞서 비율 0.472(검출기 53.2 ms)가 나온 적이 있다. 같은 기계 등급에서 검출기만 2배 느려진 것이다.
6. 판정: **CI 러너의 일시적 변동**으로 설명된다. 코드 회귀의 증거는 없다.

## 2. 증거

### 2.1 시험이 비교하는 것
- `test_runtime_detection_performance_gate.cpp` 머리말: 절대 밀리초 예산을 버리고 비율로 바꾼 이유(로컬 702 ms 대 CI 1340 ms, 1.91배)가 적혀 있다.
- 기준은 파일 안에 **얼어붙은 커널**이다(16 MB float, 12 스윕, 5회 최소). 검출기 코드를 부르지 않는다. "기계가 느려지면 둘 다 커져 비율은 그대로, 코드가 느려지면 검출기만 커져 비율이 오른다"가 설계 의도다.
- 검출기 쪽도 준비 실행 1회 버리고 5회 최소.
- 한계 0.85 의 근거(QA-A-67): P코어 0.630–0.651, E코어 0.626–0.630, 가장 가까운 회귀 1.289(E)–1.583(P).

### 2.2 코드 변경 여부
```
git diff --stat cedce22..f1bafba -- modules/preprocess modules/common   → 출력 없음(변경 0)
git diff --name-only cedce22..f1bafba                                   → enhance_basic / enhance_advanced / SPEC 문서만
```
- `runtime_detection.cpp` 는 A-103/105/106 어디에서도 바뀌지 않았다.
- A-105(`e0b19fb`)·A-106(`6f06266`) 이 들어간 뒤의 CI 통과 실행이 있다: `c72f0e8` 0.472, `cedce22` 0.556.

## 3. 기준 귀속
- CI 값은 각 실행의 아티팩트에서 읽었다(`gh run download -n xpe-preprocess-test-results`, `LastTest.log`).
- 로컬 값은 `build/ci-preprocess` RelWithDebInfo 빌드, i7-12700.

## 4. 미검증 · 한계
- 실패 실행의 CPU 모델·동시 부하는 알 수 없다(GitHub 호스팅 러너는 그 정보를 로그에 남기지 않는다).
- 같은 커밋(`f1bafba`)을 CI 에서 다시 돌려 보지 않았다. 재현 여부가 이 판독의 가장 큰 미확인 항목이다.
- 1024 진단 비율은 실패 실행에서 한계가 없어 참고만 가능하다(값은 0.053–0.064 범위였다).
- 로컬은 한 기계·한 코어 종류에서만 쟀다.

## 5. 선택지 (결정은 리더)

| 선택지 | 내용 | 근거·영향 |
|---|---|---|
| A. 같은 커밋 재실행으로 재현 확인 | CI 재실행 1–2회 | 가장 싸다. 통과하면 일시 변동으로 확정. 실패가 반복되면 B 이후로 |
| B. 게이트에 재시도 1회 | 첫 실패 시 같은 잡에서 한 번 더 | 일시 변동에는 듣지만, 진짜 회귀도 1회는 가려진다 |
| C. 표본을 늘려 판정 | 비율을 3회 재서 최소값으로 판정 | 실행 시간 3배. 일시 변동에 강해진다 |
| D. 한계 상향 | 0.85 → 1.05 등 | **권하지 않는다.** 통과 표본 최대가 0.638 이라 상향 근거가 없고, 파일이 적은 "가장 가까운 회귀 1.289" 와의 간격이 좁아진다 |
| E. 기준 커널 교체 | 검출기와 같은 메모리 접근 특성으로 | 문서가 금지한다(기준이 대상 코드를 따라가면 회귀를 못 본다). 다만 "기계 상쇄가 불완전하다"는 이번 관측은 기록해 둘 만하다 |

- 한계를 올린다면 근거가 필요하다는 리더 지적대로, 현재 분포(21회, 최대 0.638)는 **상향을 지지하지 않는다**.
