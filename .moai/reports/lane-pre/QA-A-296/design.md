## 1. 포화값 [2판 전면 정정]

### 1.1 변수 정의 (필수 1)
- `r_i` = 파이프라인에 들어온 원입력(호출자 버퍼의 uint16 값, 온도·offset·비선형 이전).
- `z_i` = 온도·offset·비선형을 거친 이득 단계 입력.
- `g_i` = 스칼라 이득 맵 값(로드 때 범위 밖 값은 1.0 으로 바꾸고 결함 목록에 올린다).
- 포화 판정은 **`r_i ≥ L` 에서만** 한다. `z_i` 로는 판정하지 않는다.

### 1.2 마스크 생성 시점·수명·aliasing (필수 1)
- 별도 마스크 버퍼를 만들지 않는다. 포화 처리는 `pipeline_core` 안에서, 스칼라 이득 단계가 `OK` 로 끝난 직후 **한 곳**에서 일어나며 거기서 호출자 입력 `img->data`(= `r`)를 읽는다.
- 근거(코드 확인): 작업 버퍼가 필요한 경로(`widen`)는 호출자 프레임을 복사해서 쓰고, 그렇지 않은 경로는 단계마다 자기 버퍼를 만든다. `img->data` 는 파이프라인이 끝나기 전에 쓰이지 않는다(`pipeline.cpp` 마지막 복사). 이 읽기는 **파이프라인 호출 안에서만** 유효하다는 것이 계약이다.
- 단독 호출 `xpe_gain_correct`/`_in` 에는 포화 처리가 없다(원입력 `r` 을 모른다). 변하지 않는다.
- 입력이 uint16 이 아니면(float 입력 등) 포화 처리는 적용되지 않고 §1.4 의 경보 규칙을 따른다.
- 출력 버퍼가 입력과 같아도(제자리) 문제가 없다: 읽기는 이득 단계가 끝난 시점이고, 그때까지 `img->data` 는 호출자 값 그대로다(작업 버퍼 경로) 또는 별도 버퍼가 출력이다.

### 1.3 설정 키와 캘 파일 기록 [2판: 평면 키]
- 파이프라인 키 `saturationLevel`: 정수 `1..65535` 또는 문자열 `"off"`. 그 밖의 값(0, 70000, 소수, 다른 문자열, 대소문자 다른 `"OFF"`)은 `XPE_ERR_CONFIG_INVALID`. 중복 키는 기존 규칙대로 거부.
- 이득 파일 config 블록의 **최상위 평면 키** (config 읽기 도구가 최상위 스칼라만 읽으므로 1판의 중첩 객체 대신 평면 키로 바꿨다):
  `saturation_status`("determined"|"undetermined"), `saturation_level`(정수 1..65535, determined 일 때만), `saturation_method`("histogram_top_pile/1"), `saturation_min_count_frac`, `saturation_min_ratio`, `saturation_max_above_frac`, `saturation_frames_used`, `saturation_frames_total`, `saturation_decided_at`(UTC ISO 8601).
- 파일 형식 버전은 올리지 않는다(config 블록은 임의 JSON 객체).
- [3판] 이 기록의 스키마와 검증은 §1.5 에 모두 적는다. "옛 파일(없음)"은 `saturation_` 로 시작하는 키가 **하나도 없는** 경우뿐이다.

### 1.4 우선순위, "없음", 적용 범위 [2판: 필수 2·3, Q4]
- 우선순위: 명시 설정 > 파일 기록 > 없음.
- **포화 처리와 S_out 상한은 스칼라 이득 경로에서만 켠다.** 다항식 이득, 이득 없음, `bypassGain`, 입력이 uint16 이 아닌 경우에는 끈다. 이때 `saturationLevel` 이 `"off"` 가 아니면 호출당 경보 1건(`XPE_WARN_SATURATION_NOT_APPLIED`, 이유 포함)을 낸다. 다항식 경로에 단조성이나 CV=0 을 주장하지 않는다(다항식은 `x/g(x)` 가 감소할 수 있다 — Reviewer 예: g=x²).
- 스칼라 경로에서 수준이 없으면(설정 없음, 파일 기록 없음 또는 undetermined): 포화 처리 끔(현재 출력과 비트 동일), 호출당 경보 1건 `XPE_WARN_SATURATION_UNSET`. `"off"` 는 의도한 끔이므로 경보 없음. 경보는 파이프라인 호출당 최대 1건이며 하위 함수에서 중복 발행하지 않는다(경보 이름으로 구별).
- [3판] 수준이 있어도 `S_out` 을 만들 수 없으면(§1.6: 중앙값이 없거나 0·비유한값) 포화 처리를 **조용히 건너뛰지 않는다**: 포화 처리를 끄고 호출당 경보 1건(`XPE_WARN_SATURATION_NOT_APPLIED`, 이유 "S_out 을 만들 수 없음")을 낸다. `S_out` 의 값 0 은 "없음"의 표지로 쓰지 않는다 — 출력의 실제 0 과 구별하기 위해 만들 수 없는 경우를 별도 분기로 처리한다.
- 임의 기본값(12800·65535)은 넣지 않는다.

### 1.5 캘 기록 스키마와 손상된 파일 [3판 전면 정정: F303-3]
- **옛 파일(없음)**: config 블록에 `saturation_` 로 시작하는 키가 하나도 없다. 이때만 "없음"이다.
- 그 밖에는 모두 이 스키마를 따라야 하며, **일부만 있거나 위반하면 이득 파일 로드 오류**(`XPE_ERR_CONFIG_INVALID`)이고 기존 로드 상태(스냅샷)는 바뀌지 않는다. 명시 설정이 있어도 손상된 파일을 정상으로 숨기지 않는다. 알 수 없는 `saturation_*` 키도 오류다.
- 공통 필수: `saturation_status`(문자열 "determined"|"undetermined"), `saturation_method`(문자열, 비어 있지 않음), `saturation_min_count_frac`(수, 0 초과 1 이하), `saturation_min_ratio`(수, 1 이상), `saturation_max_above_frac`(수, 0 이상 1 이하), `saturation_frames_total`(정수 ≥ 1), `saturation_frames_used`(정수, 0 이상, ≤ frames_total), `saturation_decided_at`(문자열, UTC ISO 8601 `YYYY-MM-DDThh:mm:ssZ` 형식 20자). 수는 비유한값이 아니어야 한다(JSON 은 NaN·Inf 를 표현하지 못하므로 문법 수준에서 거부된다).
- `determined` 이면 `saturation_level`(정수 1..65535)이 **필수**이고 `frames_used ≥ 1`.
- `undetermined` 이면 `saturation_level` 이 **없어야** 한다. `frames_used` 는 0 이상이면 되고 **0 보다 커도 된다**(후보가 있었으나 프레임 간 불합의일 때 생긴다).
- 읽기와 쓰기가 같은 스키마를 쓴다(생성 함수가 쓰는 키는 위 목록과 같다).

### 1.6 출력 규칙과 S_out [3판 정정: F303-1]
- **모집단** [4판, 리더 결정 D3]: 기하 유효 영역(버전 2 결함 파일이 영상 영역 레이어를 가지면 그 안쪽, 없으면 프레임 전체)의 화소 중 **결함 맵(BPMap) 결함 ∪ 이득 무효(범위 [0.1, 10] 밖이라 목록에 오른 화소)를 뺀** 화소의 스칼라 이득 값. 결함 위치를 gain=1 로 바꿔 넣은 값은 쓰지 않는다. 이 선택의 근거: 결함으로 확인된 값이 중앙값을 끌지 않게 한다. 크기가 다른 결함 맵은 모집단에서 빼지 않고(적용되지 않는 맵이다) 경보 규칙은 기존과 같다.
- `median(g)` 는 모집단을 정렬한 n/2 번째 값(짝수 개 평균 아님)이다. [4판] 결함 맵과 이득 맵이 **둘 다** 모집단을 정하므로 어느 한 파일의 로드 때 계산하지 않는다: 첫 포화 처리 호출에서 (이득 맵, 결함 맵) 쌍 단위로 계산해 캐시하고, **맵이 바뀌면(둘 중 하나라도 다른 맵이 설치되면) 새로 계산한다**(캐시 키는 두 맵의 소유권 식별자). **`S_out` 은 호출마다 선택된 L 로 계산한다**(`S_out = L / median(g)`; 설정값 L 이 호출마다 다를 수 있고 이득 평면은 같다). 맵 교체 후 `S_out` 이 바뀌는 것을 시험한다.
- 카드 문구의 C 는 C′(BrightAvg 평균 규칙, 변경 없음)다. [3판] `L/median(g) = L·C′/median(B)` 라는 등가식은 **g = B/C′ 가 성립하는 같은 모집단에서만, 양의 선형 스케일일 때만** 맞다. 이득 평면은 결함 위치가 1.0 으로 바뀌어 있어 일반적으로 성립하지 않으므로 이 등가식을 일반 주장으로 쓰지 않는다(정의는 위의 `L/median(g)` 하나다).
- 모집단이 비었거나 `median(g)` 가 0 이하 또는 비유한값이면 `S_out` 을 만들 수 없다 → §1.4 의 경보 규칙(끄고 경보 1건).
- `r_i ≥ L` 인 화소 → `S_out`. 그 밖의 화소 → `min(z_i/g_i, S_out)`.
- 결함 단계와의 우선순위: 포화 처리가 먼저, 결함 보정이 나중이다. 결함 화소는 포화여도 결함 보정이 값을 정한다. 이 순서 때문에 결함 화소의 이웃이 바뀌면 결함 화소 값이 바뀔 수 있다(의도).

### 1.7 단조성의 범위 [2판: 필수 3]
- 보장은 **스칼라 이득 경로, 고정된 `g_i>0`, `z` 가 `r` 의 비감소 함수일 때** 한 화소에서 `r → 이득 단계 출력` 이다: `min(z/g, S_out)` 은 `z` 의 비감소, `r=L` 에서 `S_out` 으로 올라가거나 같다.
- `r → z`(온도·offset·비선형)의 단조성은 보장하지 않는다. 시험은 비선형을 우회한 구성에서 단언한다. 최종(결함 보정 뒤) 출력의 단조성은 주장하지 않는다.
- 다항식 경로: 포화 처리를 끄므로 단조성 주장 없음.

### 1.8 회귀 모집단과 cap [2판: 필수 4, 리더 결정 1]
- **비트 동일 대상**: `r < L`, `z/g ≤ S_out`, 결함(결함 맵 ∪ 이득 분류)이 아닌 화소.
- **의도한 영향 집합**: `r < L` 이고 `z/g > S_out` 인 화소(cap 에 걸림). 비트 동일을 요구하지 않고, 장당 개수와 변화량(최소·중앙·최대)을 따로 센다. 포화 화소(`r ≥ L`)와 결함 화소 및 그 이웃은 각각 따로 센다. 기대값을 낮춰 초록으로 만들지 않는다.

## 2. 포화값 결정 (캘 생성) [2판: 필수 5]
- 규칙 판 `histogram_top_pile/1`, 프레임별로 적용한다(프레임을 합산하지 않는다).
  - 입력: 프레임의 uint16 값. 알려진 결함 화소는 히스토그램에서 뺀다(생성 시점에 로드된 결함 맵이 있고 크기가 같을 때만; 없으면 빼지 않는다). 분모 `total` = 센 화소 수(결함 제외 뒤). `total = 0` 이면 이 프레임은 후보 없음.
  - 위쪽에서 아래로 값 `v` 를 훑는다(`v ≥ 65`; 아래 64칸이 항상 존재). 점유된 값마다: (1) `v` 보다 큰 화소 수 > `max_above_frac·total` 이면 중단(맨 위 몰림 없음). (2) 개수 `c ≥ min_count_frac·total` 이 아니면 다음 값으로. (3) `c ≥ min_ratio·max(1, 아래 64칸 중앙값)` 이면 `v` 가 후보. 중앙값은 64개를 정렬한 31·32번째 평균이다(numpy.median 과 같음). 가장 위에서 처음 만족한 값 하나가 후보이며 동률 문제가 없다.
  - 프레임 간: 후보가 있는 프레임이 ≥1 이고 그 후보들이 **모두 같은 값**이면 `determined`(그 값). 후보가 서로 다르면 `undetermined`. 후보 있는 프레임이 0 이면 `undetermined`. 후보 없는 프레임이 섞여 있는 것은 허용한다(포화까지 노출하지 않은 프레임). `frames_used` = 후보가 있는 프레임 수, `frames_total` = 전체.
  - [3판] 임계값: 키가 **없으면** 문서화된 기본값(`min_count_frac` 0.0005, `min_ratio` 50, `max_above_frac` 0.001; 2G 자료에서만 맞춘 값)을 쓴다. **명시했는데** 범위 밖(`min_count_frac ∉ (0,1]`, `min_ratio < 1`, `max_above_frac ∉ [0,1]`)·숫자가 아님·형식 오류이면 생성 함수가 `XPE_ERR_CONFIG_INVALID` 를 돌려주고 파일을 쓰지 않는다. `saturation_detection` 은 `"off"` 만 허용하며 다른 값은 같은 오류다. 기록에는 실제 사용한 값이 들어간다.
  - [3판] 추정 하한: 훑는 값은 `v ≥ 65` 이다. **1..64 의 포화는 추정하지 않는다**(그 구간에서만 몰리면 `undetermined`). 설정값 `saturationLevel` 은 1..65535 를 허용하므로 두 범위는 다르다.
  - [3판] 추가 규칙: "아래 64칸 중앙값이 0 이면 분모를 `max(1, 중앙값)` 으로 쓴다"는 것은 **리더 rev4 시험에 없는 이 설계의 추가 규칙**이다(rev4 와 같다고 주장하지 않는다). 규칙 판 이름 `histogram_top_pile/1` 은 이 추가 규칙을 포함한다. 시험으로 고정한다(중앙값 0 인 구간에서 몰림 검출).
  - `decided_at` 은 생성 시각(UTC). 자동 L 갱신은 하지 않는다.
- 취득 절차: "포화까지 노출한 bright 1장 이상"이 필요하다는 문장을 `modules/preprocess/docs/` 쪽 새 문서에 쓴다(Q6 수용: 더러운 `docs/calibration/*` 는 건드리지 않는다. 정식 캘 문서 연결은 리더가 정한다).
- **실행 시 감시 [2판, 3판 정정]**: "제한된 경보 휴리스틱"이며 **캘 규칙과 다른 정책**이다(감시용 값은 캘 기록에 저장되지 않고 코드 상수다). 포화 처리가 켜진 호출에서 16행마다 한 행의 히스토그램(결함 맵 화소 제외)에, 캘 규칙에서 `max_above_frac` 만 0.5% 로 완화한 값을 적용하고 몰림 개수가 표본에서 50개 이상이어야 한다는 조건을 더해 설정값과 다른 값에 몰림이 보이면 경보만 낸다. 값을 바꾸지 않고, 몰림을 반드시 찾는다는 보장은 하지 않는다: 16행 간격과 같은 주기의 줄무늬, 작은 밝은 영역은 놓칠 수 있고, 표본이 적은 작은 프레임은 몰림 기준(≥50개)을 못 채워 침묵한다. 시험으로 표본 누락과 오경보(설정값과 같은 값에 몰릴 때 경보 없음)를 확인한다.

## 3. 줄 결함 보간 [2판: Q7]
- 대상: 버전 1 결함 맵(결함 맵 ∪ 이득 분류 목록)의 **가로로 연속한 길이 ≥ 8 의 결함 구간**. [3판] **가로·세로 모두 출하 기본은 끔**(리더 결정 D2-4). 구현은 있고 `defectLineInterpolation` 키로만 켠다. 가로를 기본으로 켜는 것은 QA 독립 재현 뒤 리더가 가로·세로 각각 정한다. 같은 자료로 고르고 같은 자료로 평가한 수치(세로 41.484 < 50.857, 가로 48.275 ≤ 48.28)는 독립 검증이 아니며, `kMinRun=8` 도 독립 확인 대상으로 둔다. QA 독립 재현 뒤 리더가 켤지 정한다.
- 구간별로 줄 건너편(위·아래, 최대 8칸, 결함 화소는 건너뜀)의 가장 가까운 정상 화소 둘에서 선형 보간한다(소수 유지, 내림 없음). 한쪽만 있으면 그 값을 쓴다. 양쪽 다 없으면 건드리지 않고 기존 경로가 처리한다.
- 선행 패스가 처리한 화소는 `visited` 로 표시하고, 그 뒤 기존 경로는 표시된 화소를 **재군집하지 않는다**: 표시된 화소는 군집 탐색의 이웃으로도 들어가지 않으므로 이미 채운 줄 화소가 `cluster.positions` 에 다시 들어가지 않는다. 읽기는 정상 화소만이고 쓰기는 결함 화소만이라 제자리 호출에서도 안전하다.
- 키 `defectLineInterpolation`: `"off"`(옛 동작, **기본**), `"rows"`, `"rows_cols"`. 단독 호출 `xpe_defect_correct`(옵션 없음)도 옛 동작 그대로다. [3판] `kMinRun=8` 과 가로 대리 시험 48.275 ≤ 48.28 은 같은 자료로 고르고 평가한 값이며 독립 확인 전이다. 독립 재현은 수치 재현이지 새 표본으로의 일반화 증명이 아니다.
- [3판] 처리한 줄을 이웃 탐색에서 빼므로 **줄에 붙은 군집의 연결성과 원래의 군집/고립 판정이 바뀔 수 있다.** 이 영향을 받는 화소는 "의도한 영향 집합"으로 따로 센다. "군집 불변" 시험은 **줄과 떨어진** 고립·소군집만 대상으로 하고, 줄에 붙은 것은 영향 집합으로 별도 시험(값이 유한하고 줄 화소는 줄 규칙대로)한다.
- 시험: 폭 1·3 줄, 8 미만 구간·줄과 떨어진 고립·군집 비트 불변(비트 비교), 줄에 붙은 군집(영향 집합), 프레임 가장자리, 가로세로 교차(세로 켠 경우), 세로 기본 끔, 소수 유지, 잘못된 키 거부, 각각 반증 팔.

## 4. 속도
- 프로파일 완료(측정: `evidence/profile_stage4_measured.txt`). 전체 ~90 ms = 이득 18~27 + 결함 53~55 + 기타 5. 결함 단계는 영상 밖 띠(이득 분류 화소 ~36.8만)의 군집 처리가 40~50 ms.
- 최적화는 출력 비트 동일을 유지한다. 후보: 군집 판정을 이웃 검사로 치환(BFS 제거), 화소별 채움 병렬화, 이득 단계 검증 벡터화·병렬화. 각 단계는 비트 비교로 확인한다.
