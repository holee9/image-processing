## 1. 포화값 설정

### 1.1 설정 키와 단위
- 파이프라인 설정 JSON 키: `saturationLevel`. 값은 정수 화소값(pixel value), 범위 `1..65535`. 문자열 `"off"` 도 허용(명시적 끔). 범위 밖·비수·중복 키는 기존 규칙대로 `XPE_ERR_CONFIG_INVALID` (`PipelineConfig::fromJson`, `xpe_strict::parse_*` 재사용).
- 단위는 **이득 보정 전의 원시 화소값**이다(offset 빼기 전). 이 정의는 카드 문구("이득 보정 전에 raw ≥ 포화값")를 따르되, 판정 위치에 대한 확인 요청이 §1.4 에 있다.

### 1.2 캘 파일 안의 저장 형식
이득(GAIN) 파일의 config JSON 블록(`config_json`, 해시 대상)에 `saturation` 객체를 둔다. bright 프레임에서 정하는 값이므로 이득 파일이 자연스럽다. 별도 파일 형식 버전 증가는 필요 없다(config 블록은 이미 임의 JSON 객체를 허용한다 — `xcal_format.h` config 규칙, 확인됨).

```json
"saturation": {
  "status": "determined",            // "determined" | "undetermined"
  "level": 12800,                    // determined 일 때만. 화소값
  "method": "histogram_top_pile/1",  // 결정 규칙 이름과 판
  "params": {"min_count_frac": 0.0005, "min_ratio_to_below64_median": 50, "max_above_frac": 0.001},
  "frames_used": 9,                  // 근거 bright 프레임 수
  "decided_at": "2026-10-23T10:00:00+09:00"
}
```
- `undetermined` 이면 `level` 을 쓰지 않는다. 값을 지어내지 않는다.
- 기존 파일에는 `saturation` 이 없다 → "캘 파일 없음"으로 읽는다(하위 호환, 기존 파일 읽기는 변하지 않는다).
- 읽기: 이득 파일 로드 때 config 를 기존 `xpe_config_parse_block` 로 읽어 스냅샷에 `sat_level`(optional) 로 둔다. 잘못된 형식(문자열 level, 범위 밖)은 로드 거부가 아니라 "없음 + 경보"로 처리하는 것이 안전한지, 거부가 맞는지는 Reviewer 판정 요청(§6 Q3).

### 1.3 우선순위와 "없음"
명시 설정(`saturationLevel`) > 이득 파일의 `saturation.level` > 없음.
- 없음: 포화 처리 끔(현재 동작과 비트 동일). **임의 기본값(12800·65535)을 넣지 않는다.** 프레임 호출마다 경보 `XPE_WARN_SATURATION_UNSET` 1건(화소별이 아니라 호출당 1건 — 기존 "프레임당 경보 1건" 관례). 매 프레임 경보가 과한지(스냅샷 세대당 1회로 줄일지)는 §6 Q4.
- `"off"` 는 의도한 끔이므로 경보를 내지 않는다.

### 1.4 출력 규칙
기호: 화소 i 의 이득 맵 값 `g_i`(= BrightAvg_i / C′, 확인됨: 스칼라 맵은 이 모양), 출력은 `x · (1/g_i)`.
- **표시**: 이득 단계 입력 프레임 `x_raw` 에서 `x_raw ≥ L`(L = 포화값) 인 화소를 "포화"로 본다. 별도 마스크 버퍼 없이 이득 단계에서 원본 입력을 한 번 더 읽어 판정하는 방안을 우선한다(파이프라인이 호출자 버퍼를 단계가 끝나기 전에 덮지 않는다는 주석 근거, `pipeline.cpp:287`; 2단계에서 코드로 확인).
- **S_out(균일 출력값)**: `S_out = L / median_valid(g)`. 즉 포화 입력을 "전형적 화소의 이득"으로 보정한 값이다. `median_valid` 는 유효 영역(결함 맵 0, 이득 유효 범위 안) 화소의 이득 중앙값이며, 이득 맵 로드(스냅샷 생성) 때 한 번 계산해 둔다(프레임마다 계산하지 않는다). 리더 예시 정의 "포화값 × C / 유효 영역 BrightAvg 중앙값" 과 같은 식이다(`g = B/C′` 이므로 `L·C′/median(B)` = `L/median(g)`).
  - 근거: 포화는 센서가 감지한 값이 아니라 하한(≥L)이므로 어떤 이득으로 곱해도 의미가 없다. 화소마다 다른 이득을 곱하면 이득 맵 무늬가 포화 영역에 찍힌다(리더 보고: s1/026 에서 1/BrightAvg 와 상관 1.0000). 균일한 한 값으로 채우면 무늬가 없다.
  - 대안: 평균 대신 최댓값/백분위. 중앙값이 이상치(결함·가장자리)에 가장 둔하고 설명이 단순해 택한다. 다른 정의는 Reviewer 가 고르면 따른다.
- **상한 제한**: 포화가 아닌 화소의 `x · (1/g_i)` 가 `S_out` 을 넘으면 `S_out` 으로 제한한다(이득이 작은 화소가 포화 바로 아래에서 포화 화소보다 밝아지는 역전 방지).
- 결과: `y_i(x) = S_out` (x ≥ L), `min(x/g_i, S_out)` (x < L).

### 1.5 단조성 보장
같은 화소에서 raw x 가 커질 때 y 가 작아지지 않음:
- x < L 구간: `min(x/g_i, S_out)` 는 x 에 대해 비감소(이득 `g_i > 0` 는 로드 시 검증됨 — `is_valid_gain`, 확인됨).
- x → L 경계: x = L-1 의 값은 `S_out` 이하이므로 x ≥ L 의 `S_out` 으로 올라가거나 같다 → 비감소(불연속 점프는 있을 수 있다).
- 앞 단계(offset·비선형) 거침: 이 보장은 "이득 단계 입력 → 출력"과 "원시 판정"에 대해서다. offset 단계는 화소별 상수를 빼는 단조 함수이고, 비선형 단계(LUT/다항식)가 단조인지는 파일에 달렸다(미확인) → 단조성 시험은 비선형 우회 구성에서 단언하고, 비선형 켠 구성은 한계로 적는다.
- 시험: 화소 하나에 raw 를 0..65535 로 훑어 출력이 비감소임을 단언, 반증 팔은 `min` 제한을 빼면 역전이 생기는 입력으로 실패 확인.

### 1.6 고정 상수 두 개에 대한 판단
- `gain_correct.cpp:376` (65535 가정): **바꿀 필요 없음**. 실제 코드는 파일의 `dose_max` 로 제한한다. 주석을 "예: 16비트 포화 65535" 정도로 정정하는 편집만 제안(동작 불변, 2단계에서 함께). 다항식 이득 경로의 포화 화소는 §1.4 규칙이 이득 단계 앞에서 먼저 잡으므로, 12800 검출기의 포화가 다항식 평가에 닿지 않는다.
- `kLofSaturationLevel = 65500`: **12800 검출기에서는 맞지 않을 가능성이 높다**(선량 그룹 평균이 12800 에서 몰려도 65500 에 닿지 않아 "포화 → 제외"가 작동하지 않는다). 다만 이것이 실제 오검출을 만드는지는 측정하지 않았다 → 결함으로 확정하지 않는다. 처리안: 캘 생성에서 포화값을 먼저 정하고(§2), 있으면 `L − 35`(65535→65500 과 같은 여유폭, 즉 65535 검출기에서는 비트 동일) 를 쓰고, 없으면 기존 65500 을 그대로 둔다(기존 동작 보존, 임의 새 기본값 아님). 켜기 전에 12800 자료에서 이 값이 LOF 판정을 바꾸는 화소 수를 먼저 센다. 이 항목은 §6 Q5 로 Reviewer 판단을 요청한다.
- 건드리지 않는 것: `panel.adc_max`(ADC 범위, 별개 의미), `readout_validate` 65535(영향 미확인, 이 카드 범위 밖이므로 기록만).

## 2. 포화값 결정 (캘 생성 시, 2단계 구현 예정)
- 입력: bright 프레임들(결함 화소 제외). 히스토그램 65536 칸, 규칙(리더 시험 rev4, 2G 자료에 맞춰 잡은 값):
  1. 최상단에 몰린 값 v: 개수 ≥ 전체의 0.05% (`min_count_frac`)
  2. v 바로 아래 64칸 중앙값의 50배 이상 (`min_ratio_to_below64_median`)
  3. v 보다 큰 화소 ≤ 0.1% (`max_above_frac`)
  4. 알려진 결함 화소 제외
- 세 임계값은 생성 도구/함수의 옵션으로 열어 두고, 값과 판을 `params`/`method` 에 기록한다(다른 검출기에서 확인되지 않은 값이라는 점을 문서에 명시).
- 조건 불충족 → `status: "undetermined"`. 값 추정 없음.
- 취득 절차: "포화까지 노출한 bright 1장 이상"이 필요하다는 문장을 캘 문서 해당 절에 추가(위치는 2단계에서 `docs/calibration` 의 절을 찾아 확정하되, 그 폴더는 현재 더러운 파일이 있어 이번 카드는 **새 문서 파일이나 `modules/preprocess/docs/` 쪽에 쓰고** 더러운 파일을 건드리지 않는다. 지정 경로가 다르면 리더가 알려 줄 것 — §6 Q6).
- 실행 시 감시: 설정값 L 과 다른 값에 몰림이 보이면 경보만. 비용 문제: 전 화소 히스토그램은 7.9 M 화소 한 패스(수 ms)라 15 ms 목표와 충돌한다 → **다운샘플(예: 16행마다 한 행)한 히스토그램**으로 같은 규칙을 적용하고, 값은 바꾸지 않는다. 시간 영향은 4단계에서 측정해 보고한다.

## 3. 줄 결함 보간 (3단계 설계)
- 목표: BPMap(버전 1 결함 맵)에서 연속 결함 줄을 찾아 기존 `correctLines`(건너편 선형 보간, 소수 유지)에 넘긴다. 고립 결함은 지금의 4칸 평균 그대로.
- 줄 분류(결함 맵 로드 때 1회, 프레임마다 하지 않는다): 가로(세로) 방향으로 길이 ≥ `kMinRun` 인 결함 화소의 최대 연속 구간을 "줄 구간(segment)"으로 보고, 인접 행(열)이 겹치면 폭 w 의 줄 그룹으로 묶는다. w ≥ 3 은 기존 규칙대로 낮은 신뢰/거부 표시(`markLowGroups`).
  - `kMinRun` 은 근거 없이 정할 수 없다. 대리 시험(리더·QA, seed 20261023, 가로줄)에서 RMSE 를 `kMinRun` 후보(예: 2·3·5·8)마다 재어 **2G 식(48.28) 이하이면서 고립 결함을 오분류하지 않는 값**을 고른다. 이 선택은 시험 전에 확정하지 않는다.
- 적용 방식: 버전 2 레이어 경로 전체를 켜면 군집·고립 처리도 `correctBlobs` 로 바뀐다(`:888-925`). 고립 결함 비트 동일 요건을 지키기 위해 **줄 구간만 먼저 `correctLines` 로 채우고 `visited` 로 표시한 뒤 기존 v1 경로를 그대로 돌리는 선행 패스**를 택한다. 이 패스는 이미 채운 화소를 건너뛰어야 하므로 기존 `visited` 를 공유한다(2단계 아님, 3단계에서 코드로 확인).
- 소수 유지: 내림하지 않는다(`correctLines` 는 float 보간, 확인됨).
- 가로줄 평가: 리더·QA 대리 시험과 같은 seed(20261023)·표본 규칙, RMSE ≤ 48.28.
- 세로줄: 대리 시험이 없으므로 같은 방식의 세로 대리를 새로 만들어 결과를 낸 뒤에만 켠다. 그 전에는 가로만 켠 상태로 두고 세로 구간은 현 경로(변화 없음).

## 4. 속도 (4단계 설계)
- 먼저 프로파일. 도구: 이미 있는 `xpe_*` 도구/시험 하니스에 구간 타이머를 `XPE_CACHE_TEST_HOOKS` 같은 시험 전용 훅으로 두거나, 별도 계측 실행 파일을 `modules/preprocess/tools/` 에 둔다(제품 경로에 계측을 남기지 않는다). 함수 단위 표(`MaskSet` 구성, 군집 분석, `median_filter_cluster`, 보간, `nth_element` 등)를 적고 그 결과로 최적화를 고른다.
- 측정 조건 고정: 같은 기계, RelWithDebInfo, 입력 `batch-20261022-1230/in/<set>/img/001.raw`, 3072×2560 한 장, 4설정(전체/gain만/defect만/둘 다 우회) × 31회, 첫 회 제외 중앙값, RAW 인수를 로그에 남김.
- 최적화 전후 비트 동일(의도한 §1·§3 변경 제외): 전용 비교 시험.
