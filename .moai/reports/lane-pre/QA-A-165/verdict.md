# QA-A-165 (`#143`) — `131 → 122 ms`. **60 ms 에 못 들어옵니다. 카드 §2 대로 멈췄습니다**

수술은 했고 수치는 불변입니다. 다만 개선 폭이 작았고, **왜 작았는지**를 분해했습니다 — 그것이 "더 짜낼 여지가 있는가" 의 답입니다.

---

## §1 수술 — `QA-A-59` 와 같은 형태

`QA-A-59` 가 `ComputeGlobalSigma` 에서 한 것을 읽고 그대로 적용했습니다:

| `QA-A-59` 가 한 것 | `ComputeTileSigmas` 에 적용 |
|---|---|
| `reserve` + `push_back` → **인덱스 저장** | 타일 루프의 두 차분 루프 |
| `std::vector<float>(n)` → **`new float[n]`** (값 초기화 0-fill 회피) | 버퍼 할당 |
| 버퍼 **한 번** 할당 후 재사용 | 최대 타일 크기로 한 번, 타일마다 재사용 |

두 차분 루프의 **순서와 산술을 그대로 두었습니다** — 선택은 순서 무관이지만, 똑같이 두는 것이 이것을 순수 최적화로 만듭니다.

### 결과 — 3072², 이 기계

| | 시간 | 목표 `60 ms` 대비 |
|---|---|---|
| `QA-A-164` 착지 직후 | 131 ms | 2.18배 |
| **이 카드 뒤** | **122 ms** (116.7 / 125.2 / 123.2) | **2.03배** |

**7% 입니다.** `ComputeTileSigmas` 가 72 ms 인데 9 ms 만 줄었습니다.

---

## 왜 작았나 — **`push_back` 은 병목이 아니었습니다**

같은 루프에서 **선택을 빼고** 차분 생성만 재 봤습니다:

| 실행 | 차분 생성만 | 스테이지 전체 | **선택이 차지** |
|---|---|---|---|
| 0 | 7.8 ms | 74.9 ms | 67.1 ms (**90%**) |
| 1 | 5.5 ms | 68.2 ms | 62.7 ms (**92%**) |
| 2 | 5.1 ms | 69.9 ms | 64.8 ms (**93%**) |

**차분 생성은 5~8 ms 뿐이고, 90% 이상이 중앙값 선택**입니다. `push_back` 제거가 고친 것은 그 5~8 ms 쪽이었습니다.

`QA-A-59` 의 수술이 `ComputeGlobalSigma` 에서 컸던 이유는 거기가 **9.4M 회 `push_back`** 이었기 때문이고, 타일 쪽은 같은 총량을 576 조각으로 나눠 **조각마다 다른 비용**이 지배합니다.

### 선택이 비싼 이유 — **호출당 고정비**

`SelectKthSmallest` 는 호출마다 **65536 항목 히스토그램을 할당·0초기화**하고, 두 패스 사이에 **다시 0초기화**하며, 65536 버킷을 **두 번 순회**합니다. `n` 과 무관한 고정비입니다.

| | 전역 σ | 타일 σ |
|---|---|---|
| `n` | 9.4M | 32,512 |
| 호출 수 | **2** | **1,152** |

같은 총 원소를 다른 조각 크기로 나눠 재 봤습니다:

| 호출당 원소 | 호출 수 | 시간 | 원소당 |
|---|---|---|---|
| 18,874,368 | 1 | 20.5 ms | **1.1 ns** |
| 294,912 | 64 | 17.7 ms | 0.9 ns |
| **32,512** | **581** | **31.9 ms** | **1.7 ns** |

타일 크기에서 원소당 **1.55배**입니다. 타일 선택이 2회이므로 `2 × 32 ≈ 65 ms` 로 관측값과 맞습니다.

### 그래서 남은 여지가 얼마인가 — **부족합니다**

고정비를 **전부** 없앤다면(히스토그램 재사용 + 건드린 버킷만 되돌리기) 선택은 `2 × 20.5 ≈ 41 ms` 가 상한 개선입니다:

```
현재   차분 6 + 선택 65 + 검출 53  ≈ 122 ms
최선   차분 6 + 선택 41 + 검출 53  ≈  98 ms      ← 여전히 60 ms 의 1.6배
```

**60 ms 는 선택 알고리즘 자체를 바꾸지 않고는 닿지 않습니다.** 근사 중앙값(히스토그램 보간 등)으로 바꾸면 수치가 움직이고, 그것은 카드 §4 의 *"수치가 하나라도 움직이면 최적화가 아니라 변경"* 에 걸립니다.

**카드 §2 대로 여기서 멈췄습니다.** 히스토그램 재사용도 하지 않았습니다 — 그것까지 해도 못 들어오는 것이 위 계산이고, *"더 짜내지 마십시오"* 가 카드의 지시입니다.

## §4 반증 — **불변 확인**

| 항목 | 결과 |
|---|---|
| 출하 vs 프로브 스칼라 `6d` | **0 / 1,048,576** × 4 프레임 |
| FPR (5시드 pooled) | uniform·scatter·edge **7.8201e-06**, lines **2.2888e-06** — 전부 동일 |
| TPR@10σ | 1.0000 / 1.0000 / 1.0000 / 0.9865 — 전부 동일 |

## 보고 (이슈 아님 — 리더 판단 대상)

1. **`ComputeTileSigmas` 와 `ComputeGlobalSigma` 의 추정기가 다릅니다.** 전역은 수평 차분과 수직 차분을 **따로** 재고 `min` 을 취합니다(`QA-A-48` 이 구조를 피하려고 넣은 것). 타일은 둘을 **한 배열에 섞어** 하나의 MAD 를 냅니다. 한 방향으로만 구조가 있는 프레임(줄무늬)에서 `min` 은 구조를 피하고 섞기는 부분적으로 먹습니다 — **`lines` 에서 타일 σ 가 참값보다 크게 나온 관측(`QA-A-163`)의 후보 원인**입니다. 바꾸면 수치가 움직이므로 이 카드에서 하지 않았습니다.
2. **히스토그램 고정비는 `SelectKthSmallest` 의 모든 호출자에 걸립니다.** 지금 큰 `n` 으로 부르는 곳은 손해가 없지만, 작은 `n` 으로 여러 번 부르는 호출자가 생기면 같은 자리를 다시 만납니다.

## 미검증 / 잔여 위험

- **"고정비를 전부 없애면 98 ms" 는 계산이지 측정이 아닙니다.** 히스토그램 재사용을 실제로 구현해 재지 않았습니다 — 상한 추정입니다.
- **이 기계가 `spec.md:271` 의 개발 기계인지 여전히 확인하지 않았습니다.** `spec.md:5` 가 경고하는 함정이고, 기존 게이트가 절대 ms 를 버린 이유입니다. **비율은 유효, 절대값은 이 기계 것.**
- 시간은 실행 간 변동이 있습니다(116.7 / 125.2 / 123.2, 약 7%). 7% 개선은 그 변동과 같은 크기라 **한 번의 측정으로는 가릴 수 없습니다** — 분해 측정(차분 5~8 ms 대 선택 65 ms)이 개선 폭보다 신뢰할 만한 근거입니다.
- 선택 비용 측정은 **균일 난수**에 대한 것입니다. 실제 차분 분포(구조 있는 프레임)에서 radix 선택의 버킷 분포가 달라질 수 있습니다.
- **타일 크기를 바꾸면 이 균형이 바뀝니다** — 타일이 클수록 호출이 줄어 고정비가 줄지만, 카드가 탐색을 금지해 재지 않았습니다.
