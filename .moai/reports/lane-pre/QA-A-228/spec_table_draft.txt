C. REQ 문구 정정안 (spec.md 본문)
======================================================================

C-1. REQ-P1A-004 [현재] "All exported functions shall return XpeErrorCode ... (XPE_OK through XPE_ERR_NETWORK_FAILED)"
  [제안] "Every exported function that reports a status shall return XpeErrorCode, drawn from XPE_OK through XPE_ERR_INVALID_CALIB_DATA."
  (헤더에는 const char*, void, bool, XpeCalibrationMode, uint32_t 를 반환하는 함수가 있고, -16/-17 이 반환된다.) 시험: 단언 0 — 내보내기 열거 시험 필요.

C-2. REQ-P1A-003 [현재] "No global mutable state shall be modified during processing calls."
  [제안] "... other than the module alert queue." (처리 함수가 알림 큐에 쓴다.)

C-3. REQ-P1A-005 [현재] "Every exported function shall validate all pointer parameters for non-NULL"
  [제안] 예외를 적는다: xpe_preprocess_init(NULL) 은 기본 설정으로 OK, xpe_defect_detect_runtime 의 metadata 는 NULL 허용.

C-4. REQ-P1A-018 [현재] "... shall return XPE_ERR_CALIBRATION_EXPIRED if the timestamp is in the past" 와 시그니처 (filePath, expiryEpochMsOut)
  [제안] "xpe_calib_check_expiry(filepath, is_expired, remaining_days) shall report through is_expired and remaining_days (expiry == now counts as expired) and return XPE_OK; XPE_ERR_CALIBRATION_EXPIRED is returned by the loaders."
  주의: 만료 경계가 함수마다 다르다(check_expiry 는 remaining_ms <= 0, xcal_reader 는 now > expiry).

C-5. REQ-P1A-019 [현재] "XPE_ERR_CALIB_NOT_LOADED if that map is not loaded"
  [제안] "XPE_ERR_INVALID_INPUT" (xpe_calib_save.cpp:44,64,84). 또는 [결정 필요]: 코드를 CALIB_NOT_LOADED 로 바꾼다.

C-6. REQ-P1A-016a [현재] "xpe_preprocess_pipeline_ex shall ... consult calibState only for a defect map"
  [제안] REQ-105 와 같게: "calibState 는 읽지 않는다(원본 호환용 인자)." 한 문장이 다른 문장과 모순되고 있다.

C-7. REQ-P1A-015 [현재] "(with its kVp interpolation table)" — [결정 필요]: 구현하거나 문구에서 지운다. 헤더(preprocess_api.h:142-143)의 "multi-SID interpolation" 도 같이.

C-8. REQ-P1A-103 [현재] "[0.1, 10.0] 범위 검사는 적재 때 한 번 일어나고 캐시에는 그 검사를 통과한 맵만 들어간다"
  [제안] "범위 밖 화소는 결함으로 분류되어 이득 1.0 으로 대체되고, 전체의 XPE_GAIN_DEFECT_MAX_FRACTION 을 넘으면 XPE_ERR_INVALID_CALIB_DATA 로 거부한다. 캐시 엔트리는 분류 결과(gainDefects)를 함께 가진다."

C-9. REQ-P1A-087 [현재] "valid handle and a FLOAT32 buffer ... shall subtract the lag contribution"
  [제안] "보정 파라미터 4개(alpha1, tau1, alpha2, tau2)가 모두 주어진 핸들에서 lag 를 뺀다. 그렇지 않은 핸들은 형식 검사 뒤 화소를 건드리지 않고 XPE_OK 를 반환한다(QA-A-226)." (제 변경이다. 갱신 누락.)

C-10. REQ-P1A-088 [현재] 706행 "lastAcqTimeSec = 0.0 · ..." — 그 필드는 QA-A-226b 에서 삭제됐다. [제안] 필드 열거에서 지우고 "hist1·hist2 를 0 으로 채운다. 시각은 쓰지 않는다(tau 는 프레임 단위)".

C-11. REQ-P1A-096 [현재] "While a stage completes successfully ... flag"
  [제안] "고스트 단계의 플래그는 핸들이 보정된(calibrated) 경우에만, binning 단계는 binningMode > 1 인 경우에만 켠다." (pipeline.cpp:339,425)

C-12. REQ-P1A-091 [현재] "any pixel non-finite ... XPE_ERR_PROCESSING_FAILED"
  [제안] "XPE_ERR_INVALID_INPUT, 아무것도 쓰기 전에 반환하고 XPE_WARN_BINNING_INPUT_NOT_FINITE 알림을 남긴다." (binning_correct.cpp:44-50)

C-13. REQ-P1A-100 [현재] "the transition shall occur inside the gain stage"
  [제안] "게인이 바이패스되고 뒤에 float 단계가 있으면 UINT16 -> FLOAT32 변환은 파이프라인이 게인 단계 밖에서 한다(pipeline.cpp:299-315)."

C-14. REQ-P1A-086 [현재] "... rather than dereference it" — isValid 는 magic 을 읽으므로 파괴된 비-NULL 포인터에서 거짓이다. [결정 필요]
  선택 1: 문구를 "NULL 만 보호한다. 파괴된 핸들의 사용은 미정의 동작"으로 바꾼다. 선택 2: 핸들 레지스트리를 둔다(크게 바뀐다).

C-15. REQ-P1A-013 [현재] 시그니처 (img, defectMapOut, configJsonOrNull), hampel_threshold 3.0~10.0
  [제안] 시그니처 (image, metadata, defect_map_output)로 고치고 hampel_threshold 문단을 삭제(이 진입점은 설정을 받지 않는다). 287~292행의 TPR 수치(0.9865)는 줄무늬 프레임 한정으로 다시 적는다(균일 프레임 TPR 은 1.000000, test_runtime_detection_rates.cpp:317-329).

C-16. REQ-P1A-010 "Algorithm" 줄의 `_mm256_subs_epu16` — 실제는 float 경로(_mm256_cvtepi32_ps, _mm256_sub_ps, +0.5 반올림). 시험 RoundsHalfUpAfterFloatOffsetSubtraction 이 그것을 고정한다. [제안] 줄을 현재 구현으로 바꾼다.

C-17. REQ-P1A-011 "UINT16 output: no overflow/wraparound at pixel = 65535" — 같은 REQ 가 FLOAT32 결과만 쓴다고 말한다. [제안] 줄 삭제.
