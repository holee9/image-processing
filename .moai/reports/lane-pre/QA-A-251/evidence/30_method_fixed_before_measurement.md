# QA-A-251 — 결함 화소 맵 평가 도구: 주입 사양과 채점 정의 (도구 구현·측정 전에 고정, 먼저 커밋)

이 문서는 도구를 만들기 전에, 그리고 1판 기준값을 재기 전에 쓴다. 결과를 본 뒤 이 문서의 사양과 정의를 바꾸지 않는다. 바꿔야 한다고 판단되면 리더에게 보고만 한다. 이슈 #273, 요구 SRS-CALIB-001 v1.4 FUNC-022·023·039.

## 0. 왜 이런 도구인가

정답 결함 맵이 없다 (AAPM TG-150 §4.3.8). 그래서 위치를 아는 결함을 실제 프레임에 심고, 어떤 맵이 그것을 얼마나 찾는지 잰다. 이 도구가 재는 1판 결과가 이후 B16 합격 수치의 기준이 된다. 도구는 맵을 만드는 쪽(1판, 이후 2판)과 독립이다. 맵 파일 하나(결함 코드 0 = 정상, 그 밖 = 결함)만 받는다.

## 1. 정의와 약속

| 용어 | 뜻 |
|---|---|
| 화소값 | 디텍터 원시 출력값 (offset 보정 전, uint16) |
| D(x,y) | 생성에 쓰는 다크 프레임들의 화소별 평균 (결함을 심기 전 값). 한 번 계산해 모든 프레임의 주입에 공통으로 쓴다 |
| n | 프레임 값 − D (밝은 영상에서는 신호, 다크에서는 잡음) |
| σ_t | 다크의 시간 잡음 대표값: 프레임마다 전체 평균과 행 평균을 뺀 뒤, 화소별로 프레임 사이 표준편차를 구해 화소 전체의 중앙값을 취한 값. 도구가 재서 truth 파일에 적는다 |
| 정답 영역 | 심은 결함이 차지하는 화소 |
| 대조군 | 결함이 아닌 띠. 맵에 들어가면 오검출 |

주입은 값을 `[0, 65535]` 로 자르고 가장 가까운 정수로 맞춘다. 모든 무작위는 시드에서 결정된다 (같은 입력·시드·옵션이면 출력 바이트가 같다). 배치용 난수와 프레임별 잡음 난수를 따로 둔다 (프레임별 잡음 난수 = 시드와 파일 이름에서 정함).

## 2. 주입 사양 (사양 버전 1)

모든 결함은 생성 입력 프레임 전체(다크·밝은 영상)와 평가 프레임에 **같은 위치**로 심는다. 종류에 따라 다크, 밝은 영상, 또는 둘 다에 작용한다.

### 2.1 화소 결함 (화소 하나, 단계별 64개)

| 종류 | 단계 | 작용 |
|---|---|---|
| `dead` (신호 소실) | a = 1.0, 0.5 | 밝은 영상만. v = D + (1 − a)·n |
| `hot` (다크 수준 상승) | h = 200, 100, 50, 25 | 모든 프레임. v = v + h (화소값 단위) |
| `noisy` (잡음 이상) | m = 4, 2, 1 | 모든 프레임. 프레임마다 새 잡음 N(0, (m·σ_t)²) 를 더함 |
| `slope` (기울기 이상) | g = 0.75, 0.9, 1.1, 1.25 | 밝은 영상만. v = D + g·n |
| `nonlinear` (직선성 이상) | c = 0.4, 0.2 | 밝은 영상만. v = D + n·(1 − c·n / 30000) |

단계 15개 × 64 = 960 화소.

### 2.2 결함 덩어리 (정사각형, 단계별 16개)

크기 2, 3, 4, 8 화소 변 × `dead` 정도 a = 1.0, 0.5 (작용은 2.1 의 dead 와 같음). 8 조합 × 16 = 128 덩어리.

### 2.3 라인 결함 (참 결함)

모델 × 단계: `dead` (a = 1.0, 0.5), `nonlinear` (c = 0.4, 0.2), `noisy` (m = 4, 2) — 작용은 2.1 과 같고 라인의 모든 화소에 적용한다. 각 모델 단계마다 모양 6가지: 행 전체, 열 전체, 행 일부(길이 = 높이/4), 열 일부(길이 = 너비/4), 인접 두 행, 인접 두 열 → 6 × 6 = 36 항목. 거기에 교차 3항목 (행 전체와 열 전체가 한 점에서 만남): `dead` a=1.0, `nonlinear` c=0.4, `noisy` m=4. 참 라인 항목 합계 39.

### 2.4 대조군 띠 (정상 줄무늬, 폭 1, 행 전체와 열 전체 각각)

| 종류 | 단계 | 작용 | 왜 결함이 아닌가 |
|---|---|---|---|
| `fixed_band` | h = 100, 30 | 모든 프레임에 일정한 더하기 | offset 보정이 없앤다 |
| `gain_band` | g = 0.8, 1.2 | 밝은 영상만 v = D + g·n | gain 보정이 없앤다 |
| `varying_band` | s = 20, 8 | 모든 프레임, 띠 전체에 프레임마다 같은 무작위 값 N(0, s²) | 프레임마다 바뀌는 행·열 잡음. 맵이 아니라 실행 중 보정의 몫 (TG-150, 연구 노트 6.2절) |

3종 × 2단계 × 2방향 = 12 항목.

### 2.5 배치

- 가장자리에서 32 화소 안쪽에만 둔다.
- 라인(대조군 포함)은 서로 행·열 번호가 24 이상 떨어지게 둔다. 두 줄 라인은 인접 두 번호를 한 자리로 센다. 교차 항목의 행과 열도 같은 규칙을 따른다.
- 화소·덩어리 결함은 모든 라인 항목의 행·열 번호에서 4 화소 이상 떨어지고, 서로 8 화소(체비쇼프 거리) 이상 떨어지게 둔다.
- 제외 영역: 지정한 맵(장비 회사 맵, 1판 맵)에서 결함인 화소와 그 주위 3 화소. 이 안에는 화소·덩어리·라인 부분 구간(길이만큼의 선분)이 들어가지 않는다. 전체 라인의 행·열 번호는 제외 화소가 있는 번호를 피해 고른다.
- 후보 위치는 시드로 정한 순서로 뽑고, 규칙을 어기면 버리고 다시 뽑는다.
- 기본 개수는 위와 같고 (`--pixels-per-level 64`, `--blocks-per-level 16`), 시험용 작은 프레임을 위해 옵션으로 줄일 수 있다. 옵션 값은 truth 파일에 기록된다. 기준값 측정에는 기본값을 쓴다.
- 기준값 측정의 시드는 **251**.

### 2.6 산출

`truth.json`: 사양 버전, 시드, 옵션, 프레임 크기, σ_t, 항목표 (번호, 분류 `pixel|block|line|control`, 종류, 단계, 모양, 위치·길이), 입력 파일 sha256. `truth_ids.u16`: 항목 번호 지도 (0 = 없음, 겹침은 나중 항목이 덮되 항목표에 겹침 화소 수를 기록). 주입된 프레임은 입력과 같은 이름으로 `frames/` 에 쓴다.

## 3. 채점 정의

입력: 맵 (결함 코드 uint8, 0 = 정상), truth. 채점은 맵의 "결함 여부"만 쓴다 (코드 값이 아니라 0 이 아닌지).

### 3.1 검출률 (종류·단계별)

- 화소 항목: 그 화소가 결함이면 검출.
- 덩어리 항목: 덩어리 화소의 50 % 이상이 결함이면 검출. 전부 결함인 비율도 함께 적는다.
- 라인 항목 (모양마다): 다른 항목과 겹치지 않는 라인 화소 중 50 % 이상이 결함이면 검출. 라인 화소 재현율(결함으로 표시된 비율)도 함께 적는다.
- 보고: 화소·덩어리는 종류 × 단계, 라인은 모델 × 단계 × 모양. 분수 `검출/항목`과 비율.

### 3.2 오경보

- 정답 영역을 사방 2 화소씩 넓힌 영역 밖에서 결함인 화소 수 N_out.
- 같은 정의를 주입 전(깨끗한) 프레임에서 만든 맵에 적용한 값 N_out(깨끗한).
- 새 오경보 = 주입 실행의 맵에서 결함이고, 깨끗한 맵에서는 결함이 아니고, 넓힌 정답 영역 밖인 화소 수. 이 값이 주입이 만든 오경보다. 100만 화소당 비율도 적는다.

### 3.3 대조군 오검출

대조군 항목마다 (다른 항목과 겹치지 않는 화소 중) 결함으로 표시된 비율을 적는다. 50 % 이상이면 그 항목은 **오검출**. 같은 띠 위치에서 깨끗한 맵의 비율도 함께 적는다 (자연 결함 몫). 요약: 12 항목 중 오검출 개수.

### 3.4 프레임 절반 분할 일치도

생성 입력을 역할마다(다크, 결함 맵용 밝은 영상) 순서대로 번호 매겨 짝수 번째와 홀수 번째로 나눠, 절반마다 맵을 만든다 (절반의 프레임 수가 최소 프레임 수보다 적으므로 최소 프레임 수 설정을 절반 크기로 낮춘다. 그 밖의 설정은 기본값). 두 맵의 Jaccard = |A ∩ B| / |A ∪ B| (결함 화소 집합). 전체, 정답 영역 안, 정답 영역 밖으로 나눠 적는다.

### 3.5 보정 오차 (국소 잡음 대비)

평가 밝은 영상(생성에 쓰지 않은 프레임)의 최종 출력(앱 구성, `xpe_preprocess_pipeline_out`)을 쓴다. 깨끗한 쪽 = 깨끗한 보정 세트(깨끗한 프레임으로 만든 offset·gain·결함 맵)로 깨끗한 평가 프레임을 처리한 출력 C. 주입 쪽 = 주입 보정 세트로 주입 평가 프레임을 처리한 출력 I. 정답 영역 화소마다 z = (I − C) / σ_loc, σ_loc = C 의 11×11 창 표준편차. 종류 × 단계별로 |z| 의 중앙값과 95 백분위수를 적는다. 기준선으로 같은 계산을 결함 보정을 끈 출력(`bypassDefect`)에도 한다. 값이 유한하지 않은 화소는 따로 센다. 대조군 띠는 이 지표에서 뺀다.

### 3.6 보정 후 라인 지표 D_n (TG-150 §4.3.9 방법 A)

평가 밝은 영상의 최종 출력 S 에서, 라인 항목(참 라인과 대조군)마다: 항목 범위 안(선을 따르는 구간)의 평균 프로파일 P 를 구하고, 항목의 첫 번호보다 하나 앞 라인과 마지막 번호보다 하나 뒤 라인의 같은 구간 프로파일을 이웃으로 삼아 D = P_항목 − (P_앞 + P_뒤)/2. 두 줄 항목은 두 줄의 평균을 항목 프로파일로 쓴다. 무상관 예측 표준편차 σ_pred = σ_pix · √1.5 / √N (N = 구간 화소 수, σ_pix = 앞 이웃 라인에서 S(i) − (S(i−1) + S(i+1))/2 의 표준편차 / √1.5). 보고: D/σ_pred (부호 있음), |D| > 3·σ_pred 인 항목 수 (기준 ±3배). 비교용으로 결함 보정을 끈 출력과 깨끗한 출력의 같은 위치 값도 적는다. 항목 밖의 일반 행·열에 대해서도 |D| > 3·σ_pred 인 행·열 수를 적는다 (자연 결함 몫).

### 3.7 사용하지 않는 것

합격·불합격은 이 카드에서 판정하지 않는다. 이 도구가 내는 수치의 1판 값이 이후 합격 수치의 기준이다.

## 4. 1판 기준값 측정 절차 (한 번, 순서대로, 한 번에 프로세스 하나)

입력: cyan_test 의 `calfiles`.

| 역할 | 프레임 |
|---|---|
| 생성 다크 | `Dark_08` ~ `Dark_14` (7장, 첫 장 `Dark_07` 제외) |
| 게인용 밝은 영상 | `Bright_23` ~ `Bright_28` (한 선량) |
| 결함 맵용 밝은 영상 | `Bright_17` ~ `Bright_28`, `Bright_31` ~ `Bright_36` (18장, 선량 혼합) |
| 평가 밝은 영상 | `Bright_29`, `Bright_30` |

1. 깨끗한 프레임으로 보정 세트 생성 (`xpe_calib_fixture_gen`, QA-A-250c 와 같은 방식) → 깨끗한 세트 (offset, gain, 결함 맵).
2. 주입: 깨끗한 세트의 결함 맵과 장비 회사 맵(`BPM.raw`)을 제외 영역으로 하여 시드 251 로 생성 입력과 평가 프레임에 주입.
3. 주입된 프레임으로 보정 세트 생성 (같은 방식) → 주입 세트.
4. 주입된 프레임을 짝수/홀수 절반으로 나눠 1판 결함 맵 두 개 생성.
5. 채점 (3.1~3.4), 보정 오차·D_n (3.5, 3.6).

`xpe_bpm_generate` 설정은 기본값 (λ = 8, 32×32, ±7 %, 128×128). 만료일 4102444800000.

## 5. 실행 범위

도구 단위 시험과 위 측정 한 번. 한 번에 하나, 각 실행 뒤 남은 프로세스 0. 전체 스위트는 돌리지 않는다. push 하지 않는다.
