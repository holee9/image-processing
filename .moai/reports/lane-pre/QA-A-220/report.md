# QA-A-220 — #230 REQ-P1A-013 성능 재측정: 215 의 유한성 검사가 런타임 검출 시간을 바꿨나 (보고서만, Refs #230)

기준: dev/preprocess `cb537ea8`(215·217·218b·219 포함). 코드 변경 없음. 증거: `evidence/`.

## 결론

1. **바뀌었다 — 약 +2~3.5 ms (2~4 %)**. 같은 세션에서 번갈아 24회씩 잰 결과 215 전보다 후가 느린 라운드가 24개 중 **19개**, 짝지은 차이의 중앙값 **+2.1 ms**, 평균 **+3.4 ms**, 최소 관측은 83.8 → 86.3 ms(**+2.5 ms**, ×1.030). 방향이 일관되고 크기가 작다.
2. **그 증가는 프레임을 한 번 더 읽는 것(37.7 MB)과 맞는다 — 단, 분리해서 재지는 못했다.** 메모리 대역 하한만으로는 약 1.1 ms(37.7 MB ÷ 34.5 GB/s, QA-A-166 의 대역폭)이고, 입구 검사 루프가 스칼라라서 계산 쪽 하한은 그보다 크다. 214b 가 결함 단계에서 잰 +1.3 ms 보다 이번 +2.1~2.5 ms 가 큰 것은 이 기계가 두 모드를 오가는 잡음(아래) 안에서 구별되지 않는다.
3. **"1.59배"는 지금 코드에 대한 값이 아니다 — 215 와 무관하게.** 같은 하네스(215 전 코드 포함)가 오늘 이 기계에서 최소 83.8 ms 를 낸다(QA-A-168 은 121.2 ms). 세션 사이에 절대 ms 가 옮겨 가지 않는다는 QA-A-174 의 규칙 그대로이고, 76 ms 하한 자체를 오늘 다시 재지 않았으며 그 하한을 쓰는 비율은 QA-A-174 가 이미 **"판정 불가"** 로 기록했다. 따라서 이 카드는 새 비율 판정을 내리지 않고, 215 가 만든 **상대 변화(×1.03)** 만 보고한다.
4. **TPR·FPR 은 그대로**: 줄무늬 프레임 10σ TPR 0.986472(948/961), 균일 10σ 1.000000(961/961), 깨끗한 프레임 FPR 4.768e-06(5/1,048,576) — 215 전·후 DLL 에서 **소수점 아래 전부 같다**(`evidence/20_`).

## 방법

- **하네스**: `A173Gate.DISABLED_ShippedWhole`(`test_zz_a173_gate.cpp`) — 3072×3072 FLOAT32 잡음 프레임(3000 ± 10), 출하 `xpe_defect_detect_runtime` 워밍업 1회 뒤 **12회 관측, 최솟값**, AVX2·단일 스레드(출하 경로), 기계 `12th Gen Intel Core i7-12700`(QA-A-168 과 같은 모델). **QA-A-168 의 하네스 파일은 저장소에 따로 없고**, 이 하네스가 같은 모양(12회 최솟값, 3072², 출하 진입점)이라 썼다 — 프레임 내용이 168 과 같은지는 확인하지 못했다.
- **215 전/후**: 카드가 말한 `76b8ac4b` 를 통째로 다시 빌드하는 대신, 현재 트리에서 `runtime_detection.cpp` 만 `76b8ac4b` 판으로 되돌려 빌드한 DLL(**전**)과 현재 빌드(**후**)를 비교했다. `76b8ac4b..HEAD` 의 이 경로 차이가 정확히 215 의 14줄뿐임을 `git diff --stat`(`runtime_detection.cpp | 14 +`)로 확인했고, 되돌린 뒤 소스를 원래대로 복원해 `cmp` 로 동일함을 확인했다(`helpers.cpp` 의 새 함수 `xpe_find_nonfinite` 는 되돌린 쪽에서 쓰이지 않는다). 두 빌드는 시험 실행 파일을 포함해 별도 디렉터리에 복사해 두고 각자 자기 DLL 을 읽게 했다.
- **번갈아**: 프로세스 하나가 두 빌드를 못 담으므로, 라운드마다 순서를 뒤집어(홀수 라운드 전→후, 짝수 후→전) **24 라운드 × 2 빌드 = 48 프로세스**, 프로세스당 12회 관측(`evidence/10_perf_alternating.txt`, 요약 `11_perf_summary.txt`).
- 출력 맵 해시(`fnv`)는 전·후 모두 `68dfffca3cdb2a4d` — 유한 프레임의 검출 결과는 비트 동일.
