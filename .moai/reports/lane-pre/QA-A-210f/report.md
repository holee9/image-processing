# QA-A-210f — 결함 화소가 있는 실데이터에서 게인 교정이 막히는가: 스칼라 경로와 나란히 (측정만, Refs #233)

기준: `b7a1b26f`(dev/preprocess). 코드 변경 없음. 증거: `evidence/` (측정 스크립트 `10_m210f.py`, `12_m210f2.py`와 출력 전문). 스칼라 생성기는 QA-A-209~210e 어디서도 바뀌지 않았다.

## 결론 (먼저)

1. **CalData_6 에서는 스칼라 경로도 막힌다 — 다항식 경로보다 훨씬 이르고 넓게.** `xpe_calib_generate_gain` 은 결함 화소(와 가장자리 저감도 화소)를 아무 처리 없이 쓰고, `xpe_calib_load_gain` 의 범위 검사 [0.1, 10.0] 가 맵 **전체**를 `INVALID_CALIB_DATA` 로 거부한다. 6개 준위 전부, 걸린 화소 39,077 ~ 44,144 개(0.41~0.47%).
2. **걸린 화소의 대부분은 결함 맵 밖이다**(준위당 25,489~29,868 개, 약 2/3). 위치로 보면 **99.9~100% 가 프레임 가장자리 64 화소 띠** 안(띠는 프레임의 8.16%)이고 값은 0.017~0.09(저감도). **띠와 결함 맵을 모두 벗어난 화소는 0 개.** 즉 이 데이터에서 스칼라 경로를 막는 것은 죽은 화소만이 아니라 **가장자리의 낮은 감도 영역**이다.
3. **다항식 경로는 그 화소들을 막지 않는다**(적용기 범위 [0.001, 1000] 만 검사하므로 게인 0.017 은 통과). 다항식 경로가 막힌 42 화소는 게인이 0 이거나 수백인 결함 화소뿐이다. 두 경로는 지금 **서로 다른 범위**를 강제한다: 스칼라 = SRS 의 [0.1, 10](적재 시), 다항식 = 적용기의 [0.001, 1000](생성 시). 같은 철학이 아니다.
4. **정상 데이터(cyan_test, 결함 250 화소)에서는 두 경로 모두 문제없다**: 스칼라 맵 5개 모두 범위 안, 적재 `OK`, `xpe_gain_correct` `OK`, 출력 유한.
5. 결함 단계는 게인 단계 **뒤**에 있고, 결함 보정은 결함 화소의 값을 **읽지 않고 덮어쓴다** — "결함 화소의 게인은 보정된 출력에 영향이 없다"는 성립한다(단 아래 조건). 그러나 적용기가 게인 단계에서 **프레임 전체**를 거부하므로, 결함 보정이 덮기도 전에 무효 게인 하나가 프레임을 막는다.
6. SRS·REQ 에 결함 화소의 게인 처리를 정한 문장은 **없다**.

## 1. 스칼라 경로, 단계별 (`11_scalar_path_on_defect_data.txt`, `13_caldata6_range_failures_detail.txt`)

생성 → 맵 범위 → 적재 → 적용. 맵은 `xpe_calib_generate_gain` 이 준위당 1프레임으로 만든 것(CalData_6: 영 dark, 준위는 평균 순서 03,04,05,06,01,02 — `bright*` 는 이미 오프셋 보정값이고 선량은 저장소에 없다, README 정정 2026-09-19).

### 생성기는 결함 화소에 무엇을 쓰나 (`xpe_calib_generate_gain.cpp`)

`accum` 은 `max(flat − dark, 0)` 의 평균, `gain_raw = float(accum / N)`(비유한이면 0), 전체 평균으로 나눠 단위 평균으로 정규화, 비유한 결과만 `1.0`(중립 게인)으로 바꾼다. **클램프도 결함 처리도 없다**: 죽은 화소(신호 0)는 게인 **0**, 매우 밝은 화소는 수십~수백이 그대로 저장된다. (결과 맵의 값은 REQ-P1A-011 이 정한 "정규화 감도 S = 1/G" 규약이고, 적용기가 `1/S` 를 쓴다.)

위치·크기(`13_caldata6_range_failures_detail.txt`): 걸린 화소 중 0.1 미만이 대부분(43,836~, 정확히 0 은 1~2 개), 10 초과는 0~37 개. **99.9~100% 가 가장자리 64 화소 띠 안**이며, 결함 맵 밖의 걸린 화소의 값은 중앙값 0.04(5% 0.017, 95% 0.092). 결함 맵 23,505 개 중 22,665 개가 같은 띠 안에 있다 — 이 데이터셋은 가장자리가 통째로 저감도·결함 영역이다. 결함 맵 화소 중 **범위 안인 것이 39~42%** (9,230~9,917 개): 결함 맵과 범위 위반은 같은 집합이 아니다.

적재가 거부하므로 `xpe_gain_correct` 단계는 도달하지 못한다(적재 실패, 스토어는 그대로).

### cyan_test (결함 `BPM.raw` 250 화소 = 0.0026%)

5개 준위 모두: 맵 범위 0.696~1.157, SRS 범위 밖 0 화소(결함 화소의 게인도 0.807~1.115), 적재 `OK`, `xpe_gain_correct`(그 준위 자신의 프레임) `OK`, 출력 유한.

## 2. 파이프라인 순서와 "결함 화소 게인은 상관없나"

- 순서 (`pipeline.cpp`): `Stage 4: Gain Correction (PRE-03)` (`xpe_gain_correct_in`, 약 250~266 행) → `Stage 5: Binning` (기본 꺼짐, `binningMode > 1` 일 때만) → `Stage 6: Defect` (`xpe_defect_correct_in`, 약 318~350 행) → `Stage 7: Ghost`. 결함 단계는 게인 단계 **뒤**다.
- 결함 보정은 결함 화소를 덮어쓰고 그 값을 읽지 않는다 (`defect_correct.cpp` ~226~232 행의 주석과 커널): "This function WRITES only pixels the defect map marks (`dm[idx] != 0`), and both correction kernels READ only pixels it does not". 따라서 **결함 맵에 든 화소의 보정 후 게인 값은 출력에 영향이 없다** — 조건은 (a) 그 화소가 결함 맵에 있고 (b) 결함 단계가 우회되지 않았고 (c) 비닝이 켜져 있지 않을 것(비닝은 결함 보정 전에 이웃을 섞는다).
- **그러나 그 전에** 적용기가 `is_valid_gain` 으로 프레임의 모든 게인을 검사해 하나라도 무효면 프레임 전체를 `CONFIG_INVALID` 로 거부한다(`gain_correct.cpp` ~423 행). 결함 화소의 게인이 0 이면 결함 보정이 덮기도 전에 프레임이 막힌다. 그래서 "무엇이든 상관없다"는 **유한하고 적용기 범위 안인 값**에 한해서만 성립한다.
- 결함 맵에 없는 저감도 화소(CalData_6 가장자리의 결함 맵 밖 약 2/3)는 결함 단계가 덮지 않는다. 그 화소의 게인이 0.04 라면 보정 후 값이 그대로 25배로 증폭된다 — 스칼라 적재가 [0.1, 10] 으로 막는 것이 바로 이 경우다.

## 3. 요구·SRS 에 결함 화소의 게인 처리 문장이 있는가

**없음.** 검색 범위: `docs/calibration/*.md`, `docs/project/*.md` (SRS-CALIB-001, RTM, SAD, SHA, README, xray-detector-calibration-prd 포함), `.moai/specs/SPEC-XPE-P1A/{spec,acceptance,research,progress}.md`; 패턴 `(defect|bad pixel|BPM|dead|defective)` 와 `gain` 이 60자 안에 함께 나오는 줄과 두 낱말이 같은 줄에 있는 줄. 읽은 관련 문장은 다음뿐이고 어느 것도 결함 화소의 게인을 정하지 않는다:

- **SRS-CALIB-FUNC-002**: "Values shall be in range [0.1, 10.0]; out-of-range values shall trigger `XPE_ERR_INVALID_CALIB_DATA` error." — 범위 위반의 처리는 정했지만 어느 화소가 위반하는지(결함 화소 포함)는 말하지 않는다. 근거란: "Range limits prevent over/under-correction artifacts."
- **SRS-CALIB-FUNC-026**: 알고리즘 (1) dark 빼기 (2) 화소별 평균 (3) 전체 평균으로 정규화 (4) 메타데이터 저장 — 결함 화소를 제외하거나 대체한다는 말이 없다.
- **REQ-P1A-011** (`spec.md`): `I_corrected = I_offset · G`, 저장 규약 S = 1/G; 결함 화소 언급 없음. **REQ-P1A-012** 는 결함 보정(양선형 + 군집 대체, 재현율 99%+) 이고 게인과의 상호작용을 정하지 않는다.

즉 시스템의 결함 화소 게인 정책은 **요구가 아니라 구현의 부산물**이다: 스칼라(적재 시 SRS 범위 [0.1,10]), 다항식(생성 시 적용기 범위 [0.001,1000]), 적용기(프레임 전체 거부).

## 6. 미검증 (Gaps)
