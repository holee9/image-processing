## 가설 판정 — **틀렸습니다**

제 `QA-A-166` 가설은 *"radix 가 상위 16비트로 나누니 동적 범위가 좁으면 2차 패스가 커진다"* 였습니다.

| 입력 | 동적 범위 | **점유 버킷** | **2차 패스** |
|---|---|---|---|
| 실제 타일 차분 | 117.6 | **2,209** | 1 / 32,512 (0.0%) |
| 격리 벤치 `N(0,1)` | 7.871 | **2,214** | 3 / 32,512 (0.0%) |
| 실제 `\|x−median\|` | 60.26 | 1,235 | 96 (0.3%) |
| 벤치 `\|x−median\|` | 4.017 | 1,254 | 84 (0.3%) |

**동적 범위는 15배 다른데 점유 버킷은 0.2% 차이입니다.** 제 가설이 놓친 것은 **float 키의 구조**입니다 — 상위 16비트는 부호·지수·가수 상위를 담으므로, 버킷 수를 정하는 것은 값의 **절대 범위가 아니라 몇 자릿수에 걸쳐 있는가**입니다. 두 입력 다 정규분포라 자릿수 분포가 닮았고, 그래서 버킷도 닮았습니다.

**2차 패스는 양쪽 다 0.3% 미만**입니다 — 가설이 지목한 바로 그 양이 차이를 만들지 못합니다.

### 같은 루프로 재면 1.04배입니다

```
[a167] selection over 576 tiles, input = real tile differences  :   64.82 ms
[a167] selection over 576 tiles, input = isolated bench N(0,1)  :   67.56 ms
[a167] ratio bench/real = 1.04x
```

**입력을 바꿔도 시간이 거의 같습니다.** 1.5배는 입력 때문이 아니었습니다.

## 진짜 원인 — **측정이 이중 모드입니다**

같은 실행 파일, 같은 인자, 같은 시험을 네 번 돌렸습니다:

```
[a166]   shipped SelectKthSmallest     65.50 ms
[a166]   shipped SelectKthSmallest     96.19 ms
[a166]   shipped SelectKthSmallest     65.35 ms
[a166]   shipped SelectKthSmallest     96.17 ms
```

**무작위 산포가 아니라 두 값 사이를 오갑니다.** 각 모드 안의 재현성은 0.2% 이하이고, 두 모드의 비율은 **96.2 / 65.4 = 1.47배** — 해소하려던 **1.5배와 같은 수**입니다.

`QA-A-166` 의 `97.28` 은 느린 모드에서, in-situ 의 `63` 은 빠른 모드에서 잡힌 것입니다. **두 측정 모두 옳았고, 서로 다른 모드를 봤습니다.**

### 이 기계는 하이브리드입니다 — 다만 확정하지 않았습니다

```
12th Gen Intel(R) Core(TM) i7-12700
NumberOfCores 12   NumberOfLogicalProcessors 20
```

12코어 / 20스레드는 **8 P-코어(SMT) + 4 E-코어** 구성입니다. **스레드가 어느 종류에 놓이느냐가 두 모드를 만든다**는 것이 가장 그럴듯한 설명이고 비율도 맞지만, **친화도를 고정해 재지 않았으므로 확정하지 않습니다.**

3072² 출하 시간은 같은 형태가 아닙니다 — 120.8 / 124.9 / 125.6 / 127.7 / 135.5 / 144.3 으로 **연속 분포**입니다. 실행이 길어 코어 이동이 평균화된 것으로 보이지만, 이것도 측정하지 않은 설명입니다.

## 덤 — **이 기계가 `spec` 의 개발 기계입니다**

`QA-A-164`·`165`·`166` 에서 제가 계속 *"이 기계가 spec 의 개발 기계인지 확인하지 않았습니다"* 로 남긴 질문입니다.

`spec.md` 의 `QA-A-84` 주석이 개발 기계를 **`i7-12700`** 으로 적고 있고, 위 조회가 이 기계를 **`12th Gen Intel(R) Core(TM) i7-12700`** 으로 답합니다.

**같은 모델입니다.** 따라서 이 레인이 보고해 온 절대 ms 는 `spec` 이 말하는 기계의 값입니다 — 제가 세 카드에 걸쳐 달아 온 유보를 **닫습니다.**

> 다만 **같은 모델이지 같은 개체라는 증명은 아닙니다.** memcpy 가 `QA-A-56` 의 40.7 GB/s 대비 35.9 GB/s(0.88배)로 나온 것은 같은 모델 안의 상태 차(메모리 구성, 동시 부하)로 설명될 수 있고, 위 이중 모드가 그런 차이를 얼마나 만드는지 보여 줍니다.

## 미검증 / 잔여 위험

- **이중 모드의 원인을 확정하지 않았습니다.** P/E 코어 배치가 가장 그럴듯하고 비율도 맞지만, **친화도를 고정해 재지 않았습니다.** 다른 설명(주파수 상태, 캐시 점유)도 배제하지 못했습니다.
