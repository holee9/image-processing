== FUNC-036
| **SRS-CALIB-FUNC-036** | **Verification metrics shall distinguish "failed" from "could not be measured."** Every `xpe_verify_*` function shall report, separately from its pass/fail result, whether each metric was actually measured. A metric that could not be measured shall never be reported as a measured value, and shall not on its own produce a pass. Until a dedicated status field exists, an unmeasurable metric shall set `overall_pass = false` on every verification path. | A single boolean cannot carry three states (passed / failed / unmeasurable), and collapsing the third into "passed" lets an unverified frame through. Observed 2026-09-28 (`#219`): `xpe_verify_offset` reported `overall_pass = true` for a uniform frame while `xpe_verify_gain` reported `false` for the same situation, and a test named for correction quality never exercised it. | Test: unit — each verification path on an unmeasurable input yields `overall_pass = false`; control — the same path on a measurable input yields a measured value |

== FUNC-038
| **SRS-CALIB-FUNC-038** | **Management-surface APIs shall carry a lifetime and error contract, traced as one requirement rather than one each.** The exported functions that administer state rather than deliver a calibration capability — cache control (`xpe_calib_cache_clear`, `xpe_calib_cache_set_max_size`), configuration getters (`xpe_calib_get_max_points`, `xpe_calib_get_poly_degree`, `xpe_calib_get_quality_meta`), lifetime (`xpe_calib_state_release`), initialization query (`xpe_preprocess_is_initialized`), and batch dispatch (`xpe_preprocess_pipeline_batch`) — shall each state, in the header at the declaration: who owns any returned memory, whether the call is valid before `xpe_preprocess_init`, and which `XpeErrorCode` values it can return. A getter shall not report a value it did not read. | Writing one requirement per management function makes the requirement set a copy of the API listing, which adds traceability rows without adding a testable claim. What these functions actually share is a contract about state and ownership, and that contract is what a caller gets wrong. Recorded 2026-09-29 (`#216`): eight exported functions were named by no requirement, and all eight are of this kind. | Test: header review — each named function declares ownership, pre-init validity, and error codes; unit — calling each before `xpe_preprocess_init` returns the declared code rather than undefined behaviour |
