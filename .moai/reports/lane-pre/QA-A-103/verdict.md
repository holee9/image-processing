# QA-A-103 — 비선형 보정 0.00 ms 확인, 결함 보정 2772 ms 원인과 최적화 (#179)

커밋 `88f425d` (dev/preprocess, 미푸시, 기준 `7fddade` = origin/main 병합)

## 1. 주장

### 1.1 비선형 보정
1. `xpe_nonlinearity_correct` 는 화소를 계산하지 않는다(`nonlinearity_correct.cpp`).
   - 설정이 없으면 반환한다(29행).
   - `mode` 키가 없으면 반환한다(33행).
   - 알려진 모드("standard"/"high_gain"/"low_dose")이면 `(void)img; return XPE_OK;` 로 반환한다(42–45행, 주석 "apply identity polynomial for now").
2. 실행 확인: 3072² 무작위 uint16 영상에 설정 5가지(null, 세 모드, 계수 포함 JSON)를 넣었다. 모두 rc=0, 바뀐 화소 0개, 0.001–0.013 ms 였다.
   - **입력과 출력이 달라지는 조건은 없다.** 그래서 "값이 바뀌는 조건에서 다시 재기"는 할 수 없었다.
3. 파이프라인은 이 단계를 늘 `nullptr` 설정으로 부른다(`pipeline.cpp:165`). 그런데도 `XPE_FLAG_NONLINEARITY_CORRECTED` 를 켠다(168행). 보정하지 않은 영상에 "보정됨" 표시가 붙는다.
4. 판정: 설정 문제가 아니다. 두 가지가 겹쳐 있다.
   - 요구 미구현: SRS-CALIB-001 FUNC-006(`SRS-CALIB-001_…md:42`) "System shall apply nonlinearity correction using lookup table (LUT) or monotonic polynomial fitting before gain correction". SPEC-XPE-P1A 는 이 단계를 범위 밖(별도 SPEC, `spec.md:55`, `:560` "SPEC-XPE-P1D")으로 두었다.
   - 파이프라인 결함: 플래그가 거짓이다.
   - 이 카드에서는 코드를 고치지 않았다(범위: 확인·판정).

### 1.2 결함 보정
5. 원인
   - `analyzeCluster` 가 호출될 때마다 `std::vector<bool> visited(W*H)` 를 새로 만들었다(수정 전 32행).
   - 이 함수는 아직 처리하지 않은 결함 화소마다 한 번 불린다(수정 전 183행).
   - 그래서 시간이 O(결함 화소 수 × W×H) 였다. 3072² 에서 호출 한 번이 약 1.2 MB 표를 할당하고 0으로 채운다.
6. 수정: 방문 표를 한 번 만들고, 호출이 끝날 때 방문한 칸(= `positions`)만 되돌린다. 알고리즘, 방문 순서, 보정 값은 그대로다.
7. 결과(3072², 결함 0.1%): 2967 ms → 18.6 ms. 출력은 네 경우 모두 수정 전과 바이트 단위로 같다.
8. 요구 ≤95 ms 를 만족한다. 파이프라인(교정 미리 적재)은 3070 ms 에서 118–294 ms 가 되었다(요구 ≤500).

## 2. 증거

### 2.1 판독
- 알고리즘
  - 결함 화소를 행 우선으로 훑는다.
  - 처리하지 않은 결함을 만나면 4-연결 BFS 로 군집을 찾는다.
  - 크기 1이면 4-이웃 평균(없으면 반경 1–3 링, `helpers.cpp:18-54`)을 쓴다.
  - 크기 2 이상이면 각 화소에 3×3 중앙값을 쓴다.
- 요구 원문
  - SRS-CALIB-001:274 "(3) Defect ≤95 ms", "3072×3072 float32 frame on Intel Core i7 or equivalent". 결함 비율은 적혀 있지 않다.
  - SRS-DEFECT-001:165 PERF-102 "평균 100 클러스터/frame", :168 PERF-105 "<95 ms/frame".
  - `sprint-plan.md:673` "typical BPM (0.1% defect rate)".
  - QA-A-102 측정은 0.1% 단일 결함이었다. 이번에는 PERF-102 조건(100 군집)을 더한 경우도 쟀다.

### 2.2 시간 분해
결함 수에 비례하는지로 원인을 확인했다(`run-before.log`).

| 경우 | 결함 화소 | 수정 전 중앙값 | 수정 후 중앙값 |
|---|---|---|---|
| p001 (0.01% 단일) | 947 | 283.1 ms | 16.2 ms |
| p010 (0.1% 단일, QA-A-102 조건) | 9437 | 2967.3 ms | 18.6 ms |
| c100 (0.1% + 100 군집, PERF-102 조건) | 9983 | 2815.1 ms | 18.8 ms |
| cols (단일 2000 + 군집 100 + 열 결함 3줄) | 11787 | 686.7 ms | 20.0 ms |

- 수정 전 시간은 BFS 시작 횟수에 비례한다.
  - p001 과 p010: 결함 10배에 시간 10.5배.
  - cols 는 결함 화소가 가장 많지만, 열 결함 하나가 BFS 한 번이라 시작 횟수가 약 2100 이고 시간도 그만큼이다.
  - 호출당 약 0.3 ms 다. 함수 단위 프로파일러는 쓰지 않았고, 이 비례 관계로 나누었다.
- 수정 후 남은 약 16–20 ms 는 결함 수와 거의 무관하다. 전체 복사(`memcpy`), `source` 스냅숏, 방문 표·처리 표 할당(각 W×H)이다. 판독만 했고 나누어 재지는 않았다.

### 2.3 출력 동일성
기준은 수정 전 바이너리가 쓴 출력 파일(`out_*_before.bin`)이다.
- 수정 후 파일과 `cmp` 결과 네 경우 모두 동일했다. MD5 는 `outputs.md5` 에 있다.
- 대조: 수정 후 출력에서 입력과 다른 화소는 827 / 8336 / 8882 / 11549 개다(결함 947 / 9437 / 9983 / 11787). 미리 채운 −1 은 0개다(`ctrl.log`). 출력이 실제로 보정된 영상이라는 뜻이다. 결함 수보다 적은 것은 선형 구조에서 보간값이 원래 값과 같은 화소가 있기 때문이다.
