## 발견

### 1. 높음 · 차단 — 유니코드 이스케이프된 최상위 품질 키를 놓침

- **무엇:** `modules/preprocess/src/helpers.cpp:165-168`은 JSON 문자열의 원문 바이트를 키와 `strncmp`로 비교한다. JSON에서 `\u005f`는 `_`이므로 `"fit\u005fr_squared"`는 최상위 `fit_r_squared`와 같은 키인데, 조회 결과는 `Absent`가 된다. 이스케이프 표기가 다른 동일 키의 중복도 감지하지 못한다. `xpe_calib_mode.cpp`의 호출부는 `Absent`를 그대로 통과시켜 잘못된 품질 값을 검증하지 않는다. #34의 최상위 키 검증 계약을 충족하지 못한다.
- **재현:** 기존 유효 gain XCal 설정의 config에 최상위 `{"fit\u005fr_squared":"bad"}`를 넣어 `xpe_calib_load_gain`을 호출한다. JSON 의미상 존재하는 품질 필드가 숫자가 아닌데도 이 함수는 해당 키를 찾지 못한다. `{"fit_r_squared":0.9,"fit\u005fr_squared":0.8}`도 동일 키 중복으로 거부해야 한다.
- **고칠 방향:** JSON 키를 이스케이프와 유니코드(필요한 surrogate pair 포함)를 해석한 뒤 비교하고, 해석된 키 기준으로 중복을 검출한다. 검증된 JSON 파서를 사용해 최상위 객체 멤버를 읽는 방식이 안전하다. 위 두 입력을 네 품질 필드 전체에 회귀 시험으로 추가한다.

### 2. 보통 · 차단 — 깨진 JSON을 정상 객체로 수용
