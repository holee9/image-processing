# QA-A-241b — Codex #157 보류 수정과 B6 재측정

## 0. B6 측정 방법 (먼저 고정한 것)

측정 전에 방법, 합격 판정, 예측을 `evidence/00_b6_method_and_predictions_before_measuring.md` 에 적어 두었고 측정 뒤에 바꾸지 않았다.

- **gain**: 한 촬영 조건의 평탄 묶음으로 만든다. 묶음은 QA-A-242 의 모양 분석으로 정했다: 평탄 4·5·6 (큰 규모 모양 좌표 +103.0 / +103.15 / +103.28, 서로 같다). 평탄 1·2 가 다른 조건이고 4·5·6 이 같은 조건이라는 것은 **추정**이다 (선량·관전압 기록 없음).
- **보류 시험**: 묶음 중 두 장으로 제품 생성기(`xpe_calib_generate_gain`, 2프레임, 암 기준 없음)가 gain 을 만들고, 남은 한 장으로 잰다. 세 조합 모두. 같은 장으로 만들고 같은 장으로 재는 순환 측정은 판정에 쓰지 않는다.
- **출하 경로**: offset 은 제품 생성기가 `dark.raw` 한 프레임에서, 결함 맵은 `BPMap.map`. 남긴 장의 원시 프레임은 `dark + 평탄` (평탄 파일은 이미 오프셋 보정값이라 같은 암을 더해서 파이프라인이 다시 뺀다). `xpe_preprocess_pipeline_out`, `{"bypassTemp":true,"bypassNonlinearity":true,"bypassBinning":true}`, 고스트 없음.
- **측정 지점과 ROI**: 결함 단계 **뒤** 출력. 결함 맵 화소와 gain 이 범위 밖이라 결함으로 분류된 화소를 제외한 전부. `FlatResidualPct = 100·std/mean`.
- **판정 장**: 평균이 2000 ADU 이상인 장만. 묶음에서는 평탄 6 (평균 2196) 한 장. 평탄 4·5 는 참고로 보고한다. (프레임 평균은 같은 선량의 반복 프레임이 없어서 쓸 수 없다.)
- **기준 1.0 % 는 그대로.** 판정 장이 1.0 % 이하면 B6 통과, 아니면 실패와 남은 성분.

## 2. B6 재측정

| 남긴 장 | gain 의 재료 | 평균 ADU | 판정 | 보류 잔여 `FlatResidualPct` | 16×16 블록 평균의 퍼짐 | 예측 (측정 전) |
|---|---|---|---|---|---|---|
| **평탄 6** | 평탄 4+5 | 2207.6 | **판정 장** | **0.842 %** | 0.118 % | 약 0.96 % |
| 평탄 5 | 평탄 4+6 | 1403.0 | 참고 (< 2000 ADU) | 0.908 % | 0.128 % | 약 1.02 % |
| 평탄 4 | 평탄 5+6 | 871.8 | 참고 (< 2000 ADU) | 1.065 % | 0.148 % | 약 1.15 % |

(ROI 는 세 경우 모두 53,3xx 화소(0.565 %)를 제외. 평균 ADU 는 ROI 안의 평탄 값. 증거 `evidence/20_b6_held_out.txt`.)

- **예측과의 차이**: 순서는 맞았고 세 값 모두 예측보다 0.09~0.12 %p 낮았다. 예측은 큰 규모 성분을 0.4 % 로 가정했는데 실제로는 0.12~0.15 % 안팎이었다. 예측이 경계(0.96 %)에서 어느 쪽인지 정하지 못했고, 결과는 통과 쪽이다.
- **남은 성분**: 총 0.842 % 에서 큰 규모(16×16 블록 평균의 퍼짐)는 0.118 % 라 거의 전부(√(0.842² − 0.118²) ≈ 0.83 %)가 화소 규모다. 242 의 샷 잡음 관계로 설명되는 크기다: 평탄 6 자신의 화소 잡음 약 0.63 % 와 두 저선량 장으로 만든 gain 의 잡음 약 0.6 % 를 제곱합하면 약 0.88 %.
- **참고 장**: 평탄 5 는 1.0 % 아래(0.908), 평탄 4 는 위(1.065). 평균 ADU 가 낮을수록 화소 잡음 때문에 값이 커지는 방향이라 판정 장이 "평균 2000 ADU 이상"이어야 한다는 방법의 이유와 같은 방향이다.
- **이 통과가 말하지 않는 것**:
  - 판정은 한 장(평탄 6)이다. 0.158 %p 여유는 이 한 장과 이 한 번의 gain 에 대한 것이다.
  - gain 은 저선량 두 장(867, 1396 ADU)에서 왔다. 선량이 더 큰 장으로 만들면 gain 의 잡음이 줄어 여유가 커질 것으로 보이나 측정하지 않았다.
  - "평탄 4·5·6 이 같은 조건"은 모양이 같다는 242 의 관측에서 온 추정이다. 보류에서 큰 규모 퍼짐이 0.12~0.15 % 로 작게 나온 것은 이 추정과 일치하지만 조건 자체의 증거는 아니다.
  - 평탄 1·2 를 포함하는 6장 gain 의 잔여(1.18~3.34 %)는 그대로이고 이 방법에서는 판정에 쓰지 않는다 (QA-A-242 의 결론: 서로 다른 조건의 장을 섞은 결과).
  - 실영상(`wrist_lat`)이 어떤 조건인지는 모른다. 이 측정은 평탄 영상의 균일도이지 실영상의 보정 품질이 아니다.

## 3. Codex #157

### (높음) 겹침 거부

`xpe_preprocess_pipeline_out` 이 `out->data == in->data` 만 거부하던 것을, 입력 버퍼(호출자가 선언한 `dataSize` 만큼)와 결과가 쓰일 `outputBytes` 구간의 겹침 전체를 거부하도록 바꿨다 (`pipeline.cpp` 의 `ranges_overlap`). 주소를 정수로 비교하고, 끝 주소가 주소 공간을 넘으면 끝으로 잘라서 "겹침" 쪽으로 판정하므로 큰 크기가 감겨 "겹치지 않음"으로 보이지 않는다. 거부는 어떤 단계를 읽거나 쓰기 전이다.

시험 (`A241Safety.PipelineOutRefusesAnyOverlap...`): 한 배열 안에 입력을 두고
- 완전 동일, 1바이트 안, 1바이트 앞, 입력의 마지막 바이트를 덮음, 입력의 첫 바이트를 덮음: 모두 `XPE_ERR_INVALID_INPUT`, **입력과 출력 바이트 전체가 그대로**이고 메타데이터 플래그 0.
- 입력 바로 뒤에서 시작, 입력 바로 앞에서 끝남(붙었지만 겹치지 않음): 통과하고 입력은 그대로, 결과는 프레임과 같다.
- 선언한 입력 크기가 `SIZE_MAX − 16` 이라 끝 주소가 감기는 경우: 거부 (`...OverflowSafe`).

### (높음) 단계별 함수의 만료

공통 검사기 하나를 `src/calib_expiry_check.cpp` 에 두었다 (`xpe_calib_snapshot_expiry_check_at(snapshot, 맵 집합, 시각)` 과 시스템 시계 버전). 파이프라인 진입점(`pipeline_core`)과 `xpe_offset_correct` / `xpe_gain_correct` / `xpe_defect_correct` 가 모두 이것을 부른다. 단계 함수는 자기 맵만 본다: offset→offset, gain→gain, defect→defect (gain 맵이 결함으로 분류한 화소 목록이 있으면 gain 도). 만료면 결과를 쓰기 전에 `XPE_ERR_CALIBRATION_EXPIRED` 와 알림. 파이프라인은 전과 같이 적재된 맵 셋을 모두 본다.

시험:
- `A241Checker.JudgesExactlyAtAndAfterTheExpiry`: 시계를 주입해서 만료 직전(−1 ms), **정확히 만료 시각**, 직후(+1 ms) 를 맵 하나씩과 전체에 대해. 정확히 만료 시각은 유효하다(`now > expiry` 가 만료, 적재기와 같은 규칙). 시스템 시계로는 정확한 밀리초를 만들 수 없어서 시계를 넣는 함수로 시험한다. 적재 안 된 맵, 요청 집합 밖의 맵, 만료 0 인 맵은 실패시키지 않는다.
- `...TheThreeSingleStageFunctionsRefuseAnExpiredMapAndWriteNothing`: 세 함수 각각 적재 후 만료되는 맵 → 만료 전에는 성공, 만료 직후 `XPE_ERR_CALIBRATION_EXPIRED`, 출력 버퍼 바이트 그대로, 알림 1건.
- `...AnExpiredMapStopsAllFourPipelineEntryPoints`: `_ex`, `_out`, `_batch`(경로 없음), `xpe_preprocess_pipeline`(경로 있음: 파일 적재가 만료 파일을 거부) 네 경로 모두 `XPE_ERR_CALIBRATION_EXPIRED`, `_out` 의 출력은 쓰이지 않음.

**시험이 실제로 터지는지 확인했다** (`evidence/43_mutation_check.txt`): 겹침 규칙을 옛 "포인터 동일만"으로, offset·gain 단계의 만료 집합을 0 으로 바꾼 변형 빌드에서 시험 셋이 실패했다 (`PipelineOutRefusesAnyOverlap...`, `...OverflowSafe`, `...TheThreeSingleStage...`). 원복 뒤 한 번 낡은(변형) DLL 이 남았다: 원복한 파일의 수정 시각이 변형 객체보다 오래돼서 ninja 가 다시 짓지 않았다. 파일을 `touch` 하고 다시 지은 뒤 이 보고서의 모든 수치(B6 보류, B1~B10 재측정, 기준 영상 해시)를 **다시 측정**했고 값이 같았다.

### (낮음) 증거 EOF 빈 줄

`QA-A-241/evidence/12_suite_final.txt` 의 끝 빈 줄을 제거했다. 이번 증거 파일은 모두 끝 빈 줄 없이 만들었다. `git diff --check` 는 `modules` 와 이번 보고서 범위에서 통과다.

### (높음 3, 중간) 리더 결정으로 닫힌 것

SAFE-004 는 출하·진단 경로에서 `xpe_preprocess_pipeline_out` 필수, 기존 제자리 진입점은 호출자가 명시적으로 고른 경우만 허용으로 SRS 문구가 바뀌었다. 코드는 그대로이고 B4 의 `pipeline_out` 동작은 이번에도 재확인했다 (입력 바이트 그대로, 결과가 제자리 호출과 바이트 동일, 플래그 동일). B2 는 체크리스트에 "상한 동작 확인, 값 잠정" 으로 적었다.

## 4. 생성기 동작의 문서화

`xpe_calib_generate_gain` 의 헤더 주석(`preprocess_api.h`)에 적었다: 평탄 프레임을 장마다 정규화하지 않고 **ADU 그대로 평균**(선량 가중)한다는 것, 선량이나 조건이 다른 장을 섞으면 선량이 큰 장이 큰 규모 모양을 정한다는 것(242 의 수치), 한 촬영 조건의 장만 넣고 여러 선량은 `xpe_calib_generate_gain_polynomial` 을 쓴다는 것. 동작은 바꾸지 않았다.

## 7. 미검증 · 잔여 위험

- **cppcheck 게이트는 이 기계에 도구가 없어 못 돌렸다.** 새 파일 `calib_expiry_check.cpp` 와 바뀐 함수가 새 지적을 만드는지는 CI 로만 확인된다.
- ASan 잡도 로컬에서 안 돌렸다. 새 시험은 짧은 대기(최대 0.6 초)를 쓰고 임시 폴더 이름이 고정이라 **ctest `-j` 병렬이면 서로 겹친다** (CI 는 순차).
- B6 판정은 한 장·한 조합 기준이고 여유가 0.158 %p 이다. 같은 방법을 다른 검출기·다른 평탄 묶음에 적용한 적은 없다.
- B6 의 "같은 조건" 은 추정이다. 이 측정은 그 추정을 시험하지 않는다 (큰 규모 퍼짐이 작게 나온 것이 일관된다는 정도).
- 단계 함수의 만료 검사는 맵을 읽을 때마다 시스템 시계를 한 번 읽는다 (비용은 재지 않았다).
- 결함 맵 단독 5 % 초과가 경고도 거부도 없다는 B3 의 사실은 이번 카드 범위가 아니라 그대로다.
- 이 보고서는 `moai-domain-humanize` 최종 패스를 거치지 않았다.
