# QA-A-250 — 측정 방법 (측정 전에 고정, 측정 전에 커밋)

이 문서는 생성과 평가를 한 번도 돌리기 전에 쓴다. 결과를 본 뒤 이 문서의 방법을 바꾸지 않는다. 바꿔야 한다고 판단되면 리더에게 보고만 하고 새 카드로 다시 잰다.

## 0. 이 방법을 정할 때 알고 있던 것

1단계(데이터 실사, `evidence/10_data_inspection.txt`)에서 프레임별 평균을 이미 봤다. 그래서 다음을 알고 있었다:

- `Dark_07` 의 평균은 10929.2 이고 나머지는 약 11020~11027 이다 (첫 프레임이 약 92 ADU 낮다).
- Bright 20장은 한 선량이 아니라 다섯 선량 묶음이다 (17~19, 20~22, 23~30, 31~33, 34~36).

아래 분할 규칙은 이 정보를 보고 바꾸지 않았다. 카드의 문구("dark 8장·bright 18장으로 생성, **남긴** dark 2장·bright 2장으로 평가")를 번호 순서 그대로 읽은 가장 단순한 규칙이다. 규칙을 확정한 뒤에, 알고 있던 정보로 결과를 예측해 `31_predictions_before_the_measurement.txt` 에 적었다.

## 1. 분할

| 역할 | 프레임 |
|---|---|
| 생성 (다크) | `Dark_07` ~ `Dark_14` (8장) |
| 생성 (밝은 영상) | `Bright_17` ~ `Bright_34` (18장) |
| 평가용으로 남김 (다크) | `Dark_15`, `Dark_16` |
| 평가용으로 남김 (밝은 영상) | `Bright_35`, `Bright_36` |

규칙: 각 계열에서 번호가 가장 큰 두 장을 남긴다. 판정은 남긴 프레임에서만 낸다.

## 2. 생성

```
xpe_calib_fixture_gen --out <세트> --expiry-ms 4102444800000
   --dark Dark_07.raw ... --dark Dark_14.raw
   --bright Bright_17.raw ... --bright Bright_34.raw
   --compare-bpm BPM.raw
```

- 크기는 기본값 3072 × 3072. 게인의 다크 참조는 기본값(다크 입력 8장의 반올림 평균). 오프셋 생성 조건 100 ms, 25 °C, BPM 설정은 도구의 기본값(λ 8.0, 마스크 32 / 128, 허용도 0.07).
- `BPM.raw`(장비 회사)는 비교에만 쓴다. `defect.xcal` 은 `xpe_bpm_generate` 의 결과다.
- 생성 세트는 저장소에 넣지 않는다 (`D:/workspace-github/xpe-data/calib-cyan-v1/`). 보고서에 sha256 을 적는다.

## 3. 평가

공통: 모듈 DLL 은 로컬 `ci-preprocess` 빌드. 세트를 적재하고(`xpe_calib_load_*`) 모듈의 공개 함수만 쓴다. 설정은 앱과 같다 (`{"bypassTemp":true,"bypassNonlinearity":true,"bypassBinning":true}`).

### 3.1 오프셋 — SRS-CALIB-FUNC-016, 프로토콜 §5.2

| 항목 | 정의 |
|---|---|
| `R` | 남긴 다크 프레임 (원시) |
| `Y` | `xpe_offset_correct` 의 출력 (uint16) |
| ROI | 모든 화소 |
| `DarkBias` | `mean(Y)` |
| `DarkReduction_dB` | `20·log10(std(R) / max(std(Y), 1e-12))`, 모집단 표준편차 |
| 합격 | `abs(DarkBias) ≤ 5 ADU` **또는** `DarkReduction_dB ≥ 10` |

판정: 남긴 다크 두 장이 **모두** 합격이면 오프셋 합격이다.

### 3.2 게인 — SRS-CALIB-FUNC-017, 프로토콜 §5.3 (1단계 B6 와 같은 형태)

| 항목 | 정의 |
|---|---|
| 입력 | 남긴 밝은 영상의 **원시** 프레임 (바탕값 포함) |
| `Y` | `xpe_preprocess_pipeline_out` 의 최종 출력 (float32) |
| ROI | 생성 세트의 게인 맵이 유한하고 0 보다 큰 화소 (자르기·가장자리 제외·결함 화소 제외 없음) |
| `FlatResidualPct` | `100 · std(Y_roi) / mean(Y_roi)`, 모집단 표준편차 |
| 판정 가능 | `mean(Y_roi) ≥ 2000 ADU` |
| 합격 | `FlatResidualPct ≤ 1.0 %` |

판정: 남긴 밝은 영상 두 장이 **모두** 합격이면 게인 합격이다.

### 3.3 결함 맵 — 판정 아님

도구가 `BPM.raw` 와 비교해 `manifest.json` 에 쓴다: 생성 수, 장비 회사 수, 둘 다, 재현율(= 둘 다 / 장비 회사), 정밀도(= 둘 다 / 생성), 오검출률(= (생성 − 둘 다) / (전체 − 장비 회사)). 실데이터 기준이 없으므로 합격/불합격을 내지 않는다. `BPM.raw` 의 0이 아닌 값은 모두 결함으로 센다 (127 과 255 의 뜻은 확인하지 않았다).

### 3.4 팬텀 — 판정 아님

팬텀 5장(흉부 3, 발 2)을 같은 구성의 `pipeline_out` 으로 보정해 float32 로 저장한다. 같은 이름의 `*_result.raw` 와의 차이(평균, 평균 절대값, p50, p99, 최대, 상관계수, 비율 중앙값)를 모든 화소와, 원시가 65535 이거나 `_result` 가 자기 최댓값인 화소를 뺀 화소에서 공개한다. `_result` 가 장비 회사 보정본인지는 저장소 안의 서술(README 등)에서 확인되지 않으면 "미확인" 으로 쓰고, 수치는 그래도 공개한다.

### 3.5 참고 표 (판정 아님)

남기지 않은 프레임의 같은 지표도 출력해 표시한다("생성" 표시). 이 줄들은 판정이 아니다.

## 4. 실행 범위

- 도구 시험(거부 경로 포함)은 `CalibFixtureGenTest.*` 만 돌린다.
- 생성 1회, 평가 1회. 한 번에 프로세스 하나. 각 실행 뒤 남은 프로세스 0 을 확인한다.
- 전체 스위트는 돌리지 않는다.
