## §2. Evidence — 증거

전문: `a56-bounds.log`. 명령 `xpe_detect_experiment --bounds`.

### 2-1. 메모리 하한 (카드 1항)

최소 트래픽은 **입력을 한 번 읽고 결함 맵을 한 번 쓰는 것**이다. 3×3 창이 화소를 논리적으로
9번 읽지만, 세 줄만 캐시에 있으면 되므로 강제(compulsory) 트래픽은 1회다.

```
입력  9,437,184 × 4 B = 37.75 MB
출력  9,437,184 × 1 B =  9.44 MB
합계                    47.19 MB
```

실측 커널 7회씩:

```
  read-only (sum)          min 4.11  med 4.22  max 4.63 ms  ->  8.9 GB/s   spread 12.3%
  copy (read+write float)  min 1.79  med 1.85  max 2.04 ms  -> 40.7 GB/s   spread 13.8%
  detector traffic shape   min 4.26  med 4.31  max 4.51 ms  -> 10.9 GB/s   spread  5.7%
```

**여기서 숫자 하나를 잘못 읽기 쉬워 명시한다.** `read-only (sum)` 의 8.9 GB/s 와
`detector traffic shape` 의 10.9 GB/s 는 **이 기계의 대역폭이 아니다.** 둘 다 원소마다
하나씩 처리하는 스칼라 루프이고, 덧셈 의존 사슬과 분기에 묶여 **대역폭에 도달하지 못한다.**
같은 데이터를 `memcpy` 로 옮기면 **40.7 GB/s** 가 나오는데, 그것이 이 기계가 실제로 낼 수 있는
스트리밍 대역폭에 가깝다(i7-12700 듀얼채널의 이론치와 같은 자릿수).

따라서:

| | 값 | 무엇인가 |
|---|---|---|
| **메모리 하한 (대역폭 기준)** | **47.19 MB ÷ 40.7 GB/s = 1.16 ms** | 완벽히 대역폭에 묶였을 때의 바닥 |
| 순진한 스칼라 1패스 | 4.31 ms | 지금 방식대로 원소별로 훑었을 때 |

**어느 쪽을 쓰든 35 ms 근처가 아니다. 메모리는 제약이 아니다.**

### 2-2. 연산 하한 (카드 1항)

픽셀당 최소 연산의 지배항은 **19 compare-exchange 정렬 네트워크를 두 번**(중앙값 1회 +
MAD 의 중앙값 1회) 도는 것이다. 세는 대신 **실측했다**:

```
  scalar 19-CE network      55.16 ms / 4,000,000 nets = 13.79 ns per network
  AVX2   19-CE network       6.77 ms / 1,000,000 x8   =  0.85 ns per network   (16.30x scalar)

  two networks per pixel x 9,437,184 pixels:
    scalar networks alone        260.29 ms
    AVX2 networks alone           15.97 ms
```

AVX2 프로브는 **가장 유리한 형태**다 — 8화소를 레인 하나씩 맡기므로 셔플이 필요 없고,
`min`/`max` 가 레인별 연산이라 그대로 매핑된다. 실제 벡터화 검출기가 취할 모양이 이것이다.

**16.30배가 폭 8을 넘는 이유**를 적어 둔다. 이득의 일부는 폭이 아니라 **명령 수준 병렬성**이다 —
스칼라 프로브는 반복마다 직렬 의존이 걸려 있고, 벡터판은 같은 의존을 8배 넓은 작업으로 상환한다.
즉 **스칼라 13.79 ns 는 스칼라가 낼 수 있는 최선이 아니다**(화소 간 ILP 를 살리면 더 빠르다).
그래서 이 비율을 "SIMD 하면 16배" 로 읽으면 안 된다 — 여기서 쓰는 것은 **AVX2 쪽 절대값**뿐이다.

### 2-3. 하한과 예산

```
C. LOWER BOUND = max(memory 4.31, AVX2 compute 15.97) = 15.97 ms
   SPEC budget 35 ms -> the bound is 0.46x the budget
   headroom above the bound: 35 - 15.97 = 19.03 ms
```

(로그는 보수적으로 4.31 ms 를 썼다. §2-1 의 1.16 ms 를 쓰더라도 max 는 바뀌지 않는다.)

**하한이 예산보다 작다 — 그러므로 (c) "이 하드웨어에서 도달 불가" 는 답이 아니다.**
그러나 그것이 (a) 를 뜻하지도 않는다. §2-4 를 보라.

### 2-4. 남은 19.03 ms 안에 들어가야 하는 것 (카드 2항)

| 항목 | 현재(실측) | 하한 | 배수 |
|---|---|---|---|
| 픽셀 루프 | 532.0 ms | 15.97 ms (네트워크만) | **33배** |
| 전역 σ | 199.8 ms | ≈11.1 ms (아래 계산) | **18배** |
| 전체 | 732.1 ms | ≈27.1 ms | **27배** |

**전역 σ 의 하한은 이렇게 계산했다.** 현재 데이터 흐름은 방향마다
차분 생성(프레임 37.75 읽기 + 차분 37.75 쓰기) → 기수 1패스(37.75 읽기) →
절댓값 변환(37.75 읽기 + 37.75 쓰기) → 기수 2패스(37.75 읽기) = **226.5 MB**,
두 방향이면 **453 MB**. 40.7 GB/s 로 나누면 **11.1 ms** 다. **연산이 공짜여도** 그만큼 든다.

이 11.1 ms 는 **줄일 수 있다** — 차분 배열을 materialize 하지 않고 기수 패스마다 프레임에서
다시 계산하면 트래픽이 2패스 × 2방향 × 37.75 MB = 151 MB ≈ **3.7 ms** 가 된다. 다만 그것은
**데이터 흐름을 바꾸는 일**이고, 이 카드의 범위가 아니다(관측으로만 적는다).

그리고 기수 히스토그램의 증분은 **256 KB 테이블로의 산발 저장**이라 벡터화되지 않는다.
전역 σ 는 **SIMD 로 줄어드는 종류의 비용이 아니다.**

### 2-5. 측정 신뢰성 (반증 규약 갈음)

구현이 없으므로 반증 대신 **측정끼리 교차 확인**한다.

1. **스칼라 네트워크 하한 대 실측 루프**: 스칼라 네트워크만 260.29 ms, A-55 가 잰 픽셀 루프
   전체는 532.0 ms. 네트워크가 루프의 **49%** 다. A-54 는 median8 도입 **전에** 두 선택이
   복제 루프의 91.7% 라고 쟀다 — 고속 경로가 선택 비용을 낮췄으니 비중이 91.7% → 49% 로
   내려오는 것이 맞다. **서로 다른 두 경로로 얻은 값이 같은 이야기를 한다.**
2. **대역폭 대조**: memcpy 40.7 GB/s 는 i7-12700 듀얼채널 이론치와 같은 자릿수다.
   다만 37.75 MB 버퍼가 L3(25.6 MB)보다 크되 아주 크지는 않아 **부분적으로 L3 를 탄다** —
   그래서 40.7 GB/s 는 순수 DRAM 대역폭의 **낙관적** 추정이다. 하한을 낙관적으로 잡는 것은
   "도달 불가" 판정을 어렵게 만드는 방향이므로 결론에 유리하게 쓰이지 않는다
3. **산포**: 모든 커널을 7회씩 재고 min/med/max 와 스프레드를 함께 찍는다

### 2-6. 맥락 확인 (카드 4항)

```

D. detector traffic shape (무거운 작업 뒤)    min 4.33  med 4.45  max 5.38 ms   spread 23.5%
```

비교는 **같은 맥락끼리**다(A 블록끼리, B 블록끼리).

## §3. 판정 한 줄 (카드 3항)

> **(b) 알고리즘 변경이 필요하다.** 하한은 15.97 ms 로 예산 35 ms 보다 작으므로 **(c) 하드웨어
> 불가는 아니다**. 그러나 **정렬 네트워크만으로 예산의 46%(15.97 ms)를 쓰고**, 현재 데이터
> 흐름의 전역 σ 가 **연산이 공짜여도 11.1 ms** 를 물어 둘만 더해도 **27.1 ms = 예산의 77%** 다.
> 남는 7.9 ms 안에 gather·abs·판정·맵 쓰기가 모두 들어가야 하고, 전역 σ 의 기수 히스토그램은
> **산발 저장이라 SIMD 로 줄지 않는다.** 따라서 **"현 알고리즘을 벡터화한다" 만으로는 35 ms 에
> 닿지 않으며**, 전역 σ 의 데이터 흐름 변경(차분 비-materialize, 또는 추정 방식 자체의 변경)이
> 함께 필요하다. SIMD 는 그 다음에 의미가 있다.

## §5. Gaps — 관측하지 않은 것

1. **AVX2 검출기를 만들어 보지 않았다.** 15.97 ms 는 네트워크 프로브의 외삽이고,
   **실제 벡터화는 이웃 수집(3행에서 셔플로 8개 벡터 만들기)을 포함**한다. 그 비용은 재지 않았다
2. **스칼라의 진짜 최선을 재지 않았다.** 프로브가 반복 의존에 묶여 13.79 ns 가 나왔으므로,
   화소 간 ILP 를 살린 스칼라는 이보다 빠르다. **16.30배는 SIMD 이득의 상한으로 읽어야 한다**
3. **전역 σ 하한 11.1 ms 는 계산이지 측정이 아니다.** 패스 구성이 내가 읽은 코드와 같다는
   전제 위에 있다
4. **40.7 GB/s 가 부분적으로 L3 를 탄다.** 37.75 MB 버퍼 대 25.6 MB L3 — 순수 DRAM 대역폭은
   이보다 낮고, 그러면 메모리 하한은 1.16 ms 보다 커진다(그래도 15.97 ms 를 넘지 않는다)
5. **단일 스레드만 봤다.** 이 CPU 는 12코어다. 멀티스레드는 하한을 크게 낮추지만
   **SPEC 이 스레드 수를 어떻게 규정하는지 확인하지 않았다** — 이건 요구 쪽 질문이다
6. **E-코어/P-코어 어디서 돌았는지 모른다.** 스케줄러가 정하며 고정하지 않았다.
   맥락 스프레드 23.5%의 일부일 수 있다
7. 3072² 한 크기, 이 기계 한 대, 이 컴파일러 한 조합

## §6. Residual-risk — 남는 위험

1. **가장 큰 위험은 Gap 5 다 — 멀티스레드를 배제하고 판정했다.** 12코어를 쓰면 픽셀 루프는
   원리상 8~10배 더 줄고, 그러면 35 ms 가 **알고리즘 변경 없이도** 닿을 수 있다.
   SPEC 이 단일 스레드를 요구하는지, 파이프라인의 다른 단계와 코어를 나눠 써야 하는지는
   **내가 답할 수 없는 질문**이고 요구 쪽 결정이다. 판정 (b) 는 **단일 스레드 전제 위에서만** 유효하다
2. **15.97 ms 는 낙관적이다.** 이웃 수집·abs·판정·맵 쓰기가 전부 빠져 있다. 실제 벡터화
   검출기가 이보다 두 배 느리면 네트워크만으로 예산을 다 쓴다
3. **판정 (b) 가 (a) 로 바뀔 여지는 전역 σ 에 달려 있다.** 차분을 materialize 하지 않으면
   11.1 → 3.7 ms 이고, 그러면 네트워크 16 + σ 3.7 = 19.7 ms 로 여유가 15 ms 생긴다.
   그 변경이 **정확성을 유지한 채 가능한지는 확인하지 않았다**
4. **이 카드는 숫자만 냈고 아무것도 고치지 않았다.** 20.9배는 그대로다
5. 실프레임에서의 성능은 여전히 미확인이다(#151). 합성 프레임의 값 분포가 기수 선택의
   버킷 분포를 결정하므로, 실프레임에서 전역 σ 비용이 달라질 수 있다
