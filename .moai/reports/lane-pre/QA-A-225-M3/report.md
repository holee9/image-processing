## 2. 음수 제거율의 원인 (M3-a)

**가설과 결과**

| 가설 | 결과 |
|---|---|
| H1 지표: 정류된 암 기준이 잔차가 된다 | **확정** |
| H2 보정기가 잡음을 키운다 | 티어 1·2 기각, 티어 3 은 잡음이 아니라 구조(4절) |

**H1 의 증거**

- C++ 하네스(`evidence/01_derive_run.txt`): 잡음 σ5 의 교정 모듈 행 36개 중 **16개**가 k=50 제거율이 음수(E2E 정의)이고, 암 기준을 **보정 전** 암 프레임으로 잡으면 음수가 **0개**다.
- 음수 행은 전부 보정된 빈 프레임이 **100 % 0 으로 잘렸고**(`clampedShare = 1`), 그 행의 `LagResidual`은 보정된 암 프레임 평균의 정확한 함수다: `100·|darkCor| / ExposureSignal`(오차 1e-9 이내로 단언). 지연의 크기와 무관하다.
- 보정된 암 프레임의 평균이 잡음에 비례한다. σ 를 1·2·5·10·20 으로 바꾸면 보정된 암 평균은 0.3919·σ 로 모두 같다(0 이력의 이론값은 σ/√(2π) = 0.3989·σ 이고 두 번째 프레임부터는 이력이 평균을 조금 낮춘다). 주의: 이 스윕은 **같은 난수열을 σ배**한 것이라 비례가 구성상 정확하고, 서로 다른 난수 표본에 대한 통계는 아니다.
- 파이썬으로 독립 확인(`evidence/03~04`; 난수열이 달라 행 수가 다르다): 음수 12/36행, 12행 모두 빈 프레임 100 % 클램프, σ 스윕에서 보정된 빈 프레임은 모든 σ 에서 정확히 0.

**메커니즘 한 줄**: 모듈은 `corrected > 0 ? corrected : 0`으로 출력을 자른다. 노출 전 암 프레임에서는 이력이 0 이라 `max(raw, 0)`이 되어 평균이 +0.39σ 로 오르고, 노출 뒤 빈 프레임에서는 과보정으로 전부 0 이 된다. 잔차가 곧 `0.39σ`가 되고, 실제 지연(`LagRaw`)이 그보다 작으면 제거율이 음수가 된다. T2 의 k=50(`LagRaw` 0.0056 % 이하)에서 가장 먼저 드러난다.

**지표 정의 보강안 (리더 결정 사항, 구현하지 않음)**

| 안 | 내용 | 측정 |
|---|---|---|
| (i) 암 기준을 보정 전 프레임에서 | `LagResidual`의 `DarkRef`를 같은 경로가 아니라 **보정 전** 암 프레임 평균으로 | 36행 중 음수 **0행** |
| (ii) 클램프된 행은 "측정 불가"로 표기 | 보정된 빈 프레임의 0 화소 비율이 1 이면 제거율 대신 불가로 | 모듈 행은 전부 100 % 클램프라 모든 행이 "불가"가 됨 |
| (iii) 지금 정의 유지 | 단독 합격 근거로 쓰지 않고 짝지표(신호 보존, 계단)와 함께 | 설계 메모의 방침과 같음 |

(i)은 과보정을 가리는 문제를 새로 만들지는 않는다. 과보정은 이미 빈 프레임 지표가 못 보고 신호 보존·계단 하강이 본다(M1 보고서 5절).

## 3. 설정 도출과 보류 평가 (M3-b)

**절차(시험 쪽)**: 교정 시퀀스(5 암 + 200 노출 + 50 빈 프레임, **참 노출을 안다**)에서, 모듈 tier 1 재귀의 double 복제본으로 `alpha1·tau1·alpha2·tau2`를 탐색한다. 비용 = 빈 프레임의 **부호 있는**(클램프 전) 잔차 평균 + 신호 보존이 허용 대역(±0.5 % 또는 ±0.1 %) 밖이면 큰 벌점. 탐색은 시드 고정의 로그 공간 무작위 언덕오르기(7 규모 × 6000 번). 복제본은 실제 모듈과 맞는지 시험한다(`TheReplicaOfTierOneMatchesTheRealModule`, 클램프 포함 0.05 ADU 이내). 평가는 **실제 모듈**로, 교정에 쓰지 않은 시퀀스에서 한다. 도출된 설정은 티어 1·2·3 에 같은 `alpha/tau`를 준다.

|---|---|---|---|---|---|---|---|

**처음 도출은 클램프에 속았다.** 첫 구현은 비용을 클램프된 값으로 계산했고, 출력된 네 설정이 모두 `mean |blank| = 0.0000 ADU`였다. 빈 프레임을 과보정으로 0 까지 눌러도 비용이 0 이라 탐색이 첫 그런 설정에서 멈춘 것이다(설계 메모 R2 와 같은 문제를 도출 단계에서 되풀이했다). 이것은 시험이 아니라 **출력된 비용을 읽다가** 발견했다(`evidence/02_first_derivation_clamp_blind.txt`). 비용을 부호 있는 값으로 바꿨고, 같은 잘못이 다시 들어오지 않도록 "도출된 설정의 부호 있는 빈 프레임 잔차가 보정 전의 1/5 미만"이라는 점검을 시험에 넣었다(반증 d1 이 이 점검으로 잡힌다).

**보류 평가에서 읽히는 것**(합격선 아님, 허용 대역별 두 설정의 범위):

| 교정 | 평가 | 신호 보존 | k=1 제거율 | k=50 제거율 | 계단 하강 k=1 잔차(티어 1) |

| T1 @27 % | **T2**(다른 진실) | 0.9791~0.9923 | 100 % | 100 % | **−6.89~−8.67 %**(과보정) |

| T2 @27 % | **T1**(다른 진실) | 1.0160 | 47.10 % | 1.67~1.71 % | **+9.09 %**(미보정) |

1. **같은 진실의 다른 수준에서는 일반화되고(T1: 보존 1.00, k=1 88~98 %, 수준과 무관한 LTI 라서 교정 구간과 같은 값), 다른 진실로는 일반화되지 않는다.** T1 에서 도출한 설정은 T2 에서 신호를 1~2 % 깎고 계단 하강에서 −7~−9 % 과보정이며, T2 에서 도출한 설정은 T1 에서 지연의 절반 넘게 남긴다(k=1 47 %, k=50 1.7 %, 계단 +9 %). 신호 보존 대역을 지킨 설정도 다른 진실에서는 어느 쪽으로든 어긋난다. 설계 메모 R5(보류 평가)가 잡으려던 실패다.
2. **빈 프레임 제거율은 T1 설정을 T2 에 적용해도 100 %다**(위 표 둘째 줄). 그 행의 신호 보존 0.979~0.992 와 계단 −6.9~−8.7 %가 과보정을 보인다. 빈 프레임 지표 단독의 맹점이 도출된 설정에서도 다시 나온다.
3. T2 교정/T2 평가의 k=50 제거율이 낮은 것(12~24 %)은 T2 의 k=50 `LagRaw`가 0.002~0.004 %로 매우 작아 분모가 작기 때문이다(관측; 다른 원인은 확인하지 않았다).
4. 티어 3 은 같은 `alpha/tau`에서 계단 하강 제거율이 티어 1 보다 낮다(T1 교정/T1 평가: 티어 3 k=1 제거율 81.17 % 대 티어 1 98.39 %, 허용 대역 ±0.1 % 설정). 혼합의 영향으로 읽히지만 이 보고서에서 혼합을 끄고 확인하지는 않았다(M4).

## 4. 부수 발견: 티어 3 의 테두리-내부 단차

잡음 σ5 의 노출 프레임에서 티어 3 의 **전체 프레임 표준편차가 원본 5.1 의 99~223 배**(505, 1137)였다. 내부만 보면 ×0.75~0.76 으로 줄어드는데도 그렇다. 가설: 티어 3 은 **내부 화소에만** 이웃 평균과의 혼합(0.7:0.3)을 적용하므로 테두리와 내부가 서로 다른 값이 된다.
파이썬 측정(`evidence/05~06`, 균일한 16×16 프레임, 잡음 0): 티어 3 에서 테두리 평균 14275.20 / 내부 평균 15467.97, **단차 1192.77 ADU**, 내부 std 0.000. 티어 1·2 는 단차 0.00. 단차는 식과 정확히 맞는다: `내부 = 0.7·(테두리 값) + 0.3·(원본 평균)`이므로 `단차 = 0.3·(원본 − 테두리 값)` = 0.3·(18251 − 14275) = 1193.
이것은 균일한 프레임에서도 생기는 구조적 인공물(1 화소 테두리 링)이고, 혼합이 제거된 지연의 30 %를 내부에 되돌려 놓는다는 설계 메모 4.1 의 구조와 같은 뿌리다. 이 보고서는 결함으로 단정하지 않고 **#238 의 후보 항목**으로 올린다. M4 에서 혼합 비율에 따라 단차가 어떻게 변하는지 이음새로 잰다.

d1 은 처음에는 안 터졌다. 점검(부호 있는 잔차)을 추가한 뒤에야 위 표가 되었고, 추가 전의 반증은 돌리지 않았다.

## 6. 증거 — 5절 형식

**주장**: 잡음의 음수 제거율은 지표의 정류된 암 기준 때문이며, 보류 평가가 포함된 설정 도출 절차가 시험 쪽에 있다.

**증거**: `evidence/01_derive_run.txt`(M3 출력 전문), `02`(클램프에 속은 첫 도출), `03~07`(파이썬 독립 확인: 원인과 테두리 단차), `08~09`(반증), `10~11`(표와 표를 만든 스크립트), `evidence/verify/`(`verify225m3.sh`: `xpe_common_oom_tests` 12, `test_xpe_common` 69, `xpe_preprocess_tests` 958/950/건너뜀 8(종료 0), 셔플 seed 22503 동일, `xpe_preprocess_oom_tests` 65, ctest 1145, export 차이 0, 헤더 문서 0건, 프리셋 12/12).

**baseline 귀속**: 위 명령과 출력은 이번 실행, 이 작업 트리에서 측정했다.

**미검증(Gaps)**:

- 도출 절차는 tier 1 복제본으로만 탐색한다. 티어 2·3 은 같은 `alpha/tau`를 받을 뿐이며 각 티어에 맞춘 설정은 구하지 않았다.
- 도출은 무작위 탐색이라 전역 최적을 보장하지 않는다. 시드 고정이며 같은 표준 라이브러리에서만 결정적이다(다른 플랫폼에서는 값이 달라질 수 있다).
- 보류 평가는 두 진실(T1, T2)과 노출 3수준·잡음 2에서만 했다. 실장비 지연이 이 둘 사이 어디에 있는지는 모른다.
- σ 스윕은 같은 난수열의 배수라 서로 다른 표본의 통계가 아니다.
- 테두리 단차는 파이썬(균일 16×16)에서 측정했고, C++ 하네스에서는 전체 프레임 std 로만 나타난다. 원인의 식은 일치하지만 다른 프레임 크기·내용에서는 재지 않았다.
- 지표 정의 보강안(i)~(iii)은 제안이며 결정은 리더/사용자다.

**잔여 위험**:

- 이 시험들은 모듈 값을 단언하지 않으므로 모듈이 나빠져도 빨개지지 않는다.
- 하네스 헤더(`ghost_oracle_harness.h`)로 코드를 옮겼으므로 M1 의 `test_ghost_oracle.cpp` 도 같은 헤더를 쓴다. 출력 줄 형식이 바뀌면 보고서 표를 만드는 스크립트(행 수를 단언)가 깨진다.
- 파이썬 확인은 난수열이 C++ 와 달라 같은 행을 재현하는 것이 아니라 같은 원인을 독립적으로 확인한 것이다.
