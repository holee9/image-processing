# QA-A-225 M6 — 클램프에 닿지 않는 빈 프레임으로 지표의 판별력 확인

브랜치 `dev/preprocess`, QA-A-225 M5(`a7d9ab7b`) 위. 시험 쪽 파일 1개와 CMake 등록 1줄만 추가했고 제품 코드·ABI 변경은 0이다. D1(합격선)은 보류이며 모듈 값에 합격선 단언은 없다.

## 2. 지표 정의에 대한 결과 (이것이 M6 의 핵심)

M5 에서 "보정 전 암 기준"을 택한 것은 **암 프레임이 클램프에 정류될 때**(받침값 0)의 처방이었다. 받침값이 있어 클램프가 없는 구성에서는 두 정의가 이렇게 갈린다.

| 구성 | 보정된 암 기준(M1) | 보정 전 암 기준(M5) |
|---|---|---|
| 받침값 0, 암이 0 으로 정류됨 (M3-a 36행) | 음수 제거율 16행 — 정류된 기준을 잼 | 음수 0행 — 단 전 행이 클램프 포화라 판별력 없음 |
| 받침값 P, 클램프 없음 (M6) | 오라클 100 %, 보정 없음 0 %, 과보정 음수, 정확 설정 양수: **옳게 가른다** | 오라클 −45.7 %: **틀림**(암 기준이 받침값 자신의 지연을 품음) |

즉 어느 정의도 모든 구성에서 옳지 않다. 어느 쪽이 옳은지는 **보정된 암 프레임이 클램프에 닿았는가**가 정한다. 이 판정을 하네스가 스스로 하게 할 수 있다(암 프레임의 클램프 비율을 이미 안다). 그것을 제품 지표 정의로 삼을지는 D1 의 일부이며 이번에 정하지 않았다.

## 3. 시험 설계

- 시퀀스: 받침값 P 가 1500 프레임(느린 Starman 꼬리 a=2.5e-3, 시상수 400 프레임이 정착하도록) → 받침값+노출 200 → 받침값 50. 노출 수준 2 %·27 %·50 %, 진실 T1(Starman 이산 LTI)·T2(유한 트랩), 잡음 σ 0·5.
- 대조군은 **생성기에서 산술로만** 만든다(모듈 미사용): 보정 없음, 오라클(`x`), 지연의 f 배를 뺀 것(0.5×, 1.5×, 2×, 3×) — `c = y − f·(생성기 값 − 진짜 x)`. 기대 제거율은 `100·(1 − |1 − f|)`.
- 모듈 행: 손으로 정한 설정 2개 × 티어 3 + 도출 설정(M3 와 같은 방법, 받침값 없는 T1 27 % 보정 시퀀스에서, 밴드 ±0.5 %) × 티어 3. 도출 설정: α1 0.00594 τ1 2.809 α2 0.00016 τ2 44.770, S 0.0272(생성기의 정상상태 합은 0.0336).
- 필터: 빈 프레임 k=1·10·50 과 암 프레임 모두에서 0 화소가 하나도 없는 행만 표에 남긴다. 108행 중 104행이 남았고, 제외 4행은 티어 2 의 과보정 설정(0.1/1/0.01/20)이 50 % 수준에서 k=1 을 전부 0 으로 만든 행이다(`evidence/03`).
- 단언한 것(모두 대조군·지표 성질): 각 대조군의 제거율이 산술값과 일치, 부호 있는 잔차의 부호, 2×가 보정 없음과 부호 없는 지표에서 같고 부호 있는 잔차에서 크기 같고 부호 반대, 오라클이 M5 정의에서 `100·|P − 보정 전 암|/노출`(받침값 자신의 지연)만큼 어긋남, 필터의 양성 대조(클램프에 닿는 모듈 행이 실제로 존재). 모듈 값에는 단언 0건.
- 허용 오차: 화소가 float32(26000~44000 에서 한 단계 약 0.002~0.004 ADU)이고 k=50 지연이 몇 ADU 라 대조군은 산술값에서 수 천분의 %p 어긋난다. 허용 오차는 `100·0.004 ADU / |행의 지연(ADU)|` 로 행마다 정했다(2 % 수준의 k=50 은 최대 0.4 %p).

## 5. 증거 — 5절 형식

**주장**: 클램프에 닿지 않는 설계에서 지표(보정된 암 기준)가 보정 없음 0 %·오라클 100 %·과보정 음수·정확 설정 양수로 가르고, 보정 전 암 기준은 이 설계에서 오라클을 −45.7 % 로 읽으며, 부호 없는 지표는 과보정과 부족 보정을 못 가른다.

**증거**: `evidence/04_controls.txt`(대조군 30줄), `02_module_rows_clamp_free.txt`(104행), `03_rows_excluded_touch_clamp.txt`(제외 4행), `01_pedestal_tests_final.txt`(시험 출력), `05~06`(반증 7개), `evidence/verify/`(전체 검증).

**baseline 귀속**: 위 명령과 출력은 이번 실행, 이 작업 트리(HEAD `a7d9ab7b` + 이번 변경)에서 측정했다.

**반증**(한 번에 하나, 전체 빌드, 원복 `cmp` 일치): 7개 전부 발화.

| 손상 | 빨강이 된 시험 |
|---|---|
| p1 보정된 암 기준을 보정 전 암으로 | 대조군(M1·M6)·M3-a 항등식 |
| p2 클램프 비율을 항상 0으로 | M3-a 항등식, **필터의 양성 대조** |
| p3 부호 있는 잔차의 부호 제거 | M6 대조군 |
| p4 대조군이 엉뚱한 프레임의 지연을 뺌 | M6 대조군 |
| p5 빈 프레임에서 받침값 제거 | M6 대조군 |
| p6 M5 정의를 보정된 암으로 되돌림 | M1·M6 대조군 |
| p7 제거율을 raw 가 아닌 잔차로 나눔 | M6 대조군 |

이번에는 "빨강 먼저"가 해당하지 않는다. 제품 코드가 없고 새 시험은 기존 하네스 위의 새 측정이라, 처음부터 초록이 나온다(처음 빨강은 허용 오차를 정확히 0 에 가깝게 잡은 내 시험 쪽 실수였다). 대신 위 반증이 시험이 판별력을 가졌는지를 보인다.

**미검증(Gaps)**:

- 받침값은 **지연 생성기가 지연을 만들어 주는 신호**로 설계했다. 받침값이 지연 없는 오프셋(전자 오프셋)인 경우는 재지 않았다. 그 경우 모듈은 받침값에 곱해진 합 S 만큼 빈 프레임에서 더 빼게 되는데, 파이프라인에서 고스트 단계 앞에 오프셋 보정이 있어 받침값이 거의 0 으로 들어오는지는 `pipeline.cpp` 에서 오프셋이 1단계라는 것만 보았고 고스트 단계의 위치는 확인하지 않았다.
- 받침값 크기(0.4·포화)와 1500 프레임은 하나씩만 골랐다. 다른 값에서 도출 설정의 양성 범위가 같은지는 재지 않았다.
- 정확한 설정은 T1 에서 도출한 한 벌뿐이다. T2 에서 정확한 설정(T2 를 위한 도출)은 만들지 않았으므로, "T2 진실에서 정확한 설정이 양수로 읽히는가"는 확인하지 못했다.
- 보정 전 암 기준이 옳은 구성(암이 클램프에 정류됨)에서 M1 정의가 틀리다는 것은 M3-a 에서 확인했고 이번에 다시 재지 않았다.
- 오라클이 M5 정의에서 −45.7 % 가 되는 크기(`P` 의 3.3 %)는 T1 의 b 계수 합에서 나온다. T2 에서의 크기는 `evidence/04` 에 있으나 식으로 따로 유도하지 않았다.

**잔여 위험**:

- 표를 인용하는 사람이 "제거율 M5"를 쓰면 이 구성에서 완벽 보정이 −45.7 % 로 읽힌다. 어느 정의를 헤드라인으로 둘지는 D1 의 일부로 남겨 두었다. 보고서·이슈에서 제거율을 인용할 때는 어느 정의인지, 그리고 클램프 비율을 함께 적어야 한다.
- 부호 없는 지표만으로 합격선을 세우면 지연의 2배를 빼는 보정기가 "보정 없음"과 같은 점수를 받는다. D1 은 부호 있는 잔차를 함께 요구할지 정해야 한다.
