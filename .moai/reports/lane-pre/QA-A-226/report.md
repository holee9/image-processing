## 3. "교정됨"의 정의

네 키가 **모두 주어지고 값이 비어 있지 않을 때**만 교정됨이다. 값이 아니라 설정의 사실을 본다.
`xpe_ghost_create`는 빈 값을 "없음"으로 취급해 기본값을 유지하므로 빈 값은 교정으로 세지 않는다. 시험으로 고정했다
(`ThreeOfFourParametersIsStillUncalibrated`, `TierAndOtherKeysAloneDoNotCalibrate`, `EmptyValuesCountAsNotGiven`).

## 5. 명시했지만 순방향 불안정한 설정 (S ≥ 1) — 측정과 제안, 구현은 결정 뒤

정상상태 이득 `S = α1/(1−e^(−1/τ1)) + α2/(1−e^(−1/τ2))` (프레임당 dt = 1 가정). 상수 입력 5000, 200프레임, DLL 실측(`evidence/02_stability_S.txt`):

| 설정 | S | 티어 1 마지막 프레임/입력 | 티어 2 | 티어 3 |
|---|---|---|---|---|
| 0.02 / 3 / 0.003 / 30 | 0.1621 | 0.8381 | 0.8257 | 0.8230 |
| 0.2 / 3 / 0 / 30 | 0.7055 | 0.2945 | 0.2406 | 0.2290 |
| 0.3 / 3 / 0 / 30 | 1.0583 | **0.0000** | 0.0000 | 0.0000 |
| 옛 내장 기본값 0.9 / 1 / 0.05 / 20 | 2.4490 | **0.0000** | 0.0000 | 0.0000 |
| 0.2 / 3 / 0.02 / 30 | 1.3156 | **0.0000** | 0.0000 | 0.0000 |

읽는 법: 상수 입력에서 티어 1 출력은 정확히 `입력 × (1 − S)`이다(0.2945 = 1 − 0.7055). S ≥ 1이면 0으로 잘려 신호가 전부 사라진다.
실제 지연 영상 `y = x/(1−S)`가 존재하려면 S < 1이어야 하므로 S ≥ 1은 물리적으로 말이 되지 않는 설정이다.
티어 2·3은 α에 `w = 1 + 0.5·평균/32768`을 곱하므로 문턱이 `S·w`로 올라간다. 티어 1에서 S = 0.7055인 설정이 레벨 30000의 티어 2에서는 0이 된다(`S·w = 1.03`, 같은 증거 파일 끝부분).

제안(구현하지 않음, 리더 결정):

- **(a) 받아들인다.** 문서에 "S ≥ 1이면 신호가 지워진다"를 적고 끝낸다. 호출자가 책임진다.
- **(b) S ≥ 1을 `XPE_ERR_CONFIG_INVALID`로 거절한다 (권장).** 가중치 없는 식에서도 실패하는 조건이라 측정으로 필요조건임이 확인됐다. 단, 이 문턱은 dt = 1 단위(6절 제안)에 의존하고, 보정 공식을 고정하려고 옛 값 0.9/1/0.05/20(S = 2.449)을 명시한 시험(첫 전체 실행에서 빨강이 된 22건에 P1A066 T4·OOM 파이프라인 2건·타이밍 프로브)이 거절되므로 그 시험들을 안정한 값으로 옮겨야 한다. 값이 바뀌면 기대값 계산도 같이 바뀐다.
- **(c) 티어별 `S·w_max`까지 거절한다.** `w_max`는 평균 입력 범위에 달려 있어 근거 있는 상한이 아직 없다. 실장비 데이터가 나오기 전에는 권하지 않는다.

권장 이유: (b)는 측정으로 확인된 사실(S ≥ 1 → 출력 0)에만 기대고, (c)는 아직 없는 상한을 가정한다.

## 6. D6 — `tau` 단위와 `acquisitionTime` 사용 방식

코드 사실(`ghost_correct.cpp`): `dt = (lastAcqTimeSec > 0) ? (acquisitionTime − lastAcqTimeSec) : 1.0`, `dt ≤ 0`이면 1.0.
`decay = exp(−dt/tau)`. `acquisitionTime`은 `uint64` 정수 초(메타데이터 필드). 헤더·핸들 주석은 `tau`를 "frames"라고 적는다.

설정 0.02/3/0.003/30, 상수 입력 1000, 프레임 2·3의 시각만 바꿔 실측(`evidence/01_d6_acquisition_time.txt`):

| 프레임 2의 시각(프레임 1 = 100, 프레임 3 = 프레임 2 + 1) | 프레임 2 보정값 | 프레임 3 보정값 |
|---|---|---|
| 같은 초 (dt = 0 → 1.0으로 대체) | 977.000 | 959.768 |
| 1초 뒤 | 977.000 | 959.768 |
| 5초 뒤 | 977.000 | 970.683 |
| 600초 뒤 | 977.000 | 977.000 |
| 10⁷초 뒤 | 977.000 | 977.000 |
| 시각 전부 0 (미상) | 977.000 | 959.768 |
| 시각이 거꾸로(100, 90, 91) | 977.000 | 959.768 |

관찰:

1. **단위가 섞여 있다.** 시각이 없거나 0이면 프레임, 있으면 초로 쓰인다. 같은 `tau`가 입력에 따라 다른 단위가 된다.
2. **프레임 사이 간격이 그 프레임이 아니라 다음 프레임에 반영된다.** 프레임 2의 보정값은 간격과 무관하게 항상 977이다(직전 프레임의 이력을 감쇠 없이 쓴다). 간격은 프레임 2 보정 뒤 이력 갱신에만 쓰이고 프레임 3부터 보인다. 간격을 이력에 먼저 반영하는 규약(225 설계 메모의 T1)이라면 프레임 2는 dt = 1에서 982.768, dt = 5에서 993.683, dt = 600에서 1000.000이어야 한다.
3. **정수 초 시각으로는 초당 1프레임보다 빠른 영상에서 시간 모델이 성립하지 않는다.** 같은 초의 프레임은 dt = 0이라 1.0으로 대체되므로 결과적으로 dt ≡ 1(프레임)이 된다. 초당 1프레임보다 느린 영상에서만 초가 단위가 된다.

단일 단위 제안(구현하지 않음, 리더 결정):

- **프레임을 단위로 한다 (권장).** 성공한 호출마다 dt = 1, `acquisitionTime`은 감쇠에 쓰지 않는다. 환자·검사가 바뀌는 단절은 이미 계약인 `xpe_ghost_reset()`(SRS-CALIB-FUNC-014)이 담당한다. 메타데이터 ABI를 건드리지 않고 구현할 수 있고, 위 3번 때문에 실사용(초당 1프레임 이상)에서는 지금도 사실상 이 동작이다.
- **초를 단위로 하려면** 서브초 시각 필드가 필요하다. 메타데이터 구조는 ABI 잠금 대상이므로 계약 변경 결정이 먼저다. 그 경우에도 간격을 보정 전에 반영하도록 순서를 고쳐야 한다(관찰 2).
