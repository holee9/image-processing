## 2. 설계와 변경 (`modules/preprocess/tools/xpe_calib_fixture_gen.cpp`, 프레임 모드만)

방법 문서: `evidence/30_method_fixed_before_measurement.md`, 방법 커밋 `922d3204`.

| 규칙 | 내용 |
|---|---|
| `--out` | 없거나 **빈 디렉터리**여야 한다. 파일이 하나라도 있으면 종료 코드 **14** 로 거부 (아무것도 쓰기 전). **빈 디렉터리는 허용한다** (시험으로 고정) |
| 작업 디렉터리 | `--out` 옆 `<out>.building-<pid>-<ms>`. 그 이름이 이미 있으면 쓰지 않고 실패. 다른 실행의 `.building*` 는 지우지 않는다. 옛 코드가 시작 때 고정 이름을 `remove_all` 하던 부분을 없앴다 |
| 게시 | 4개 파일이 다 만들어진 뒤 `rename(work, out)` 한 번. 빈 `--out` 은 먼저 지우고(빈 디렉터리만 지워진다), 이름 바꾸기가 실패하면 다시 만든다. 실패는 종료 코드 8, 작업 디렉터리는 지운다 |
| 삭제된 것 | 기존 파일을 `old_*` 로 옮기고 되돌리는 코드 전부 (Codex 가 지적한 복원 오류 미검사 포함) |

중단(강제 종료·정전) 뒤 상태는 이제 둘 중 하나다. 게시 전이면 `--out` 은 그대로이고 고유 이름의 작업 디렉터리가 남을 뿐이며, 다음 실행은 그것을 건드리지 않는다. 게시 뒤면 완전한 세트다. 옛 방식의 "`--out` 이 비고 백업만 남았다가 다음 실행이 지움" 상태는 만들어지지 않는다. 남은 `.building-*` 는 사람이 지운다.

## 5. 미검증과 잔여 위험

- 실제 프로세스 강제 종료 시험은 하지 않았다. "중단 뒤 `--out` 이 그대로다" 는 설계에서 나온 결론이고, 시험은 같은 프로세스 안의 강제 실패 경로만 확인한다. 이름 바꾸기 한 번이 원자적이라는 것은 파일시스템 성질에 기댄 가정이다 (같은 볼륨, 로컬 디스크).
- 같은 `--out` 으로 동시에 두 실행을 돌리는 시험은 없다. 설계상 먼저 이름 바꾸기에 성공한 쪽이 이기고 뒤쪽은 종료 코드 8 이지만 확인하지 않았다.
- 남은 `.building-*` 는 자동으로 지워지지 않는다 (다른 실행 것인지 알 수 없어서).
- POSIX 에서는 빈 디렉터리 위 이름 바꾸기가 되므로 "빈 `--out` 먼저 지움" 이 필수가 아니지만, 그 분기는 컴파일·실행하지 않았다 (Windows 한 환경).
- 돌리지 않은 것: 전체 스위트, ctest, clang-tidy, doxygen, cyan_test 재평가 (카드대로 생성 로직이 같으므로 생략 — 산출물 해시 동일로 대체).

## 6. 실행 범위와 정리

시험은 `CalibFixtureGenTest.*` (반증 실행의 `FramesMode*:TheBpm*` 필터 포함), 생성 1회. 한 번에 프로세스 하나였고 끝난 뒤 `xpe_preprocess_tests`·`xpe_calib_fixture_gen` 프로세스는 0개. push 하지 않았다. IAP 문서 갱신(덮어쓰기 불가를 1.3 에 반영)은 리더 몫이라 건드리지 않았다.
