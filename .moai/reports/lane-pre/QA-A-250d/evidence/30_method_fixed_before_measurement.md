# QA-A-250d — 방법 (측정 전에 고정, 측정 전에 커밋)

## 0. 왜

Codex #201 발견 4: QA-A-250c 의 게시는 기존 `--out` 의 파일 네 개를 `<out>.building/old_*` 로 옮긴 뒤 새 파일을 옮겼다. 그 사이에 프로세스가 죽으면 `--out` 이 불완전하고, 다음 실행이 고정 이름 `<out>.building` 을 지워 백업이 사라진다. 리더가 설계를 단순화하기로 결정했다 (카드 `QA-A-250d`): 덮어쓰기를 없앤다.

## 1. 설계 (프레임 모드만, 합성·`--caldata` 경로는 그대로)

| 규칙 | 내용 |
|---|---|
| `--out` | 없거나, **비어 있는 디렉터리**여야 한다. 파일 하나라도 들어 있으면 종료 코드 **14** 로 거부한다 (아무것도 읽거나 쓰기 전). 빈 디렉터리는 **허용**한다 |
| 작업 디렉터리 | `--out` 옆 `<out>.building-<pid>-<ms>` (실행마다 고유). 이미 있는 이름이면 쓰지 않고 실패한다. 다른 실행의 `.building*` 는 지우지 않는다 |
| 게시 | 4개 파일이 모두 만들어진 뒤 디렉터리 이름 바꾸기 **한 번** (`work` → `--out`). 빈 `--out` 이 있으면 먼저 지운다 (빈 디렉터리만 지워진다). 이름 바꾸기가 실패하면 종료 코드 8, 빈 `--out` 이었다면 다시 만들어 둔다, 작업 디렉터리는 지운다. 성공으로 단언하지 않는다 |
| 옮겨 두기 | 없다. 기존 파일을 옮기거나 되돌리는 코드를 지웠다 |
| 동시 실행 | 같은 `--out` 으로 동시에 돌려도 작업 디렉터리가 서로 다르고, 먼저 게시한 쪽이 이기고 뒤쪽은 이름 바꾸기 실패(종료 코드 8)로 끝나며 자기 작업 디렉터리만 지운다. 이 경로의 시험은 없다 (미검증) |
