카드가 "전제부터" 를 요구한 것이 맞았다. **구현은 QA-A-110/111/112 에서 끝났고 main 에 있다.**

| 요구 | 구현 | 위치 |
|---|---|---|

| **게인 앞 단계** | 파이프라인 3단계(오프셋 뒤, 게인 앞) | `pipeline.cpp` |

**순서 확인**: `TheCorrectionRunsAfterOffsetAndBeforeGain` 이 결과로 보인다 — 같은 프레임을 오프셋 켜고/끄고 두 번 돌려 출력이 다르다. 비선형이 오프셋보다 먼저였다면 두 실행이 LUT 에 같은 값을 넣어 출력이 같았을 것이다.

### 카드가 요구한 반증 — 새로 만들어 확인했다

> "LUT 을 항등으로 바꾸면 출력이 달라져야 합니다. 안 달라지면 LUT 이 배선만 되고 안 쓰이는 것"

`NonlinApplyTest.AnIdentityTableChangesTheOutputComparedToTheRealOne`(신규) 이 그것을 파이프라인 수준에서 단언한다:

1. 실제 표로 파이프라인을 돌린다 → 플래그가 켜진다.
2. 손으로 쓴 항등 표(`LUT[i] = i`)를 적재해 같은 프레임을 돌린다.
3. 항등 표는 **화소를 하나도 움직이지 않는다**(입력과 바이트 일치) — 이것이 대조군이다.
4. 실제 표의 출력이 항등 표의 출력과 **다르다**. 같다면 "배선만 되고 안 쓰인다" 는 뜻이다.
5. 한두 화소가 아니라 **절반 이상**이 다른지까지 센다.

통과(`RUN_EXIT=0`). QA-A-111 의 반증(조회를 항등 계산으로 바꾸면 잔차·플래그 시험이 빨강)과 방향이 다르다 — 그쪽은 코드를 약화시켰고, 이쪽은 **데이터를 중립으로 바꿔** 코드가 그것을 실제로 읽는지 본다.

**남은 것은 6b(다항식)·6c(모드 선택)뿐이고, QA-A-112 에 적은 대로 지금 구현할 근거는 측정에서 나오지 않는다**(CPU 대상에서 6a 로 충분: 3072² 적용 6.9 ms = 예산의 1.4%, 표 8 KB).

## 2. (a) 선량 D 의 출처 — 조사 (구현 안 함)

### 후보 1 — 영상 신호 평균

**cyan_test 가 실제로 쓰는 방식이다.** `tests/test_data/cyan_test/README.md:107-113` 의 다중 게인 CalSet 이 선량 레벨을 **ADU 값으로** 적는다:

| 파일 | ADU | README 의 설명 |
|---|---|---|
| `CalSet_14037.raw` | 14,037 | "선량 레벨 1 (약 20% 선량)" |
| `CalSet_20985.raw` | 20,985 | "선량 레벨 3 (약 50% 선량)" |
| `CalSet_42677.raw` | 42,677 | "선량 레벨 5 (약 100% 선량)" |

즉 **선량을 절대 단위가 아니라 검출기 응답으로 대리**한다. API 주석이 `dose_levels` 를 "mGy or relative units" 로 적은 것과 일치한다 — 상대 단위면 ADU 로 충분하다.

| | |
|---|---|
| 필요한 입력 | 오프셋 보정된 프레임 하나. **추가 입력 없음** |
| 지금 있는가 | 있다. 게인 단계는 오프셋·비선형 뒤에 오므로 그 시점의 프레임이 곧 입력이다 |
| 임상 영상에서 성립하는가 | **이것이 핵심 문제다.** 교정용 플랫 필드는 피사체가 없어 평균이 곧 검출기 입사 선량에 비례한다. 임상 영상은 피사체가 빔을 감쇠시키므로 평균이 **선량 × 평균 투과율** 이 된다. 같은 선량이라도 흉부와 손에서 다른 D 가 나오고, 그 D 로 게인을 고르면 **피사체가 교정을 바꾸는** 결과가 된다 |

가능한 보정: 조사야 안의 **직접 조사 영역**(피사체 밖)만으로 평균을 낸다. 그 영역이 있는지는 촬영마다 다르고, 마스크가 필요하다. 이 판단은 조사만 했고 실험하지 않았다.

### 후보 2 — AEC 노출 지표

**메타데이터에는 없다.** `XpeImageMetadata`(`xpe_types.h:108-116`)는 `bodyPart`·`kVp`·`mAs`·`SID_mm`·`pixelPitch_mm`·`acquisitionTime`·`flags` 뿐이다.

다만 **EI 계산 자체는 이 저장소에 이미 있다** — `modules/enhance_advanced/src/detail/exposure_index.h:12`:

> `EI = c1 * g * mean(pixel_values_roi) + c2` (IEC 62494-1)

**이것은 후보 1 을 표준화한 것이다** — 입력이 결국 ROI 화소 평균이다. 따라서 후보 2 는 독립된 정보원이 아니라 후보 1 의 한 형태이고, 같은 피사체 감쇠 문제를 물려받는다. 게다가 `enhance_advanced` 는 **전처리 뒤 단계**라, 게인 보정이 그 결과를 쓰려면 층이 거꾸로 된다.

**진짜 AEC 지표**(장비의 전리함 판독)는 DICOM 태그로 오지만(`ExposureIndex` 0018,1411 등), 이 저장소에서 그것을 읽어 `XpeImageMetadata` 로 옮기는 경로는 **없다**(검색 범위: `modules/` 전체와 `clients/` 전체에서 `AEC|exposure index|ExposureIndex|deviation index` grep).

### 후보 3 — 메타데이터 확장

| | |
|---|---|
