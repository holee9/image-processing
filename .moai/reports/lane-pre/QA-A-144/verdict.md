### (a) 하한 — **6.23 ms 가 아니라 16.29 ms 입니다**

`d0` 의 6.23 ms 를 하한으로 쓰면 틀립니다. 결함이 하나도 없으면 함수가 **보정 루프를 통째로 건너뜁니다**:

```cpp
defect_correct.cpp:169-173
    bool hasDefects = false;
    for (size_t i = 0; i < n; ++i) { if (dm[i] != 0) { hasDefects = true; break; } }
    if (!hasDefects) { ...; return; }          ← 전 프레임 탐색 없이 반환
```

**결함이 하나만 있어도 16.29 ms** 이고, 1개에서 943개까지 **평평합니다**(16.29 / 16.36 / 15.96 — 잡음 안). 즉 그 10 ms 는 결함 수와 무관한 **구조적 비용**입니다:

| 성분 | 근거 |
|---|---|
| 결함 맵 9.4 MB 복사 (`dm_local`, 락 안) | `:156` |
| 프레임 37.7 MB `memcpy` (읽기+쓰기 ≈ 75 MB) | `:167` |
| 전 프레임 탐색 패스 | `:169` 이후 본 루프 |

**따라서 실제 하한은 16.3 ms 이고, 그중 보정 연산은 0 에 가깝습니다.**

### 커널만의 비용 — 직접 못 재서 **기울기로 유도**했습니다

`xpe_interpolate_pixel` 은 내부 헤더에 선언돼 있으나 **DLL 에서 내보내지지 않아** 시험 바이너리가 링크하지 못합니다(`LNK2019` 로 확인). 그래서 밀도 기울기로 유도했습니다 — **실제 경로의 한계비용**이라 오히려 합성 측정보다 낫습니다:

```
(33.64 - 16.29) ms / (94371 - 1) 결함  =  184 ns/결함
교차 확인 (0.1% -> 1%): (33.64 - 18.45) / (94371 - 9437) = 179 ns/결함
```

**SPEC 조건(0.1%)에서 보정 연산은 9437 × 184 ns ≈ 1.7 ms — 전체 18.45 ms 의 약 9%** 입니다.

**군집 비용**: 같은 결함 수에서 군집이 19.21 vs 고립 18.45 — **+4.1%**. 3×3 median 이 4근방 평균보다 비싸지만 차이가 작습니다.

### 3. 회귀 게이트 — **필요합니다. 다만 수치는 CI 를 한 번 보고 정해야 합니다**

**필요한 이유**: 이 경로를 재는 것이 아무것도 없습니다. 검출 게이트(`test_runtime_detection_performance_gate.cpp`)는 `xpe_defect_detect_runtime` 만 부르고, `Integration.PipelinePerformance3072x3072` 는 DISABLED 이며, degraded 예산은 64×64 입니다. **지금 보정이 느려지면 아무 저항 없이 main 에 들어갑니다** — 검출이 유예 기간에 치렀던 그 대가와 같습니다.

**형태**: 비율이 아니라 **절대 예산**. 검출에서 비율 게이트가 기계 편차로 죽은 전례(로컬 702 → CI 1340 ms, 1.91배)가 있고, 지금 그 자리에 절대 400 ms 가 들어가 CI 에서 4.1배 여유로 통과했습니다.

**수치는 제안하지 않습니다.** 로컬 19.21 ms 에서 유도하면 `#144` 에서 한 실수를 반복하는 것입니다. **`dev/preprocess` 를 한 번 밀어 CI 실측을 받은 뒤** 그 값의 4배(검출과 같은 규율)로 정하는 것을 제안합니다.

## §4 반증 — 측정 카드용 두 가지

### ① 하한이 진짜 하한인가 — **처음 잡은 값이 틀렸습니다**

`d0`(6.23 ms)를 하한으로 적을 뻔했습니다. **코드를 읽어 보니 그 경로는 보정 루프를 건너뜁니다**(`:173` 조기 반환). 결함 1개를 재서 **16.29 ms** 라는 진짜 하한을 얻었고, 1~943 구간이 평평한 것이 그 구조적 성격을 확인해 줍니다.

**만약 6.23 을 하한으로 썼다면 목표가 2.6배 타이트하게 잡혀 도달 불가가 됐을 것입니다** — 카드가 경고한 "하한이 부풀면 목표가 느슨해진다" 의 반대 방향 사고입니다.

**그리고 커널만의 비용은 직접 못 쟀습니다** — 심볼이 안 내보내져 링크 실패(`LNK2019`)했습니다. *"제외했다고 적고 포함해 재는"* 것을 피하려고, 기울기 유도로 바꾸고 **그 사실을 적습니다.**

### ② 측정이 눈멀지 않았는가 — **밀도에 반응합니다**

```
결함     1 →  16.29 ms
      9437 →  18.45 ms
     94371 →  33.64 ms
```

**결함 수가 100배 늘 때 시간이 2.1배 늘고**, 기울기가 두 구간에서 일치합니다(184 / 179 ns). 밀도 0 은 6.23 ms 로 확연히 다릅니다.

**재고 있는 것이 보정이 맞습니다.**

## 미검증

- **CI 에서 재지 않았습니다.** 위 수치는 전부 개발 기계(i7-12700)입니다. CI 계수 1.43 은 **형제 경로(검출)의 실측**을 빌린 것이고, 보정 경로에서 직접 재지 않았습니다 — 보정은 메모리 복사 비중이 더 커서 계수가 다를 수 있습니다.
- **UINT16 조건으로 재지 못했습니다** — API 가 FLOAT32 만 받습니다. SPEC 의 조건 기술이 이 함수와 맞지 않는다는 것이 위 발견 ②입니다.
- **군집 비율을 한 가지(2×2 전부)만** 쟀습니다. 실제 패널의 군집 분포는 모릅니다.
- **`dm_local` 복사와 `memcpy` 를 따로 쪼개지 않았습니다.** 16.3 ms 를 세 성분으로 나눈 것은 코드 구조를 읽은 귀속이지 개별 측정이 아닙니다.
- **최적화 가능성을 보지 않았습니다** — 카드 §5 가 금지했습니다. 다만 하한의 90%가 복사·탐색이라는 사실은 최적화를 한다면 어디인지를 말해 줍니다.

## 잔여 위험

- **45 ms 가 CI 에서 빠듯할 수 있습니다.** CI 계수를 형제 경로에서 빌렸기 때문입니다. 보정이 더 메모리 바운드라면 계수가 1.43 보다 클 수 있습니다 — 게이트 수치를 CI 실측 뒤로 미루자는 제안이 그 위험에 대한 대응입니다.
- **AVX2 목표를 지우면 "성능 후퇴" 로 읽힐 수 있습니다.** 실제로는 없는 코드의 목표를 지우는 것이고, 스칼라가 이미 그 수치보다 빠릅니다.
- **`< 30ms (AVX2)` 를 남겨 두면** 다음 사람이 AVX2 경로가 있다고 믿습니다. 오늘 이 저장소에서 여러 번 본 형태입니다.
