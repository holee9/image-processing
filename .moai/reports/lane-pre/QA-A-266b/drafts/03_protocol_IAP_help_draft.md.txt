[초안 — 적용은 리더가 한다] QA-A-266b (이슈 #273). 세 문서에 붙인다: 검증 프로토콜(`docs/calibration/ALGORITHM-VERIFICATION-GUIDE.md` 의 다크 지표 절 — 위치는 리더가 정한다), IAP(`docs/calibration/IAP-CALIB-001_Image_Acquisition_Protocol.md` §1.2 관측된 주의점), 사용자 도움말(`docs/help/content/` 의 다크 품질 지표 설명).

## A. 검증 프로토콜 — 다크 지표의 단계와 ROI 정의

**한 문장 요약.** 다크 지표는 같은 이름이라도 *어느 단계의 값인가*가 다르다. 단계를 적지 않은 DarkBias 는 비교하지 않는다.

| 지표 | 단계 | 잰 영상 | 모집단 | 한계값(SRS) |
|---|---|---|---|---|
| DarkBias, DSNU (옛 `xpe_verify_offset`) | 출력 | offset 단계가 쓴 UINT16 영상(0 바닥·반올림 이후) | 원시의 어두운 10분위 | `abs(DarkBias) ≤ 5` 화소값(FUNC-016) |
| `darkBiasSigned`, `dsnuSigned`, `darkReductionDb` | 부호 있는 잔차 | `x = float(raw) − map` (0 바닥·반올림 이전) | 같은 ROI | **없음** (승인 전) |
| `darkBiasOutput`, `dsnuOutput` | 출력 | 새 함수가 계산한 UINT16 출력 | 같은 ROI | 옛 지표와 같은 값(비트 동일) |
| `clampRatePct` | 부호 있는 잔차 | x < 0 인 화소 비율 | **프레임 전체** | 없음 |
| `zeroOutputRatePct` | 출력 | UINT16 출력 = 0 인 화소 비율 (x < 0.5) | **프레임 전체** | GUI 의 기존 ClampRate ≤ 1 % 와 같은 양 |

**ROI.** 원시 영상의 어두운 10분위: `raw < percentile10(raw)`(엄격한 `<`, 값은 정렬한 사본의 `⌊0.1 N⌋` 번째 원소, 히스토그램으로 같은 값을 얻는다). 원시에 변동이 없으면(`(최대−최소)/평균 ≤ 0.01`) ROI 를 만들지 않는다. ROI 가 **2화소 미만이거나 프레임의 1 % 미만**(정수 비교 `roi × 100 < N`)이면 ROI 지표는 측정하지 않는다. 다른 모집단으로 대체하지 않는다(FUNC-035).

**DarkReduction.** raw ROI 에 변동이 없으면(표준편차 0) 정의되지 않으므로 측정하지 않는다. 값 0 이나 무한대로 채우지 않는다.

**읽는 순서.** ① 반환 코드, ② `validMask` 의 비트, ③ 비트가 켜진 필드만. 미측정을 0 점이나 합격으로 표시하지 않는다.

**해석 주의.** 부호 있는 bias 가 음수이고 `clampRatePct` 가 높으면, 출력 단계의 DarkBias 가 작아 보여도 어두운 화소의 큰 비율이 0 으로 잘린 것이다(`Dark_16`: −4.05, 전체 화소의 83 %). 출력이 부호 있는 값보다 작아질 수 있는 경우(작은 양의 잔차가 0 으로 반올림, 65535 포화)가 있으므로 두 단계의 크기를 직접 비교하지 않는다.

**다크 두 수준 (사실 기록).** `Dark_08~16` 은 raw 전체 평균이 11026.5 와 11020.6 두 수준으로 갈리고(차이 약 5.82 화소값, Codex 독립 재현), 맵을 만든 7장도 4:3 으로 섞여 있다. 그래서 한 맵의 부호 있는 bias 는 한 무리에서 약 +1.9, 다른 무리에서 약 −3.9 로 나온다(프레임별 ROI 값). 원인은 확정하지 못했다. 확인 방법은 촬영 요청서 항목에 있다(리더).

## B. IAP — §1.2 "관측된 주의점"에 덧붙일 문단
> 다크 한 장씩의 평균 화소값이 두 수준(약 11026.5 / 11020.6, 차이 약 5.8)으로 갈리는 현상이 관측됐다(`Dark_08~16`). 한 offset 맵으로 두 수준 모두를 보정할 수 없어, 맵 품질을 부호 있는 잔차로 재면 한 수준에서 약 +1.9, 다른 수준에서 약 −3.9 화소값이 남는다. **원인은 모른다.** 다음 촬영에서는 다크를 연속으로 여러 번 찍고, 장마다 **취득 시각, 판독 모드, 리셋 방식, 온도, 게이트·판독 설정**을 기록한다. 이 기록이 있어야 수준 전환이 시간·온도·모드 중 무엇과 관련되는지 가릴 수 있다. 파일 이름만으로는 알 수 없다.

## C. 사용자 도움말 — "다크 보정 품질 지표" 설명(사용자 글)
> **다크 보정 품질, 어떻게 읽나요**
> 다크(X선을 끄고 찍은 영상)에서 offset 보정이 잘 됐는지는 보정 뒤 평균이 0 에 가까운지로 봅니다. 그런데 보정 결과는 0 보다 작아질 수 없어서(음수는 0 으로 잘립니다), 보정이 너무 많이 빼도 평균이 작은 양수로 보일 수 있습니다.
> 그래서 두 가지 값을 함께 봅니다.
> - **보정 직전 잔차**(부호 있음): 음수면 너무 많이 뺀 것입니다. 이 값이 −4 정도인데 화면의 평균이 +0.2 로 보인다면, 어두운 화소의 대부분이 0 으로 잘리고 있다는 뜻입니다.
> - **0 으로 잘린 화소의 비율**: 프레임 전체 기준입니다. 높을수록 어두운 부분의 정보가 사라지고 있습니다.
> 값 옆에 "측정 안 됨"이 표시되면 계산할 수 없었던 것입니다(어두운 화소가 너무 적거나 모두 같은 값). 합격이나 0 으로 읽지 마세요.
> 한계값(합격 기준)은 아직 부호 있는 값에 정해지지 않았습니다. 화면의 합격 표시는 기존 기준(보정 결과 기준)을 따릅니다.
