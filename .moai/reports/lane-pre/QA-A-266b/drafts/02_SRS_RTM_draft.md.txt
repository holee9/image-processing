## 0. 요구 번호를 정한 방법 (R239-3)
- 새 요구 ID: **`SRS-CALIB-FUNC-040`**.
- 방법: SRS 본문에서 `grep -o "SRS-CALIB-FUNC-[0-9][0-9][0-9]" | sort -u` 로 ID 를 모았다. 001 부터 039 까지 빈 번호 없이 이어지고 039 가 마지막이다(`main` 과 dev/preprocess `HEAD` 의 SRS 모두 같다). `docs/` 와 `.moai/` 전체에서 `SRS-CALIB-FUNC-04x` 를 찾았으나 사용처가 없고, 로컬·원격 38개 ref 의 `docs/` 에서도 `SRS-CALIB-FUNC-040` 은 없다. (`SRS-FUNC-040` 은 다른 문서 XPE-SRS-001 의 로깅 요구이며 접두사가 달라 충돌하지 않는다.)
- 한계: 이 번호는 위 검색 시점에서 비어 있다는 뜻이다. 적용할 때 다른 작업이 먼저 가져갔는지 한 번 더 확인한다.

## A. SRS 문장

### FUNC-016 (dark/offset 지표) — 기존 동작 설명과 규범 변경을 나눈다
**(a) 기존 동작 설명 (규범을 바꾸지 않는다, 덧붙이는 설명)** — 지표별 단계와 모집단:
| 지표 | 기존 구현이 재는 단계 | 모집단 | 비고 |
|---|---|---|---|
| `DarkBias`, `DSNU_ADU` (`xpe_verify_offset`) | offset 단계가 쓴 UINT16 출력(0 바닥·반올림 이후) | 원시의 어두운 10분위 | 한계값은 FUNC-016 의 `abs(DarkBias) ≤ 5` 화소값 |
| `DarkReduction_dB` (`xpe_verify_offset`) | 같은 UINT16 출력 대 원시 | 같은 ROI | |
| `ClampRate` — E2E 평가 프로토콜 §5.2 의 정의 | **0 바닥 이전 잔차** `R − D < 0` 의 비율 | **프레임 전체** | 5 % 를 넘으면 보고·검토 |
| `ClampRate` — GUI(`MetricsComputationService`) | 최종 출력이 0 인 화소의 비율 | sampled preview 의 최종 출력 | 한계 ≤ 1 % 는 GUI 사양서(XPE-GUI-CALIB-001) 표에 있고 SRS-CALIB-001 에는 없다 |
> 위 표는 각 문서·코드가 **현재 하는 일**의 설명이다. 같은 이름 `ClampRate` 가 단계와 모집단이 다른 두 양을 가리킨다는 사실을 적는 것이 목적이고, 어느 쪽이 규범인지는 정하지 않는다.

**(b) 규범 변경 제안 (승인 필요, 승인 전에는 적용하지 않는다)** — 한 문장:
> `ClampRate` 는 단계와 모집단을 이름에 담아 둘로 나누어 보고한다: `ClampRatePct`(0 바닥 이전 잔차, 프레임 전체)와 `ZeroOutputRatePct`(UINT16 출력 0, 프레임 전체). 기존 GUI 의 한계와 5 % 검토 기준을 어느 쪽에 적용할지는 이 요구에서 정하지 않으며 별도 승인 사항이다.

### FUNC-035 (어두운 ROI) — 고치는 문장
- "`dark_roi_min_pixels = 1% of pixel_count`" 뒤에: "정수로 비교한다(`roi × 100 ≥ pixel_count`, 내림 없음). 표본 표준편차가 필요한 지표는 ROI 가 2화소 이상일 때만 측정한다."
- 원시 변동의 조건은 구현 그대로 적는다: `(min + max) / 2 > 0` 이고 `(max − min) / ((min + max) / 2) > 0.01` (산술 평균이 아니라 최소와 최대의 중간값).
- "프레임 전체에서 재는 비율 지표는 ROI 가 없어도 측정된다(`FUNC-040`의 `CLAMP_RATE`)."
- **알려진 호환성 예외(리더 결정)**: 현재 `xpe_verify_offset` 은 1 %를 내림으로 비교하고 두 번째 화소 조건이 없다. 이 SRS 가 정수 비교로 정해져도 옛 함수가 적합하다고 표시하지 않는다. 별도 호환성 후속 카드로 추적한다(아래 이슈 초안).

### FUNC-036 (측정됨/측정 불가 구분) — 덧붙일 한 문장
> `XpeOffsetQuality`(FUNC-040)는 지표 그룹마다 `validMask` 비트로 측정 여부를 싣는다. 비트가 꺼진 필드는 측정값이 아니며 어떤 합격 판정의 입력도 될 수 없다.

### FUNC-037 (지표 구조체) — 덧붙일 한 문장
> `XpeCalibrationMetrics` 의 확장은 이 요구의 범위다. 부호 있는 offset 품질은 별도 구조체 `XpeOffsetQuality`(FUNC-040)가 싣고, 기존 구조체의 필드 이름·오프셋·의미는 바꾸지 않는다.

### 신설 FUNC-040 — 부호 있는 offset 품질
> **SRS-CALIB-FUNC-040. 시스템은 offset 보정의 품질을 0 바닥 이전의 부호 있는 잔차로도 보고해야 한다.**
> 원시 다크 영상과 offset 맵(또는 그 파일)을 입력으로 받아, 잔차 `x = float(raw) − map` 에 대해 어두운 ROI(FUNC-035)의 평균·표본 표준편차·`DarkReduction_dB` 와, 프레임 전체의 `x < 0` 비율(`ClampRatePct`)과 UINT16 출력이 0 인 비율(`ZeroOutputRatePct`)을 보고한다. UINT16 출력에서 잰 DarkBias·DSNU 도 같은 호출에서 함께 보고한다. **같은 raw ROI 를 쓰고 `xpe_verify_offset`(FUNC-016) 과 이 함수가 모두 해당 지표를 측정한 경우, 같은 offset 출력 산술과 통계의 결과로 비트 단위로 같아야 한다.** 한쪽이 측정하지 않으면 0 을 값으로 비교하지 않고 측정 상태의 차이로 표시한다(두 함수의 ROI 최소 판정은 FUNC-035 의 알려진 호환성 예외로 다를 수 있다). 입력으로 받은 맵의 SHA-256 을 보고한다. 이 함수는 어떤 보정 묶음 상태에도 의존하지 않는다. 측정할 수 없는 지표는 측정된 값으로 보고하지 않는다(FUNC-036). 부호 있는 값에는 합격 한계를 정하지 않는다.
> **근거:** UINT16 출력에서만 재면 음의 DarkBias 가 0 바닥에 묻힌다(`Dark_16`: 부호 있는 평균 −4.05, UINT16 에서 +0.19, **프레임 전체 화소의 83 %** 가 0 으로 잘림). **시험:** 단위 — 아래 RTM, 실데이터 — `Dark_08~16`.
