# 3단계 — 운영자 앱 사용자 흐름 (통과 조건, 2026-10-08)

순서: pre 기본(1단계, 닫힘) → post 기본(2단계) → **운영자 앱 사용자 흐름(이 문서)** → DICOM(마지막). 고스트·고급 처리(Phase 2)는 보류.

통과 조건은 실행 전에 적는다. 판정은 앱을 실제로 돌린 결과(UIA E2E + 저장 산출물)로만 한다. 전경 입력(Keyboard/Mouse)을 쓰는 시험은 판정 근거로 쓰지 않는다.

근거 요구: `.moai/project/pipeline-spec.md` §6.1(출시 모드에서 건너뛸 수 없음: (1) offset, (2) gain, (EI-0) 전체 영상 EI, (5)~(8) 로그·잡음·대비·선명화, (14)~(17) 표시·DICOM), §성능 `PERF-P1-001` ≤ 3000 ms. 변경 기록 §13(극성은 Presentation LUT 에서 반전, 기본 창은 해부 영역 자동 창).

| # | 통과 조건 | 판정 방법 | 상태 |
|---|---|---|---|
| U1 | 앱이 CI 산출 DLL(출처 기록 있는 것)로 Native 시작. 옛 DLL 이면 Mock 으로 조용히 바뀌지 않고 갱신 안내로 거부 | `tools/Start-ImageProcTestNative.ps1` + 표시된 모드·DLL 출처 | 대기 |
| U2 | 실데이터 보정 세트(`xpe-data/calib-real-v2`)와 실영상을 빠른 시작 문서의 단계대로 불러온다 | 문서 단계를 그대로 따르는 E2E | 대기 |
| U3 | 앱의 **기본** 처리 체인 = 전처리((1)(2)(3)) → (EI-0) → (5) 로그 → (6) 잡음 → (7) CLAHE → (8) USM → Modality → VOI(자동 창) → Presentation(반전). 출시 모드에서 (5)~(8) 을 끄는 설정이 없다 | 체인 계획·실행 기록(단계 이름 목록) 단언 | 미구현 (GUI-C-234) |
| U4 | 앱이 그린 영상이 같은 DLL·같은 입력의 모듈 체인 출력(2단계 기준 `m2-post-v2/05_FINAL_default_inverted_auto_window.png` 를 만든 경로)과 **비트 동일** | 저장 PNG/uint16 바이트 비교 | 미구현 (GUI-C-234) |
| U5 | EI/DI 값이 화면·결과 기록에 나온다 | UIA 값 + 결과 JSON | 미구현 (GUI-C-234) |
| U6 | 수동 W/L 이 자동 창보다 우선, 메뉴로 자동 복귀 | E2E | GUI-C-233 (검토 중) |
| U7 | 실패 경로: 보정 파일 손상·크기 불일치·네이티브 오류 → 처리 실패 알림, 이전 영상으로 조용히 넘어가지 않음, 결과 기록에 단계·코드 | E2E + 가짜 백엔드 시험 | GUI-C-232c/d (검토 중) |
| U8 | 한 프레임 처리(불러오기 뒤 표시까지) ≤ 3000 ms (`PERF-P1-001`), 앱 안 측정, CI 중앙값 기준 | 앱 기록 시간, 5회 중앙값 | 대기 |
| U9 | 사용자가 빠른 시작(영·한)만 보고 U2→U3→U6 을 따라 할 수 있다. 문서 인용이 앱 실제 문자열과 일치 | 문서 인용 대조 시험 + 리더가 문서대로 1회 수행 | 대기 |
| U10 | Native E2E 전체가 CI 에서 초록(어느 잡이 도는지 확인, 통과 수 대조) | CI 로그 | 대기 |

범위 밖: DICOM 저장·전송(4단계), 고스트·래그, Phase 2 고급 처리, 레거시 `clients/` 뷰어의 기본값(사용자 결정 전까지 현행 유지).

이 문서의 모든 항목이 통과하면 사용자에게 "실사용 가능" 으로 보고한다(영상 + 따라 하기 절차 포함).
