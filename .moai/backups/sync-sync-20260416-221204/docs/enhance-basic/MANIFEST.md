### 2️⃣ SRS - 소프트웨어 요건 명세

**경로**: `docs/enhance-basic/SRS-ENHANCE-BASIC-001_Software_Requirements_Specification.md` (190줄)

**포함 내용**:
- **FR-100**: EI 기준선 (6개 요건)
  - EI = K_gain × Q_mean
  - DI 계산 및 범위
  - EI 계산 타이밍 (로그 전)
  - K_gain 로드
  - EI_T 기본값
- **FR-200**: Log Transform (5개 요건)
  - log(I + ε) 공식
  - ε 검증
  - 우회 불가
  - 범위 보호
  - 단조성
- **FR-300**: CLAHE (6개 요건)
  - Pizer 1987 알고리즘
  - 타일 크기 [16~128]
  - 클립 한계 [0.01~0.1]
  - 쌍선형 보간
  - 해부학 프리셋
  - 우회 가능
- **FR-400**: Window/Level (6개 요건)
  - 선형/비선형 모드
  - DICOM VOI LUT 호환
  - 표준 프리셋
  - WW > 0 검증
  - 출력 클립 [0, 1]
- **SAF-100**: 데이터 무결성 (5개 요건)
- **SAF-200**: 구성 검증 (3개 요건)
- **PERF-100**: 처리 속도 (3개 요건)
  - Phase 1b < 80ms
  - 선형 스케일링
  - 메모리 누수 없음
- **PERF-200**: 메모리 (2개 요건)
  - < 100MB 피크
  - CLAHE 작업 < 10MB

**총 요건**: 40+개  
**목표 대상**: 개발자, QA

### 4️⃣ SHA - 소프트웨어 위험 분석

**경로**: `docs/enhance-basic/SHA-ENHANCE-BASIC-001_Software_Hazard_Analysis.md` (149줄)

**포함 내용**:
- ISO 14971:2019 위험 관리 기준
- **7개 위험 식별**:
  - **HAZ-EB-001**: Log(0) 오류 (ε 검증 실패)
  - **HAZ-EB-002**: EI를 로그 후 계산 (도메인 규칙 위반)
  - **HAZ-EB-003**: CLAHE 과도 증폭 (clip_limit 범위 외)
  - **HAZ-EB-004**: 잘못된 Window Preset (검사 유형 오류)
  - **HAZ-EB-005**: WW ≤ 0 (파라미터 검증 실패)
  - **HAZ-EB-006**: Log 단조성 위반 (대비 반전)
  - **HAZ-EB-007**: 구성 파일 손상 (JSON 오류)
- 각 위험마다:
  - 위험 상황 (상세)
  - 원인 (소프트웨어 관점)
  - 영향 SWU
  - 심각도 (평가)
  - 확률 (평가)
  - 위험도 (전제어)
  - 통제 요건
- 위험 통제 요약 표

**목표 대상**: 안전 담당자, QA

### 7️⃣ TDS - 테스트 데이터 명세

**경로**: `docs/enhance-basic/TDS-ENHANCE-BASIC-001_Test_Dataset_Specification.md` (128줄)

**포함 내용**:
- **Log Transform 검증** (4개 테스트 케이스):
  - 균일 필드, ε 바닥, 단조성, 동적 범위
  - Golden Hash 잠금 (SHA-256)
  - 합격 기준 (수치 오차 < 0.01%)
- **CLAHE 검증** (3개 팬텀):
  - 균일 필드, 스텝 에지, 저선량
  - Golden Hash
  - 정량적 기준 (σ, seam, CNR)
- **EI/DI 검증** (4개 테스트 케이스):
  - 표준, 과다, 저선량, 스티치 억제
  - Golden Hash
  - 정확도 기준 (EI ±2%, DI ±0.1)
- **Window/Level 검증** (2개 모드):
  - 선형, 비선형 (시그모이드)
  - Golden Hash
  - 정확도 기준
- **Golden Reference 관리**:
  - 생성 및 잠금 프로세스
  - 저장소 경로
- **테스트 데이터 체크리스트** (8개 항목)

**목표 대상**: QA, 개발자 (테스트 검증)

