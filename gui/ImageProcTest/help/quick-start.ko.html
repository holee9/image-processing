빠른 시작

실제 원본 영상으로 1단계 전처리 확인하기

가지고 있는 원본(raw) 영상과 보정 맵으로 첫 처리 단계(offset, gain, defect)를 네이티브 모듈에서 실행하고, 잘 될 때와 안 될 때 앱이 무엇을 보여 주는지 확인합니다. 메뉴와 화면의 이름은 앱에 표시되는 영어 그대로 적었습니다. 영어판은 Quick Start 입니다.

준비물

  • 네이티브 DLL 폴더: xpe_common.dll, xpe_display.dll, xpe_preprocess.dll과 이들이 함께 읽는 fmt.dll, spdlog.dll. 현재 main에서 빌드한 DLL을 쓰십시오. 아래 실행 스크립트가 지금 DLL이 최신인지 알려 줍니다.
  • 보정 폴더: offset.xcal, gain.xcal, defect.xcal 세 파일이 폴더 바로 아래에 있어야 합니다(하위 폴더는 찾지 않습니다). 원본 영상과 같은 검출기 크기로 만든 것이어야 합니다.
  • 원본 영상: 16비트 little-endian 화소의 .raw 파일. 가로·세로 크기를 알고 있어야 합니다(3번 참고).
  • 실행 스크립트 tools\Start-ImageProcTestNative.ps1: 1번의 명령을 대신 실행합니다. 스크립트가 하는 일은 손으로도 그대로 할 수 있습니다.

절차

  1. Native 백엔드로 앱을 띄웁니다. 스크립트로:
    .\tools\Start-ImageProcTestNative.ps1 -NativeDir D:\xpe\dlls -CalibDir D:\xpe-data\calib-real-v2 -RawWidth 3072 -RawHeight 3072
    손으로(PowerShell) 같은 일을 하려면:
    $env:XPE_NATIVE_DIR = "D:\xpe\dlls"; $env:XPE_NATIVE_DIR_EXCLUSIVE = "1"
    .\ImageProcTest.exe --automation-backend Native --automation-calib "D:\xpe-data\calib-real-v2" --automation-width 3072 --automation-height 3072
    (스위치 이름의 "automation"은 옛 이름일 뿐이고, 일반 실행에서도 앱이 그대로 적용합니다. XPE_NATIVE_DIR_EXCLUSIVE=1은 앱이 그 폴더에서만 DLL을 찾게 합니다.)
    정상 화면: 창 제목에 [MOCK]이 없고, 빨간 MOCK BACKEND 배너가 없고, 창 아래쪽 줄에 mode=Native | common=xpe_display 1.0.0 | display=1.0.0 | src=<DLL folder name> 같은 글이 나옵니다(src는 DLL을 읽은 폴더 이름).
    그렇지 않고 제목이 [MOCK]으로 시작하고, 아래 줄이 mode=Mock (requested Native)이고, 배너가 MOCK BACKEND — Native was requested but could not be used. Images and results are synthetic; not for clinical judgement. 라면 DLL을 찾지 못했거나 불러오지 못한 것입니다. 이때의 결과는 모두 가짜입니다.
    Mock으로 시작해서 바꾸려면: Backend > Backend Mode > Native 로 실행 중인 앱을 바꿀 수 있고, 바꾸는 즉시 Pipeline > Run Preprocessing (Phase 1a) 가 켜집니다. 보정 폴더와 원본 크기는 따로 지정해야 합니다(2번, 3번). File > Save Settings 로 선택을 저장하면 다음 실행부터 Native로 시작합니다.
  2. 보정 패널을 엽니다: View > Calibration Paths Panel (체크 표시 항목이며 기본은 숨김). 오른쪽에 Calibration paths 패널이 열리고 Offset, Gain, Defect 세 줄이 보입니다.
    --automation-calib나 스크립트로 시작했다면 세 줄에 이미 그 폴더가 표시됩니다. 아니라면 기본값 data/calibration/offset, data/calibration/gain, data/calibration/defect(앱 폴더 기준 상대 경로이고 보통 존재하지 않음)가 보입니다. 경로가 비어 있을 때만 (not set)이 나옵니다. 각 줄의 Browse... 를 눌러 Select calibration directory 대화상자에서 .xcal 세 파일이 바로 들어 있는 폴더를 고릅니다. 세 줄에 같은 폴더를 써도 됩니다. 경로가 설정되면 초록색으로 표시됩니다.
  3. 원본 영상을 엽니다: File > Open Raw... (도구 모음의 Load Raw Image 버튼도 같습니다) 로 Load Raw Image 대화상자에서 .raw 파일을 고릅니다.
    정상 화면: 영상 요약이 RAW 3072x3072, min=…, max=…, bytes=18874368 로 시작합니다. 지정한 가로·세로, 그리고 bytes 가 가로 × 세로 × 2 입니다.
    파일 길이가 크기를 정합니다. 파일이 정확히 가로 × 세로 × 2 바이트이면 지정한 크기로 열립니다. 그렇지 않으면 앱은 모양이 틀린 영상을 열지 않습니다. 정사각형 영상이면 파일 길이로 알아낸 크기로 열고 요약에 이를 적습니다. 예: RAW 3072x3072, min=…, max=…, bytes=18874368 [size from the file length: 18874368 bytes = 3072x3072x2, the settings said 1024x1024 (2097152 bytes)], 그리고 경고 알림이 하나 뜹니다. 그 밖의 길이는 Load failed: Raw file is too small. Expected at least … bytes, got … bytes. (또는 Raw file has … bytes, more than …) 로 거절되고, 화면의 영상은 그대로입니다. 직사각형 영상이면 --automation-width, --automation-height (스크립트의 -RawWidth, -RawHeight) 를 정확히 주십시오.
    이 시점의 화면은 보정 전 원본이고, 아래 줄은 단계를 실행하기 전까지 chain: not run 입니다.
  4. 전처리 단계를 실행합니다: Pipeline > Run Preprocessing (Phase 1a). Native 백엔드에서만 켜집니다.
    정상 화면: 창 아래쪽 줄이 chain: preprocess=Applied, gsvg=NotRequested, ai_bone_suppress=NotRequested; times: preprocess=<n> ms, …; display input=chain 이 됩니다. preprocess=Applied 와 display input=chain 이 함께 보이면 화면의 영상이 보정된 영상이라는 뜻입니다. (times 는 단계에 걸린 시간이고, 이 안내를 확인한 기계에서 3072 × 3072 가 약 0.3초 걸렸습니다.)
    같은 내용이 로그에도 글로 남습니다. View > Logs Panel 을 켜고 분석 패널의 Log 탭을 누르면 됩니다(최신 줄이 위): Chain preprocess: Applied — Preprocess: xpe_preprocess_pipeline_out (offset -> gain -> defect, input kept) on 3072x3072 (Abdomen). 괄호 안은 도구 모음에서 고른 촬영 부위입니다. 이 단계는 모듈의 파이프라인 함수를 쓰며, 열어 둔 원본 영상에는 쓰지 않습니다.
    볼 수 있는 경고 (로그에서 ALERT WARN NATIVE_ALERT 로 시작하는 줄): 실제 1단계 보정 세트에서는 XPE_WARN_GAIN_PIXELS_CLASSIFIED_DEFECT: 44053 of 9437184 pixel(s) (0.467%) have a gain outside [0.1, 10.0] and are marked defective… (그 화소는 gain 1.0 을 쓰고 결함 단계로 넘어갑니다) 와 XPE_WARN_CALIB_SESSION_UNSPECIFIED: calibration maps are loaded together and at least one carries no session id… 가 나옵니다. 만료일이 없는 보정 파일에서는 파일마다 한 번씩 XPE_WARN_NO_EXPIRY: the offset calibration file has expiryEpochMs = 0 (no expiry)… 도 나옵니다.
    상태 줄의 CalibrationEval(…) 로 시작하는 부분은 설정의 보정 모드를 되풀이할 뿐이고, 단계의 결과는 chain: 줄입니다.
  5. 보정 영상을 저장합니다: File > Save Corrected Image (float32 .raw)... 는 모듈이 만든 보정값을 그대로 씁니다. 헤더 없는 raw float32 little-endian, 가로 × 세로 × 4 바이트(3072 × 3072 이면 37748736 바이트)입니다. 보관하고 비교할 파일은 이것입니다. File > Save Corrected Image (16-bit PNG)... 는 눈으로 보기 위한 그림입니다. 값의 1~99 백분위를 0..65535 로 늘린 것이라 데이터가 아닌 표시용 파일입니다. 두 항목은 지금 열려 있는 영상에서 Run Preprocessing 이 적용될 때까지 꺼져 있고, 새 영상을 열면 다시 꺼집니다.
    대화상자는 원본 파일 이름에 _corrected_f32le.raw (PNG 는 _corrected_16bit.png) 를 붙여 원본이 있는 폴더를 제안합니다. 저장되면 상태 줄이 크기와 SHA-256 을 알려 줍니다: Saved corrected image (float32 raw): …\wrist_lat_3072x3072_corrected_f32le.raw — 37748736 bytes, sha256 …. 같은 형식의 기준 영상과 비교하려면 해시를 비교하십시오. 예를 들어 PowerShell 의 Get-FileHash <file> -Algorithm SHA256 로 구하고, 해시가 같으면 바이트가 같습니다.
  6. 원본과 보정 영상을 비교합니다: View > Compare Mode 에는 Swipe (F5), Split (F6), Overlay (F7), Difference (F8), Source Only, Processed Only 가 있고, 영상 위의 버튼 여섯 개도 같은 기능입니다. Source 는 보정 전 원본, Processed 는 보정된 영상, Difference 는 보정으로 바뀐 곳을 보여 줍니다. View > Reset Comparison View 는 확대와 위치를 처음으로 되돌립니다.
    기대하는 모습: 검출기와 선량 분포에서 오는 음영이 보정 영상에서 더 평평하고, 결함 화소가 두드러지지 않아야 합니다. 보정 영상은 표시를 위해 밝기를 다시 맞춘 것이라(가장 밝은 값이 최대 밝기) 회색 값이 아니라 모양을 비교하십시오. 이 안내의 점검은 화면의 그림이 아니라 5번에서 저장한 float 파일을 1단계 기준 영상과 SHA-256 으로 비교했습니다. 그림은 직접 보고 판단하십시오.

문제가 생겼을 때

단계가 실패하면 아래 줄이 display input=raw 로 끝나고 화면은 보정 전 원본입니다. 보정이 실행되지 않은 것입니다. preprocess: 뒤의 문장이 이유입니다.

화면에 보이는 것뜻과 조치
제목이 [MOCK] 으로 시작, mode=Mock (requested Native), Pipeline > Run Preprocessing 이 꺼짐 네이티브 DLL을 찾지 못했거나 불러오지 못했습니다. XPE_NATIVE_DIR 폴더를 확인하십시오(xpe_common.dll, xpe_display.dll, 이 단계에는 xpe_preprocess.dll 도 필요). Backend > Native DLL Diagnostics 는 상태 줄에 display DLL 을 찾았는지와 위치를 보여 주고, 시도한 경로를 로그에 씁니다.
preprocess: Preprocessing skipped: calibration file(s) not found — …\offset.xcal, …\gain.xcal, …\defect.xcal 보정 폴더 바로 아래에 세 파일이 없습니다(상위 폴더이거나 빈 폴더일 수 있음). 앱이 찾아본 경로가 문장에 그대로 나옵니다.
preprocess: Loading offset calibration failed (-5) 맵이 만료되었습니다(-5 는 XPE_ERR_CALIBRATION_EXPIRED). 문장은 처음 실패한 파일을 말하며 나머지도 만료되었을 수 있습니다. 보정을 새로 만드십시오.
preprocess: Loading gain calibration failed (-17) -17 은 XPE_ERR_INVALID_CALIB_DATA 입니다. 파일 형식은 맞지만 값이 요구가 허용하는 범위(gain 은 0.1~10.0)를 벗어났습니다. 2026-10-03 에 빌드한 DLL 과 2026-10-05 에 만든 gain 맵에서 나왔고, 같은 맵을 2026-10-07 에 빌드한 DLL 은 받아들였으므로 DLL 이 최신인지도 확인하십시오.
preprocess: xpe_preprocess_pipeline_out failed (-1) 맵과 원본 영상의 크기가 다를 수 있습니다. 코드만 말하고 이유는 말하지 않습니다(-1 은 XPE_ERR_INVALID_INPUT). 영상 요약의 크기와 맵을 만든 크기를 비교하십시오.
Load failed: Raw file is too small… 파일 길이가 지정한 크기에도, 정사각형 크기에도 맞지 않습니다(3번).

오류 코드는 xpe_error.h 의 것입니다: -1 invalid input, -5 calibration expired, -8 buffer too small, -16 calibration not loaded, -17 invalid calibration data.

이 점검이 다루지 않는 것

  • 단계는 모듈의 파이프라인 함수 xpe_preprocess_pipeline_out 입니다. 온도 보상, 비선형, binning 은 건너뛰도록 지정하고(앱에는 온도·선형성 표·binning 설정이 없습니다) ghost 보정기는 주지 않습니다. 따라서 실행되는 단계는 offset, gain, defect 입니다(파이프라인 함수가 스스로 하는 검사는 앱이 들여다보지 않습니다). 이 함수가 생기기 전에 빌드한 DLL 에서는 offset, nonlinearity, gain, defect 를 하나씩 부르는 옛 방식으로 돌아가고 로그에 this xpe_preprocess.dll has no xpe_preprocess_pipeline_out 이 남습니다. 이 문장이 보이면 DLL 을 갱신하십시오.
  • 단계에 주는 노출 값 일부는 고정입니다(거리 1000 mm, 2.0 mAs). 관전압과 화소 간격은 앱 설정값입니다.
  • 화면의 그림은 보정된 float 영상을 표시용으로 다시 맞춘 것(가장 밝은 값을 최대 밝기로)입니다. 저장한 float 파일은 다시 맞추지 않습니다.
