Scope

Current Build Scope and Limitations

The app runs on two backends. The Mock backend produces synthetic results and exists for shell and automation checks. The Native backend calls the real modules. Which one is running is always visible: a Mock window carries [MOCK] in its title and a red banner.

Native Backend

  • Real xpe_common and xpe_display calls: display pipeline with modality, VOI and presentation LUTs
  • Pipeline > Run Preprocessing (Phase 1a): offset, nonlinearity, gain and defect stages of xpe_preprocess on the loaded raw image, with the calibration maps named in the Calibration paths panel (see the Quick Start)
  • Also present in the Pipeline menu and not covered by the Quick Start: Run Deterministic Baseline (Phase 1b) and Run AI Bone Suppression
  • Falls back to Mock when the DLLs cannot be loaded, and says so in the title bar, the bottom line and the banner

Always Available

  • Raw image loading (.raw, 16-bit little-endian) at the width and height set in the settings, and the recent-file list
  • File > Save Corrected Image (float32 .raw)... and (16-bit PNG)... after Run Preprocessing applied
  • Source-vs-processed comparison viewport: swipe, split, overlay, difference, source only, processed only, zoom, pan and an optional detached viewer
  • Calibration paths panel (Offset, Gain, Defect folders)
  • Logs, alerts, evidence export and the offline help pages

Not Available

  • An input field for the raw image's width and height: set them with --automation-width and --automation-height or in appsettings.json. A square image whose length does not match is opened at the size its length gives, with a note; any other mismatch is refused
  • File > Open DICOM... (Phase 1b), Tools > QA Constancy and Tools > GSDF Calibrate... are disabled
  • The Focus toggle in the top bar is dimmed and marked as not applied
  • Phase 2 and Phase 3 premium or assistive features beyond the single AI bone suppression item

What Phase 1a Runs

The app calls the module's own pipeline function, xpe_preprocess_pipeline_out, which never writes the raw image you opened. Temperature compensation, nonlinearity and binning are bypassed (the app has no temperature, no linearity table and no binning setting) and no ghost corrector is given, so the stages that run are offset, gain and defect. Distance (1000 mm) and exposure (2.0 mAs) given to the stage are fixed; the tube voltage and the pixel pitch come from the app's settings. A DLL built before that function existed is called stage by stage instead (offset, nonlinearity, gain, defect), and the log says so. The picture on screen is the corrected float image rescaled to the 16-bit range by its brightest value; the saved float file is not rescaled.

Ownership Boundary

Real DICOM behavior remains owned by xpe_dicom.dll. The comparison viewport is a host review surface: it preserves the source frame, displays processed output as a separate layer, and records viewport state for evidence.
