Quick Start

Check Phase 1a Preprocessing on a Real Raw Image

Run the first processing stage (offset, gain, defect) on your own raw image with your own calibration maps using the native modules, then compare A/B results and record a verdict and notes. Menu and control names below match the English app labels.

What You Need

  • A folder with the native DLLs: xpe_common.dll, xpe_display.dll, xpe_preprocess.dll and xpe_enhance_basic.dll, plus the runtime DLLs they load (fmt.dll, spdlog.dll). Use DLLs built from the current main; the launch script below reports whether yours are. To get them: run .\tools\Get-CiNativeDlls.ps1 from the repository folder. It needs the GitHub CLI (gh) logged in (gh auth login) and downloads about 300 MB (about 730 MB unpacked, test executables included). It takes only the output of a successful push run on main; a build of a branch that is not merged yet cannot be downloaded with it. It puts the DLLs of the newest green main build in build\e2e-native-dlls (with the DLLs they load and the calibration-set generator xpe_calib_fixture_gen.exe; that folder is emptied first, so do not point it at a folder you use for anything else) and records where they came from in provenance.json, so the launch script can report MATCH. The launch script uses that folder when you leave out -NativeDir.
  • A calibration folder that directly contains offset.xcal, gain.xcal and defect.xcal (subfolders are not searched), made for the same detector size as your raw image. If you do not have one: make it from the public release testdata-calib-v1, which holds the original CalData_6 frames. Download them with gh release download testdata-calib-v1 -R holee9/image-processing -D D:\xpe-data\CalData_6 (about 120 MB; the release lists their SHA-256 values in SHA256SUMS.txt, and it also holds the first-stage reference image wrist_lat_3072x3072_corrected_v2_f32le.raw used for the comparison in step 5). Then run the generator that came with the DLLs: .\build\e2e-native-dlls\xpe_calib_fixture_gen.exe --out D:\xpe-data\calib-real --caldata D:\xpe-data\CalData_6 --expiry-ms 4102444800000 (about 2 seconds). D:\xpe-data\calib-real is then your calibration folder. --expiry-ms writes the expiry date 2100-01-01 into the files; without it the module warns once per file that the file has no expiry date (XPE_WARN_NO_EXPIRY). The procedure for making a set from your own dark and flat frames, and the options for the second-generation defect map (--bpm-v2 --bpm-margins 6,2,1,1), are in part 1 of docs/calibration/IAP-CALIB-001_Image_Acquisition_Protocol.md in the repository. The CalData_6 procedure above and the cyan_test procedure in that document use different inputs.
  • A raw image: a .raw file of 16-bit little-endian pixels. You must know its width and height. The app has no input field for them and does not work them out from the file (see step 3).
  • The launch script tools\Start-ImageProcTestNative.ps1, which runs the command in step 1 for you. Everything it does can also be typed by hand.

Procedure

  1. Start the app on the Native backend. With the script:
    .\tools\Start-ImageProcTestNative.ps1 -CalibDir D:\xpe-data\calib-real -RawWidth 3072 -RawHeight 3072
    (Without -NativeDir the script uses build\e2e-native-dlls; add -NativeDir D:\xpe\dlls to use another DLL folder.)
    By hand (PowerShell), the same thing:
    $env:XPE_NATIVE_DIR = "D:\xpe\dlls"; $env:XPE_NATIVE_DIR_EXCLUSIVE = "1"
    .\ImageProcTest.exe --automation-backend Native --automation-calib "D:\xpe-data\calib-real" --automation-width 3072 --automation-height 3072
    (The switch names say "automation" for historical reasons; the app applies them in a normal launch too. XPE_NATIVE_DIR_EXCLUSIVE=1 makes the app look for DLLs in that folder only.)
    You should see: a window title without [MOCK], no red MOCK BACKEND banner, and runtime information in the top header like mode=Native | common=xpe_display 1.0.0 | display=1.0.0 | src=<DLL folder name> (src is the name of the folder the DLLs were loaded from; versions depend on the loaded DLLs).
    If instead the title starts with [MOCK], the header says mode=Mock (requested Native) and the banner reads MOCK BACKEND — Native was requested but could not be used, then a colon and the reason, then Images and results are synthetic; not for clinical judgement. The DLLs were not found or could not be loaded; the reason names the DLL, its path and what is wrong with it (see the troubleshooting table). Nothing you do from here is real.
    Starting on Mock and switching: Backend > Backend Mode > Native switches the running app, and Pipeline > Run Preprocessing (Phase 1a) is enabled as soon as the switch has happened. The calibration folders and the raw image size still have to be set (steps 2 and 3). File > Save Settings stores the choices, so the next start comes up on Native.
  2. Open the calibration panel: View > Calibration Paths Panel (it is a check mark; the panel is hidden by default). A panel titled Calibration paths appears on the right with three rows: Offset, Gain, Defect.
    If you started with --automation-calib or the script, all three rows already show the folder. Otherwise the rows show the defaults data/calibration/offset, data/calibration/gain and data/calibration/defect (relative to the app's folder; they normally do not exist, and a row shows (not set) only when its path is empty): press Browse... on each row, pick the folder in the Select calibration directory dialog, and choose the folder that directly contains the three .xcal files. The same folder can be used for all three rows. The path appears in green when it is set.
  3. Open the raw image: File > Open Raw... (the toolbar button Load Raw Image does the same) and choose the .raw file in the Load Raw Image dialog.
    You should see an image summary that starts RAW 3072x3072, min=…, max=…, bytes=18874368: the width and height you gave, and bytes equal to width × height × 2.
    The size is never guessed. The file must be exactly width × height × 2 bytes; otherwise it is not opened and the picture on screen stays as it was. The message gives the size that was needed and the bytes the file has: Load failed: Raw file is too small. Expected at least … bytes, got … bytes. or Load failed: Raw file has … bytes, more than the … bytes of …. Set the right --automation-width and --automation-height (the script's -RawWidth and -RawHeight). When calibration maps are in the calibration folders, the image is also refused if its size differs from the maps' (The offset calibration map … is 1024x1024, but the raw image is 3072x3072.). A length that fits does not prove the shape or that the file has no header: a 3072 × 3072 image and a 2048 × 4608 image are the same length, so the size you set must be the size the image was recorded at.
    Preprocessing is on by default, so opening the image automatically runs preprocessing → basic enhancement → display. Check the chain details described in the next step and the HUD to confirm that preprocessing applied. Without calibration files the details say preprocess=Skipped: preprocessing correction did not apply. Native also shows a red NOT CORRECTED banner. chain: not run is the detail before a run; the current footer uses a shorter summary.
  4. Run the preprocessing stages: Pipeline > Run Preprocessing (Phase 1a). The item is enabled only on the Native backend.
    It runs the stages again on the image that is open.
    You should see the chain details in the processing-summary tooltip in the footer. A successful run with the default settings reads chain: preprocess=Applied, enhance_basic=Applied, gsvg=NotRequested, ai_bone_suppress=NotRequested; times: preprocess=<n> ms, …; display input=chain. preprocess=Applied and display input=chain together mean the corrected result was used as the display input; enhance_basic=Applied means the basic enhancement ran too: logarithm, noise reduction, contrast (CLAHE) and sharpening, always on in the default processing and with no setting that turns them off. times gives the stage durations; actual values depend on the image and runtime environment. Read the sentence beginning Exposure index: … in the EI/DI row of Metrics. When measured, it shows uncalibrated EI (uncalibrated measurement) and the EI and DI values. It uses uncalibrated constants and is not a pass criterion. The Korean text in parentheses in the original log is displayed in English on screen.
    The log says the same in words. Switch it on with View > Logs Panel and the Log tab of the analysis panel (newest line first): Chain preprocess: Applied — Preprocess: xpe_preprocess_pipeline_out (offset -> gain -> defect, input kept) on 3072x3072 (Abdomen). The word in brackets is the body part chosen in the toolbar. The stage runs the module's own pipeline function, which never writes the raw image you opened.
    Warnings you may see (log lines starting ALERT WARN NATIVE_ALERT): with the real first-stage calibration set, XPE_WARN_GAIN_PIXELS_CLASSIFIED_DEFECT: 44053 of 9437184 pixel(s) (0.467%) have a gain outside [0.1, 10.0] and are marked defective… (those pixels get gain 1.0 and go to the defect stage) and XPE_WARN_CALIB_SESSION_UNSPECIFIED: calibration maps are loaded together and at least one carries no session id…. For calibration files that carry no expiry date there is also XPE_WARN_NO_EXPIRY: the offset calibration file has expiryEpochMs = 0 (no expiry)…, once per file. These three warnings came from the CalData_6 set and from files without an expiry date. With a cyan_test set made as described in IAP-CALIB-001 and given an expiry date, none of the three appeared. What does appear when the exposure of the image is outside the range (a measured phantom image gave DI of about 11) is ALERT WARN NATIVE_ALERT: Exposure deviation: DI=… (outside [-3.0, +3.0] range) in the log, even though the calibration worked. It is an alert about the exposure measure of the processed image, not a warning of a calibration stage.
    A log or action-detail message beginning CalibrationEval(…) only repeats the correction modes of the settings; check the chain: details and the HUD for the stage result.
  5. Save the corrected image: File > Save Corrected Image (float32 .raw)... writes the corrected values exactly as the module produced them: raw float32, little-endian, no header, width × height × 4 bytes (37748736 bytes for 3072 × 3072). This is the file to keep and to compare. File > Save Corrected Image (16-bit PNG)... writes a picture to look at: the 1st to the 99th percentile of the values stretched to 0..65535, so it is a display file, not data. Both items are enabled when preprocessing has applied to the current image and a corrected result is available to save. Automatic processing on open can meet this condition too.
    The dialog suggests the raw file's name followed by the image size (left out if the name already contains it) and _corrected_f32le.raw (or _corrected_16bit.png) in the raw file's folder: wrist_lat_3072x3072.raw becomes wrist_lat_3072x3072_corrected_f32le.raw, and input.raw becomes input_3072x3072_corrected_f32le.raw. When the file is written, the status line says so and gives its size and SHA-256: Saved corrected image (float32 raw): …\wrist_lat_3072x3072_corrected_f32le.raw — 37748736 bytes, sha256 …. To compare with a reference image of the same format, compare the hashes, for example with PowerShell Get-FileHash <file> -Algorithm SHA256; identical hashes mean identical bytes.
  6. Compare the raw and the corrected image: View > Compare Mode offers Swipe (F5), Split (F6), Overlay (F7), Difference (F8), Source Only and Processed Only; the same six are buttons above the image. Source is the uncorrected raw, Processed is the corrected image, Difference shows where the correction changed the picture. View > Reset Comparison View returns zoom and position to the start.
    What to expect: shading from the detector and the beam should be flatter in the corrected image, and defect pixels should no longer stand out. The corrected image is rescaled for display (its brightest value is mapped to full scale), so compare shapes, not gray levels. This guide's own check judged the saved float file against the first-stage reference image by SHA-256 (step 5), not the picture on screen; look at the picture yourself.

Compare A/B Results and Record a Verdict

Opening an image from a new path with File > Open Raw... adds one item named after the file to Study Queue, with source manual. Reopening the same path uses the existing item. A failed read does not add an item.

Read the result actually displayed

The three footer areas show the processing summary and applied window, stage durations, and the latest warning or error or verdict-refusal reason. Tooltips give chain and action details. Over the image, the top-left STUDY HUD shows the item ID and image summary; the top-right WINDOW HUD shows the applied window values, VOI mode and Calib result. Read the algorithm from the lane's result label. A new choice in a picker or Parameters may differ from the settings already applied to the picture. When Native skips requested preprocessing because calibration data is missing, the NOT CORRECTED banner remains. Basic enhancement and display can run without preprocessing correction having applied.

Choose Reference and Candidate settings

The LANE A — REFERENCE and LANE B — CANDIDATE dropdowns choose the grid correction to apply to the same original. A sets the main pipeline; B chooses the Candidate settings. The four choices are not software versions or approval levels.

ChoiceProcessing requested
No grid correctionRequests no grid correction. It does not switch preprocessing off.
Grid suppressionRequests grid suppression.
Virtual gridRequests a virtual grid.
Preprocess + virtual gridRequests preprocessing and a virtual grid.

Preprocessing has its own switch in Parameters; the first three choices do not turn it off. The Grid correction radios (None / Suppress / Virtual) in Parameters edit the same Candidate setting as the B dropdown and do not change A. If Candidate: settings changed - apply again or Stale appears, apply again with Pipeline > Run Preprocessing (Phase 1a) before comparing.

The nine Metrics rows

Metrics shows four rows of stage results and durations for preprocess, enhance_basic, gsvg and ai_bone_suppress, followed by VOI source, VOI center, VOI width, Calibration stages and EI/DI. These are measurements of the displayed A/B results, not pass criteria. Delta is B − A only when two separate lane runs have measured values. If B reuses A's result, it is one run with no independent Delta. not measured and not run do not mean a successful measurement.

Save notes and a verdict

Enter notes in the field between VERDICT and the verdict buttons at the bottom. It has the tooltip Optional notes for this verdict rather than a visible Notes label. Press Pass, Defer or Fail to record the verdict and notes for the loaded item. Check the counts by verdict in the top RUN-SET badge and the Run-set tab. Changing an item's verdict replaces its old verdict without counting it twice.

Save & Next → saves the selected verdict and notes, then only selects the next queued item: it does not load the next image automatically. Open that item's RAW with File > Open Raw... so the current image matches the selected item before recording its verdict. Choose a verdict first; saving is refused when the image and item do not match. With no queued item left, the current item is retained. This is separate from saving a corrected image in step 5. Export bundle at the top creates a ZIP from the current run-set's evidence folder, which also includes recorded verdicts, notes and backend information. Do not treat a failed save or export message as completion.

The current Pipeline menu order

Run Preprocessing (Phase 1a) → Run Deterministic Baseline (Phase 1b) → Run AI Bone Suppression → Apply Display Pipeline → Use Automatic Window. This is not a procedure that requires clicking every item in sequence. Opening an image runs the default processing automatically; apply again after changing settings. Baseline is a separate check that runs the fixed chain twice and checks for byte-identical outputs. Use Automatic Window returns from a manual window to an image-based automatic window.

Current limitations: AI bone suppression needs xpe_ai.dll and model files. Set AI model directory in Parameters to the folder holding bone_suppress.onnx. An enabled menu item does not prove that a model is ready or that execution succeeded. There is no GUI path to run the advanced enhancement module independently yet (#283). The policy for permitting or blocking uncorrected images remains undecided (#274). Do not interpret NOT CORRECTED as an approved condition of use.

When Something Is Wrong

In the chain details, display input=raw means the display used the original rather than the chain's processed output. Check the stage result and the HUD to see whether preprocessing applied, and read the reason after preprocess:.

What you seeWhat it means and what to do
Title starts with [MOCK]; header says mode=Mock (requested Native); Pipeline > Run Preprocessing dimmed The native DLLs were not found or could not be loaded. Check the folder in XPE_NATIVE_DIR (it needs xpe_common.dll and xpe_display.dll, and xpe_preprocess.dll for this stage). Backend > Native DLL Diagnostics reports in the status line whether the display DLL was detected and where, and writes the paths it tried to the log. The banner says why after the colon: … was not found at '…' (that DLL is not in the folder; the path is where it was looked for), … could not be loaded (the file is damaged or is not a DLL) or … does not export … (an older build than this application expects) (update the DLLs). An old xpe_common.dll or xpe_display.dll left in the application's own folder is a common cause when you start the app by hand: unless XPE_NATIVE_DIR_EXCLUSIVE=1 is set, the application's folder is searched before XPE_NATIVE_DIR. With the launch script (it sets XPE_NATIVE_DIR_EXCLUSIVE=1) only the DLL folder is searched, and the banner names the DLL that is missing or damaged there. If XPE_NATIVE_DIR_EXCLUSIVE=1 is set and XPE_NATIVE_DIR is not, the banner says XPE_NATIVE_DIR does not name it: set the folder.
preprocess: no calibration data: calibration file(s) not found — …\offset.xcal, …\gain.xcal, …\defect.xcal (the HUD's Calib line says not run (no calibration data)) The calibration folder does not directly contain the three files (it may be the parent folder, or empty). The message lists the exact paths the app looked for. Preprocessing is on by default; without the files it is skipped, not run, and the picture is not corrected.
preprocess: Loading offset calibration failed (-5) The map is expired (-5 is XPE_ERR_CALIBRATION_EXPIRED). The message names the first file that failed; the others may be expired too. Make a new calibration.
preprocess: Loading gain calibration failed (-17) -17 is XPE_ERR_INVALID_CALIB_DATA: the file is well formed but its values are outside what the requirement allows (gain must lie in 0.1 to 10.0). Seen with DLLs built on 2026-10-03 and a gain map made on 2026-10-05; the same map was accepted by DLLs built on 2026-10-07, so also check that your DLLs are current.
preprocess: xpe_preprocess_pipeline_out failed (-1) The maps and the raw image may have different sizes. The message gives only the code, not the reason (-1 is XPE_ERR_INVALID_INPUT). Compare the size in the image summary with the size the maps were made for.
Load failed: Raw file is too small… The file length is not width × height × 2 (step 3), or the image size differs from the calibration maps' size.
Preprocessing not run: this xpe_preprocess.dll has no xpe_preprocess_pipeline_out… The native DLLs are older than the app: they have no xpe_preprocess_pipeline_out. Nothing was processed. Update the DLLs and start the app again.
Load failed: The offset calibration map … is 1024x1024, but the raw image is 3072x3072. The calibration maps in the folder were made for another image size. The image is not opened. Open an image of the maps' size, or point the calibration folder at maps made for this size.
Save failed: The process cannot access the file because it is being used by another process. The target file is open in another program. The save did not happen and the previous file is unchanged; close the other program, or save under another name.

Error codes come from xpe_error.h: -1 invalid input, -5 calibration expired, -8 buffer too small, -16 calibration not loaded, -17 invalid calibration data.

What This Check Does Not Cover

  • What you see: the picture is drawn with a window the module picks from the image itself (the anatomy, with the empty background left out), and with the polarity of a reading display: bone bright, air dark. The display line in the log says so: VOI(auto, LinearExact, C=…, W=…). A window you choose by hand (a value you edit, a body-part preset) wins over the automatic one; Pipeline > Use Automatic Window goes back to it. The saved float file (step 5) is not windowed and not inverted: the window and the polarity only change what is drawn.
  • The stage is the module's own pipeline function, xpe_preprocess_pipeline_out, called with temperature compensation, nonlinearity and binning bypassed (the app has no temperature, no linearity table and no binning setting to give them) and without a ghost corrector. So the stages that run are offset, gain and defect (and whatever checks the pipeline function makes on its own; the app does not look inside). With a DLL built before that function existed, the app does not process anything: the chain line reads preprocess=RequestedNotApplied with Preprocessing not run: this xpe_preprocess.dll has no xpe_preprocess_pipeline_out (the DLL is too old). Update the native DLLs and start the app again., and Save Corrected Image stays dimmed. Update the DLLs.
  • Exposure values passed to the stage are partly fixed (1000 mm distance, 2.0 mAs); the tube voltage and pixel pitch come from the app's settings.
  • The picture on screen is the corrected float image rescaled for display (its brightest value is mapped to full scale). The saved float file is not rescaled.
