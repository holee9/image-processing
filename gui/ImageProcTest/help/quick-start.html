Quick Start

Check Phase 1a Preprocessing on a Real Raw Image

Run the first processing stage (offset, nonlinearity, gain, defect) on your own raw image with your own calibration maps, using the native modules, and see what the app tells you when it works and when it does not.

What You Need

  • A folder with the native DLLs: xpe_common.dll, xpe_display.dll and xpe_preprocess.dll, plus the runtime DLLs they load (fmt.dll, spdlog.dll). Use DLLs built from the current main; the launch script below reports whether yours are.
  • A calibration folder that directly contains offset.xcal, gain.xcal and defect.xcal (subfolders are not searched), made for the same detector size as your raw image.
  • A raw image: a .raw file of 16-bit little-endian pixels. You must know its width and height. The app has no input field for them and does not work them out from the file (see step 3).
  • The launch script tools\Start-ImageProcTestNative.ps1, which runs the command in step 1 for you. Everything it does can also be typed by hand.

Procedure

  1. Start the app on the Native backend. With the script:
    .\tools\Start-ImageProcTestNative.ps1 -NativeDir D:\xpe\dlls -CalibDir D:\xpe-data\calib-real-v2 -RawWidth 3072 -RawHeight 3072
    By hand (PowerShell), the same thing:
    $env:XPE_NATIVE_DIR = "D:\xpe\dlls"; $env:XPE_NATIVE_DIR_EXCLUSIVE = "1"
    .\ImageProcTest.exe --automation-backend Native --automation-calib "D:\xpe-data\calib-real-v2" --automation-width 3072 --automation-height 3072
    (The switch names say "automation" for historical reasons; the app applies them in a normal launch too. XPE_NATIVE_DIR_EXCLUSIVE=1 makes the app look for DLLs in that folder only.)
    You should see: a window title without [MOCK], no red MOCK BACKEND banner, and a line at the bottom of the window like mode=Native | common=xpe_display 1.0.0 | display=1.0.0 | src=<DLL folder name> (src is the name of the folder the DLLs were loaded from).
    If instead the title starts with [MOCK], the bottom line says mode=Mock (requested Native) and the banner reads MOCK BACKEND — Native was requested but could not be used. Images and results are synthetic; not for clinical judgement., the DLLs were not found or could not be loaded. Nothing you do from here is real.
    Starting on Mock and switching: Backend > Backend Mode > Native switches the running app, but Pipeline > Run Preprocessing (Phase 1a) then stays dimmed until the app is restarted. After switching, choose File > Save Settings, close the app and start it again; the saved settings start it on Native.
  2. Open the calibration panel: View > Calibration Paths Panel (it is a check mark; the panel is hidden by default). A panel titled Calibration paths appears on the right with three rows: Offset, Gain, Defect.
    If you started with --automation-calib or the script, all three rows already show the folder. Otherwise the rows show the defaults data/calibration/offset, data/calibration/gain and data/calibration/defect (relative to the app's folder; they normally do not exist, and a row shows (not set) only when its path is empty): press Browse... on each row, pick the folder in the Select calibration directory dialog, and choose the folder that directly contains the three .xcal files. The same folder can be used for all three rows. The path appears in green when it is set.
  3. Open the raw image: File > Open Raw... (the toolbar button Load Raw Image does the same) and choose the .raw file in the Load Raw Image dialog.
    You should see an image summary that starts RAW 3072x3072, min=…, max=…, bytes=18874368: the width and height you gave, and bytes equal to width × height × 2.
    Check the size every time. The app reads exactly width × height × 2 bytes from the start of the file. If the file is longer than that, nothing complains: you get a wrongly shaped picture and a bytes= value larger than the summary's size. If the file is shorter, the load fails with Load failed: Raw file is too small. Expected at least 33554432 bytes, got 18874368. Either way, restart with the right --automation-width and --automation-height (the script's -RawWidth and -RawHeight).
    The image on screen is now the uncorrected raw. The bottom line still shows chain: not run until you run a stage.
  4. Run the preprocessing stages: Pipeline > Run Preprocessing (Phase 1a). The item is enabled only on the Native backend.
    You should see in the line at the bottom of the window: chain: preprocess=Applied, gsvg=NotRequested, ai_bone_suppress=NotRequested; times: preprocess=<n> ms, …; display input=chain. preprocess=Applied and display input=chain together mean the picture on screen is the corrected one. (times is how long the stage took; about 0.3 s is what 3072 × 3072 took on the machine this guide was checked on.)
    The log says the same in words. Switch it on with View > Logs Panel and the Log tab of the analysis panel (newest line first): Chain preprocess: Applied — Preprocess: offset -> nonlinearity -> gain -> defect on 3072x3072 (Abdomen). The word in brackets is the body part chosen in the toolbar.
    Warnings that are normal: ALERT WARN NATIVE_ALERT: nonlinearity correction did nothing: no LUT is loaded… (the app loads no linearity table, so that stage passes the frame through unchanged), and, for calibration files that carry no expiry date, XPE_WARN_NO_EXPIRY: the offset calibration file has expiryEpochMs = 0 (no expiry)… once per file. Maps made with an expiry date do not produce the second one.
  5. Compare the raw and the corrected image: View > Compare Mode offers Swipe (F5), Split (F6), Overlay (F7), Difference (F8), Source Only and Processed Only; the same six are buttons above the image. Source is the uncorrected raw, Processed is the corrected image, Difference shows where the correction changed the picture. View > Reset Comparison View returns zoom and position to the start.
    What to expect: shading from the detector and the beam should be flatter in the corrected image, and defect pixels should no longer stand out. The corrected image is rescaled for display (its brightest value is mapped to full scale), so compare shapes, not gray levels. This guide's own check did not judge the picture itself, only the lines above; use your reference image from the first stage to judge the result.

When Something Is Wrong

After any failure of the stage, the bottom line ends with display input=raw and the picture is the uncorrected raw: the correction did not run. The message after preprocess: says why.

What you seeWhat it means and what to do
Title starts with [MOCK]; mode=Mock (requested Native); Pipeline > Run Preprocessing dimmed The native DLLs were not found or could not be loaded. Check the folder in XPE_NATIVE_DIR (it needs xpe_common.dll and xpe_display.dll, and xpe_preprocess.dll for this stage). Backend > Native DLL Diagnostics reports in the status line whether the display DLL was detected and where, and writes the paths it tried to the log.
Run Preprocessing dimmed although the bottom line says mode=Native You switched to Native through the menu. Save Settings, close the app and start it again (step 1).
preprocess: Preprocessing skipped: calibration file(s) not found — …\offset.xcal, …\gain.xcal, …\defect.xcal The calibration folder does not directly contain the three files (it may be the parent folder, or empty). The message lists the exact paths the app looked for.
preprocess: Loading offset calibration failed (-5) The map is expired (-5 is XPE_ERR_CALIBRATION_EXPIRED). The message names the first file that failed; the others may be expired too. Make a new calibration.
preprocess: Loading gain calibration failed (-17) -17 is XPE_ERR_INVALID_CALIB_DATA: the file is well formed but its values are outside what the requirement allows (gain must lie in 0.1 to 10.0). Seen with DLLs built on 2026-10-03 and a gain map made on 2026-10-05; the same map was accepted by DLLs built on 2026-10-07, so also check that your DLLs are current.
preprocess: xpe_offset_correct failed (-1) (older DLLs: (-8)) The maps and the raw image have different sizes. Neither code says so: -1 is XPE_ERR_INVALID_INPUT, -8 is XPE_ERR_BUFFER_TOO_SMALL. Compare the size in the image summary with the size the maps were made for.
Load failed: Raw file is too small… or a wrongly shaped picture with bytes= larger than width × height × 2 The width and height given at start do not match the file (step 3).

Error codes come from xpe_error.h: -1 invalid input, -5 calibration expired, -8 buffer too small, -16 calibration not loaded, -17 invalid calibration data.

What This Check Does Not Cover

  • The app runs the stages one by one: offset, nonlinearity, gain, defect. The module's own pipeline function also does readout-artifact validation, temperature compensation, binning correction and ghost correction; the app does not run those, so its picture can differ from the module pipeline's output.
  • Exposure values passed to the stages are partly fixed (1000 mm distance, 2.0 mAs); the tube voltage and pixel pitch come from the app's settings.
  • There is no command that saves the corrected image.
