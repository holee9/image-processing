# 1부 — 현행 운영 절차 (검증됨)

## 1.1 무엇을 만드는가

앱(`gui/ImageProcTest`)은 보정 폴더 바로 아래의 세 파일만 읽는다.

| 파일 | 내용 | 만드는 생성기 |
|---|---|---|
| `offset.xcal` | 다크 프레임의 화소별 평균 (오프셋 맵) | `xpe_calib_generate_offset` (method `mean`) |
| `gain.xcal` | 한 선량 평탄 영상의 화소별 평균을 전체 평균 1 로 정규화한 맵 (1포인트 게인) | `xpe_calib_generate_gain` |
| `defect.xcal` | 결함 화소 맵 2판(`--bpm-v2`). 결함 화소 평면과 **촬영 영역 평면**, 확장 블록(줄 결함·덩어리 목록)을 담는다 | `xpe_bpm_generate_v2` + `xpe_bpm_find_lines` (`--bpm-v2` 를 줄 때). 1판 `xpe_bpm_generate`(다크: 32×32 창 중앙값·MAD, λ=8 / 밝은 영상: 128×128 창 평균 ±7 %)는 `--bpm-v2` 를 주지 않을 때만 쓴다 |

적용은 `출력 = floor(raw − offset + 0.5) / gain` 뒤 결함 화소를 이웃 값으로 채운다. 분자는 먼저 반올림해 정수로 만든다(GUI-C-250 이 반올림 없는 식과 비교하니 화소의 약 86~88 % 가 0.05 넘게 달랐고, 반올림 식은 0.004 이내로 맞았다).

**offset 은 맵 하나로 운영한다**(사용자 결정 2026-10-15). 촬영 조건마다 맵을 고르지 않는다. 그래서 다크는 **실제 촬영과 같은 적분 시간**으로 찍는다.

## 1.2 취득

모든 프레임은 **오프셋 보정 전 원시 프레임**, uint16 리틀엔디언, 헤더 없음, 3072 × 3072 (파일 크기 18,874,368 바이트)이다.

| 종류 | 장 수 | 조건 | 도구가 막는 것 |
|---|---|---|---|
| 다크 | **최소 5장** (검증: 8장) | X선 끔. 실제 촬영과 같은 적분 시간. 직전 판독 뒤 50초 이상 지나서 찍는다. **목록에는 촬영한 전체 다크를 첫 장까지 넣는다.** 첫 장(안정화 전 프레임)은 도구가 한 번만 뺀다 — 아래 "첫 다크 한 번만 제외" 참고 | 목록 6장 미만(쓰는 장 5장 미만) → 종료 코드 10. `--keep-first-dark` 이면 5장 |
| 게인용 평탄 영상 | **한 선량에서 최소 5장** (검증: 6장) | 피사체 없음, 조사야가 검출기 전체를 덮음, 실제 촬영과 같은 SID·필터. 오프셋을 뺀 평균 화소값이 2000 이상이고 포화가 없을 것 | 5장 미만 → 10. 프레임 평균(오프셋 뺀 값) 최대/최소 > 1.25 (선량 혼합) → 12 |
| 결함 맵용 밝은 영상 | **최소 10장** (검증: 18장) | 게인용과 같은 조건. 선량은 여러 개여도 된다 | 10장 미만 → 10 |

공통 거부: 크기가 틀리거나 없는 파일 → 9, 65535 화소가 프레임의 0.1 % 초과(포화) → 11, 한 역할(다크·게인·결함 맵) 안에 같은 파일(별칭 경로 포함)이나 같은 내용(sha256)이 두 번 → 13. 게인용과 결함 맵용 사이의 공유는 허용한다. 거부되면 **아무 파일도 쓰지 않는다.**

**관측된 주의점 (cyan_test, 규칙으로 검증한 것은 아님)**
- 첫 다크 프레임(`Dark_07`)의 평균 화소값이 다른 다크보다 약 97 낮았다. 나머지 다크는 11026.4 와 11020.6 두 수준을 오갔다(차이 5.8). offset 맵에 첫 장을 넣으면 생성에 안 쓴 다크의 편차가 +14.2 / +8.5 가 되고, 빼면 +2.4 / −3.4 가 된다(2026-10-16 리더 측정). 그래서 도구가 첫 장을 뺀다(1.2 표).
- **첫 다크 한 번만 제외.** 다크 목록에는 촬영한 **전체 다크 영상을 첫 장까지 포함해** 취득 순서대로 넣는다(예: `Dark_07~14`). 첫 장은 검출기가 안정되기 전에 찍힌 영상이므로 생성 도구가 목록의 첫 장을 **한 번만** 제외하고, 남은 같은 목록을 offset 지도, 게인의 다크 참조(`--gain-dark-ref mean`), 결함 맵(1판·2판)에 똑같이 쓴다. 사용자가 첫 장을 직접 빼서 넣으면 도구가 한 장을 더 빼므로 빼지 않는다. 다크가 한 장뿐이면 거부한다(종료 코드 10, 출력 폴더 없음). 이미 안정된 영상만 담은 목록은 `--keep-first-dark` 로 목록 전체를 쓰게 할 수 있다. `dev/preprocess b96707d5` 이전에 만든 세트는 offset·게인에 목록을 그대로 쓰고 2판 결함 맵에서만 한 장을 더 뺐으므로 이 규칙과 다르다.
- **manifest 확인.** `manifest.json` 의 `dark_policy` 에서 `given`(준 목록, 경로·sha256) 대비 `used`(쓴 목록)가 첫 장 하나만 적고, `first_dark_excluded` 가 `true`, `one_list_for_all_stages` 가 `true` 인지 본다. 제외된 장은 입력 목록에 역할 `dark_excluded_first` 로 남는다. `--gain-dark-ref` 가 `none` 이나 파일이면 `one_list_for_all_stages` 가 `false` 이고 `stages_on_the_used_list` 에 `gain_dark_reference` 가 빠진다. 2판이면 `defect_format.dark_frames_used` 가 `used` 장 수와 같아야 하고 `first_dark_excluded_by` 는 `generator`(`--keep-first-dark` 이면 `none`)다.
- **2판은 명시 옵션.** `--bpm-v2` 를 줘야 2판 결함 맵이 만들어진다("2판을 개발 기준으로 채택"이 "CLI 기본값 자동 전환"은 아니다). 2판 파일을 같은 API 로 불러도 보정 결과가 1판과 다르다(방향성 보간, 덩어리 표시, 촬영 영역 밖 보존). 2판 파일은 옛 DLL 이 읽지 못하므로(`XPE_ERR_CONFIG_INVALID`) 파일 판 × DLL 조합을 함께 적어 둔다. SRS 합격 기준은 그대로이며 완화하지 않는다.
- 게인 잔차는 신호가 낮을수록 커졌다. 순신호 화소값 약 2.7~2.9k 프레임은 1.09~1.26 %(기준 1.0 % 초과), 5.9k 이상은 0.41~0.78 %였다. 게인용 평탄 영상은 실제 촬영 신호에 가까운 선량으로 찍는다.

## 1.3 생성

도구: `xpe_calib_fixture_gen.exe`. 병합된 `main` 의 CI 산출물 `xpe-ci-preprocess-binaries` 에 들어 있고, `tools/Get-CiNativeDlls.ps1` 이 내려받는다. 이 스크립트는 **`main` 에서 성공한 push 실행**의 산출물만 받는다(병합 전 브랜치의 산출물은 받지 않는다). 그리고 `-Dest` 폴더를 비우므로 **개인 폴더**를 지정한다.

원시 프레임(`Dark_*`, `Bright_*`)은 git 으로 추적하지 않는다(`.gitignore` 의 `tests/test_data/**/*.raw`). 로컬 위치는 `tests/test_data/cyan_test/calfiles/` 이고, 데이터셋 설명(검출기, 수집일 2026-04-02, 파일 구성)은 추적되는 `tests/test_data/cyan_test/README.md` 에 있다. 새 작업 환경에는 이 폴더를 따로 복사해야 한다.

```powershell
xpe_calib_fixture_gen.exe --out <보정 폴더> --expiry-ms <만료 Unix ms> `
    --dark-list <다크 목록.txt> `
    --bright-list <게인용 평탄 목록.txt> `
    --bpm-bright-list <결함 맵용 밝은 영상 목록.txt> `
    --bpm-v2 --bpm-margins 6,2,1,1
```

- `--bpm-v2`: 결함 맵 2판으로 만든다. 주지 않으면 1판이며, 1판은 줄 결함·촬영 영역 밖 표시가 없다.
- `--bpm-margins 6,2,1,1`: 촬영 영역 밖 여백(좌,상,우,하 순서, 화소 수). 값은 사용자 결정(2026-10-16)이다 — 이 검출기는 왼쪽 열 0~5, 위쪽 행 0~1, 오른쪽 열 3071, 아래쪽 행 3071 이 촬영 영역이 아니다(차폐·더미 화소). 근거는 QA-A-252b 경계 진단이고 계획서는 `.moai/project/bpm-v2-plan.md` 7절이다. 2판은 이 화소를 결함 판정과 국소 통계에서 빼고 "촬영 영역 밖"으로 표시한다. 기본값은 `0,0,0,0` 이라 **다른 검출기에서는 그 검출기에서 따로 측정한 값을 줘야 한다.**

- 목록 파일: 한 줄에 경로 하나, `#` 은 주석, 상대 경로는 목록 파일 기준. `--dark F` / `--bright F` / `--bpm-bright F` 반복으로 대신할 수 있다.
- `--bpm-bright` 를 생략하면 게인용 평탄 영상을 결함 맵에도 쓴다(이때는 10장 이상 필요).
- 다크 목록 파일에는 촬영한 **전체 다크를 첫 장까지** 넣는다(첫 장은 도구가 한 번만 뺀다).
- `--keep-first-dark`: 첫 장을 빼지 않고 목록 전체를 쓴다(이미 안정된 영상만 담은 목록용). 이 옵션을 쓰면 최소 장 수는 5장이다.
- 게인의 다크 참조는 기본 `--gain-dark-ref mean`(도구가 쓰는 다크의 평균). 평탄 영상이 이미 오프셋 보정된 데이터면 `none`. `none` 이나 파일이면 manifest 의 `one_list_for_all_stages` 가 `false` 가 된다.
- 장비 회사 결함 맵과 비교만 하려면 `--compare-bpm <파일>` (세트에는 쓰지 않는다, 결과는 `manifest.json`).
- `--expiry-ms`: 예) `4102444800000` 은 2100-01-01 이다. 만료가 지나면 앱이 보정 단계에서 프레임을 거부한다(`XPE_ERR_CALIBRATION_EXPIRED`). 0 은 만료 없음이며 적재마다 경고가 난다. 유효 기간은 현장 정책으로 정한다(검증된 권장값 없음).

`--out` 은 **새 폴더(없거나 비어 있는 폴더)**여야 한다. 이미 세트가 있는 폴더에 덮어쓰지 않는다 — 새 폴더에 만들고 앱의 보정 폴더를 바꾼다. 비어 있지 않은 `--out` 은 종료 코드 14 로 거부하고 아무것도 쓰지 않는다. 생성은 같은 상위 폴더의 실행별 임시 폴더에서 하고, 네 파일이 모두 생긴 뒤 폴더 이름 바꾸기 한 번으로 `--out` 에 게시한다 — 중간에 실패하면 `--out` 은 생기지 않는다(QA-A-250d).

종료 코드 0 이면 `<보정 폴더>` 에 `offset.xcal`·`gain.xcal`·`defect.xcal`·`manifest.json` 이 생긴다. `manifest.json` 에 입력 파일별 경로·sha256·평균, 장 수, 설정이 기록된다. `--bpm-v2` 를 주면 `defect_format` 항목, 모든 세트에 `dark_policy` 항목도 생긴다(`xcal_version`, `margins_ltrb`, `pixels_outside_imaging_area`, `line_groups`, `blobs` 등).

도구는 진행 표시 없이 끝나고 **네 줄만 출력한다**: 세 파일의 sha256, 결함 화소 수(QA-A-259 실측 2,353 — 이전 방식 세트의 GUI-C-250 실측은 2,209), `manifest.json` 경로. 소요 시간은 QA-A-259 실측 149.2초(같은 18장, 최대 작업 집합 2,002 MiB, 3072×3072 도구 전체 기준이라 PERF-002 와 비교하지 않는다)이며, 이전 방식은 GUI-C-250 실측 2분 31초였다.

**검증된 예 (cyan_test, QA-A-250c, 세트 `calib-cyan-v3`)** — 다크 `Dark_07~14`(첫 장 제외 규칙 이전에 만든 세트), 게인 `Bright_23~28`(한 선량), 결함 맵 `Bright_17~28`·`Bright_31~36`(18장, 평가용 29·30 제외). (이 세트는 `--bpm-v2` 이전 방식으로 만들었다.)

**현재 도구의 실측 (QA-A-259 §4)** — 입력 다크 `Dark_07~14`(8장, 도구가 첫 장을 빼 `Dark_08~14` 7장 사용), 게인 `Bright_23~28`, 결함 맵 `Bright_17~28`·`31~36`(18장), `--bpm-v2 --bpm-margins 6,2,1,1 --expiry-ms 4102444800000`. 종료 코드 0, offset sha256 `5569bacf66fb25f10b9137ebf3f466e9ce8d94857c90dc4a7340df362c290c39`, gain `a7ddadbd5b69a350c44c638fd8887096ca4cb448eda322e5d8976575c7520d22`, defect `4579e06bcf5be09828935eb48c71bd78d1f51afc9fc97f83e678158dfa2f105c`(결함 화소 2,353). 위 `calib-cyan-v3` 와는 조건이 달라 숫자를 섞어 비교하지 않는다. 예전 1판·2판 비교(QA-A-256)는 결함 맵 다크가 1판 7장, 2판 6장이었음을 함께 적어 인용한다.

## 1.4 앱에서 쓰기

```powershell
tools/Start-ImageProcTestNative.ps1 -CalibDir <보정 폴더> -RawWidth 3072 -RawHeight 3072
```

이후 순서는 빠른 시작(`gui/ImageProcTest/help/quick-start.ko.html`)을 따른다. 정상이면 **로그 패널**에 `Chain preprocess: Applied — Preprocess: xpe_preprocess_pipeline_out (offset -> gain -> defect, input kept) on 3072x3072 (Abdomen)` 줄이 생기고, 상태줄에는 `chain: preprocess=Applied, …` 가 나온다. **보정 단계의 경고·오류는 없다.** 다만 알림 목록에 `ALERT WARN NATIVE_ALERT: Exposure deviation: DI=10.99 (outside [-3.0, +3.0] range)` 가 보일 수 있다. 이것은 노출 지표 알림이며 보정 단계 경고가 아니다(GUI-C-250 에서 정상 처리와 함께 관측).

## 1.5 검증 결과 (2026-10-15)

| 항목 | 기준 | 결과 | 근거 |
|---|---|---|---|
| offset | FUNC-016 `\|DarkBias\| ≤ 5` (화소값) 또는 `DarkReduction_dB ≥ 10` (생성에 안 쓴 다크) | DarkReduction 21.68 / 21.80 dB → 통과. - 검증한 데이터셋은 cyan_test 하나(검출기 1대)다. CalData_6 는 다크 1장·평탄 영상이 이미 오프셋 보정된 상태라 이 절차의 입력 조건을 만족하지 않는다.

- 운영자가 쓸 품질 판정 도구(FUNC-016·017 지표 계산)는 아직 없다. 위 판정은 개발 하니스로 했다.
- 선량 혼합 한도 1.25 는 cyan_test 하나에서 정했다. 선량 단계가 25 % 미만인 패널에서는 혼합이 통과할 수 있다.

## 6. 캘리브레이션 영상 유형별 취득 프로토콜

### 6.1 Dark Frame (오프셋 맵용)

#### 6.1.1 목적

X-ray 발생기가 OFF인 상태에서 픽셀별 어두운 전류(offset)를 측정합니다.

- **사용처**: Offset Map 생성 (다른 모든 영상에서 차감)
- **특성**: 온도, PREP time에 매우 민감

#### 6.1.2 필요 장비

- 검출기 (X-ray 실 내 정상 위치)
- X-ray 발생기 (OFF 상태)
- 환경: X-ray 실 표준 조명 가능 (어둠 불필요)
- NTC 온도 센서

#### 6.1.3 X-ray 조건

| 항목 | 설정 |
|-----|------|
| **X-ray 발생기** | **OFF** (조사 없음) |
| **Anti-scatter Grid** | 제거 또는 위치 (영향 미미) |
| **선원 거리 (SID)** | 기록만 (영향 없음) |

#### 6.1.4 팬텀 설정

| 항목 | 설정 |
|-----|------|
| **팬텀** | **없음** (필요 없음) |
| **검출기 앞** | 자유 공간 |

#### 6.1.5 취득 단계 (Factory 프로토콜)

**Factory**: 온도×PREP time 매트릭스 (42 dark map entries)

**단계 1**: 온도 포인트 설정 (6개)

온도 포인트: 15°C, 20°C, 25°C, 30°C, 35°C, 40°C
```

**단계 2**: PREP time 레벨 설정 (7개)
```
PREP time: 1초, 2초, 5초, 10초, 15초, 20초, 30초
```

**단계 3**: 각 온도×PREP time 조합마다 다음 실행

```
FOR each Temperature T in [15, 20, 25, 30, 35, 40]:
    FOR each PREP_Time P in [1, 2, 5, 10, 15, 20, 30]:

        ├─ 검출기를 온도 T로 조절
        ├─ 온도 변화 < 0.1°C/분 확인

        ├─ HnVue에서 PREP time = P 초로 설정
        └─ 이 기간 동안 검출기 판독 준비 (전하 누적 시뮬레이션)
        
        Step 3c. Dark Frame 수집
        ├─ N = 100 프레임 연속 수집
        │  (X-ray는 계속 OFF)
        ├─ 프레임 시간 간격: 1 프레임/초
        └─ 획득 시간: 약 100초
        
        Step 3d. 메타데이터 기록
        ├─ 파일명: dark_T[temp]_P[prep_time].raw
        ├─ 취득 시간, 온도, PREP time, 프레임 수
        └─ 예: dark_T25.0_P10.0.raw
        
        Step 3e. 합격 기준 확인 (6.1.7 참조)

**단계 4**: 모든 42개 조합 완료 확인

| Factory | Field |

#### 6.1.7 합격 기준

**취득 후 각 dark map에 대해 다음을 확인**:

| 기준 | 임계값 | 합격/불합격 판정 |
|-----|--------|---------|

#### 6.1.8 주의사항

1. **온도 안정화 필수**: 매 온도마다 최소 10분 대기 (드리프트 < 0.1°C/분)

4. **환경 진동**: 취득 중 진동 최소화 (근처 장비 OFF)
5. **저장 형식**: `.raw` 16-bit unsigned 또는 DICOM 형식

#### 6.1.9 취득 시간 추정

- **온도 1개**: 약 7 × 100초 + 온도 변경 시간 = ~12분
- **온도 6개 전체**: 약 72분 (+ 온도 변경/안정화 = ~2시간)

### 6.2 Flat-field Frame (게인 맵용)

#### 6.2.1 목적

균일한 X-ray 조사 하에서 픽셀별 감도(게인)를 측정합니다.

- **사용처**: Gain Map 생성 (픽셀 표준화)
- **특성**: SID, 필터, 팬텀에 매우 민감

#### 6.2.2 필요 장비

- 검출기 (정상 위치)
- X-ray 발생기 (RQA-5 스펙트럼 설정)
- 균일 산란 팬텀 (3cm PMMA)
- Anti-scatter Grid (제거 또는 기록)
- NTC 온도 센서

#### 6.2.3 X-ray 조건

| 항목 | 설정 |
|-----|------|
| **kVp** | **70 kVp** (RQA-5 표준) |
| **필터** | **21 mm Al** (RQA-5 표준) |
| **노출 시간** | 30~50 ms (선량계 확인) |
| **mAs** | 신호 40~60% 포화되도록 조절 |
| **Anti-scatter Grid** | **제거** (균일성 영향) |

#### 6.2.4 팬텀 설정

| 항목 | 설정 |
|-----|------|
| **팬텀** | 3cm PMMA 균일 산란 팬텀 |
| **위치** | 검출기 정면, 중심 정렬 |
| **높이** | X-ray 빔 중앙 (혼자 시야 필드) |

#### 6.2.5 취득 단계 (Factory 프로토콜 - Duo-SID 방식)

**목표**: 두 개의 SID에서 각각 20 프레임씩 플랫-필드 취득 (힐 효과 보상)

**단계 1**: SID 설정 (두 거리)

```
SID_min = 110 cm  (또는 최단 허용 거리)
SID_max = 150 cm  (또는 최장 임상 거리)
```

**단계 2**: SID_min에서 취득

```
Step 2a. SID 설정 및 확인
├─ X-ray 튜브-검출기 거리를 110 cm로 설정
├─ 눈금자로 정확히 측정 (±1 mm)
├─ 검출기 중심과 X-ray 중심 정렬
└─ 환기/냉각 장비 확인 (열 누적 방지)

Step 2b. mAs 조절 (신호 40~60% 포화)
├─ 테스트 노출: 기본 mAs로 한 프레임 취득
├─ 신호 수준 확인 (평균 ADU 기대값):
│  40% 포화 = 2621 ADU (14-bit)
│  60% 포화 = 3932 ADU (14-bit)
├─ 신호 < 40%: mAs 증가
├─ 신호 > 60%: mAs 감소
└─ 재테스트 후 확정

Step 2c. Dark Frame 취득 (Flat-field 직전)
├─ X-ray OFF로 설정
├─ 검출기가 dark frame을 자동 수집
├─ N = 20 프레임 (flat-field과 동일 수)
└─ 파일명: dark_sid110_pre.raw

Step 2d. Flat-field Frame 취득
├─ X-ray ON (70 kVp, 21 mm Al, 확정된 mAs)
├─ PREP time = 10초 설정 (안정화)
├─ 10초 대기 (검출기 자동 준비)
├─ P = 20 프레임 연속 수집
│  (각 프레임 = 단일 노출)
├─ 프레임 간격: 1 프레임/초
├─ 획득 시간: 약 20초
└─ 파일명: ff_sid110_70kv_21al.raw

Step 2e. 메타데이터 기록
├─ 취득 시간, SID, kVp, 필터, mAs
├─ 평균 신호 수준 (ADU)
├─ 신호 표준편차
└─ 팬텀 위치, 온도
```

**단계 3**: SID_max에서 취득 (단계 2 반복)

```
mAs를 SID_max에 맞춰 조절
(일반적으로 더 큰 거리 = 더 높은 mAs 필요)

예: SID_max = 150 cm에서 신호 40~60% 포화되도록
(증가된 거리 = 신선량 감소 = mAs ↑)
```

**단계 4**: 다중 게인 레벨 취득 (선택, 권장)

```
고급: 신호 10%, 30%, 50%, 70%, 90% 포화 수준에서
각각 P=20 프레임씩 취득 (다항식 게인 피팅용)
```

#### 6.2.6 취득 수량

| Factory | Field |
|---------|-------|
| **P = 20 프레임** × 2 SID | **P = 20 프레임** (또는 기준 SID 1개) |
| + Dark: 20 × 2 | + Dark: 20 |
| **총 80 flat-field 프레임** | **총 40 프레임** (또는 20) |

#### 6.2.7 합격 기준

**취득 후 각 flat-field 세트에 대해**:

| 기준 | 임계값 | 합격/불합격 |
|-----|--------|----------|
| **신호 범위** | 40~60% 포화 | < 40%: **불합격** (신호 부족) |
| | | > 60%: **불합격** (과포화 위험) |
| **균일성** | σ/μ < 1% (80% FOV) | > 1%: **불합격** (팬텀/조정 확인) |
| **중심 빔 위치** | (cx, cy) 기록 | 편차 > 5mm: **재조정** |
| **암부 신호** | < 5% 포화 | 암부 > 5%: **불합격** (스캐터 과다) |
| **프레임 수** | P ≥ 20 | P < 20: **재촬영** |

**조치**:
- **합격**: 맵 생성 진행
- **불합격**: Section 8 참조

#### 6.2.8 주의사항

1. **팬텀 위치**: 프레임마다 동일 위치 (움직임 없음)
2. **Anti-scatter Grid 제거**: 그리드 있으면 균일성 악화
3. **빔 중심 기록**: (cx, cy) 픽셀 좌표 기록 (힐 효과 보상)
4. **튜브 열 관리**: 연속 노출 시 냉각 대기 필요
5. **신호 안정화**: PREP time = 10초 필수

#### 6.2.9 취득 시간 추정

- **SID 1개** (2 SID 방식): 약 5분 (팬텀 설정 제외)
- **2 SID 전체**: 약 15분 (SID 변경 + 재정렬)

### 6.3 불량 픽셀 맵 (BPM) 생성용 영상

#### 6.3.1 목적

세 온도 수준에서 핫(hot) 픽셀과 데드(dead) 픽셀을 검출합니다.

- **사용처**: Bad Pixel Map (결함 픽셀 검출 및 보간)
- **특성**: 온도 의존 (핫 픽셀), 신호 의존 (데드 픽셀)

#### 6.3.2 필요 장비

- 검출기
- X-ray 발생기 (70 kVp, 21 mm Al, 팬텀)
- NTC 온도 센서
- 균일 산란 팬텀

#### 6.3.3 X-ray 조건

| 항목 | 설정 |
|-----|------|
| **kVp** | **70 kVp** (표준) |
| **필터** | **21 mm Al** (표준) |
| **신호 수준** | **50% 포화** (일정한 조건) |
| **SID** | 기준 거리 (예: 110 cm) |

#### 6.3.4 측정 절차

**세 온도에서 각각**: 200 Dark + 200 Flat-field 프레임

```
FOR each Temperature T in [cold, nominal, warm]:
    
    T_cold   = 15°C (또는 최저 임상)
    T_nominal = 25°C (기준)
    T_warm   = 35°C (또는 최고 임상)
    
    Step 4a. 온도 조절 및 안정화
    ├─ 검출기를 온도 T로 설정
    ├─ 온도 안정화: ±0.1°C 이내
    └─ 최소 10분 대기
    
    Step 4b. Hot Pixel 검출 (Dark Frame)
    ├─ X-ray OFF
    ├─ T = 200 dark 프레임 수집
    │  (온도 의존 누설 전류 측정)
    ├─ PREP time = 20초 (최대 누설 조건)
    └─ 파일명: dark_bpm_T[temp].raw
    
    Step 4c. Dead Pixel 검출 (Flat-field Frame)
    ├─ X-ray ON (70 kVp, 21 mm Al)
    ├─ 신호 = 50% 포화 (명확한 신호/노이즈)
    ├─ T = 200 flat-field 프레임 수집
    │  (응답 없는 픽셀 검출)
    └─ 파일명: ff_bpm_T[temp]_50sat.raw
```

#### 6.3.5 취득 수량

| 항목 | 수량 |
|-----|------|
| **온도 포인트** | 3개 (15°C, 25°C, 35°C) |
| **Dark Frame/온도** | 200 |
| **Flat-field Frame/온도** | 200 |
| **총 프레임** | (200+200) × 3 = **1,200 프레임** |

#### 6.3.6 합격 기준

**검출 후 BPM에 대해**:

| 기준 | 임계값 | 조치 |
|-----|--------|------|
| **결함 픽셀 비율** | < 1% | > 1%: **불합격** (검출기 불량) |
| **Hot pixel 격자** | 나이퀴스트 조건 (2×2 이상 간격) | 밀집 결함: **대안 검출기** |
| **Dead pixel 패턴** | 임의 분포 | 줄(row)/열(column) 패턴: **재검사** |
| **온도 의존성** | 뜨거운 쪽 more defects | 반대: **재촬영** |

#### 6.3.7 주의사항

1. **온도 정확도**: 각 온도마다 정확히 설정 (±0.5°C)
2. **PREP time**: Hot pixel 검출에는 긴 PREP time (20초) 권장
3. **프레임 200개 필수**: 통계 신뢰도 높음

#### 6.3.8 취득 시간 추정

- **온도 1개**: 약 50분 (dark + flat-field)
- **3 온도 전체**: 약 2.5~3시간

### 6.4 비선형성 측정용 영상

#### 6.4.1 목적

여러 신호 수준에서 픽셀 응답 곡선을 측정합니다 (선형화 곡선 계산).

- **사용처**: 비선형성 Look-Up Table (LUT) 또는 다항식 계수
- **특성**: 신호 수준에 매우 의존

#### 6.4.2 필요 장비

- 검출기
- X-ray 발생기 (70 kVp, 21 mm Al)
- 스텝 웨지 또는 여러 산란 팬텀
- NTC 온도 센서

#### 6.4.3 신호 수준 설정

**최소 5개 신호 수준** (권장 7~10개):

| 신호 수준 | ADU 값 (14-bit) | 포화 비율 |
|----------|--------|-----------|
| Level 1 | 655 | 5% |
| Level 2 | 1310 | 10% |
| Level 3 | 2621 | 20% |
| Level 4 | 4096 | **30%** |
| Level 5 | 6553 | **50%** |
| Level 6 | 8192 | 62.5% |
| Level 7 | 10240 | 78% |
| Level 8 | 11469 | 88% |
| Level 9 | 12290 | 94% |

#### 6.4.4 측정 절차

```
FOR each Signal_Level E in [5%, 10%, 20%, ..., 90%]:
    
    Step a. 신호 수준 맞춤 (mAs 조절)
    ├─ 테스트 프레임 1개 취득
    ├─ 평균 신호 확인

    └─ 최대 3회 반복 조절
    
    Step b. 다중 프레임 취득 (신뢰도)
    ├─ N = 16 프레임 연속 수집
    │  (같은 mAs 설정)
    ├─ 프레임 평균화 (노이즈 감소)
    └─ 파일명: nlin_E[level]_[percent]sat.raw
```

#### 6.4.5 취득 수량

| 항목 | 수량 |
|-----|------|
| **신호 수준** | 최소 5 (권장 7~10) |
| **프레임/수준** | 16 |
| **총 프레임** | 5 × 16 = **80 프레임** (최소) |

#### 6.4.6 합격 기준

**비선형성 보정 후**:

| 기준 | 임계값 |
|-----|--------|
| **R² 값** | > 0.999 (다항식 피팅) |
| **잔차 > 1%** | < 5% 픽셀 |
| **보정 후 평탄도** | σ/μ < 0.5% |

#### 6.4.7 주의사항

1. **신호 선형성**: mAs와 신호의 선형 관계 확인
2. **포화 회피**: 90% 포화 이상 피할 것 (과포화 시작)
3. **온도 안정**: 측정 중 온도 변동 < 0.5°C

#### 6.4.8 취득 시간 추정

- **신호 5개 수준**: 약 20분 (각 수준당 1회 조절 가정)

### 6.5 Lag/Ghost 측정용 영상

#### 6.5.1 목적

노출 후 전하 갇힘 시간 상수(Lag)를 측정합니다.

- **사용처**: 래그 보정 계수 (지수 상수 τ 등)
- **특성**: 신호 수준, 온도, 노출 조건 의존

#### 6.5.2 필요 장비

- 검출기
- X-ray 발생기 (70 kVp, 21 mm Al)
- 균일 산란 팬텀
- NTC 온도 센서

#### 6.5.3 측정 절차

**9개 신호 수준에서 각각: FSRF + RSRF 측정**

```
FOR each Signal_Level E in [2%, 5%, 10%, 20%, 30%, 50%, 70%, 80%, 92%]:
    
    Step a. 검출기 안정화
    ├─ 20개 dark 프레임 취득
    │  (신호 가공을 위한 기준선)
    └─ 파일명: dark_lag_E[level].raw
    
    Step b. FSRF 측정 (Falling Step Response Function)
    │ (노출 ON → OFF 모니터링)
    │
    ├─ 노출 수준을 E% 포화로 설정 (mAs 확인)
    ├─ X-ray ON
    ├─ N_pre = 200 프레임 수집 (안정 신호)
    ├─ X-ray OFF (즉시)
    ├─ N_post = 200 프레임 연속 수집
    │  (감쇠하는 래그 신호 기록)
    ├─ 프레임 시간: 30 Hz (약 33 ms 간격)
    └─ 파일명: fsrf_E[level]_[percent]sat.raw
    
    Step c. RSRF 측정 (Rising Step Response Function)
    │ (노출 OFF → ON 모니터링)
    │
    ├─ N_pre = 50 dark 프레임
    ├─ X-ray ON (신호 수준 E%)
    ├─ N_post = 200 프레임 수집
    │  (상승하는 신호 + 미세 과조사 기록)
    └─ 파일명: rsrf_E[level]_[percent]sat.raw
```

#### 6.5.4 취득 수량

| 항목 | 수량 |
|-----|------|
| **신호 수준** | 9개 |
| **FSRF 프레임/수준** | 200 + 200 = 400 |
| **RSRF 프레임/수준** | 50 + 200 = 250 |
| **Dark 프레임/수준** | 20 |
| **총 프레임/수준** | 400 + 250 + 20 = **670** |
| **전체 총계** | 670 × 9 = **6,030 프레임** |

#### 6.5.5 합격 기준

**래그 보정 후**:

| 기준 | 임계값 |
|-----|--------|
| **1차 프레임 래그** | < 0.3% |
| **50차 프레임 래그** | < 0.01% |
| **지수 피팅 R²** | > 0.98 |
| **신호 수준 선형성** | 반경향성 일관 |

#### 6.5.6 주의사항

1. **프레임 레이트**: 일정한 프레임 간격 (30 Hz 권장)
2. **노출 전환**: 즉시 X-ray 켜짐/꺼짐 (서서히 아님)
3. **온도 안정**: 측정 중 온도 변동 < 1°C

#### 6.5.7 취득 시간 추정

- **신호 수준 1개**: (400+250+20) / 30 fps ≈ 23초
- **9 수준 전체**: 약 3.5분 (수준 간 전환 제외)

## 8. 취득 실패 판정 및 재촬영 조건

### 8.1 실패 원인 분류

| 원인 | 증상 | 즉시 조치 |
|-----|------|--------|
| **온도 불안정** | ΔT > 0.5°C | 30분 대기 후 재촬영 |
| **신호 부족** | 평균 < 요구값의 50% | mAs ↑ 또는 기지 조절 |
| **신호 과잉** | 포화 > 임계값 | mAs ↓ 또는 거리 ↑ |
| **노이즈 과다** | σ > 임계값 | 프레임 수 ↑ 또는 환경 개선 |
| **팬텀 오위치** | σ/μ 불균일 | 팬텀 재정렬 |
| **X-ray 불안정** | 프레임 간 신호 편차 > 3% | 튜브 재워밍업 |
| **검출기 결함** | 계속되는 불합격 | 검출기 교체 검토 |

### 8.2 재촬영 절차

#### 8.2.1 온도 불안정 원인

**원인 분석**:
- 실내 에어컨 변동
- 검출기 워밍업 불충분
- 튜브 열 방출

**재촬영 조건**:
```
1. 원인 제거 (에어컨 안정화, 추가 워밍업 등)
2. 온도 안정화 대기: 30분 이상
3. 온도 편차 < 0.1°C/분 확인
4. 영상 재촬영
```

#### 8.2.2 신호 수준 불적절

**원인 분석**:
- mAs 설정 부정확
- SID 변경
- 팬텀 이동
- X-ray 필터 손상

**재촬영 조건**:
```
Dark Frame 불합격:
└─ 원인: X-ray OFF 확인 불완전
   재촬영: X-ray OFF LED 재확인 후

Flat-field Frame 불합격:
├─ 신호 < 40% 포화:
│  └─ mAs를 20~30% 증가
├─ 신호 > 60% 포화:
│  └─ mAs를 20~30% 감소
└─ 불균일 (σ/μ > 1%):
   └─ 팬텀 위치 확인, 재정렬
```

#### 8.2.3 아티팩트 발견

**증상**: 포화 픽셀, 스트라이프, 명확한 결함 영역

**재촠영 조건**:
```
1. 원인 식별:
   - 포화: mAs 감소 필요
   - 스트라이프: X-ray 간섭 또는 튜브 불안정
   - 결함: 검출기 결함 또는 팬텀 오염
   
2. 조치:
   - mAs 수정 또는 환경 개선
   - 장비 재확인
   
3. 재촬영
```
