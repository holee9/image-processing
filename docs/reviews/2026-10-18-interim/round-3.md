# 3차 리뷰 — 통합·추적성 및 발견 재확인

이슈: #276. 1·2차의 발견을 고정 Git 객체와 관련 이슈에 다시 대조했다. 새 제품 수정 없이 기존 발견의 해소 여부, 거짓 양성, 최종 통합 가능성을 재평가했다.

## 전수 재확인

- 시작/종료 HEAD5개가 동일함을 확인했다. 스캔은 작업 트리 임시 파일 대신 고정 Git 객체를 읽는다.
- pre7파일, post5파일, GUI24파일, 문서3파일이 main과 다른 제품/문서 경로다. 이는 레인별 diff 개수이며 서로 겹치는 DICOM 파일을 합산한 고유 변경 수가 아니다.
- GUI24파일에는 제품 gui/4파일과 진단 clients/15파일 및 DICOM5파일이 포함된다. 제품 GUI를 clients/만으로 판정하는 검색 범위 오류를 피했다.
- 코드 인용과 문서 상태 표시는 독립 실행 근거로 대체하지 않았다. common의 △ 정정, AI OOD 문턱 정정 등 이미 해소된 표현 문제는 현재 미수정 결함으로 중복 집계하지 않았다.
- QA271의 철회 문구는 pre75c00431에서 '철회된 원문'으로 추가 표시된 보고서 전용 변경이다. 이를 보정 알고리즘 수정이나 B16 통과로 읽지 않는다.
- B16 기존118/178 실패·31개 판정 보류·새 촬영 뒤 지표 결정은 유지한다.

## 링크 후보 반증

정규식이 찾은33개 후보를 그대로 결함 수로 쓰지 않았다. 수식·코드의 대괄호, 존재하는 디렉터리, 빌드 생성 HTML을 제외하고 고정 tree에 실제로 없는 Markdown/디렉터리 링크10개를 확인했다:

- docs/display/README.md:7, xpe-display-prd.md:9의 SPEC-XPE-MASTER.md(실제는 SPEC-XPE-MASTER/spec.md).
- docs/post-processing/xpe/README.md:349~356의 ghost-correction/calibration/panel-defect/enhance-basic/enhance-advanced/ai-module/display/dicom 경로(현재 상대 경로의 단계가 한 단계 부족).

이는 일반 탐색 링크 문제이며 요구 산출물 자체가 모두 없다는 주장이 아니다. 생성 도움말 HTML의 배포 결과는 별도 미검증이다.

## 최종 중간 판정

고정 main의 제품 CI는 성공했지만 최신 레인 조합은 병합·동일 헤더/DLL·DOC-06·통합 CI 검증이 완료되지 않았다. 해당 조합의 통합 승인과 제품 전체/규제/임상 완료 선언을 보류한다. 각 발견의 해결 방향과 구체 게이트는 report.md에 정리했다.
